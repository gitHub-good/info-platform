- **概览 11 块并列无主次**：今日区（推荐/异动/政策 3 块）+ V2.0 工作台（热度/推荐摘要/事件/大盘健康 4 块）+ 平台健康三卡——「最新推荐摘要」与主位「今日推荐」同屏重复推荐心智；V2.2 招牌产出「全市场 Top10」概览缺位；运维信息与投资决策信息同权重并列。

### ⚖️ 拍板一 · 信息流豁免分页：保留无限滚动，配套补偿提前入一批

**裁决**：信息流 `/feed` **豁免分页，保留无限滚动**；配套「已加载 N 条」常驻计数 + 浮动「回到顶部」按钮**由 UI 建议的二批提前至一批交付**（清单 #6）。

**理由**（对用户「列表展示的需要使用分页展示」的口径解析）：

1. **诉求意图**：用户痛点指向**查询型列表**（有筛选、有 total、消费目的 = 检索回看定位）——事件流/推荐中心/订阅管理命中此列，全量分页化；信息流是**阅读型流水**（时间倒序、卡片连续消费、无检索心智），翻页打断阅读心流，feed 类产品业界惯例均为无限滚动。用户口径按意图解释而非字面穷举。
2. **工程成本**：后端游标协议（nextCursor 无 total），分页化需补 total + page 模式 ≈ +1 人天后端，收益/成本比低。
3. **痛点真因**：「失控感」（不知加载了多少、深滚回不去）用配套解决即可，不需要换形态——故配套与豁免裁决**绑定同批交付**（PM 校准点：UI 原建议二批，若配套滞后则豁免裁决在主体上线后「裸奔」，不合理）。
4. **复议出口**：用户若再提「信息流也要分页」→ 走变更控制（UI 界面歧义单流程已承诺 1 日内出改稿，后端 +1d），本拍板版本化留档不悄悄改。

### ⚖️ 拍板二 · 订阅管理分页化：归二批（V3.1），不进一批也不沉 backlog

**裁决**：订阅管理 `/subscriptions` 分页化归**二批 M26**（UI 建议采纳，清单 #9）。

**理由**：①管理页性质属查询型列表，在用户「列表需要分页」口径覆盖范围内，**沉 backlog 违背口径完整性**；②但个人自用订阅量小（量级 ~10），一批抢线价值低；③一批事件流/推荐中心改造确立「游标 → M9 分页」改造范式（含后端 page/size 契约模式），二批复用范式成本更低。**二批收口后全站「加载更多」游标形态清零**（信息流为唯一豁免项，拍板一在册）——「列表分页化」诉求以「查询型全分页 + 阅读型豁免有补偿」的完整口径闭环。

## 📝 用户故事与验收标准

### 故事 1 · 双行顶栏导航（诉求四）

作为 平台使用者，我想要 侧边栏换成顶部导航（主行分组 Tab + 页签行页面页签），以便 获得更宽的内容阅读带宽、当前分组页面一目了然。

验收标准：

- 场景 1（桌面双行形态）：Given lg+ 视口 When 打开任一页 Then 主行（Logo + 总览/数据/分析/运维 4 分组 Tab + 铃铛/登出）与页签行（当前分组页面页签）渲染，桌面左侧栏与 `lg:pl-56` 缩进移除；「总览」单页组点击直达 `#/overview` 且不渲染页签行；顶栏 sticky（主行 top-0 / 页签行 top-14）毛玻璃生效。
- 场景 2（17 页可达性零损失）：Given navConfig 4 分组 17 页 When 逐页导航 Then 每页经顶栏 ≤2 次点击可达，当前页签带 `aria-current="page"` 与 2px 蓝系指示条；`/market-top/methodology` 子路由命中「全市场推荐」页签；分析/运维组 7 项页签在 768px 内容宽内放得下（极窄横向滚动兜底、当前页滚入可视区）。
- 场景 3（窄屏兼容零回归）：Given <lg 视口 When 打开页面 Then 顶栏单行（汉堡 + 当前页标题 + 铃铛 + 登出），抽屉内分组 17 项完整导航；Escape 关闭/遮罩点击/焦点圈定/选中即收起逻辑零改动保留。
