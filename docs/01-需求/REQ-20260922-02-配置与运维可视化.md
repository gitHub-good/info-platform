# 📥 配置与运维可视化 · 轻量需求设计报告（v1.1）

> 把 LLM 模型配置、数据源配置、任务执行搬到前端页面可视化：看得见、改得了、立即生效、手动可控，并给全部页面一个统一入口。

## 📌 需求元信息

- 编号：REQ-20260922-02（承接 [REQ-20260920-01](./REQ-20260920-01-信息整合平台.md)，v1 已交付 T01~T33）
- 类型：功能（主体）+ 优化（统一导航）
- 优先级：Must（v1.1 主题）
- 来源：业务方原始诉求（"把模型配置、抓取数据源配置、数据展示，任务执行等都使用前端页面可视化出来，并且前端页面都交互设计的好看操作起来方便合理"）

## 📌 背景与问题

**现状**：v1（M1~M3）已交付标的聚合、AI 简报、政策时事、watchlist、成本报表、Job 日志等 6 个业务页面，后端 5 个定时任务（政策抓取、政策倾向判断、异动检测、推送补推、每日推荐）与全部配置运行正常。但**配置与运维侧仍是"黑盒"**：

1. **LLM 模型配置看不了也改不了**：provider 清单（DeepSeek/GLM/预留通义/Kimi）、模型名、单价、日预算、告警阈值、缓存 TTL、超时重试全部写死在 `application.yml`；API key 走环境变量，配没配、配的谁，前端无从知晓。
2. **数据源配置看不了改不了**：7 个数据源（行情/财务/估值/公告/新闻/政策/事件）的 mock 开关、端点 URL、超时、重试、取数条数同样是静态配置；想临时切 mock 验证或调超时，只能改文件重启。
3. **任务只能看历史，不能干预**：Job 执行日志页是只读的；想"立刻抓一次政策""手动重跑每日推荐"无从下手，只能等下个调度周期。
4. **改配置必须重启**：所有配置改动都要重启服务才生效，"调个预算止损"变成"改文件→停服务→起服务"。
5. **页面入口分散**：6 个业务页各自孤立 hash 路由，无统一导航与总览；个人信息流（T27 后端服务）甚至没有前端入口。

**不做的代价**：每次调参都要登录服务器改 yml 并重启，运营效率低且容易改错；任务行为不可控，验证链路（改配置→看效果）无法闭环；新页面继续无序堆放，入口越来越难找。

## 🎯 目标

v1.1（M4，约 1 个月）达成：

- **配置可视**：LLM 模型配置与数据源配置全部可在前端查看与编辑，API key 脱敏展示、明文永不回显。
- **保存即生效**：高频运营参数（日预算、告警阈值、单价、缓存 TTL、mock 开关）保存后**无需重启**即对新请求生效。
- **任务可控**：全部定时任务可查看调度状态与上次执行结果，支持"立即执行"手动触发并实时看到状态流转。
- **入口统一**：全站统一导航（桌面侧边栏/移动端收起），所有页面 ≤1 次点击可达；补个人信息流前端入口。
- **一屏总览**：概览页展示今日成本水位、异动、政策、任务与数据源健康度。

## 📝 用户故事与验收标准

### 故事 1 · 统一导航与信息架构

作为 个人投资者，我想要 一个覆盖全部页面的统一导航（桌面侧边栏、移动端收起），以便 任何功能一次点击可达、不用记散落的 URL。

验收标准：

- 场景 1（全量可达）：Given 用户已登录 When 打开任意页面 Then 导航按"总览 / 数据（自选、标的详情、政策）/ 分析（AI 简报、信息流）/ 运维（任务中心、Job 日志、成本报表、模型配置、数据源配置）"分组展示，当前页高亮，全部页面 ≤1 次点击可达。
- 场景 2（登录守卫）：Given 未登录 When 直接访问任一 hash 路由 Then 跳转登录页，登录成功后回到原目标页。
- 场景 3（导航健壮性）：Given 任一业务接口失败 When 页面渲染 Then 导航本身正常展示（导航不依赖业务数据），业务区显示既有错误态组件。

INVEST 自检：独立 高 / 可估时 是（≈2.5 人天）/ 可测试 是。

### 故事 2 · LLM 模型配置可视化

作为 个人投资者，我想要 在前端查看并修改 LLM provider 配置（模型、单价、日预算、告警阈值、缓存 TTL、超时）且保存后立即生效，以便 不碰服务器文件即可调参止损、按厂商调价同步成本口径。

验收标准：

- 场景 1（查看）：Given 已登录 When 打开"模型配置"页 Then 展示 provider 列表（名称/模型/启用/默认/fallback/输入输出单价/超时）与全局参数（日预算、告警阈值、缓存 TTL 分档、重试），数值均来自当前生效配置。
- 场景 2（改预算即生效）：Given 当前日预算 20000 token When 修改为 5000 并保存 Then 提示保存成功，不重启服务，下一次 LLM 调用按 5000 执行预算守卫，且成本报表页显示的预算上限同步为 5000。
- 场景 3（改单价）：Given deepseek 输入单价 1.0 元/百万 token When 修改为 2.0 保存 Then 后续调用成本按 2.0 估算，历史留痕成本不重算。
- 场景 4（key 脱敏）：Given deepseek 已通过环境变量注入 key When 查看配置 Then key 字段仅显示"已配置（尾 4 位 ****abcd）"，不出现完整明文；When 在页面录入新 key 保存 Then 保存成功后仍只显示脱敏态，刷新页面不回显明文。
- 场景 5（非法值拦截）：Given 单价输入负数、预算输入 0 或负数、告警阈值不在 (0,1] 区间、TTL 输入非正整数 When 保存 Then 校验拦截并提示具体原因，原值不变，未发起保存请求或后端返回明确错误码。
- 场景 6（重启不丢配置）：Given 页面修改预算并保存成功 When 重启服务后再次打开配置页 Then 显示的仍是修改后的值（配置持久化在非易失介质，不回滚）。

INVEST 自检：独立 中（依赖配置底座 T34）/ 可估时 是（接口 1.5 + 前端 2 人天拆分）/ 可测试 是。

### 故事 3 · 数据源配置可视化

作为 个人投资者，我想要 在前端查看并修改 7 个数据源的运行模式与弹性参数、看到每个源的健康状态，以便 快速定位"哪个源挂了"、临时切 mock 验证、按限频情况调超时与条数。

验收标准：

- 场景 1（查看与状态）：Given 已登录 When 打开"数据源配置"页 Then 以卡片列出全部 7 个数据源（行情/财务/估值/公告/新闻/政策/事件），每卡显示：启用态、运行模式（mock/真实）、关键参数（超时/重试/取数条数）、最近一次抓取结果与时间（取自 data_source_event）。
- 场景 2（切 mock 即生效）：Given 行情源当前为真实模式 When 切换为 mock 保存 Then 保存成功后新的标的详情聚合请求该分区走 mock 数据（无需重启），卡片模式标识同步为 mock。
- 场景 3（调超时）：Given 聚合总超时 2000ms When 修改为 3000ms 保存 Then 新的聚合请求按 3000ms 预算执行（Should 级热生效）。
- 场景 4（非法值拦截）：Given URL 输入非法格式、超时或条数输入 0/负数/非数字 When 保存 Then 校验拦截并提示原因，原配置不变。
- 场景 5（空态）：Given 某源从未产生过 data_source_event When 查看该卡片 Then 显示"暂无抓取记录"占位，不报错不空白。

INVEST 自检：独立 中（依赖配置底座 T34）/ 可估时 是（接口 1.5 + 前端 1.5 人天拆分）/ 可测试 是。

### 故事 4 · 任务执行中心

作为 个人投资者，我想要 在前端看到全部定时任务的调度状态与上次执行结果，并能"立即执行"某个任务、实时看到状态流转，以便 改完配置立刻验证效果、不等到下个调度周期、快速发现失败任务。

验收标准：

- 场景 1（任务总览）：Given 已登录 When 打开"任务中心"页 Then 列出全部 5 个平台任务（政策抓取/政策倾向判断/异动检测/推送补推/每日推荐），每项显示：调度开关、调度参数（间隔或 cron）、上次执行时间/状态/耗时、可推算的下次执行时间。
- 场景 2（手动触发）：Given 政策抓取任务当前空闲 When 点击"立即执行" Then 任务异步启动，页面 5 秒内显示"运行中"（轮询刷新），执行结束后状态更新为成功/失败并写入 job_execution_log，点击可查看本次执行详情（复用既有日志字段）。
- 场景 3（触发见效）：Given 手动触发政策抓取成功 When 打开政策时事页 Then 可看到新抓取入库的条目（触发→效果闭环）。
- 场景 4（防重入）：Given 某任务正在运行 When 再次点击"立即执行" Then 按钮置灰并提示"任务运行中"，不产生第二次并发执行。
- 场景 5（从未执行空态）：Given 某任务注册后从未执行 When 查看任务中心 Then 上次执行显示"从未执行"，下次执行时间正常展示，不报错。
- 场景 6（启停明示）：Given 每日推荐调度当前关闭 When 在页面开启并保存 Then 若热切换实现则不重启即按 cron 调度；若架构裁定需重启，则页面明示"重启后生效"（两者择一，不许无提示的静默不生效）。

INVEST 自检：独立 高（复用 job_execution_log 留痕）/ 可估时 是（接口 2 + 前端 2 人天拆分）/ 可测试 是。

### 故事 5 · 概览仪表盘（Should）

作为 个人投资者，我想要 打开平台先看到一屏总览（今日 LLM 成本水位、异动条数、最新政策、任务健康、数据源健康），以便 10 秒内判断"今天平台是否正常、有没有值得看的事"。

验收标准：

- 场景 1（总览内容）：Given 当日已产生 LLM 调用与异动 When 打开总览页 Then 一屏展示：今日 LLM 成本与预算水位条（复用成本报表口径）、今日异动条数、最近 24h 政策条数、任务健康摘要（近 24h 失败次数）、数据源健康摘要（最近抓取成败），每项卡片可点击跳转对应页面。
- 场景 2（空态）：Given 当日无任何调用与事件 When 打开总览 Then 各卡片显示 0 或"暂无数据"，不报错。

INVEST 自检：独立 高（聚合既有接口）/ 可估时 是（2 人天）/ 可测试 是。

### 故事 6 · 个人信息流前端页（Should）

作为 个人投资者，我想要 一个个人信息流页面承载 T27 已交付的信息流服务（订阅命中 + 关键词高亮 + 游标分页），以便 v1 故事 5 的"只看与我相关的"在前端真正可用。

验收标准：

- 场景 1（信息流展示）：Given 用户已有主题/标的订阅 When 打开信息流页 Then 展示按时间倒序的命中内容流，命中关键词高亮，向下滚动触发游标分页加载。
- 场景 2（空态）：Given 用户无任何订阅 When 打开信息流 Then 显示引导空态（提示去配置订阅），不报错。

INVEST 自检：独立 高（后端 T27 已交付）/ 可估时 是（1.5 人天）/ 可测试 是。

## ⚖️ 优先级排序

**MoSCoW 粗排**：Must = 统一导航、LLM 配置、数据源配置、任务中心；Should = 概览、连通性测试、任务热切换、信息流页（见条目清单表）。

**RICE 精排**：

> Reach = 一个 2 周迭代内触达的交互次数（单人量级，仅作相对比较）；Impact：3=massive，2=high，1=medium；Confidence：100%=有数据，80%=有依据推测；Effort=人天。

| 模块 | Reach | Impact | Confidence | Effort(人天) | RICE 分数 |
| --- | --- | --- | --- | --- | --- |
| 统一导航 | 700 | 1 | 100% | 2.5 | (700×1×1)/2.5 = 280 |
| 概览仪表盘 | 140 | 1 | 80% | 2 | (140×1×0.8)/2 ≈ 56 |
| 任务执行中心 | 120 | 2 | 80% | 4 | (120×2×0.8)/4 ≈ 48 |
| 个人信息流页 | 60 | 2 | 80% | 1.5 | (60×2×0.8)/1.5 ≈ 64 |
| LLM 模型配置 | 60 | 2 | 80% | 3.5 | (60×2×0.8)/3.5 ≈ 27 |
| 数据源配置 | 50 | 2 | 80% | 3 | (50×2×0.8)/3 ≈ 27 |

排序结论：**导航先行（成本最低、每次使用都触达），配置底座与任务接口并进，前端页随后，概览与信息流收尾**——任务中心与 LLM 配置是本次痛点核心（改不了配置、控不了任务），虽 RICE 低于高频展示项，但 MoSCoW 为 Must 不可延后。

## ⚙️ 非功能需求

- **安全**：API key 明文永不回显前端、不写入前端 console 与网络日志；前端录入的新 key 传输与存储方案（加密/环境变量同步等）由架构裁定，需求红线只有"不回显、不留痕"。
- **一致性**：配置保存成功后刷新页面仍为新值；服务重启后配置不回滚（持久化到非易失介质，介质选型归架构）。
- **防重入**：同一任务同时只允许一个手动触发实例在运行。
- **校验**：单价 ≥0、预算 >0、告警阈值 ∈(0,1]、TTL/超时/条数为正整数、URL 合法格式；前后端双侧校验。
- **体验**：新页面沿用既有暗色主题与 shadcn/ui 组件风格；所有"重启后生效"的配置项必须在保存时明示，不允许静默不生效。

## ⚠️ 依赖与风险

| 依赖/风险 | 说明 | 对策 |
| --- | --- | --- |
| 热生效机制选型 | Spring 条件装配（@ConditionalOnProperty）为启动期生效，任务启停/间隔热切换与现状冲突 | 需求已分级：高频运营参数热生效 Must，任务热切换降为 Should 并允许"明示重启生效"；具体机制（DB 配置表/刷新总线等）交架构 Spike 或 ADR |
| API key 前端写入的存储安全 | 明文落库有泄露风险（本地单人场景风险有限但不可忽视） | 需求红线：明文不回显、不留痕；存储加密方案交架构 ADR，接受"key 仍走环境变量、页面只读状态"的降级实现 |
| 手动触发并发防护 | SQLite 单写者模型下并发跑 Job 可能锁冲突 | 防重入为 Must 验收场景（场景 4）；触发接口串行化/排队由架构设计 |
| 单价修改的报表口径 | 调价后历史成本留痕与现价估算可能混淆 | 需求明确：历史留痕不重算，新调用按新单价（故事 2 场景 3） |
| 配置页自身误操作 | 预算改太小会拦截正常调用，mock 忘切回会污染真实数据 | 保存时二次确认 + 显示当前用量/模式对比；数据源卡片常显当前模式标识 |
| 范围蔓延 | "可视化"易滑向业务页重做、权限体系 | Won't 清单已明确不做项，新增走变更控制 |
