# 📥 提示词模板可视化治理 · 轻量需求设计报告（v1.0）

> 把 4 个 AI 场景的提示词模板搬到前端页面可视化维护：新增/编辑/删除全页面化，场景与模板的关联可配置切换，保存即生效、版本可回滚，且任何操作都不破坏生成链路。

## 📌 需求元信息

- 编号：REQ-20260922-03（承接 [REQ-20260922-02](./REQ-20260922-02-配置与运维可视化.md)，其 M4 已交付验收 Go；平台需求序列第 3 批）
- 类型：功能（主体）+ 优化（导航接入）
- 优先级：Must（M5 主题）
- 来源：业务方原始诉求（"提示词模版也需要使用可视化页面维护，新增，删除，修改，并且提示词在使用的地方也使用可配置化进行关联起来，这样比较灵活符合业务诉求"）

## 📌 背景与问题

**现状**（代码核实，2026-09-22）：

1. T20 已落地 `prompt_template` 表（V8 迁移）：`brief_type`（TINYINT）+ `version`（语义版本 TEXT）+ `template`（`---SYSTEM---`/`---USER---` 分段 + `{{key}}` 占位符）+ `status`（1 启用 / 0 废弃），UNIQUE(brief_type, version)；播种 4 类模板（1 个股简报 / 2 事件归因 / 3 政策解读 / 4 每日推荐）。T29 将每日推荐升级 v1.1（v1.0 置废留痕）。
2. **"场景→模板"按 briefType 硬编码**：AIBriefService（个股/事件归因/每日推荐）、PolicyTendencyService（政策解读）每次生成前按 `findActiveByBriefType`（该场景 status=1 的最新版本）现查模板。
3. **改模板只能动数据库**：无管理接口、无页面；连"调一处措辞"都要写 SQL 或 Flyway 迁移（T29 先例），无法试错、无回滚操作通道。
4. M4 已把模型/数据源/任务配置页面化（runtime_config 唯一权威，ADR-0017/0020），**提示词是最后一块"改得了却看不见"的 AI 配置**。

**不做的代价**：提示词是 AI 产出质量的第一杠杆（T29 仅注入阅读画像就显著改变推荐口径），但当前调整成本=改库+无回滚，导致"不敢调、调了忘"；模板版本全貌与各场景当前用哪版，只能查表才知道。

**有利条件**（需求核实结论）：生成链路每次现查激活模板，模板/绑定变更后**下一次生成天然用新值**；LLM 响应缓存键含渲染后消息全文哈希（LlmCache `keyOf`），模板变更自动缓存失效——"即时生效"无缓存障碍（机制确认归架构，见风险表）。

## 🎯 目标

M5（约 5.5 人天）达成：

- **全量可视**：4 场景全部模板版本一页可见，激活版本显著标识，"哪个 AI 能力在用哪版提示词"一眼看清。
- **页面维护**：新增/编辑/删除全页面化，编辑即落新版本，保存激活后下一次生成即用新值。
- **版本安全**：任何修改自动留旧版可回滚；删除有守卫，任何操作后每个场景仍有且仅有一个启用模板，生成链路永不因页面操作中断。
- **降低门槛**：编辑时提供该场景可用占位符清单与用途说明，不翻代码即可安全改写模板。

### ⚖️ 需求侧拍板（四个裁决点）

| 裁决点 | 结论 | 理由 |
| --- | --- | --- |
| "删除"语义 | **置废版本可物理删除；激活版本禁止直接删除（须先把激活切走）；编辑升级旧版走置废留痕（沿 T29 先例）** | T29 先例的"置废"是**版本被替代**（v1.0→v1.1），不是用户显式删除；用户"删除"心智是"清掉不要的版本"→ 对已置废版本物理删满足字面诉求且列表清爽。物理删只发生在"本就没在用"的版本上，运行安全；活跃版本链靠"编辑即新版本+自动置废"天然留痕可回滚 |
| 新增模板的场景归属 | **仅支持既有 4 场景的模板变体/新版本，不做全新自定义场景** | 用户原话的"新增"指模板而非场景，无新场景诉求证据；新场景牵动 BriefType 枚举、上下文构造器、触发入口、结果消费整条链路，属"新 AI 能力立项"而非"配置可视化"。列入 Won't，有真实诉求走变更控制 |
| 绑定粒度 | **场景级：每场景有且仅有一个激活（启用）版本，绑定即激活** | 与现状运行语义（`findActiveByBriefType`）完全对齐，生成链路（AIBriefService 3 类 + PolicyTendencyService）零改动即获得可配置能力；"场景+版本"双维绑定会造出 status 列与绑定表两份真相，且无按版本路由的消费方。版本回滚 = 把激活切回旧版本 |
| 占位符安全 | **保存时校验，分级：结构性问题硬拦截；移除既有占位符默认拦截、逐项显式确认后放行；新增无来源占位符仅警告** | 分段标记缺失现状会抛 IllegalStateException（数据损坏）、system 段含 "json" 是 DeepSeek JSON mode 前提（V8 播种不变量）——两者必须硬拦截；移除占位符=上下文信息静默丢失且多为误删，默认拦住，但有意精简是合法诉求，留确认通道；新增键渲染时原样保留可见（现状语义），警告即可 |

## 📝 用户故事与验收标准

### 故事 1 · 模板列表与绑定总览

作为 个人投资者，我想要 一个提示词模板管理页，按 4 个 AI 场景分组查看全部版本、激活状态与模板内容，以便 知道每个 AI 能力当前用的是哪版提示词、历史版本长什么样。

验收标准：

- 场景 1（导航与分组）：Given 已登录 When 打开"提示词模板"页（侧栏运维组新增入口，第 13 页）Then 按 4 场景分组（个股简报/事件归因/政策解读/每日推荐）列出全部版本，每版本显示：版本号、状态（激活/已置废）、更新时间、占位符数量；当前激活版本显著标识。
- 场景 2（内容查看）：Given 每日推荐存在 v1.0（置废）与 v1.1（激活）When 展开版本详情 Then SYSTEM/USER 两段分开展示，`{{key}}` 占位符高亮。
- 场景 3（异常空态）：Given 某场景无启用版本（如手工改库造成的数据异常）When 查看该分组 Then 明确警示"该场景无启用模板，AI 生成将失败"，不静默空白。

INVEST 自检：独立 高 / 可估时 是（1 人天）/ 可测试 是。

### 故事 2 · 模板编辑与新增

作为 个人投资者，我想要 在页面上编辑模板内容或新建版本，保存时自动落为新版本并激活，以便 调优提示词不碰数据库，每次修改可追溯、可回退，且下一次生成立即用新值。

验收标准：

- 场景 1（编辑即新版本）：Given 个股简报当前激活 v1.0 When 编辑内容保存 Then 落库为新版本行并置为激活，原 v1.0 自动置废（沿 T29 升级语义）；列表刷新后两版本均在、状态正确。
- 场景 2（即时生效）：Given 修改个股简报模板并保存激活 When 手动触发一次 AI 简报生成 Then 本次生成使用新模板内容（模板变更不命中旧缓存，产出按新模板口径）。
- 场景 3（分段标记硬校验）：Given 编辑内容删除了 `---USER---` 标记（或两标记顺序颠倒）When 保存 Then 校验拦截并提示具体缺失项，不落库。
- 场景 4（json 字样硬校验）：Given 编辑后 system 段不含 "json" 字样 When 保存 Then 拦截并提示"system 段须含 json 字样（JSON 输出模式前提）"。
- 场景 5（移除占位符拦截 + 确认放行）：Given 当前激活版含 `{{subjectName}}` When 保存版移除了它并直接保存 Then 拦截并逐个列出"将被移除的占位符"及各自注入的数据说明；When 用户逐项勾选"确认移除"后再保存 Then 放行落库。
- 场景 6（新增无来源占位符警告）：Given 保存版新增了该场景上下文不提供的 `{{foo}}` When 保存 Then 警告"该占位符无上下文来源，渲染时将原样发给模型"，确认后可保存（不阻断）。
- 场景 7（版本号规则）：Given 编辑保存 Then 版本号默认自动递增次版本（v1.1→v1.2），可选升主版本（v2.0）；生成的版本号与该场景既有版本冲突时拦截。

INVEST 自检：独立 中（依赖 T45 管理接口）/ 可估时 是（接口 2 + 前端 3 人天拆分）/ 可测试 是。

### 故事 3 · 激活切换与版本删除

作为 个人投资者，我想要 把激活切换到任意保留版本（含旧版本，即回滚），并物理删除确认不要的置废版本，以便 试错新提示词后随时退回稳定版，删除有守卫、永不破坏生成链路。

验收标准：

- 场景 1（激活切换/回滚）：Given 每日推荐当前激活 v1.1 When 把激活切到 v1.0 Then v1.0 成为该场景唯一启用版本、v1.1 自动置废，下一次每日推荐生成按 v1.0 模板执行。
- 场景 2（删除激活版本拦截）：Given 版本为场景当前激活版本 When 点击删除 Then 拦截并提示"激活版本不可删除，请先切换激活到其他版本"。
- 场景 3（删除置废版本）：Given 版本已置废 When 确认删除（二次确认）Then 物理移除该版本行，列表不再显示，其余版本与激活状态不受影响。
- 场景 4（激活唯一不变量）：Given 执行任一保存/切换/删除操作成功后 When 查询该场景 Then 有且仅有一个 status=1 版本（不出现双激活或零激活的可见中间态）。

INVEST 自检：独立 中（与故事 2 共用接口，操作语义独立）/ 可估时 是（含在 T45/T48 内）/ 可测试 是。

### 故事 4 · 场景占位符注册表与编辑器对照（Should）

作为 个人投资者，我想要 编辑模板时看到该场景全部可用占位符及用途说明、并可一键插入，以便 不用翻代码就知道能写哪些 `{{key}}`、各自注入什么数据。

验收标准：

- 场景 1（清单展示）：Given 打开个股简报模板编辑器 When 查看占位符对照区 Then 列出该场景上下文构造器实际提供的全部占位符（如 subjectName/price/newsList 等）及一句话用途说明。
- 场景 2（一键插入）：Given 点击占位符项 `{{price}}` When 插入 Then 光标位置插入 `{{price}}` 文本。
- 场景 3（校验同源）：Given 故事 2 场景 5/6 的保存校验 When 执行 diff Then 校验基准与对照区清单来自同一数据源，口径一致。

INVEST 自检：独立 高（只读接口 + 编辑器增强）/ 可估时 是（0.5 后端 + 并入编辑器前端）/ 可测试 是。

## 🗂️ 范围

**本期做（M5）**：

- 提示词模板管理页（运维组导航接入）：4 场景分组列表、版本详情查看（SYSTEM/USER 分段 + 占位符高亮）。
- 模板编辑与新增：保存校验（分段标记 / json 字样 / 占位符分级）、编辑即新版本、自动版本号、保存激活。
- 激活切换（含回滚旧版本）与置废版本物理删除（守卫：激活不可删、切换保持唯一）。
- 场景占位符注册表只读接口 + 编辑器对照与一键插入。
- 变更即时生效：模板/激活变更后下一次生成即用新值。

**本期不做（Won't）**：

- 全新自定义 AI 场景（新 briefType）——牵动整条生成链路，有真实诉求另行立项（裁决点 2）。
- 同场景多模板并行分流 / A-B 实验（绑定粒度裁定为场景级单激活）。
- 模板导入导出、跨场景复制（各场景占位符集合不同，复制语义有限）。
- 模板变更审计日志（版本行本身即留痕，单人场景不另建审计）。
- 模板内容条件逻辑 / 变量运算（模板保持纯文本 + `{{key}}` 占位符的既有约定）。

> 范围蔓延一律走变更控制：新增条目须重新评估影响面并同步相关方，禁止悄悄加。

## ⚖️ 优先级排序

**MoSCoW 粗排**：Must = 列表总览、编辑与新增、激活切换与删除（用户点名的"维护 + 可配置关联"核心）；Should = 占位符对照（降低误改风险，可随后补齐）。

**RICE 精排**：

> Reach = 一个 2 周迭代内触达的交互次数（单人量级，仅作相对比较）；Impact：3=massive，2=high，1=medium；Confidence：80%=有依据推测；Effort=人天。

| 模块 | Reach | Impact | Confidence | Effort(人天) | RICE 分数 |
| --- | --- | --- | --- | --- | --- |
| 模板列表与绑定总览 | 40 | 2 | 80% | 1.5 | (40×2×0.8)/1.5 ≈ 43 |
| 模板编辑与新增 | 20 | 3 | 80% | 3 | (20×3×0.8)/3 = 16 |
| 激活切换与删除 | 10 | 2 | 80% | 1.5 | (10×2×0.8)/1.5 ≈ 11 |
| 占位符对照 | 20 | 1 | 80% | 1 | (20×1×0.8)/1 = 16 |

排序结论：触达频率低于 M4 各页（低频运营动作），但属**能力解锁型**需求——提示词是全部 4 条 AI 产出的质量杠杆，且用户直接点名，MoSCoW 为 Must 不因 RICE 相对值延后。实现顺序按依赖：管理接口 → 列表页 → 编辑器与版本操作 → 占位符对照。

## ⚙️ 非功能需求

- **一致性（激活唯一不变量）**：任何页面操作成功后，每个场景有且仅有一个 status=1 版本；前后端双侧守护。
- **即时生效**：模板内容或激活版本变更后，下一次生成即用新值，无需重启（已核实 LlmCache 缓存键含渲染后消息全文哈希，模板变更天然缓存失效；是否存在其他缓存层由架构确认）。
- **校验兜底**：分段标记、json 字样、激活守卫在后端接口必须强制（前端校验仅为体验）。
- **体验**：沿用暗色主题与 shadcn/ui；模板正文用等宽字体编辑；删除与激活切换为破坏性操作须二次确认；保存成功反馈明确"已激活，下次生成生效"。
- **可追溯**：编辑升级的旧版本置废留痕（T29 先例），仅显式删除才物理移除。

| 两份真相风险 | 若绑定关系另立配置表与 prompt_template.status 并存，可能漂移 | 需求已裁定：绑定 = 激活（status=1 唯一），不另立绑定真源；存储介质与实现归架构 |
| 缓存口径 | 若存在消息内容哈希之外的缓存层，模板变更后可能命中旧产出 | 需求核实 LlmCache 键含渲染后全文哈希（变更天然失效）；架构确认生成链路无其他缓存，必要时纳入风险注记 |
| 版本号排序语义 | version 为 TEXT 字典序（`ORDER BY version DESC` 取激活），非受控生成可能出现 v1.10 < v1.9 类错序 | 版本号由接口自动生成（两段式递增，冲突拦截），不让用户自由填写；展示序与排序口径由架构校验 |
| 误删/误切换 | 单人误操作直接劣化 AI 产出质量 | 删除/切换二次确认 + 激活守卫 + 编辑即新版本（旧版必留可回滚） |
| 手工改库绕过页面 | 直接 SQL 可能造出双激活/零激活 | 页面异常空态警示（故事 1 场景 3）；不变量守护仅承诺接口路径 |
| 范围蔓延 | "模板治理"易滑向自定义场景、A/B 实验、提示词市场 | Won't 清单已明确不做项，新增走变更控制 |
