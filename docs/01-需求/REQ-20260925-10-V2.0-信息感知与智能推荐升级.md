# 📥 V2.0 信息感知与智能推荐升级 · 版本蓝图（v2.0）

> 从「标的聚合 + 日频推荐」升级为「全市场信息感知 + 事件驱动智能推荐」：30 个主流平台分钟级不间断采集，AI 全行业归类与事件提取，行业走向前置判断，重大事件触发的动态主动推荐，抓取大盘实时监控，UI 2.0。本文件是**版本级蓝图**（能力域差距 + 关键裁决 + M13~M18 分期路线图 + 北极星指标 + 风险表）；每期启动时另立 REQ 细化冻结（沿 M7~M12 惯例）。

## 📌 背景与问题（V1.x 基线与差距盘点）

**现状**（V1.x 已交付，M1~M12）：

- 数据源：6 业务源双备选链（行情东财+腾讯 / 财务东财+新浪 / 公告东财+巨潮 / 新闻新浪 / 政策 gov.cn / 事件本地）+ 页面化降级链配置（ADR-0033/0034）。
- 标的池 5221 只 A 股 + 4 指数（每日自动同步，M7）；政策倾向 AI 判断；AI 简报 4 类（提示词页面化，M5）；个性化推荐（订阅 + 阅读画像，M2/M11）；通知中心 SSE。
- 任务中心 7 个 Job 页面化管理；成本治理（日预算/告警）；留痕生命周期（M10）；列表分页体系（M9/M12）。

**不做的代价**：平台停留在「标的视角的聚合查询工具」，而愿景是「全市场信息的主动感知与推荐引擎」——没有广度采集就没有感知，没有 AI 管道就没有理解，没有事件驱动就没有「主动」，三者构成 V2.0 的不可拆分主线。

## 🎯 目标与北极星指标

V2.0 整体（M13~M18 六期，粗估合计约 85 人天）达成：

- **30 平台**：≥30 个主流信息平台接入并稳定运行，分三批交付（试点 2~3 / 批次一 9~12 / 批次二 +8~10 / 批次三 +6~8）。
- **分钟级感知**：高价值快讯源 1~5 分钟轮询；「实时」口径 = 感知延迟 P50 ≤5 分钟、P90 ≤15 分钟（源发布→入库，见裁决 2）。
- **AI 管道**：入库资讯 100% 过规则预筛与跨源去重、批量过行业归类（申万一级），高重要性条目进事件提取；产出行业热度榜、行业日报/周报、事件→行业影响链与走向判断。

- **大盘**：源维度抓取量/成功率/延迟/资讯量趋势/行业分布/AI 管道吞吐与成本一屏可视，30 秒级刷新。
- **UI 2.0**：设计系统刷新 + 抓取大盘/行业热度/事件流/推荐中心 4 个新页面 + 既有页面组件级升级（不推倒重做）。

## ⚖️ 二、关键裁决（PM 拍板）

### 裁决 1 · 「数据源增删改」的范围边界

**裁决**：V2.0 做两层——①**平台预置源库的启用/停用/参数化**（限频、抓取间隔、取数条数、字段映射微调、降级链编排，沿用既有配置中心体系）；②**通用 RSS/JSON API 源的配置化新增**（标准协议，URL + 间隔 + 字段映射模板，页面新增即生效）。**完全自由的「任意网站自定义爬虫规则」（XPath/CSS 选择器可视化配置、JS 渲染页、登录态源）为 Won't，V3 候选**；HTML 解析类站点走「开发侧适配入预置源库」通道，按里程碑批量交付，页面仍可启停/调参。

**理由**：

1. 主流财经信息平台绝大多数提供 RSS/结构化 API 或稳定 HTML 列表，两层方案已覆盖「自增源」主诉求的八成场景；剩余两成（重 JS 渲染/登录态）恰恰是反爬与合规风险最集中的区域。
2. 完全自由的解析规则配置是另一个量级的产品：规则调试器、实时预览、版本管理、反爬对抗，每项都是独立工程，单人使用场景投入产出严重不成比例。
3. 质量可控：预置源由平台适配并测试，用户只做运营动作；通用源走标准协议、映射字段是有限集合，出错面小、可自动校验（连通性测试）。
4. 增删改语义随此裁决定型：**增** = 通用源页面新增 / 预置源启用；**删** = 停用 + 软删（历史数据保留、配置归档可恢复），预置源不提供物理删除（平台资产）；**改** = 参数化编辑（热生效，沿用 ADR-0017/0033 口径）。

### 裁决 2 · 「实时」的定义

**裁决**：V2.0 的「实时」= **分钟级轮询感知**。高价值快讯源（财联社电报、新浪 7×24 等）1~5 分钟轮询；一般资讯源 15~30 分钟；部委政策源 30~60 分钟。验收口径：**感知延迟 P50 ≤5 分钟、P90 ≤15 分钟**（源发布→平台入库）。「任务不间断」= 7×24 调度不停 + 失败退避重试 + 恢复后增量补抓，**不是零延迟**。**秒级推送为 Won't**。

**理由**：

1. 体系是拉取式 HTTP 采集，无推送通道；秒级感知需要对端 websocket/私有协议合作或常驻连接，主流站点不开放，不在可控范围。
2. A 股信息的价值衰减曲线在分钟级（T+1 交易、盘后公告集中披露），分钟级已覆盖个人投资者的决策时效；把口径定在做不到的秒级只会骗自己。
3. 30 源秒级轮询 = 反爬封禁风险与带宽成本双爆炸（东财 push2 封禁已实证，ADR-0030/0031），与「礼貌抓取」合规红线直接冲突。
4. UI 明示「数据延迟：分钟级」管理预期；延迟实测（P50/P90）进大盘持续可视，用数据而不是口号定义「实时」。

### 裁决 3 · 「前置性行业发展判断」的呈现形态

**裁决**：三种形态分阶段交付，全部是「AI 分析 + 可解释依据」，**不做黑盒预测、不做股价/点位预测**：

1. **行业热度榜**（M15）：近 24h/7d 资讯量 + 事件密度 + 情感加权的行业排名，可下钻行业资讯/事件清单——「现在哪里在起变化」。
2. **行业周报 AI 分析**（M15 日报起步，M17 升级周报）：周期性自动生成「本周回顾 / 事件归纳 / 政策动向 / AI 观点」，每条观点附依据引用（可回溯资讯/事件原文），标注置信度与「AI 分析仅供参考」——「变化意味着什么」。
3. **事件→行业影响链**（M17）：类型化事件触发行业影响评估（如「半导体设备出口管制收紧→利空/利好行业清单 + 逻辑链」），走向判断以趋势性表述呈现——「未来可能往哪走」。

**理由**：用户要的是「有依据的前置判断」而非「算命」；三形态把判断锚定在可回溯的事实（资讯/事件）上，既兑现愿景又守住合规与 AI 幻觉两条红线。具体股价预测/买卖指令为永久 Won't（见范围节）。

### 裁决 4 · V2.0 北极星指标的选择

**裁决**：北极星 = **信息感知延迟 P50 + 行业覆盖率**，配规模（稳定源数/日资讯条数）、价值（推荐采纳信号率）、成本护栏（管道日成本占比/单条成本）三类辅助指标（全表见「目标」节）。

**理由**：不用「推荐收益率/ simulated 收益」做北极星——收益不可控（市场决定）、无法归因（单一变量不可拆）、且滑向投资建议合规红线。感知延迟与行业覆盖是平台**自己可控、可测、可归因**的能力指标，且直接对应用户愿景原话（「实时感知」「全面覆盖全行业」）；价值类用「采纳信号率」（点击/标记有用）而非收益，衡量的是推荐的相关性与时效是否被用户认可。

## 📝 四、版本级用户故事与验收标准（代表故事）

> 每条 ≤2 人天的细化故事在当期 REQ 产出；此处为七域各一条代表故事，锁定版本级验收语义。

### 故事 1 · 通用源自增（能力域 C）

作为 个人投资者，我想要 在数据源页面新增一个通用 RSS/JSON 源（填 URL、抓取间隔、字段映射即可生效），以便 平台没预置的信息渠道我自己 10 分钟内接入，不用等开发排期。

验收标准：

- 场景 1（新增即生效）：Given 源列表无某 RSS 源 When 在源管理页「新增通用源」填入 RSS 地址、间隔 5 分钟、映射标题/链接/发布时间并保存 Then 源出现在列表（类型=通用 RSS），首次抓取在 1 个间隔内执行并入库 ≥1 条。
- 场景 2（配置错误可诊断）：Given 填入非法 URL 或映射缺失 When 保存或点「连通性测试」 Then 前后端校验拦截并提示具体原因；测试按钮反馈可达性与解析结果。
- 场景 3（停用与软删）：Given 某通用源持续失败 When 用户停用 Then 调度立即停止、大盘显示停用态；删除为软删（历史数据保留、配置归档可恢复）。
- 场景 4（预置源边界）：Given 任一预置源（如财联社）When 查看 Then 仅提供启停与参数编辑，无删除入口（裁决 1）。

INVEST 自检：独立 高 / 可估时 是（T101~T106）/ 可测试 是。

### 故事 2 · 分钟级不间断感知（能力域 B）

作为 个人投资者，我想要 高价值资讯源分钟级增量抓取、故障自动恢复并补齐增量，以便 重大事件 5 分钟内进入平台，隔夜发生的事早上一屏看全。

验收标准：

- 场景 1（增量与去重）：Given 财联社电报 5 分钟内新增 3 条 When 调度触发 Then 仅 3 条入库（重复指纹拦截），入库时间与源发布时间差可在大盘观测。
- 场景 2（断流恢复）：Given 某源连续失败 30 分钟后恢复 When 下一轮调度 Then 按退避策略恢复并从上次游标增量补抓，不重不漏。
- 场景 3（错峰与限频）：Given 30 源同时启用 When 调度运行 Then 各源按配置间隔错峰执行，单源请求频率不超其限频配置，限频命中大盘可见。

INVEST 自检：独立 高 / 可估时 是（T103/T104）/ 可测试 是。

### 故事 3 · 批次源接入验收（能力域 A）

作为 平台使用者，我想要 每批新源有一致验收口径（连通/条数/延迟/成功率），以便 30 源规模扩张时质量不滑坡。

验收标准：

- 场景 1（批次验收）：Given 批次一源接入完成 When 连续 7 天观察 Then 每源周成功率 ≥95%、日均有产出（低频源如实标注预期），感知延迟 P50 进大盘统计。
- 场景 2（失效告警）：Given 某源连续失败超阈值 When 达到阈值 Then 大盘标记异常并经通知中心提醒，不阻塞其他源调度。

INVEST 自检：独立 高 / 可估时 是（按源 0.5~1 人天）/ 可测试 是。

### 故事 4 · AI 行业归类与事件提取（能力域 D）

作为 个人投资者，我想要 每条入库资讯自动打行业标签、重要资讯自动提取为结构化事件（类型/标的/重要性/情感），以便 按行业看信息、按事件抓重点，不用逐条读。

验收标准：

- 场景 1（行业归类）：Given 一条新能源行业资讯 When 管道处理 Then 打上申万一级行业标签（多行业取主标签），置信度低于阈值的条目走兜底通道并标记。
- 场景 2（事件提取）：Given 一条「某公司业绩预告净利增 80%」高重要性资讯 When 进入事件提取 Then 产出结构化事件（类型=业绩预告/标的=该公司/方向=利好/重要性=高/原文引用）并进入事件流。
- 场景 3（成本分级）：Given 当日入库 3000 条 When 管道跑完 Then 全量仅过预筛+批量归类，高重要性子集（≤20%）进事件提取，日管道成本在护栏内且成本报表可见。

INVEST 自检：独立 中（依赖资讯流）/ 可估时 是 / 可测试 是（抽检口径见 M15 验收要点）。

### 故事 5 · 行业热度与前置判断（能力域 D）

作为 个人投资者，我想要 行业热度榜（24h/7d）与 AI 行业周报（事件归纳/政策动向/走向判断），以便 先看行业再选标的，对中期方向有依据地预判。

验收标准：

- 场景 2（周报生成）：Given 每周日晚 When 周报任务触发 Then 自动生成本周行业周报，每条观点附依据引用（回溯原文）与置信度，页面标注「AI 分析仅供参考」。
- 场景 3（影响链）：Given 一条政策类高重要性事件 When 查看影响链 Then 展示受影响行业清单（利好/利空+一句话逻辑），可展开完整逻辑链。

INVEST 自检：独立 中（依赖 M15 管道）/ 可估时 是 / 可测试 是。

### 故事 6 · 事件驱动动态推荐（能力域 E）

作为 个人投资者，我想要 重大事件发生时平台主动推送「事件+逻辑+相关标的」推荐卡片，以便 不用盯盘刷资讯，高价值机会主动找我。

验收标准：

- 场景 3（可解释与降噪）：Given 任一推荐卡片 When 查看 Then 展示触发事件、关联逻辑、相关标的与原文链接；低重要性事件不触发推送，推送频次上限可配置。

INVEST 自检：独立 中（依赖 M15）/ 可估时 是 / 可测试 是。

## ⚖️ 六、优先级排序（版本级）

**MoSCoW 粗排**：Must = A（30 源三批）、B（分钟级感知）、C（源运营化两层）、D 核心（预筛/归类/事件提取/热度榜）、E（动态推荐）、F（大盘）、G 新页面与设计系统；Should = D 深化（周报/影响链/走向判断）、既有页面精修、源质量评分；Could = 概念板块维度、通用 RSS 示例包扩充、源评分可视化；Won't 见范围节。

**RICE 精排**（能力域粒度，版本内排序证据）：

> Reach = 一个 2 周迭代内触达的使用次数（单人量级相对值）；Impact：3=massive，2=high，1=medium；Confidence：80%=有依据推测（V1.x 数据/已实证源行为），70%=含未实测环节（源连通性/归类准确率）；Effort=人天（含三批分摊）。

| 能力域 | Reach | Impact | Confidence | Effort(人天) | RICE 分数 |
| --- | --- | --- | --- | --- | --- |
| G UI 2.0 | 600 | 1 | 80% | 12 | (600×1×0.8)/12 = 40 |
| E 动态推荐 | 40 | 3 | 60% | 11 | (40×3×0.6)/11 ≈ 6.5 |
| D AI 管道 | 80 | 3 | 70% | 29 | (80×3×0.7)/29 ≈ 5.8 |
| F 大盘 | 60 | 1 | 80% | 5 | (60×1×0.8)/5 ≈ 9.6 |
| A 批次源接入 | 100 | 3 | 70% | 30 | (100×3×0.7)/30 = 7 |
| B+C 框架底座 | 30 | 3 | 80% | 15 | (30×3×0.8)/15 ≈ 4.8 |

排序结论：**依赖约束优先于 RICE**——B+C 框架是全部域的地基必须先行（RICE 低但 MoSCoW Must 且不可跳过）；A 随框架分批滚动；D 是 E 的前置且单位价值高；G 的 RICE 最高但内容未定时先做界面是空转，故集中收口期交付（设计系统与图表组件可在 M15 起随新页面增量沉淀）。这不是 RICE 失效，而是版本内拓扑排序：**先通路（采集）、再理解（AI）、后呈现（推荐/UI）**。

## ⚙️ 七、非功能需求

- **合规红线**：只抓公开可访问数据；尊重 robots 与源站限频，礼貌抓取（合规 UA/referer）；不模拟登录、不绕付费墙、不破解加密接口；数据仅本机自用分析、不再分发；AI 输出一律「分析参考」口径。
- **成本护栏**：分级管道（全量规则预筛 → 批量归类 → ≤20% 条目深度分析）+ 日预算守卫（复用 M3 成本治理）+ 管道成本大盘可视；预算触顶自动降级（暂停深度分析只保预筛+归类）并在页面明示。
- **数据质量**：跨源指纹去重为入库前置（财经同稿率高）；AI 归类置信度门槛 + 低置信兜底通道；坏数据隔离不进推荐；抽检机制纳入每期验收；源质量评分作为批次验收与淘汰依据。
- **存储**：资讯量级预估日净 ≥2000 条（年百万级），生命周期治理沿用 M10 体系扩键空间，需求锁「清理窗口可配且默认保留 ≥180 天」（行业分析需要长回溯，实现归架构）。
- **调度健壮**：单源失败不阻塞其他源；退避超限进入静默期并告警；恢复自动补抓；新增源维度 Job 视图接入任务中心（复用 M4 体系）。
- **性能**：大盘 30 秒级刷新；信息流/行业页在数据量增长后仍满足既有分页与三态基线（M9/M12 口径）。
- **体验**：UI 2.0 不改变既有信息架构主干（4 分组导航可扩「行业/大盘」入口）；新页面沿用暗色主题基调；UI 明示「数据延迟：分钟级」。

## 🚩 九、里程碑（V2.0 里程碑区）

- **M13 · 源接入框架与运营化底座（≈15 人天）**：源注册表页面化（预置源启停/参数化/软删）+ 通用 RSS/JSON 源配置化引擎 + 分钟级增量调度 + 资讯统一落库与跨源去重 + 试点源 2~3 个。交付：30 源扩张与页面自增源的地基。
- **M14 · 批次一高价值源接入 + 抓取大盘 v1（≈14 人天）**：快讯/媒体/部委 9~12 源 + 源维度与全局大盘。交付：感知广度第一批跨越 + 运营驾驶舱 v1。
- **M15 · AI 归类与分析管道（≈15 人天）**：分级管道（预筛→归类→事件提取→行业聚合）+ 行业热度榜 + 行业日报 v1 + 事件流页 v1。交付：平台的「理解引擎」。
- **M16 · 动态主动推荐（≈11 人天）**：事件→标的关联→推荐卡片→SSE 推送 + 推荐中心页 + 反馈闭环。交付：愿景核心「优质标的主动找我」。
- **M17 · 批次二源接入 + 行业深化（≈14 人天）**：累计 ≥22 源 + 行业周报 + 事件→行业影响链 + 走向判断 v1。交付：前置性行业判断三形态齐备。
- **M18 · 批次三源接入 + UI 2.0 + V2.0 收口（≈16 人天）**：至 ≥30 源 + 设计系统刷新与 4 新页面精化 + 北极星全量测量。交付：V2.0 整体验收。
