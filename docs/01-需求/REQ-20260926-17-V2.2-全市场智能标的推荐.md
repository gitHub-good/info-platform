## 📌 背景与问题（V2.0/V2.1 基线与差距盘点）

**现状**（V2.0 版本闭门 + V2.1 M19 交付后）：

- **数据面已达标**：30 资讯源 7×24 分钟级轮询（感知延迟 P50 3.22min）+ 六业务源降级链；L0~L3 管道（规则预筛去重 / 35 枚举分类 / ≤20% 高价值事件提取 ≥8 类 / 行业热度 24h·7d 聚合）；5221 A 股标的池每日 06:00 自动同步；资讯库第 19 页原始数据可视；trace-v1 溯源口径十九页走查全达标。
- **分析面**：事件流 / 行业热度榜 / 日报周报（trend-v1 走向判断）/ 事件→行业影响链 12 类模板。
- **推荐面三体系**：①每日推荐 Top5（日频，自选池内，订阅+画像加权，V1.x 存量）；②动态主动推荐（M16：快速通道 / 三级关联 / 白名单可解释卡片 / SSE 推送 / adopt-v1 反馈闭环，推荐中心第 18 页）；③——全市场推荐不存在。
- **治理面**：提示词模板页面化（M5）、成本护栏两级降级 + cost-v2 预算校准（¥2.60/日）、留痕生命周期（默认 ≥180 天）、北极星机制常驻（ns-v1 六指标）。

**对照 V2.2 愿景逐条差距**：

| # | 愿景要求 | 现状 | 差距定级 |
| --- | --- | --- | --- |
| 1 | 结合**所有标的**信息 AI 分析出 Top10 | 推荐范围 = 自选池数十只（每日 Top5）+ 事件关联标的（动态推荐）；从未对全市场横向扫描 | **最大缺口**：全市场 5221 的评估与排序体系不存在 |

**不做的代价**：平台当前是「事件发现 + 自选视角推荐」，愿景是「全市场主动发现引擎」——没有全量因子快照就没有横向比较的基础，没有漏斗就没有全市场 × LLM 深析的成本可行解，没有评分级依据四件套则「最有价值」只是口号。三者构成 V2.2 不可拆分主线；同时调研已证伪的方向（LLM 全量准实时）必须显式挡在门外，防返工。

## 🎯 目标与北极星指标

V2.2 整体（M20~M22 三期，粗估合计约 39 人天）达成：

- **全量评分**：5221 标的每日盘后因子快照 + 价值分合成（v1 四维便宜算子，DB 内计算），覆盖率 100%，评分可复算、分解到因子可查、逐条回溯依据（trace-v1 口径）。
- **四层漏斗**：快照全量 5221 → 粗筛 Top 5%~10%（约 300）→ LLM 深析 30~50 → Top10 榜单；深析引用与库对账、违禁断言零命中、成本护栏触顶降级。
- **Top10 榜单页**：全市场推荐页（全站第 20 页）——排名 / 评分分解 / 深析摘要 / 入榜依据事件（trace-v1）/ 一键加自选 / 更新时间戳 + 触发事件；方法论页与免责文案随批。
- **准实时双层**：高重要性事件触发增量重评端到端 P50 ≤15 分钟；盘后日频全量兜底（次日 08:00 前完成）。
- **三推荐体系统一口径**：并存分工、互链互通、采纳反馈（adopt）与合规口径统一，不合并重构。
- **零回归**：动态推荐 / 每日推荐 / 管道 / 30 源采集 / 既有 19 页全部不回归。

**北极星指标**（v2.2 验收口径，沿 ns-v1 先例：首测后允许校准一次并版本化同步）：

| 类别 | 指标 | 目标 | 采集口径 |

## ⚖️ 二、关键裁决（PM 拍板）

### 裁决 1 · v1 因子集：四维 Must（现有数据面 100% 支撑）+ 2 条件因子（随 Spike 定夺）+ 资金印证/EPS 列 v2

**裁决**：v1 因子集 = **事件催化强度（主维）+ 行业热度传导 + 基本面边际（事件近似口径）+ 风险扣分**，四维全部为全量便宜算子、原料 100% 来自现有数据面、零新源依赖；**估值分位与量价异动为 2 个条件因子**，随 M20 Spike-A（行情/估值批量快照可行性）定夺纳入与否，不可行即裁、不阻塞主线；**龙虎榜/大宗/增减持（资金印证维）与 EPS 一致预期（财务因子库）列 v2**，本期仅立 Spike-B 预检留档，另立 REQ 接续。

| 调研五维 | v1 落法 | 原料现状 | v2 候选 |
| --- | --- | --- | --- |
| 事件催化强度（主维） | 近 5/10 交易日关联事件数 × 类型权重 × 方向 × 时效衰减 | L2 类型化事件（业绩预告/回购增持/重大合同等 ≥8 类）+ trace 关联 ✅ 全就绪 | — |
| 行业热度传导 | 所属行业 24h/7d 热度分 + 影响链上下游传导加成 | 热度聚合 + 影响链 12 类模板 ✅ 全就绪 | — |
| 基本面边际 | **事件近似口径**：业绩预告/快报/回购增持等基本面类事件的超预期方向信号（Zacks 超预期动量的事件侧近似） | 基本面类事件已提取 ✅ | 独立财务因子库 + EPS 一致预期（Spike-B：东财 datacenter 预估接口可得性） |
| 风险扣分 | 利空事件密度（方向 × 重要度）+ ST/风险警示标的排除或强扣（名称规则判定） | 事件方向/重要度 ✅ + 标的名规则 ✅ | 解禁临近、监管处罚专项 |
| 估值 / 量价印证 | **条件因子**：估值分位或量价异动（Spike-A 通过则纳入 v1，否则顺延） | 行情/估值源为按需拉取型，全量批量快照未验证 ⚠️ | 历史分位序列积累后升级 |
| 资金与机构印证 | v1 不做（A 股对应物 = 龙虎榜/大宗/增减持，结构化源未验证） | 公告源有公告但未结构化 ⚠️ | Spike-B 预检 → v2 因子（调研缺口 #3） |

**合成口径**：每维 0~100，加权合成总分；**权重页面化可配、热生效**（沿配置中心 ADR-0017 惯例），评分快照记录权重版本号（可复算可审计）；「有突破」标签 = 事件催化 ≥ 阈值 且 行业传导 ≥ 阈值 且 风险扣分 ≤ 阈值（三阈值可配）。

**理由**：

1. 四维 Must 的原料全部在库（事件/热度/影响链/标的名）——V2.2 主线**零数据源依赖**，交付确定性最高（调研 §4.4 Confidence 中高的直接依据：缺口均为存量技术重组）。
2. 未验证的数据源不进 Must 链：调研信息缺口 #2/#3 明示龙虎榜/增减持/EPS 预估可得性未验证，押注未验证源 = 把版本风险押在最不可控环节；Spike 结论留档后 v2 另立 REQ，失败不伤 v1。
3. 「基本面边际」取事件近似口径而非财务因子库：业绩公告本就是 L2 已提取的事件类型，超预期信号与 Zacks 口径在事件侧同源；独立因子库需批量财务拉取链路（工程量 + 限频风险），v1 不值。
4. 风险扣分只做确定性最高的两个子项（利空密度 + ST 排除），解禁数据无源不做。

### 裁决 2 · Top10 榜单承载：新页「全市场推荐」（全站第 20 页），推荐中心不动

**裁决**：新建页面 **「全市场推荐」，路由 `#/market-top`，分析组，全站第 20 页**；推荐中心（第 18 页）保持动态推荐流不动，两页互链。对比过的备选：推荐中心页内双 Tab（Tab1 全市场 Top10 / Tab2 动态推荐）——不采纳。

**理由**：

1. **V2.0 先例**：每个新能力域配独立承载页（大盘 / 热度榜 / 事件流 / 推荐中心四页皆如此）；Top10 是 V2.2 的核心价值主张（用户愿景点名的 Top10），值得独立入口与导航权重。
2. **信息架构不同型**：Top10 是榜单型（排名 + 评分分解 + 入出榜变动 + 更新时间戳 + 方法论/免责入口），动态推荐是卡片流型（时间序 + 逐卡事件逻辑链 + 反馈闭环）；调研对照（TipRanks Perfect 10 榜单页 / Danelfin 排名页）均为独立核心页。
3. **不破坏已验收交互**：推荐中心 M16 刚建立基线（23 卡四类一致性 100% 验收）、M19 刚交付十九页走查判定表——双 Tab 改造等于重构刚验收的页面，与 V2.1 拍板三「不破坏已验证交互」同理。
4. **心智统一靠互链**：两页页顶互链（「全市场视角 → 全市场推荐」/「事件动态 → 推荐中心」）+ Top10 卡片入榜依据事件可下钻事件流——沿 V2.1 源页面轻整合先例（同域内聚、异域轻整合），成本远低于页面重构。

**页面要素**（需求口径，视觉归 UI 设计师）：榜单卡 ×10（排名 / 总分 / 分维分解 / 深析摘要〔亮点 + 风险〕/ 入榜依据事件〔trace-v1 达标〕/ 一键加自选 / 更新时间戳 + 触发事件标注）；页头（上次全量重算时间 + 最近增量重评事件 + 数据延迟口径说明）；方法论页入口；免责文案常驻。

### 裁决 3 · 三推荐体系：并存分工 + 三统一，不合并

**裁决**：三体系**并存、定位分工明确化、三个口径统一**；合并重构为 Won't（V3 候选）。

| 体系 | 触发 | 范围 | 价值函数 | 承载 | V2.2 动作 |
| --- | --- | --- | --- | --- | --- |
| 每日推荐 Top5 | 日频 | 自选池内（数十只） | 订阅 + 阅读画像加权 | 存量承载不动 | **不动**；长期去向挂观察（若被「Top10 + 自选筛选」替代再议下线，走变更控制） |
| 动态主动推荐 | 事件触发（分钟级） | 事件三级关联标的 | 单事件关联逻辑链 | 推荐中心第 18 页 | **不动**；页顶互链接入 |
| 全市场 Top10 | 盘后全量 + 事件增量 | 全市场 5221 | 四维因子加权价值分 + LLM 深析 | 全市场推荐第 20 页（新） | **V2.2 主角** |

**三个统一**：①**入口互链**——推荐相关页面互达（推荐中心 ↔ 全市场推荐 ↔ 事件流），「推荐」心智一个家族；②**反馈口径统一**——Top10 曝光/点击/加自选/标记计入 adopt 体系采纳信号（北极星可比）；③**合规与依据口径统一**——免责文案、trace-v1 溯源、白名单/违禁校验三体系同一标准。

**不合并的理由**：每日推荐的个性化权重函数与 Top10 的市场因子分是**两套价值函数**（「我关注的里挑好的」vs「全市场挑最好的」），合并 = 重构已验收存量（M16 基线）且丢掉个性化视角，收益低风险高；业界同样并存（TipRanks 榜单 vs 个股个性化信号）。调研视角结论：三体系分别对应「个性化订阅 / 事件驱动提醒 / 全市场主动发现」三种范式，是同一推荐产品的三种模式而非三个重复建设。

### 裁决 4 · 「准实时」= 双层口径，不做全市场分钟级刷新

**裁决**：

1. **层 1 · 事件触发分钟级增量**：高重要性事件入库 → 关联标的 → 因子局部重算 → 挤入/挤出判定 →（新入榜且无近期深析时补深析）→ 榜单版本更新 + UI 时间戳与触发事件呈现。端到端 **P50 ≤15 分钟、P90 ≤30 分钟**（口径：事件入库时间戳 → 榜单版本时间戳；较 M16 卡片 ≤10min 略宽，因含因子重算与挤入挤出判定；实现复用既有事件流与调度基建，方式归架构）。
2. **层 2 · 盘后日频全量兜底**：每日盘后全量重算（5221 快照 → 粗筛 → 深析 → 榜单刷新），执行窗口可配，**需求锁「次日 08:00 前完成」**（对齐日报生成时点惯例）；增量链路异常时由全量兜底自然修复。

**Won't**：全市场分钟级全量刷新（调研 Q4/Q5 证伪：业界无先例、成本不成立）；tick 级行情扫描（无 tick feed，沿 V2.0 裁决 2 边界）。

**理由**：把「每一个分析都需要准实时」翻译为可执行口径——受影响标的分钟级、全市场日频，正是 TipRanks（每晚全量）/ Danelfin（每日刷新）+ 事件触发深析的业界分层共识；UI 明示评分时间戳与触发事件，用数据管理预期（沿 V2.0「用数据而不是口号定义实时」原则）。

### 裁决 5 · 北极星与合规落地（个人自用红线）

**裁决**：北极星 = Top10 采纳信号率 + 事件增量重评时效 P50（全表见「目标」节）；依据完整性双 100% 为硬验收不参与校准。合规四条落地：

1. **定位声明页面化**：「数据整理与信息展示，不构成投资建议」——全市场推荐页、方法论页、深析摘要区**三处必载**（沿 [合规预检-21财经AI条款](../02-设计/合规预检-21财经AI条款.md) 既有口径）。
2. **违禁断言校验**：深析输出黑名单扫描（「必涨 / 保证收益 / 稳赚」类确定性断言与买卖指令类表述），复用 M16 白名单校验先例，命中即拦截并降级模板兜底呈现。
3. **个人自用红线**：不对外提供服务、不收费、不代客决策；若未来分享，分享「管道与工具」不分享推荐结果（调研 Q6：对外荐股无牌照即触线，有判例）。
4. **历史统计免责**：历史命中/兑现率统计页附「历史统计不构成收益承诺」——统计是留痕回算的信息呈现，不是业绩预测。

## 📝 四、版本级用户故事与验收标准（代表故事）

> 每条 ≤2 人天的细化故事在当期 REQ 产出；此处为代表故事，锁定版本级验收语义。

### 故事 1 · 全市场评分与因子分解可查（M20）

作为 个人投资者，我想要 全市场每只标的都有一个「价值评分」且分数能分解到因子与依据事件，以便 知道分数从哪来、哪些标的在起变化，而非黑盒数字。

验收标准：

- 场景 1（全量覆盖）：Given 标的池 5221 只 When 盘后快照任务完成 Then 每只活跃标的均有当日因子快照与总分（停牌/当日无数据按例外口径标注不隐藏），覆盖率对账 100%。
- 场景 2（因子分解可回溯）：Given 某标的评分 When 展开分解 Then 各维分值与该维依据条目（事件卡 / 行业热度）可查且逐条满足 trace-v1 口径。
- 场景 3（可复算）：Given 同一输入数据集 When 评分引擎重跑 Then 总分与分维零漂移；评分快照含权重版本号，历史快照按当时权重可复现。
- 场景 4（权重可配）：Given 页面调整某维权重 When 保存 Then 下一次重算生效无需重启；非法权重组合（如负值/和不归一）被校验拦截。

INVEST 自检：独立 中（原料全在库，无新增外部依赖）/ 可估时 是 / 可测试 是（覆盖/幂等/回溯均可断言）。

### 故事 2 · 全市场 Top10 榜单（M21）

作为 个人投资者，我想要 每天打开「全市场推荐」页看到全市场最优 Top10 榜单（排名 / 评分分解 / 深析摘要 / 入榜依据），以便 用一个入口完成「今天值得关注什么」的决策起点。

验收标准：

- 场景 1（榜单可达）：Given 已登录 When 打开 `#/market-top` Then 页面渲染（分析组，全站第 20 页），榜单呈现恰 10 张卡（不足 10 如实呈现并标注原因），页头展示上次全量重算时间、最近增量触发事件与数据延迟口径。
- 场景 2（卡片依据完整）：Given 任一榜单卡 When 查看 Then 排名 / 总分 / 分维分解 / 深析摘要（亮点 + 风险）/ 入榜依据事件（trace-v1 达标）/ 更新时间戳齐备；「有突破」标的带标签且标签判定口径可查。
- 场景 3（深析合规）：Given 深析摘要 When 渲染 Then 无违禁确定性断言（黑名单扫描零命中），页级免责文案常驻。
- 场景 4（方法论可达）：Given 任一评分或因子 When 想了解口径 Then 一键到达方法论页，且方法论页权重与口径与当期引擎版本一致（版本对齐断言）。

INVEST 自检：独立 中（依赖 M20 引擎）/ 可估时 是 / 可测试 是（要素齐备性与对账可断言）。

### 故事 3 · 一键加自选（M21）

作为 个人投资者，我想要 Top10 卡片一键加入自选清单，以便 榜单发现 → 持续跟踪的动线不中断（加自选后动态推荐与异动推送自动覆盖）。

验收标准：

- 场景 1（一键加自选）：Given 某 Top10 卡片 When 点击「加自选」 Then 标的进入自选清单（复用存量能力），按钮态变「已自选」。
- 场景 2（幂等防护）：Given 标的已在自选 When 再点 Then 无重复添加并提示已在清单。
- 场景 3（采纳信号）：Given 加自选动作 When 完成 Then 计入 Top10 采纳信号统计（北极星口径）。

INVEST 自检：独立 高（复用存量自选接口）/ 可估时 是（≤1 人天）/ 可测试 是。

### 故事 4 · LLM 深析可解释与成本受控（M21）

作为 个人投资者，我想要 只有粗筛后的 30~50 只有 LLM 深度分析、每条结论附真实引用、成本有护栏，以便 深析可信且不失控。

验收标准：

- 场景 1（漏斗收敛）：Given 全量快照 5221 When 粗筛+深析执行 Then 进入深析的标的数落在 30~50 配置区间，全量 LLM 逐股分析永不发生（层数断言常驻）。
- 场景 2（引用对账）：Given 深析输出的任一结论性表述 When 校验 Then 其引用的事件/资讯真实存在于库（引用与库对账，防幻觉——沿 M16 白名单先例），无引用的表述走模板化中性文案。
- 场景 3（成本护栏）：Given 深析日成本触顶 When 触发 Then 当日深析自动暂停、榜单以因子分排序兜底呈现并在页面明示「深析暂停」，次日自动恢复；深析成本进 cost 报表可视。
- 场景 4（提示词治理）：Given 深析提示词 When 修改 Then 走 M5 模板页面化治理（版本化 / 激活切换 / 占位符校验），下一次深析即生效。

INVEST 自检：独立 中（依赖 M21 粗筛）/ 可估时 是 / 可测试 是（层数/对账/护栏均可断言）。

### 故事 5 · 事件触发准实时更新（M22）

作为 个人投资者，我想要 重大事件发生时受影响标的的评分与榜单分钟级更新，以便 榜单不是隔夜旧闻。

验收标准：

- 场景 1（增量时效）：Given 一条高重要性事件入库 When 增量链路处理 Then 受影响标的因子重算与榜单版本更新端到端 P50 ≤15 分钟（事件入库时间戳 → 榜单版本时间戳，留痕可统计）。
- 场景 2（挤入挤出）：Given 某标的因事件分数跃升进入前 10 When 榜单刷新 Then 该标的入榜且卡片标注「事件驱动入榜 + 触发事件」；被挤出标的进变动留痕可见。
- 场景 3（榜单防抖）：Given 无新事件与数据变化 When 榜单重渲染 Then 排名与评分稳定不变（无输入变化不重排）。
- 场景 4（全量兜底）：Given 增量链路异常 When 次日盘后全量重算 Then 榜单恢复正确且与增量期偏差可对账。

INVEST 自检：独立 中（依赖 M21 榜单机制）/ 可估时 是 / 可测试 是（时间戳/防抖/兜底可断言）。

### 故事 6 · 依据四件套与历史统计（M22）

作为 个人投资者，我想要 方法论公开、依据可溯源、推荐历史有统计、页面有免责，以便 对榜单的信任建立在可核验的事实上。

验收标准：

- 场景 1（方法论页完整）：Given 方法论页 When 查看 Then 维度定义 / 权重（与当期引擎一致）/ 合成口径 / 数据源清单 / AI 局限性说明齐备。
- 场景 2（历史统计）：Given 已运行 ≥30 天榜单留痕 When 查看统计 Then 呈现历史入榜标的的后续事件兑现 / 相对表现统计（口径留档可回算），页面附「历史统计不构成收益承诺」免责。
- 场景 3（溯源走查）：Given V2.2 全部新展示面 When trace-v1 走查 Then 全市场推荐页 / 方法论页 / 统计页 / 详情评分区块全部达标（判定表进 V2.2 收口总单）。

INVEST 自检：独立 高（消费既有留痕）/ 可估时 是 / 可测试 是（走查与对账可断言）。

## 🗂️ 五、范围

**V2.2 做（M20~M22）**：

- **股价预测 / 买卖点位 / 投资指令 / 收益承诺**——永久 Won't（合规红线，沿 V2.0）；违禁扫描拦截。
- **对外提供推荐结果 / 多用户**——个人自用红线（调研 Q6），沿 V1.x 起定位。
- **港美股 Top10**——沿 V2.0 A 股聚焦裁决。
- **自然语言条件选股交互（问财式）**——调研 Q1 取「②评分榜单为主干」，①列 V3 候选观察。
- **新增资讯源扩容**——30 源已达标，V2.2 不以扩源为主题（数据面差距已闭环）。

> 范围蔓延一律走变更控制：新增条目须重新评估影响面并同步相关方，禁止悄悄加。

## ⚖️ 六、优先级排序（版本级）

**MoSCoW 粗排**：Must = 四维因子快照与评分引擎、粗筛、LLM 深析（含引用对账/违禁扫描/成本护栏）、Top10 合成与全市场推荐页、方法论页、一键加自选、事件增量重评、盘后全量兜底、免责三处必载（缺任一则「全市场 Top10 有依据推荐」不成立）；Should = 历史命中统计 v1、榜单变动留痕呈现、报告/推荐面互链精修；Could = 深析摘要多轮生成质量迭代、榜单维度筛选（按行业/有突破标签过滤）；Won't 见范围节。

**RICE 精排**（期粒度，版本内排序证据）：

> Reach = 两周迭代内触达使用次数（单人量级相对值，沿 V2.0 口径）；Impact：3=massive，2=high；Confidence：80% = 原料全就绪的存量重组，70% = 含 LLM 深析质量等待实测环节；Effort = 人天（含验收分摊）。

| 分期（能力包） | Reach | Impact | Confidence | Effort(人天) | RICE 分数 |
| --- | --- | --- | --- | --- | --- |
| M20 因子快照与评分引擎 | 50 | 3 | 80% | 13 | (50×3×0.8)/13 ≈ 9.2 |
| M21 漏斗 + 深析 + Top10 榜单页 | 40 | 3 | 70% | 14 | (40×3×0.7)/14 = 6.0 |
| M22 事件增量 + 四件套收尾 | 30 | 2 | 70% | 12 | (30×2×0.7)/12 = 3.5 |

排序结论：**依赖约束优先于 RICE**（沿 V2.0 拓扑排序结论）——M20 是 M21/M22 的地基不可跳过；M21 的 Confidence 折价来自 LLM 深析质量（版本最大不确定项），故其验收内置抽检 ≥90% + 模板兜底 + 引用对账三重保险，且成本护栏保证「深析失败/暂停时榜单仍成立（因子分兜底）」——主价值链对深析质量不设单点依赖。

## ⚙️ 七、非功能需求

- **合规红线**：免责三处必载（全市场推荐页 / 方法论页 / 深析摘要区）+ 违禁断言黑名单扫描 + AI 输出一律「信息展示不构成投资建议」口径 + 个人自用不对外不收费（裁决 5 全量）。
- **成本护栏**：深析标的数上限（30~50 配置）+ 深析日成本占日预算比护栏（≤30% 可配，首跑校准）+ 触顶自动降级（只停深析，因子快照与榜单不受影响）+ 单股深析成本留痕 + cost 报表可视（复用 cost-v2 体系）。
- **数据质量**：评分可复算（同输入同输出，权重版本入快照）；深析引用与库对账（防幻觉）；低质量/失败深析隔离不进榜单（因子分兜底）；快照覆盖对账常驻。
- **防抖与幂等**：无输入变化榜单不重排；入榜/出榜需满足分数差阈值（可配）——具体算法归架构，需求锁验收语义（故事 5 场景 3）。
- **性能**：全量快照计算窗口归架构裁量，需求锁「次日 08:00 前完成全量重算与榜单刷新」；新页面加载沿 M9/M12 分页与三态基线。
- **留痕与存储**：评分分解快照 + 榜单版本 + 深析结果按推荐留痕治理（供历史统计回算与审计），生命周期沿用 M10 体系扩键，默认保留 ≥180 天（对齐资讯库口径）。
- **UI 一致性**：全市场推荐页与方法论页基于 ui-tokens-v2 基准构建（复用分页/徽章/卡片/空态组件）；导航分析组 +1 项（19 → 20 页）。
- **零回归**：动态推荐（M16）/ 每日推荐 / 管道 L0~L3 / 30 源采集 / 既有 19 页全部不回归（每期验收常驻项）。

## ⚠️ 十、依赖与风险

| 依赖/风险 | 说明 | 对策 |
| --- | --- | --- |
| LLM 深析质量与幻觉（高） | 深析是 Top10 叙事的主要来源，幻觉引用直接击穿「依据可靠」主张 | 引用与库对账白名单校验（M16 先例）+ 结构完整率抽检 ≥90% + 违禁扫描 + 模板兜底 + 深析失败/暂停时因子分排序兜底（主价值链不设单点依赖） |
| 评分抖动与榜单频繁进出（中高） | 因子日频变化 + 事件增量叠加，可能造成榜单高频重排伤害可信度 | 防抖口径（无输入变化不重排 + 入榜分数差阈值可配）+ 变动留痕可审计；具体算法归架构，验收语义已锁（故事 5 场景 3） |
| 行情/估值批量快照限频（中高） | 行情源为按需拉取型，5221 全量批量拉取未验证（东财 push2 封禁前科 ADR-0030/0031） | 条件因子独立于 Must 链（Spike-A 否决即裁，四维主线零影响）；批量窗口错峰与降级归架构裁量 |
| Spike-B 数据源不可得（中） | 龙虎榜/增减持/EPS 预估可能无免费结构化源 | 资金印证/EPS 本就列 v2，spike 失败不阻塞 v1（四维 Must 零新源依赖）；结论留档供 v2 REQ 立项依据 |
| 成本放量（中） | 深析 30~50 只/日 + 事件增量补深析，成本随事件密度波动 | 深析上限配置 + 日预算占比护栏 + 触顶降级（只停深析）+ cost 报表监测 + 首跑校准（cost-v2 先例） |
| 榜单质量无金标准（中） | 「最有价值」无法用收益验证（合规与归因双重不可行） | 采纳信号率代理指标（≥20% 首跑校准）+ 人工抽检（沿 M18 命中率抽样先例）+ 依据完整性硬验收；不用收益指标（裁决 5） |
| 合规（高，对策已有） | 具体标的推荐 + AI 生成内容天然贴近投顾边界 | 裁决 5 四条：免责三处必载 + 违禁扫描 + 个人自用红线 + 统计页免责；调研 Q6 判例背书口径 |
| 范围蔓延（中） | 「全市场」「最有价值」易诱发无边界因子扩张与回测诉求 | Won't 清单显式挡（LLM 全量准实时/回测引擎/资金印证 v2/合并重构）+ v2 因子另立 REQ + 变更控制 |
| 与既有推荐的并存复杂度（低中） | 三体系并存若口径不一会造成用户困惑 | 裁决 3 三统一（互链/adopt/合规）在 M21 随批交付；每日推荐去向挂观察走变更控制 |
