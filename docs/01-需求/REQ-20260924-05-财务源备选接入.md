# 📥 财务源备选数据源接入 · 轻量需求设计报告（v1.0）

> 财务源接入第二 provider 纳入 ADR-0033 降级链体系：东财失败或空响应自动降级备选、恢复自动回归，页面降级链编辑自动出现新选项（前端零改动）；公告源同族风险一并除单点（Should）。

## 📌 需求元信息

- 编号：REQ-20260924-05（承接 M7 后备选源补强线 ADR-0030/0031/0033——财务/公告为注册表中最后两个单点源；平台需求序列第 5 批）
- 类型：优化（稳定性补强；新增 provider 接入为手段，除单点为目的）
- 优先级：Must（M8 主题）
- 来源：线上问题（2026-09-24 财务源 RestClient 编码回归事故 f3cdcc1 + 东财 datacenter 间歇变慢 0.1s~3.3s 实测）+ 用户原始诉求（"财务源加备选增强稳定性"）

## 📌 背景与问题

**现状**（代码与提交核实，2026-09-24）：

1. **事故实证**：2026-09-24 财务源 RestClient `uri(String)` 对 `%22` 二次编码，东财返回 9501 错误体被当作"无数据"→ 财务分区整个回归窗口 MISSING（已修复 f3cdcc1）。事故期间行情/估值有腾讯备选、A 股列表有新浪备选自动兜底（ADR-0030/0031），**唯财务源无兜底裸奔**——`SourceProviders` 中 FINANCE 注册表仅 `eastmoney` 单 provider。
2. **稳定性特征**：东财 datacenter 间歇变慢，实测 0.1s~3.3s 波动，财务源弹性预算 noRetry(2s)，尾部请求已逼近超时线；主源侧"端点可用但返回空/错误体"的形态（本次 9501 事故即此类）正是 ADR-0031 把**空响应**纳入降级触发条件的实证场景。
3. **公告同族风险**：公告端点（`np-anotice-stock.eastmoney.com`）与财务端点（`datacenter-web.eastmoney.com`）不同域名，但同属东财系——2026-09-22 ISSUE-A 实测**两端口同日被 WAF 收紧**（均需补浏览器 UA + 站内 Referer），风控联动实证；公告真实数据在用（详情页公告分区），东财系整体故障时公告分区同样裸奔（ANNOUNCE 注册表亦仅 `eastmoney`）。
4. **既有体系纯增量**：ADR-0033 降级链模型已建成（`SourceProvider` 枚举 + `SourceProviders` 注册表 + `fallbackChain` 页面可视化配置 + DB 配置优先/代码默认链兜底 + `FallbackChainRunner` 链执行）。**接入第二 provider = 枚举登记 + 注册表补行 + 链执行消费点扩展**，页面降级链编辑自动出现新选项，前端零改动。

**不做的代价**：财务指标是详情页六大分区之一，也是 AI 简报财务数值事实回链的取数源（幻觉控制回查）——东财系故障（封禁/风控收紧/请求构造回归）期间财务分区长时间 MISSING，AI 简报财务段随之退化；财务/公告单点不除，下次东财事故仍裸奔，且两源风控联动、大概率同挂。

**有利条件**：降级链模型、链执行器、页面可视化、弹性降级语义全部既有（ADR-0031/0033）；ADR-0031 已沉淀备选源接入模式（备选 client 输出主源中间结构、adapter 组合、失败/空响应触发降级、来源标注文案），本需求是「第四/第五个消费点 + 新 provider」的复制推广。

## 🎯 目标

M8（约 6 人天，Must 部分 4 人天）达成：

- **财务源双 provider**：默认链 `[eastmoney, 备选]`，东财失败或空响应自动降级备选整轮重拉、恢复后自动回归东财；页面可换主源/裁剪/清备选。
- **口径可信**：备选源报告期口径与东财一致（非 TTM 混用），核心指标数值经抽样交叉核对容差内，兜底轮数据可用可信。
- **公告源除单点（Should）**：同模式接入备选，东财系联动故障时公告分区有兜底。
- **可观测**：降级轮 WARN 留痕 + 来源标注可区分兜底轮；OK/MISSING/FAILED 三态契约不变。

### ⚖️ 需求侧拍板（四个裁决点）

| 裁决点 | 结论 | 理由 |
| --- | --- | --- |
| 范围 | **财务源 Must + 公告源 Should，一并纳入本期 M8**。公告设出口条款：备选源调研无可行源则公告范围走变更控制移出，不阻塞财务 Must 交付 | 公告虽与财务不同域名，但同属东财系且 ISSUE-A 实证两端口同日 WAF 收紧——财务挂公告大概率同挂，只补财务等于除一半单点；公告真实数据在用。定 Should 而非 Must：公告无事故实证（证据强度弱于财务），且公告备选源可得性独立未验证，设变更控制出口防调研风险绑架整个里程碑 |
| 字段口径 | **最小完备集 = 报告期 + 营收 + 归母净利 + ROE 四项，缺任一该源不合格**；净利率/毛利率允许缺失降级展示（源直接提供或由营收/净利派生均可，派生方式归架构），沿既有「字段缺失→不产出」语义，不报错不阻断分区。**报告期口径为硬性要求**：备选源须按报告期口径供数（与东财 F10「最新报告期累计口径」同口径），**TTM-only 源不合格**。上线门槛：抽样 ≥5 只标的与东财同报告期交叉核对，营收/归母净利相对偏差 ≤1%（舍入/单位差），比率类（净利率/毛利率/ROE）绝对偏差 ≤0.5 个百分点，超差源不入链 | 兜底的首要目标是换源无感（ADR-0031 选型同款理由）：跨源口径漂移（TTM vs 报告期累计）会让用户对比同一指标得出错误结论，兜底价值不抵口径混乱，宁缺毋滥；最小完备集取「报告期定位 + 规模 + 盈利 + 回报」四要素，缺任一则分区失去可读性，净利率/毛利率为派生性指标可放宽 |
| 默认链 | **接入后默认链调整为 `[eastmoney, 备选]`**（auto 语义——ADR-0033 注册表全链即默认链的自然结果）；存量 DB 已显式编排 `fallbackChain` 的行不覆盖（用户编排权威）；页面可换主源/裁剪/清备选 | 用户立项目的就是自动降级增强稳定性，接入即默认生效才达成目的；ADR-0033 已定「DB 配置优先、代码默认只兜底」，存量显式配置不动是既有语义的直接应用 |
| 失败语义 | **直接沿用 ADR-0031/0033 既有语义，无新增裁决**：主源失败或空响应（事故签名）→ WARN 留痕（provider 名 + 链位）→ 备选整轮重拉；全链失败 → 末级异常上抛（前级挂 `suppressed`）→ 既有弹性降级 MISSING（财务/公告挂不阻断其他分区）；`RawFetch.source` 标注实际命中源（「东方财富财务→XX 备选」格式） | 语义已成熟且三消费点（行情/估值/A 股列表）实证过，财务/公告照抄即用；本次 9501 事故的"空响应"形态恰在既有触发条件覆盖内 |

### 🔍 候选源验收要求（交架构选型，需求不指定具体源）

财务备选源由架构调研选定，须同时满足（公告备选源同款要求，独立调研）：

1. **公开免费**：无付费 token/积分墙（不引入 tushare 积分区等，沿 Spike-1 选型约束）。
2. **核心指标可得**：最小完备集（报告期 + 营收 + 归母净利 + ROE）齐备；**报告期口径与东财一致，TTM-only 不合格**；净利率/毛利率可得或可派生为加分项。
3. **A 股全覆盖**：标的池沪深全量股票均可查；港股对齐主源现状（主源可查则备选同求，主源本身不覆盖的场景不苛求备选——主源港股可得性由 T55 顺带核实沉淀）。
4. **限速友好**：支持礼貌抓取（限速可控、失败可重试、无激进 WAF），单标的查询形态（详情页按标的取数）。
5. **验收兜底**：调研无可行源 → 财务源降级走变更控制并如实记录结论，**绝不凑数接入口径不合格的源**——宁缺毋滥。

## 📝 用户故事与验收标准

### 故事 1 · 财务备选源接入与自动降级

作为 个人投资者，我想要 财务源接入备选数据源并纳入降级链——东财失败或返回空数据时自动切换备选拉取、恢复后自动回归，以便 东财故障期间标的详情的财务分区仍有数据可看，不再整段空白。

验收标准：

- 场景 1（主源健康直用）：Given 东财财务端点正常 When 打开标的详情（A 股股票）Then 财务分区数据来自东财（每轮仍先东财），来源标注「东方财富财务」。
- 场景 2（故障自动降级）：Given 东财财务端点失败（HTTP 错误/异常）或返回空响应 When 同一取数请求 Then 备选源整轮重拉成功，财务分区仍有数据，来源标注为「东方财富财务→XX 备选」格式（XX = 备选 provider 展示名）。
- 场景 3（全链失败降级展示）：Given 东财与备选源均失败 When 取数完成 Then 财务分区按既有弹性语义降级 MISSING（不报错、不阻断详情页其他分区），末级异常前级挂 `suppressed` 保留诊断链。
- 场景 4（恢复自动回归）：Given 某轮经备选源兜底成功且下一轮东财恢复 When 下一轮取数 Then 财务数据自动回归东财来源（无需人工切回、无需重启）。

INVEST 自检：独立 高（消费点自包含，复用既有链执行器）/ 可估时 是（并入 T55/T56）/ 可测试 是。

### 故事 2 · 降级链页面可视化与编排

作为 个人投资者，我想要 数据源配置页财务卡片的降级策略区块自动出现备选源选项——可换主源、可排序、可清空备选，以便 不发版即可按需编排财务源降级链。

验收标准：

- 场景 1（新选项自动出现）：Given M8 部署完成（FINANCE 注册表已含第二 provider）When 打开数据源配置页 Then 财务卡片「降级策略」区块从「暂无备选源」变为 主源徽章 + 备选链 chips 展示（默认链 `[eastmoney, 备选]`），**前端零改动**（选项来自 `availableProviders` 注册表契约）。
- 场景 2（编排生效）：Given 财务卡片降级链编辑 Dialog When 点亮/排序 provider（首个为主源）或全部熄灭（仅主源）后保存 Then 保存走 PATCH `fallbackChain`，反馈「降级链已更新，下一次取数生效」，下一次取数按新链执行（强制单源可作排障入口）。
- 场景 3（存量配置不覆盖）：Given 某 DB 行已显式编排过 `fallbackChain` When M8 部署后取数 Then 按用户已编排链执行，不被新默认链覆盖。

INVEST 自检：独立 高（ADR-0033 既有能力验证）/ 可估时 是（并入 T58 冒烟）/ 可测试 是。

### 故事 3 · 字段口径对齐与数值合理容差

作为 个人投资者，我想要 备选源兜底轮的财务数值与东财同口径、同量级可信，以便 跨源对比同一指标不产生口径性误判（TTM 与报告期累计混看等）。

验收标准：

- 场景 1（最小完备集）：Given 备选源兜底轮成功 When 查看财务分区 Then 报告期、营收、归母净利、ROE 四项必齐；净利率/毛利率可得则展示、缺失则该字段不产出（不报错、不阻断分区其余字段）。
- 场景 2（口径一致）：Given 备选源接入前选型验证 When 抽样 ≥5 只标的与东财同报告期数值交叉核对 Then 营收/归母净利相对偏差 ≤1%，比率类绝对偏差 ≤0.5 个百分点（超差源不入链）；备选源报告期为报告期口径（TTM-only 源已在选型阶段排除）。
- 场景 3（缺失值防御）：Given 备选源某字段返回空/`-`/短行 When 映射处理 Then 对应字段不产出（沿映射白名单既有语义），不出异常、不产出错误数值。

INVEST 自检：独立 高（选型门槛 + 展示断言独立）/ 可估时 是（并入 T55/T58）/ 可测试 是。

### 故事 4 · 公告源备选接入（Should）

作为 个人投资者，我想要 公告源同样接入备选并纳入降级链，以便 东财系联动故障（封禁/WAF 同日收紧）时公告分区仍有最新公告可看。

验收标准：

- 场景 1（同模式降级）：Given 东财公告端点失败或空响应 When 取数 Then 备选源兜底成功后公告分区有数据（标题/时间/URL 列表形态与主源一致），来源标注备选；全链失败按既有语义 MISSING 不阻断其他分区。
- 场景 2（不可得不阻塞）：Given 公告备选源调研无可行源（不满足候选源验收要求）When M8 验收 Then 公告范围走变更控制移出本期，不阻塞财务 Must 验收（公告维持东财单源现状并留档结论）。

INVEST 自检：独立 高（复制故事 1 模式到 ANNOUNCE 桶）/ 可估时 是（T57）/ 可测试 是。

### 故事 5 · 降级可观测

作为 个人投资者，我想要 财务（及公告）源的兜底轮可被区分与追溯，以便 知道当前数据来自哪个源、东财是否正在故障，排障与验证有据。

验收标准：

- 场景 1（留痕与标注）：Given 发生一次降级兜底 When 查看日志与来源标注 Then WARN 留痕含 provider 名与链位，`RawFetch.source` 标注实际命中源；健康徽章与连通性测试可区分兜底轮。
- 场景 2（契约不变）：Given 任一轮取数（主源直用/备选兜底/全链失败）When 查看分区状态 Then OK/MISSING/FAILED 三态契约与心跳签名不变（沿 ADR-0031 从简口径，不改 `DataSourceEventRecorder` 公共签名）。

INVEST 自检：独立 中（与故事 1 共用链路、断言独立）/ 可估时 是（并入 T56/T58）/ 可测试 是。

## ⚖️ 优先级排序

**MoSCoW 粗排**：Must = 备选财务源接入、降级链接入、口径对齐验证、可观测（事故驱动的主链路，缺一不达成立项目的）；Should = 公告源备选（价值真实但无事故实证、源可得性待调研，可延后不阻塞验收）。

**RICE 精排**：

> Reach = 一个 2 周迭代内受益的交互次数（详情页财务/公告分区查看 + AI 简报财务取数，单人量级仅作相对比较）；Impact：3=massive，2=high，1=medium，0.5=low；Confidence：80%=有依据推测，50%=待源调研证实；Effort=人天。

| 模块 | Reach | Impact | Confidence | Effort(人天) | RICE 分数 |
| --- | --- | --- | --- | --- | --- |
| 财务备选 + 降级链（T55+T56） | 60 | 2 | 80% | 3.5 | (60×2×0.8)/3.5 ≈ 27 |
| 公告备选（T57） | 40 | 1 | 50% | 2 | (40×1×0.5)/2 = 10 |
| 演练验证（T58） | — | 支撑项 | — | 0.5 | 不参与精排（验收保障） |

排序结论：本需求是**单点清除型**——降级链体系已覆盖行情/估值/列表三消费点，财务/公告是最后两个单点，Must 顺序即实现顺序：选型验证 → 链接入 → 演练；公告 Should 随调研结论决定纳入或走变更控制。

## ⚙️ 非功能需求

- **三态契约不变**：OK/MISSING/FAILED 与心跳签名不动（沿 ADR-0031 从简口径，不改 `DataSourceEventRecorder` 公共签名）。
- **弹性预算口径**：主源轮 + 备选轮合用同一 ResilienceSpec 预算（沿 ADR-0031；东财挂起至超时则兜底不保证为既有已知限制，接受）；具体参数归架构。
- **缓存语义**：财务缓存 TTL（现 1h）与公告缓存语义不变，备选轮产物同样入缓存——故障期兜底数据也缓存，避免每个请求都打备选源放大限速压力。
- **幂等只读**：纯读源，无写路径。
- **礼貌抓取**：限速、UA/Referer 等要求按选定源的实测口径（归架构）；备选源接入不得引入更激进的抓取模式。
- **前端零改动**：降级链新选项依赖 `availableProviders` 动态来自注册表（ADR-0033 契约）——此为验收点；若前端存在 provider 展示名硬编码映射，仅允许补一条映射的微调（任务内完成，不算前端改造）。

## 📋 任务拆解建议（T55 起，≤2 人天，供架构对接）

> 技术实现方式（源选型、client/中间结构设计、链执行接入位）与最终拆分以架构方案为准，本表仅给需求侧粒度建议。

| 编号 | 任务名 | 依赖 | 估时(人天) | 里程碑 |
| --- | --- | --- | --- | --- |
| T55 | 后端·备选财务源选型验证与客户端：候选源调研定源（按候选源验收要求：公开免费/最小字段集/报告期口径/A 股全覆盖/限速友好）+ 交叉核对抽样（≥5 只容差验证）+ Client 实现（输出与东财 F10 对齐的中间结构或经字段映射对齐）+ 缺失值防御 + 单测（含主源港股可得性核实沉淀） | — | 2 | M8 |
| T56 | 后端·财务源降级链接入：`SourceProvider` 增枚举 + `SourceProviders` FINANCE 注册表补行（默认链 `[eastmoney, 备选]`）+ `FallbackChainRunner` 扩财务消费点（失败/空响应触发、整轮重拉、全链失败 suppressed、来源标注）+ 降级/回归/全链失败单测 | T55 | 1.5 | M8 |
| T57 | 后端·公告源备选接入与降级链（Should）：公告候选源独立调研（无源走变更控制出口）+ 同模式接入（ANNOUNCE 注册表 + 链执行 + 标注）+ 单测 | T56（模式复用；调研可并行） | 2 | M8 |
| T58 | 测试·备选降级演练与验收：东财强制单源/故障注入下财务（及公告）分区兜底轮验证 + 数值容差抽样复核 + 页面降级链编辑冒烟（前端零改动确认）+ 可观测核对（WARN/标注/三态） | T56（公告场景另需 T57） | 0.5 | M8 |

## 🚩 里程碑

- **M8 · 财务源备选接入（≈6 人天，Must 4 人天）**：财务源接入备选 provider 纳入降级链 + 公告源 Should 除单点。交付：六大分区源中财务/公告两个最后单点清除，东财系故障自动兜底、恢复自动回归，降级链体系全源覆盖（多 provider 源）。

## ⚠️ 依赖与风险

| 依赖/风险 | 说明 | 对策 |
| --- | --- | --- |
| 候选源不确定性（核心） | 公开免费且报告期口径、最小字段集齐备的财务备选源需调研——新浪/腾讯等财务接口的口径与覆盖未验证（Spike-1 财务仅实测东财） | 按候选源验收要求调研定源（T55）；无源走变更控制如实留档，宁缺毋滥不凑数 |
| 口径漂移 | 备选源字段口径（TTM vs 报告期累计、单位万元 vs 元、比率分母口径）与东财不一致，兜底轮数值误导 | TTM-only 选型即排除；上线前交叉核对容差门槛（营收/净利 ≤1%、比率 ≤0.5pp），超差不入链 |
| 弹性预算冲突 | 两轮调用合用预算，东财挂起至超时则兜底不保证（ADR-0031 已知限制） | 沿既有限制接受并留档；备选轮产物入缓存，降低故障期对备选源的放大压力 |
| 公告源联动风险 | 公告备选源可得性独立未验证，Should 范围可能落空 | 变更控制出口（故事 4 场景 2）：不阻塞财务 Must 交付 |
| 前端零改动假设 | `availableProviders` 动态契约若在前端有展示名硬编码，新 provider 可能显示原始 code | T58 冒烟确认；如有硬编码仅补一条映射微调（任务内完成） |
| 港股覆盖 | 主源对港股财务指标的可得性未实测沉淀 | T55 顺带核实沉淀结论；备选对齐主源现状，不达标不阻塞本期 |
