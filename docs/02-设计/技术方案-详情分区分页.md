- 状态：评审中
- 关联：[需求](/docs/01-需求/REQ-20260925-09-详情分区分页.md) · [UI 设计](/docs/02-设计/ui-详情分区分页.md)（D1~D9 已含 4 可选 Props 复用路径） · ADR-0037 · 前置基线 [M9 技术方案](/docs/02-设计/技术方案-列表分页与查询条件.md)/[ADR-0035](/docs/02-设计/adr/0035-列表页码分页双模式与深分页从简.md)
- 方案货架对照：缓存 Cache-Aside（方案 04，首屏沿用不动）+ 弹性四件套（方案 07，子端点全链复用）+ 深分页从简（方案 05 裁剪，LIMIT/OFFSET 仅本地事件表使用，外呼源走源原生页码）——取舍详见 §3 与 ADR-0037

## 🎯 1. 背景与目标

### 1.1 现状（代码核实 2026-09-22）

详情页唯一取数路径是 `GET /api/v1/subjects/{id}/detail?sections=...`（`AggregationService` 并行聚合 + `SourceCache` 快照缓存按 subjectId 键控）。四个列表分区直出全部条目，无翻页：

| 分区 | 现状代码事实 | 源分页能力 |
| --- | --- | --- |
| 公告 | `EastMoneyAnnounceClient` 固定 `page_index=1`、`extractList` 丢弃 `total_hits`；巨潮备选（ADR-0034）仅第一页 | 原生分页 + 总数（本方案实测确认，见 §1.2） |
| 新闻 | `SinaNewsClient.buildUrl` 固定 `page=1`；`NewsSourceAdapter.isRelevant` 本地关键词过滤 | 源支持 page（实测确认）；按标的命中数无源计数 |
| 政策 | `GovPolicyClient` Jsoup 解析 `https://www.gov.cn/zhengce/` 目录页（约 9 条） | 无分页参数；**「最新政策」页 HTML 列表为 AJAX 空壳（本方案实测，见 §1.2）** |
| 事件 | `EventSourceAdapter` 全量查 `findBySubjectId` → 内存 7 天窗过滤 → `MAX_ITEMS=10` 截断 | 本地表 `idx_anomaly_subject_time(subject_id, trigger_time)` 天然可分页可 count |

### 1.2 实测证据（2026-09-22，本方案交付前置项，curl 直连源）

| # | 实测项 | 结果 | 结论 |
| --- | --- | --- | --- |
| 1 | 新浪 `feed.mix.sina.com.cn` page=1/2/3/50（lid=2510、num=20、带 UA+Referer） | 全部 HTTP 200、每页 20 条；page=1 末条 ctime=1718771044 与 page=2 首条 ctime=1718764760 顺序衔接、无重叠；page=50 仍 20 条 | **深翻可用**（无 403/无空页/无重复回吐）；翻页延迟 0.18~0.33s；page=1 偶发慢（一次实测 6.5s，受既有 2s 超时护栏保护）。新闻「加载更多」形态不触发变更控制 |
| 2 | 东财 `np-anotice-stock` page_index=1/2/3/5/6（page_size=10、600519） | 全部 200、每页 10 条；`total_hits=1074` 各页恒定；notice_date 跨页倒序衔接（p1 末 2026-06-12 ↔ p2 首 2026-06-12 同日多条） | **`page_index` 深翻 + `total_hits` 透出均可用**；延迟 0.08~0.32s |
| 3 | gov.cn `https://www.gov.cn/zhengce/zuixin/` HTML | HTTP 200，但 `<ul id="list-1-ajax-id">` 为**空**，条目由页内同步 AJAX 从 `./ZUIXINZHENGCE.json` 加载；既有选择器 `div.list.fl > ul > li` 在该页 **0 命中** | **policyUrl 直接指向 zuixin HTML 页不可行**；须改取 JSON 文件 |
| 4 | gov.cn `https://www.gov.cn/zhengce/zuixin/ZUIXINZHENGCE.json` | HTTP 200，JSON 数组 **1100 条**，字段 `TITLE / SUB_TITLE / URL（绝对链）/ DOCRELPUBTIME（yyyy-MM-dd）`，按时间倒序 | **政策扩容的正确载体**：静态 JSON、无鉴权、单次可取任意前 N 条 |

### 1.3 目标与非目标

**目标**（对齐需求 22 条 GWT）：三分区子端点契约（公告/事件/新闻）+ 聚合首屏总数附加键 + 政策源扩容（Should）+ 配置迁移两件（`announcePageSize` 3→10、`policyUrl`→JSON）。

**非目标**：政策翻页 / 新闻总数 / 分区页大小选择器 / 分页状态进 URL / 公告 >5 页深翻（需求 Won't，均已裁决）；不新增鉴权（平台单用户无鉴权层，沿现状口径）；不动聚合接口既有响应键（零回归红线）。

## 🗺️ 2. 方案总览

**核心思路（一段话）**：首屏照旧走聚合接口（缓存与三态语义一字不动），四个分区的「看更多」交互改走**三个新增的分区子端点**——公告 `/announcements`、事件 `/events` 是带 total 的页码分页，新闻 `/news` 是带 hasMore 的源页取数；**翻页/加载一律绕过 SourceCache 快照直调源**（每请求恰好一次外呼，产品上限天然封顶）；聚合响应**附加**一个 `sectionPagination` 键透出首屏总数（非破坏，前端首屏分页条有总数可渲染）；政策不新增端点，只换数据载体（zuixin JSON）+ 单页扩容。

### 裁决一览（细节见 §3/§4，留痕见 ADR-0037）

| # | 决策点 | 裁决 |
| --- | --- | --- |
| D1 | 契约形态 | **分区子端点**（`/subjects/{id}/announcements|events|news`），非聚合接口参数化 |
| D2 | 翻页与缓存 | **子端点绕过 SourceCache 直调源**（首屏聚合缓存不动，不引入页码维度的缓存键） |
| D3 | 首屏总数 | 聚合响应**附加** `sectionPagination` 键（announcements/events 列表值仍为裸数组，非破坏） |
| D4 | 新闻停止条件判定 | **前端判定**（客户端已知累积 docid 集是「新增」的唯一真相）；后端契约无状态：单请求 = 单源页过滤结果 + `hasMore`（源页耗尽信号） |
| D5 | 公告 5 页上限 | **后端 400 硬拒绝**（page>5），前端 maxPages 显示层封顶双保险；外呼放大封顶由此成立 |
| D6 | 巨潮备选翻页语义 | 响应字段 `paginationSupported:false` + `total:null`；`moreUrl` 恒透出（东财/巨潮按生效 provider 构造源站列表 URL） |
| D7 | `announcePageSize` 3→10 | **Flyway 一次性条件迁移 V19**（仅当现值=3 置 10，保留页面其他改动）+ 校验器补 1~50 上限 |
| D8 | `policyUrl` 扩容 | 缺省改指 `ZUIXINZHENGCE.json` + `GovPolicyClient` 增 JSON 解析分支（输出同款 raw 契约 `title/url/pubDate`，adapter 零改动）+ 新参数 `policyMaxItems`（缺省 30）+ V20 条件迁移 |
| D9 | 事件分页实现 | `AnomalyRepository` 端口扩展 `countRecentBySubject` + `findRecentPage`（SQL 窗口+LIMIT/OFFSET，命中既有索引，沿 ADR-0035 从简口径） |

## ⚖️ 3. 候选方案对比

### 3.1 契约形态（核心裁决）

| 维度 | 方案 A：聚合接口分区参数化（`/detail?sections=announce&page=2`） | 方案 B：分区子端点（`/subjects/{id}/announcements?page=2`）✅ |
| --- | --- | --- |
| 思路 | 翻页仍走聚合端点，page 参数作用于（隐式约定的）唯一列表分区 | 每个可翻页分区一个资源子端点，各自独立参数与响应契约 |
| 三约束满足（仅目标分区刷新/零重拉/三态一致） | 响应仍是整张 SubjectDetail：其他分区键为 null，前端须合并；「page 属于哪个分区」靠 sections 隐式约定，多分区+page 时语义歧义需专门校验 | 天然满足：一次请求=一个分区；sourceStatus 单分区字段直接对齐聚合口径（同一 adapter 产出） |
| 契约确定性 | 三种分页语义（page/size/total vs page/hasMore vs 无）挤一个端点，参数模式爆炸（M9 双模式先例是**同语义加过滤**，此处是**异语义**） | 每端点单一语义；新闻端点可不接受 size（源页大小是运维配置） |
| 开发量 | Controller 改动小但 AggregationService/SubjectDetail 契约耦合改动大、测试面在存量 1432 用例上回归 | 新增 Controller/Service/View 三件套 ×3，存量聚合路径**零改动** |
| 可回滚/可替换性 | 聚合契约一旦被前端依赖 page 参数，回滚牵动主路径 | 纯增量端点，废弃即删；聚合路径不动 |
| REST 语义 | `?sections=announce&page=2` 查询方式编码进参数组合 | `/subjects/{id}/announcements` 名词子资源，动词由 GET 表达 |

**选择：方案 B。** 对齐五维度：成熟度（子资源分页是 REST 通行做法）/ 学习成本（无新框架）/ 可替换性（纯增量）/ 运维成本（零新部署面）；方案 A 的「省端点」收益被三约束的实现别扭度吃掉。ADR-0035 的双模式先例**不适用于此**——那是同一列表资源加过滤条件，这是三个异构分页语义，对号入座后子端点是标准解。

### 3.2 翻页与缓存关系

| 维度 | 方案 A：各页独立缓存（缓存键扩为 subjectId+page+size） | 方案 B：翻页绕缓存直调源 ✅ |
| --- | --- | --- |
| 实现代价 | `SourceCache` 键类型 Long→复合键，7 源共用组件全量波及；页界漂移使页缓存价值低（陈旧页误导） | `fetchPage` 走「熔断→弹性→事件」骨架但不读写缓存；`SourceCache` **零改动** |
| 外呼成本 | 翻页命中缓存省外呼 | 每次翻页恰好 1 次外呼（公告 5 页封顶 / 新闻 ≤2 次每点击、≤10 源页累计 / 事件 0 外呼），产品上限即外呼上限 |
| 一致性 | 页缓存 TTL 内翻回旧页，与源站页界漂移叠加更难解释 | 每页所见即源站当前态，页界漂移口径与 PRD 非功能裁决一致 |

**选择：方案 B（从简）。** 翻页是用户主动低频动作，不是热点读；缓存货架（方案 04）的适用前提「读多写少扛流量」在翻页场景不成立。首屏高频路径继续吃快照缓存（公告 5min/新闻 2min），本条不触动。

### 3.3 其余裁决（简列，详见 §4）

- **首屏总数形态**：改列表值为对象（`announcements: {items,total}`）= 破坏性变更，被否；附加 `sectionPagination` 键 = 纯增量，前端类型加可选字段。
- **新闻停止条件归属**：后端无法判定「新增」（不知道前端已有哪些 docid），传 excludeDocid 清单上限失控，被否；前端判定 + 后端无状态契约 + `hasMore` 源页耗尽信号。
- **事件分页实现**：SQL 窗口+分页 vs 全量内存分页——本地表带 `idx_anomaly_subject_time`，SQL 直落索引（沿 ADR-0035 LIMIT/OFFSET 从简 + 毫秒级实测口径）；内存全量在活跃标的增长后浪费，被否。

## 🔧 4. 详细设计

### 4.1 接口契约

三个子端点均挂 `SubjectSectionPageController`（`interfaces/aggregation`，`/api/v1/subjects` 前缀复用）；统一走 `Result<T>` 包装与 `GlobalExceptionHandler`（400=2001 参数错、404=30001 标的不存在）。校验复用 `PageQuery` 口径：`page≥1`（防溢出上限 `MAX_PAGE=1,000,000`）、显式 `size` 1~50 越界 400 拒绝不截断。

#### 4.1.1 公告分区 `GET /api/v1/subjects/{subjectId}/announcements?page=&size=`

请求：`page` 必填（≥1，**上限 5**——超限 400「page 超过上限 5，更多历史公告请走源站」）；`size` 可选，缺省 = 运行时 `datasource.ANNOUNCE.params.announcePageSize`（迁移后缺省 10），显式传值走 1~50。

```json
// 200 · Result<AnnouncementPageView>
{ "code": 0, "message": "ok", "data": {
    "items": [ { "title": "...", "publishedAt": "2026-08-15", "category": "其他",
                 "url": "https://pdf.dfcfw.com/pdf/H2_AN..._1.pdf" } ],
    "page": 2, "size": 10,
    "total": 1074,                    // 东财 total_hits 透出；巨潮生效时为 null
    "paginationSupported": true,      // 本次请求实际生效 provider 是否支持翻页（东财 true / 巨潮 false）
    "moreUrl": "https://data.eastmoney.com/notices/stock/600519.html",  // 源站列表出口，恒透出
    "sourceStatus": "ok",             // ok | missing | failed | timeout，与聚合口径同源
    "source": "东方财富公告"           // 生效 provider 标注（巨潮时「东方财富公告→巨潮资讯备选」）
} }
```

语义细则：

- 越界页（page ≤5 但超出源总页数）：200 + `items:[]` + 如实回显 page/size/total（沿 ADR-0035 越界页语义，前端检测回第 1 页）。
- 巨潮生效（东财当次请求失败走链位 1）：返回巨潮第一页条目 + `paginationSupported:false` + `total:null`；若请求 page>1 时东财恰好失败而巨潮接住，返回 `items:[]` + `paginationSupported:false`（前端据 false 渲染降级文案并保留当前内容，不视为错误）。
- `moreUrl` 构造：东财 `https://data.eastmoney.com/notices/stock/{6位代码}.html`；巨潮生效 `https://www.cninfo.com.cn/new/fulltextSearch?notautosubmit=&keyWord={6位代码}`。6 位代码取自 `subject.external_codes`（派生逻辑同 `AnnounceSourceAdapter.resolveStockCode`）。

#### 4.1.2 事件分区 `GET /api/v1/subjects/{subjectId}/events?page=&size=`

请求：`page` 必填（≥1，无 5 页上限——本地数据翻完即止）；`size` 可选，缺省 10（原 `MAX_ITEMS` 语义升级为页大小常量），显式 1~50。

```json
// 200 · Result<EventPageView>
{ "code": 0, "message": "ok", "data": {
    "items": [ { "anomalyType": "PRICE_CHANGE", "changePct": 5.2, "currentPrice": 1680.0,
                 "triggerTime": "2026-09-20T02:00:00Z", "detail": "..." } ],
    "page": 1, "size": 10,
    "total": 37,                      // 7 天窗内精确 count，与页切片同窗口同口径（窗界=请求时刻-7d）
    "sourceStatus": "ok", "source": "事件监控"
} }
```

- 越界页：200 + `items:[]` + total 如实（同 4.1.1 口径）。
- 空窗（total=0）：`items:[]`、`sourceStatus:"missing"`（维持聚合页现状 missing 兜底语义，前端不渲染分页条）。

#### 4.1.3 新闻分区 `GET /api/v1/subjects/{subjectId}/news?page=`

请求：`page` 必填 = **源页码**（≥1，PageQuery 上限）；**不接受 `size`**（出现即 400「size 仅公告/事件端点可用」——源页大小是运维配置 `newsPageSize`，不属调用方自由度，契约确定性优先）。

```json
// 200 · Result<NewsPageView>
{ "code": 0, "message": "ok", "data": {
    "items": [ { "externalId": "sinacn-...", "title": "...", "publishedAt": "...",
                 "summary": "...", "url": "...", "source": "...", "keywords": "..." } ],
    "page": 2, "size": 20,            // size 回显源页大小（newsPageSize）
    "hasMore": true,                  // 源页未耗尽（本源页条数 == 源页大小且非空）；空页/不满页 = false
    "sourceStatus": "ok", "source": "新浪财经新闻"
} }
```

- `items` = 该源页经 `isRelevant` 过滤后的**命中条目**（docid 已映射为 `externalId`，前端去重稳定标识——映射文件 `sina-news.json` 已含 `docid→externalId`，零改动）。
- 空源页/流耗尽：`items:[]` + `hasMore:false`；无命中但有条目：`items:[]` + `hasMore` 按源页满否如实。
- **停止条件判定在前端**（D4）：前端持有累积 `Set<externalId>`；「新增」= 过滤掉已见 id 后非空。规则：单次点击串行最多探 2 个源页（第 1 个源页零新增→自动探下一页）；连续 2 源页零新增、或 `hasMore:false`、或累计探页达 10 → 停止并渲染「没有更多相关新闻」。后端单请求恰好 1 次外呼，外呼约束（≤2/点击、≤10 累计）由前端请求次数天然保证。

#### 4.1.4 聚合接口附加键（非破坏）

`GET /api/v1/subjects/{id}/detail` 响应 **新增可选键** `sectionPagination`（`SubjectDetail` record 追加一个字段，既有键全部不动）：

```json
"sectionPagination": {                       // 仅对应分区 sourceStatus=ok 时出现
  "announce": { "total": 1074, "paginationSupported": true, "moreUrl": "https://..." },
  "event":    { "total": 37 }
}
```

- 首屏分页条的总数由聚合响应直接提供，**不发第二次请求**；公告 total 随 SourceCache 快照缓存（5min TTL 内一致）。
- 新闻/政策永不出现（无总数语义）；missing/failed/timeout 分区不出现（非 ok 不渲染分页控件，与三态契约互斥）。

#### 4.1.5 错误码汇总

| 场景 | HTTP | code | 说明 |
| --- | --- | --- | --- |
| page 缺失/非法/越上限（公告 >5） | 400 | 2001 | PageQuery 口径字段级 msg |
| size 越界（1~50）/ news 端点出现 size | 400 | 2001 | 拒绝不截断 |
| 标的不存在 | 404 | 30001 | 与聚合端点同口径 |

### 4.3 核心流程

#### 4.3.1 公告翻页（含降级链）

```
前端点击「下一页」(page=2)
→ GET /subjects/{id}/announcements?page=2
→ SubjectSectionPageService：resolveSubject(404 口径) → PageQuery 校验 + page≤5
→ RoutingSourceAdapter.fetchPage(subject, 2, size)          # REAL/MOCK 路由与聚合同源
→ AnnounceSourceAdapter.fetchPage：
    FallbackChainRunner（DB 链优先，缺省 ["eastmoney","cninfo"]）
    ├ eastmoney: client.fetchAnnouncementPage(code, 2, size)
    │    → RawFetch{ items, total=total_hits, paginationSupported=true, page/size 回显 }
    └ cninfo(仅当东财失败/空)：page==1 → 第一页条目 + paginationSupported=false
                              page>1  → items=[] + paginationSupported=false
→ AnnouncementPageView 组装（moreUrl 按生效 provider 构造）
→ 200；失败/超时 → sourceStatus 降级（不抛 HTTP 错）
```

外呼预算：每请求最多 1 次东财 + 1 次巨潮兜底（同现状 doFetch 两轮合用 2s 预算，noRetry 沿 ADR-0011/0034）。

#### 4.3.2 新闻加载更多（前端状态机，D4）

```
首屏：聚合响应 news.items（源页 1 命中）→ seenIds=Set(externalId)，nextSourcePage=2，explored=1
点击「加载更多」：
  loop（本点击最多 2 轮）：
    GET /subjects/{id}/news?page=nextSourcePage
    newHits = items.filter(id ∉ seenIds)
    追加渲染 newHits，seenIds += ids
    if newHits 非空 → 结束本次点击（按钮保留）
    if newHits 空 → 续探一轮（explored++）；连续 2 轮空 → stopped=true（渲染「没有更多相关新闻」）
    if hasMore=false → stopped=true
  累计 explored≥10 → stopped=true（不再发请求）
失败：保留已展示条目 + 分区错误行 + 重试（重发同一目标源页）；在途：按钮 disabled + aria-busy
```

#### 4.3.3 事件分页与首屏总数

- 子端点：`since = now - 7d`（每请求现算，与现状 RECENT_WINDOW 口径一致）→ `countRecentBySubject` + `findRecentPage(offset=(page-1)*size)`，零外呼。
- 首屏：`EventSourceAdapter.doFetch` 改调 `findRecentPage(subjectId, since, 0, PAGE_SIZE)` 并在 data map 附 `total`（count 一次本地毫秒级查询）→ 聚合 `assemble` 提取进 `sectionPagination.event`。`MAX_ITEMS=10` 常量语义变更为默认页大小，截断逻辑移入 SQL。

#### 4.3.4 政策扩容（T93）

`GovPolicyClient.fetchPolicies()` 增分支：`policyUrl` 以 `.json` 结尾 → RestClient 取 JSON 数组 → 截取前 `policyMaxItems` 条 → 逐条转 raw map `{title: TITLE, url: URL, pubDate: DOCRELPUBTIME}`（**与 HTML 分支输出同契约**，`PolicySourceAdapter` 的行业过滤/单位切分/映射零改动）；否则走既有 Jsoup HTML 分支（页面手改回 HTML URL 即回退，热生效）。`PolicyFetchJob` 共享此 client——扩容后每轮入库约 9→30 条（`existsBySourceUrl` 去重幂等，M9 政策时事页时间窗检索受益，无额外风险）。

### 4.4 关键技术点

- **缓存一致性**：`sectionPagination.announce.total` 随 SourceCache 快照缓存（5min），子端点 total 每次实时——两者短窗内可能不同（源站新公告），接受（页界漂移同类固有现象，PRD 非功能已裁决）。
- **mock 模式**：三个 mock adapter 覆写 `fetchPage`——公告 mock 返回全量条目切片 + `total=条数`、`paginationSupported:true`；新闻 mock 第 2 页起 `items:[]` + `hasMore:false`；事件 mock 窗口切片。满足 PRD 场景 5（mock 下不报错）即可，不模拟真实深翻。
- **5 页上限的双层语义**：后端 400 是权威（外呼封顶成立），前端 maxPages 是体验（不可点）；400 响应走分区错误态（保留内容），合规前端不会触达。
- **页界漂移**：公告跨页同日多条可能重复（东财 notice_date 同日粒度），PRD 接受为固有现象；新闻已按 externalId 去重兜底；事件 trigger_time 整秒唯一性足够（业务键同日同类型仅一条）。
- **可测性预留**：三子端点均为无状态 GET，页码/上限/降级/越界可直接断言；`fetchPage` 绕缓存使测试不受 TTL 干扰；V19/V20 迁移可 up/down 验证。
