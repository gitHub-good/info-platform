## 🎯 1. 设计总览与关键决策

| # | 决策 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 导航接入 | 运维组追加第 6 项「提示词模板」（全站第 13 页），hash 路由 `#/prompt-templates`，图标 `MessageSquareText` | 紧邻模型/数据源配置，同属「改 AI 产出的运维入口」；图标语义（消息模板）贴切且已验证既有 lucide 版本导出 |
| D2 | 页面布局 | **单列纵向滚动：4 场景分区（Section Card）× 每场景版本卡网格**，不做左右分栏 | PRD 故事 1 核心是「4 场景 × 全部版本一页可见」的总览诉求——分栏会把总览拆成 4 次点击；版本量级小（每场景典型 1~3 版），一屏可滚动看完；复用 LlmConfig「分区卡 + 卡网格」范式，一致性最高 |
| D3 | 版本详情形态 | **版本卡内联展开**（卡头常驻、点「详情」展开正文区），不用 Dialog | 既有 `ui/dialog` 固定 `max-w-md`，装不下多行长模板（横向滚动伤阅读）；内联展开宽度随卡片、展开态互不干扰；实现零成本（组件内一个 boolean state） |
| D4 | 编辑器形态 | **页内替换式编辑视图**：同一路由下「列表视图 ⇄ 编辑视图」state 切换（带未保存守卫 + sessionStorage 草稿兜底），不用 Dialog | 长文本编辑 + 占位符对照侧栏需要完整画布；Dialog 加宽属组件 API 变更且仍局促；hash 不变（`#/prompt-templates`）避免路由新增，返回 = 单击「返回列表」 |
| D5 | 编辑器实现裁决（从简） | **纯原生 textarea（等宽字体）单框编辑 + 下方只读「分段预览」**（实时切分 SYSTEM/USER、占位符着色），**不做语法着色编辑器** | 模板是纯文本 + 2 个独占行标记，textarea 保真无歧义；着色编辑需 overlay 同步滚动，实现重且易错位；预览只读渲染只需正则切分（`TemplateTextView`），成本 1/10 且信息等价 |
| D6 | 占位符对照 | **编辑器右侧 sticky 对照栏**：该场景全部 `{{key}}` + 一句话用途，点击插入光标处；数据一律来自 T46 注册表接口，与保存校验同源 | PRD 故事 4（清单 + 一键插入 + 校验同源）；对照需在编辑全程可见，故随编辑器而非弹层 |
| D7 | 三级校验形态 | **硬校验：校验面板 rose 逐条 + 保存按钮禁用**；**移除占位符：保存确认 Dialog 逐项勾选「确认移除」，全勾才放行**；**未知占位符：面板与 Dialog 内 amber 警告，不需勾选**。后两级合并进同一个「保存确认 Dialog」 | 硬错误无放行通道（结构损坏/JSON 前提），禁用保存比「点击后再报错」更防误操作；移除是「有意精简」合法诉求 → 留显式确认通道（逐项勾选 = 逐项知情）；未知仅提醒不拦（PRD 裁决点 4 原文语义）；合并 Dialog 避免连弹两层 |
| D8 | 激活醒目性 | 激活卡 `ring-1 ring-emerald-500/40` 边框 + emerald「使用中」徽章；置废卡 `opacity-60` + muted「已置废」徽章；**场景分区头右侧常驻「当前使用 vX.Y」徽章**（扫读不看卡即知绑定） | 沿 LlmConfig 停用卡 `opacity-60` 先例；状态色全部带文字（§5.1 惯例）；场景头徽章满足 PRD「哪个 AI 能力在用哪版一眼看清」 |
| D9 | 版本号交互 | **用户不填版本号**：选择递增策略（次版本=默认 / 主版本）+ 实时预览「将保存为 vX.Y」；递增基准 = 该场景当前最大版本；冲突由后端拦截提示刷新 | PRD 风险表「版本号 TEXT 字典序错序」对策：不让自由填写；UNIQUE(brief_type, version) 冲突兜底在后端 |
| D10 | 保存反馈 | 复用 `SaveFeedbackBar`：hotFields 枚举「{场景} {新版本号} 已保存并激活」+「下一次生成即用新版本」；模板变更全部即时生效（无 restart 语义），`EffectBadge` 不出场 | PRD 非功能「保存成功反馈明确已激活，下次生成生效」；M4 §4.2「禁止静默反馈」红线延续；生成链路每次现查激活模板，天然无重启项 |
| D11 | 草稿兜底 | 编辑视图为组件 state（hash 不变），dirty 草稿写 `sessionStorage`（key 含 briefType），重进编辑器提示恢复或丢弃 | 30 行级模板误刷新丢稿代价高；兜底实现 ≤30 行，单人桌面场景够用 |

## 🗺️ 2. 信息架构

### 2.1 导航接入（navConfig / App.tsx 各一处追加）

| 项 | 值 |
| --- | --- |
| 分组 | 运维（第 6 项，追加在「数据源配置」之后） |

| to | `/prompt-templates` |

| testid | `nav-item-prompt-templates`（navConfig 现有约定自动生成） |

### 2.2 页面状态模型（单路由两视图）

```
#/prompt-templates
  │
  ├── 列表视图（默认落地）
  │     4 场景分区 × 版本卡网格
  │     ├── [新建版本]（场景头）──┐
  │     └── [编辑]（版本卡）──────┤
  │                              ▼
  └── 编辑视图（state 切换，hash 不变）
        基于某底稿版本的模板编辑 + 占位符对照 + 三级校验 + 保存确认
        └── [返回列表] / 保存成功后手动返回（dirty 离开需确认，D11）
```

- 进入编辑视图 = 携带「场景 + 底稿版本」两要素；「新建版本」以该场景**当前激活版本**为底稿预填，「编辑」以所点版本为底稿预填（两者殊途同归：保存都落新版本并激活，PRD 故事 2 场景 1）。
- 视图切换不产生历史记录（`navigate` 不用），浏览器后退离开整页——编辑守卫靠 D11 草稿兜底，不做 `beforeunload` 拦截（从简）。

### 2.3 数据与视图映射（按需求文档假定接口能力，契约联判见 §6.2）

| 视图元素 | 数据来源 |
| --- | --- |
| 场景分区 ×4（名称/说明） | 前端静态映射（BriefType 1 个股简报 / 2 事件归因 / 3 政策解读 / 4 每日推荐） |
| 版本卡（版本号/状态/updated_at/template 全文） | T45 列表接口，按场景分组返回 |
| 占位符数量徽章 | 前端对 template 正则统计（唯一 `{{key}}` 个数），不依赖后端冗余字段 |
| 占位符对照栏（key + 用途说明） | T46 注册表接口（编辑视图打开时按 briefType 拉取） |
| 校验 diff 基准（移除/新增占位符） | **底稿版本 template 与 T46 清单**（同源，故事 4 场景 3） |

## 📄 3. 页面设计

> 页头沿用全站惯例：`h1 text-xl font-medium`「提示词模板」+ 一句 `text-sm text-muted-foreground` 说明「4 个 AI 场景的提示词一页治理：版本全量可见、编辑即时生效、可回滚」；内容区 `max-w-6xl`（同 LlmConfig/TaskCenter）。

### 3.1 列表视图：模板列表与绑定总览

**线框**：

```
┌ #/prompt-templates · 提示词模板 ────────────────────────────────┐

│ │ ┌ v1.1 [使用中] ─────────────┐ ┌ v1.0 [已置废] ───────────┐ │ │
│ │ │ 更新 09-22 10:12 · 占位符 12│ │ 更新 09-21 08:00 · 占位符12│ │ │
│ │ │ [编辑] [详情 ∨]             │ │ [设为激活] [编辑] [删除]  │ │ │
│ │ │ ┄┄ 详情展开区（§3.2）┄┄     │ │ [详情 ∨]                 │ │ │
│ │ └────────────────────────────┘ └──────────────────────────┘ │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ ┌ 事件归因 · 当前使用 [v1.0] · 占位符注册 7 项      [新建版本] ┐ │
│ │ （同上结构，单版本场景仅 1 卡）                              │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ ┌ 政策解读 … ┐ ┌ 每日推荐 · 当前使用 [v1.1] … ┐                  │
│   （每日推荐含 v1.0 置废卡：T29 升级留痕的真实样例）              │
│                                                                │
│ 版本卡网格：1 列（mobile）→ 2 列（lg）；场景分区 flex flex-col gap-4│
└────────────────────────────────────────────────────────────────┘
激活卡整卡 ring-1 ring-emerald-500/40；置废卡 opacity-60；
场景内排序：激活卡置顶，其余按版本号倒序
```

**交互说明**：

1. **场景分区（Card 包裹）**：分区头 = 场景名 + 「当前使用 vX.Y」emerald 徽章（D8）+「占位符注册 N 项」muted 小字（来自 T46，懒加载：列表视图不请求，编辑时才拉——分区头该字段在未拉取前不显示，从简）+ 右侧 primary sm 按钮「新建版本」。
2. **版本卡（VersionCard）**：卡头一行 = 版本号（`font-mono`）+ 状态徽章 + 元信息（更新时间 `MM-dd HH:mm`、占位符 N 项）；操作行按状态分化：
   - 激活卡：`[编辑]`（default sm）+ `[详情 ∨]`（ghost sm）；**无「设为激活」「删除」**——激活卡不可自证切换，删除走禁用规则（交互 4）。
   - 置废卡：`[设为激活]`（default sm）+ `[编辑]`（outline sm）+ `[删除]`（outline sm，hover `text-rose-400`）+ `[详情 ∨]`（ghost sm）。
   - 激活卡的删除入口：不放按钮（比「禁用按钮」更省一行；拦截语义由置废卡可见的操作行差异自明）。若走查发现用户找不到删除，降级方案 = 激活卡放 disabled 删除按钮 + `title`「激活版本不可删除，请先切换激活」（二选一，默认前者）。
3. **「编辑」语义标注**：编辑总是产生新版本。按钮 `title="基于此版本创建新版本，保存后自动激活"`；编辑器头部再明示（§3.3），不在列表层加长文案。
4. **激活醒目性（D8 落地）**：激活卡边框高亮 + 「使用中」emerald 徽章；置废卡整卡 `opacity-60`（沿 LlmConfig 停用卡先例，悬停恢复 `opacity-100` 保证操作可读）；状态色均带文字。
5. **场景异常空态（PRD 故事 1 场景 3，Must）**：某场景有版本但**无激活版本**（如手工改库）→ 分区头下方 rose 警示条「该场景无启用模板，AI 生成将失败」，且该场景全部版本卡的 `[设为激活]` 均可点（自助修复通道）；某场景**完全无版本** → muted 占位「该场景暂无模板版本（播种数据应保证至少 1 版，此态属数据异常）」+ 同样 rose 警示条。不静默空白。

**组件清单**：`ui/card`、`ui/badge`、`ui/button`、`ui/skeleton`、自研 `VersionCard`、`TemplateTextView`（§5.2）、`SaveFeedbackBar`（场景级操作反馈）。

**三态**：

| 态 | 表现 |
| --- | --- |
| loading | 4 分区骨架：每分区 `Skeleton h-10`（分区头）+ `Skeleton h-24` ×2（版本卡） |
| empty | 分场景两档（交互 5）；4 场景全空 = 整页数据异常 → 按错误态处理 |
| error | 整页加载失败：`text-sm text-destructive`（`role="alert"`）+ outline「重试」（M4 §4.1 基线）；操作失败反馈见 §4.2 |

### 3.2 版本详情展开（内联，PRD 故事 1 场景 2）

**线框**（版本卡展开区）：

```
│ ┌ v1.1 [使用中] … [编辑] [详情 ∧] ──────────────────────────┐ │
│ │ SYSTEM                                                     │ │
│ │ ┌ bg-muted rounded p-2 font-mono text-xs ────────────────┐ │ │
│ │ │ 你是金融信息分析师。基于用户提供的数据，生成结构化 json  │ │ │
│ │ │ 简报。规则：…                                           │ │ │
│ │ └─────────────────────────────────────────────────────────┘ │ │
│ │ USER                                                       │ │
│ │ ┌ 同上 ──────────────────────────────────────────────────┐ │ │
│ │ │ 标的：{{subjectName}}({{subjectCode}})，行业：…         │ │ │
│ │ │ {{price}} {{newsList}} …                               │ │ │
│ │ └─────────────────────────────────────────────────────────┘ │ │
│ └─────────────────────────────────────────────────────────────┘ │
```

**交互说明**：

1. **展开/收起**：点 `[详情 ∨]` 或卡头切换（`aria-expanded`）；多卡可同时展开（互斥管理收益低，从简）。展开区随卡内容增高，无弹层。
2. **分段展示**：`TemplateTextView` 按 `---SYSTEM---` / `---USER---` 独占行标记切分，各段前置 muted 小标签「SYSTEM」「USER」，正文 `pre whitespace-pre-wrap font-mono text-xs`。**模板原文含标记**（存储格式不变），展开区只是隐藏标记行、分块渲染——展示层切分，不改数据。
3. **占位符高亮**：仅 `{{key}}`（双花括号 + `\w+` 键名，与渲染正则同口径）着色——注册表内 `bg-sky-500/20 text-sky-300`；**不在注册表内 amber**（详情视图即提前暴露未知占位符）。user 段 JSON 形状约束的**单花括号 `{summary, …}` 不着色**（渲染不替换它们，高亮口径必须与渲染一致，防误导）。
4. 分段标记缺失/顺序错（历史脏数据，页面操作不可能造成）：展开区降级整段 `pre` 原文展示 + 顶部 rose 一行「分段标记缺失或顺序错误，渲染将失败——请编辑修复」。

**交互说明**：

1. **底稿与标题**：头部标注「{场景}（基于 vX.Y）」；进入即预填底稿 template 全文（激活版或所点版本，§2.2）。「返回列表」= outline sm；dirty 时点击弹确认 Dialog「未保存的修改将丢弃，确认返回？」（取消可继续编辑）。
2. **模板正文（D5）**：原生 `<textarea>` + Tailwind（`min-h-96 resize-y font-mono text-sm whitespace-pre`，`spellCheck=false`），保留 `---SYSTEM---` / `---USER---` 原文标记直接编辑——**所见即所存**，不做双输入框（system/user 分开编辑会引入「存储格式拼装」心智，与 DB 存储格式有转换层；单框保真，从简裁决）。分段预览并入校验面板（见 5）。
3. **版本策略（D9）**：分段按钮组（复用 DatasourceConfig「真实/mock」分段样式：Button 组，选中 default、未选 ghost）：`次版本 v1.2`（默认）/ `主版本 v2.0`；按钮文案内直接带预览号（由前端按场景当前最大版本推算：次 = 最大版 minor+1，主 = 最大版 major+1 且 minor=0）。预览号下方 muted 说明「保存后自动激活，原激活版本置废留痕」。版本号**无自由输入框**。
4. **占位符对照栏（D6，PRD 故事 4）**：
   - 列表项 = `{{key}}`（`font-mono text-xs`）+ 一句话用途说明（T46 返回的 description）+ 该键在当前文本中的使用次数（`×2` muted，实时统计，帮助判断「这个键用没用到」）。
   - **点击插入**：向 textarea 光标处（`selectionStart`）插入 `{{key}}` 文本并把光标移到插入串之后、重新聚焦 textarea（PRD 场景 4.2）；键盘可达（列表项为 button）。
   - 栏内底部实时显示「文本中未注册占位符」amber 清单（若有）——与保存校验同源同结果，编辑时即可见，不用等保存。
   - 数据态：加载中骨架条 ×6；加载失败 → 栏内错误文案 + 「重试」outline xs 按钮，**不阻断编辑**（对照是辅助能力）；本栏数据失败时保存校验降级为「仅硬校验 + 后端兜底」。
5. **校验面板（实时，输入防抖 300ms）**：逐行呈现、随输入刷新：
   - 分段标记检查：SYSTEM/USER 标记各一处且 SYSTEM 在前（emerald ✓ / rose 具体缺失项文案，如「缺少 ---USER--- 标记」「标记顺序错误：---USER--- 须在 ---SYSTEM--- 之后」）。
   - system 段含 `json` 字样检查（emerald ✓ / rose「system 段须含 json 字样（JSON 输出模式前提）」）。
   - 占位符 diff（基准 = 底稿版本内容，见 §6.2 联判 3）：「移除 N 项（保存时需确认）」+「新增未知 N 项（可保存，警告）」逐项列出（amber）。
   - 面板不拦截输入，只呈现；硬错误行 rose 置顶。
6. **保存按钮状态**：dirty 且无硬错误时可点；未变更时禁用（防误存，M4 §4.3 惯例）；saving 中「保存中…」禁用；存在硬错误时禁用 + `title` 指向校验面板首条错误。
7. **保存流程（三级校验，PRD 场景 2.3~2.6 + 2.7）**：
   - 点击「保存并激活」：前端先跑硬校验（面板同款逻辑，双保险）→ 无移除且无未知 → 直接提交；有移除或未知 → 弹「保存确认 Dialog」（§3.4）。
   - 提交体携带 `baseVersion + versionStrategy + confirmedRemovedKeys[]`（§6.2 联判 2）；后端返回结构化错误时映射进反馈条/面板（硬错误类映射面板 rose；冲突类提示「版本号冲突，请刷新列表后重试」+ 自动重拉列表更新预览号）。
   - 成功：反馈条 emerald「已保存 · 即时生效：{场景} v1.2 已保存并激活；下一次生成即用新版本（旧缓存自动失效）」（D10 逐项枚举：新版本号 + 生效语义）；编辑器以新版本为新底稿重置（dirty 清零），「返回列表」回列表即见新卡置顶。
8. **草稿（D11）**：输入防抖写 `sessionStorage["prompt-draft-{briefType}"]`（存底稿版本号 + 正文 + 策略）；再次进入编辑器且存在草稿时提示「检测到未保存草稿（基于 v1.1，09-22 10:30）」+ `[恢复草稿] [丢弃]`；保存成功或点丢弃时清除。

**组件清单**：`ui/card`、`ui/badge`、`ui/button`、`ui/dialog`（离开确认/保存确认）、`ui/skeleton`、自研 `PlaceholderPanel`、`TemplateTextView`（分段预览）、`SaveFeedbackBar`、原生 `<textarea>`。

**三态**：

| 态 | 表现 |
| --- | --- |
| loading | 编辑器骨架：正文框 `Skeleton h-96` + 对照栏 `Skeleton h-64`（底稿来自列表数据时正文无 loading，仅对照栏有） |
| empty | 对照栏为空清单（T46 未登记该场景任何占位符）→ muted「该场景暂无注册占位符」；不影响编辑 |
| error | 对照栏加载失败（交互 4，可重试不阻断）；保存失败 → 反馈条 rose（ApiError.msg），表单保持 dirty 原文 |

### 3.4 保存确认 Dialog（移除确认放行 + 未知警告，D7）

**线框**：

```
┌ 保存确认 · 个股简报 ──────────────────────────────────┐
│ 以下 1 个占位符将从模板移除，移除后生成简报不再注入    │
│ 对应数据；确认为有意精简后可保存。                     │
│                                                       │
│ 将移除的占位符（须逐项确认）：                         │
│ [ ] 确认移除 {{roe}} —— 净资产收益率 ROE               │
│                                                       │
│ 警告（无需确认，仅提醒）：                             │
│ {{foo}} 无上下文来源，渲染时将原样发给模型             │
│                                                       │
│                          [返回修改] [仍要保存（须全勾）] │
└───────────────────────────────────────────────────────┘
ui/dialog 默认宽度；「仍要保存」在移除项未全勾选时禁用
仅未知占位符、无移除项时：不弹 Dialog，直接保存（面板警告已
足够，不多一层弹窗）
```

**交互说明**：

1. **移除清单**：每项 = 原生 `<input type="checkbox">` + label「确认移除 {{key}} —— {注册表用途说明}」（说明缺失时「（注册表未登记用途）」）；全勾后「仍要保存」激活，点击后携带 `confirmedRemovedKeys` 提交（PRD 场景 2.5 的「逐项勾选后放行」）。
2. **未知警告区**：Dialog 内只读 amber 列表（不需勾选，PRD 场景 2.6「确认后可保存」语义由本 Dialog 的「仍要保存」点击承担）；若 diff 同时含两类，同屏分区呈现（上勾选/下警告），一次决策。
3. **勾选不跨打开持久**：Dialog 每次打开重置（改模板后再保存重新逐项确认）；「返回修改」关闭 Dialog 回编辑器，正文不变。
4. **后端二次兜底**：提交后后端重校验（硬规则 + 移除集 + 未知警告），错误码结构见 §6.2 联判 2；后端判定的移除集与前端不一致时（并发/口径差），按后端返回的 `REMOVAL_CONFIRM_REQUIRED + removedKeys` 重新弹本 Dialog 预勾选已确认项。

### 3.5 激活切换与删除（PRD 故事 3）

**激活切换确认 Dialog**：

```
┌ 切换激活 · 每日推荐 ─────────────────────────────────┐
│ 将激活 v1.0（回滚），当前激活 v1.1 将自动置废留痕。   │
│ 即时生效：下一次每日推荐生成即用 v1.0 模板。           │
│                        [取消] [确认切换并激活]         │
└──────────────────────────────────────────────────────┘
```

**删除确认 Dialog**（仅置废版本可触发）：

```
┌ 删除版本 · 每日推荐 v1.0 ────────────────────────────┐
│ 物理删除不可恢复；该版本已置废、不在生成链路使用，     │
│ 删除不影响其余版本与激活状态。                        │
│                  [取消] [确认删除（rose 文案按钮）]    │
└──────────────────────────────────────────────────────┘
```

**交互说明**：

1. **设为激活**（置废卡按钮）：点击弹确认 Dialog（上左）→ 确认后调激活接口 → 成功：该场景列表刷新（新激活卡高亮、原激活卡置废灰显，**以前端重拉的服务端状态为准，不做乐观更新**——低频操作，刷新成本低于一致性风险，PRD 场景 3.1/3.4）+ 场景分区内 `SaveFeedbackBar` emerald「已激活 v1.0 · 即时生效：下一次每日推荐生成即用该版本」；失败：同位置 rose + ApiError.msg。
2. **删除守卫（PRD 场景 3.2）**：激活版本无删除按钮（§3.1 交互 2，默认形态）；若实现降级形态（disabled 按钮 + `title`），文案统一为「激活版本不可删除，请先切换激活到其他版本」。置废版本删除须过确认 Dialog（上右，rose 明示「物理删除不可恢复」）→ 成功：卡片消失 + 反馈条「已删除 v1.0」；失败：反馈条 rose。
3. **操作防重**：确认 Dialog 的确认按钮在请求在途时「执行中…」禁用（M4 §4.4 防连点惯例）；场景级互斥（同场景切换/删除/保存共用一个在途锁，避免并发操作打到同一不变量）。
4. **唯一不变量呈现（PRD 场景 3.4）**：任何操作成功后前端重拉列表，若返回某场景 0 激活（不应发生），立刻呈现 §3.1 交互 5 的 rose 警示条——不变量守护以后端事务为准，前端只做可见性兜底。

### 4.2 操作反馈矩阵

| --- | --- | --- |

- 列表加载失败时操作不可达（无数据可操作）；操作失败不清空已展示列表。

## 🎨 5. 设计规范约定

### 5.1 色彩语义（复用暗色 token，零新增 CSS 变量）

| 语义 | class 约定 | 用途 | 对暗底对比度 |
| --- | --- | --- | --- |
| 使用中 / 激活 / 即时生效 | `text-emerald-400` + `bg-emerald-500/15`；激活卡边框 `ring-emerald-500/40` | 「使用中」徽章、场景头「当前使用 vX.Y」、成功反馈 | ≥ 9:1 |
| 移除确认 / 未知警告 / 校验提醒 | `text-amber-400` + `bg-amber-500/15` | 校验面板移除/未知行、未知占位符高亮 | ≥ 10:1 |
| 硬校验错误 / 删除危险 / 无启用警示 | `text-rose-400` + `bg-rose-500/15`（文本 `text-destructive`） | 校验面板硬错误、删除按钮 hover、无启用模板警示条 | ≥ 7:1 |
| 已置废 / 中性 | `bg-muted text-muted-foreground` + 卡 `opacity-60` | 「已置废」徽章、占位符 N 项等元信息 | ≥ 7:1 |
| 占位符高亮（注册表内） | `bg-sky-500/20 text-sky-300` | `{{key}}` 高亮（详情 + 预览） | ≥ 9:1 |
| 分段标记行（预览） | `text-violet-400` | `---SYSTEM---` / `---USER---` 标记行 | ≥ 7:1 |
| 场景身份 | 不配色 | 场景名用纯文字，不为 4 场景分配固定色 | 状态色语义已满载，避免色噪 |

- 状态色全部带文字；占位符高亮口径 = 渲染正则同口径（仅 `{{\w+}}`，单花括号 JSON 形状不着色，§3.2 交互 3）。

### 5.2 自研组件清单（新增，全部轻量、零新依赖；页面域目录 `components/prompt/`，对齐 `components/feed/` 等既有先例）

| 组件 | 职责 | 实现要点 |
| --- | --- | --- |
| `VersionCard` | 版本卡：徽章/元信息/操作行/内联详情开关 | 激活卡 ring 高亮、置废 `opacity-60` hover 恢复；`aria-expanded`；分段正则与渲染同口径 |
| `TemplateTextView` | 只读模板渲染：SYSTEM/USER 分段 + 占位符高亮 | 正则切分（标记行隐藏、标记缺失降级原文 + rose 提示）；`pre wrap font-mono text-xs`；详情与编辑预览共用 |
| `PlaceholderPanel` | 占位符对照栏 | sticky；条目 = button（点击插入回调）+ 用途 + 次数；含未注册占位符 amber 区、加载/错误态 |
| `PromptTemplateEditor` | 编辑视图主体（表单 + 校验面板 + 版本策略） | 页面域组件（先放 `pages/` 内，仅本页使用不抽公共目录）；草稿 sessionStorage |

复用既有：`ui/card / badge / button / dialog / skeleton`、`SaveFeedbackBar`（success 相 hotFields 承载枚举文案）；原生 `<textarea>` / `<input type="checkbox">`（无对应 ui 组件，沿 JobLog 原生 select 先例，不新增依赖）。`EffectBadge` / `Switch` / `ui/table` / `ui/tabs` 本页**不使用**（模板无重启生效语义；激活是排他破坏性确认操作不用开关；卡片布局不用表格；tabs 全站零使用不启用）。

### 5.3 版本号与校验规则（前端呈现口径）

| 规则 | 前端行为 |
| --- | --- |
| 次版本递增 | 场景当前最大版本 `v{M}.{m}` → `v{M}.{m+1}`（分段按钮文案直接带预览号） |
| 主版本递增 | `v{M}.{m}` → `v{M+1}.0` |
| 冲突 | 后端 UNIQUE 拦截 → 反馈条 rose「版本号冲突（可能列表已过期），已刷新，请重试」+ 重拉列表重算预览号 |
| 分段标记 | SYSTEM/USER 各一处、独占行、SYSTEM 在前；实时校验 + 保存双跑 |
| json 字样 | system 段（切分后）包含 `json`（大小写不敏感，与现状播种口径一致）；实时 + 保存双跑 |
| 移除占位符 | diff 基准 = 底稿版本内容；保存时逐项勾选放行，`confirmedRemovedKeys` 随请求上行 |
| 未知占位符 | 文本中存在、T46 清单不存在 → 警告不拦；预览高亮 amber + 面板行 + Dialog 警告区 |

### 5.4 可达性底线

- 正文/状态文字对比度 ≥ 4.5:1（§5.1 已核）；焦点可见（全站 `focus-visible:ring-2 ring-ring/50` 惯例）。
- 占位符插入按钮、详情展开、Dialog 操作全部键盘可达；展开钮 `aria-expanded`；textarea 显式 `aria-label`。
- 校验面板 `role="status"`；硬错误行 `role="alert"`；反馈条 `aria-live="polite"`（SaveFeedbackBar 既有）。
- 颜色不单独承载信息：使用中/置废/警告均文字徽章，占位符高亮同时用于详情与预览（同形对照）。

### 6.2 给架构的联判点（T45/T46 接口契约落实，按需求文档假定能力的细化）

| # | 联判点 | 设计侧诉求 |
| --- | --- | --- |
| 1 | 列表接口形态 | 建议 `GET /api/v1/prompt-templates` 按 4 场景分组**携带 template 全文**（详情展开与 diff 基准都要用，免二次请求；单人体量无压力）；若不带则须返回 `placeholderCount` + 详情单查接口（二选一，默认前者） |
| 2 | 新建版本接口 | `POST`（按场景）请求体建议 `{ baseVersion, template, versionStrategy: MINOR\|MAJOR, confirmedRemovedKeys: string[] }`；响应 `{ version, … , warnings: string[] }`。**错误需结构化分级**：硬校验（逐条文案）、`REMOVAL_CONFIRM_REQUIRED`（附 removedKeys 清单）、版本冲突（专用错误码）——前端按级映射面板/Dialog/反馈条（D7） |
| 3 | diff 基准口径 | 前端以**底稿版本内容**为移除/新增 diff 基准（编辑置废旧版场景下 ≠ 当前激活版）；后端校验请同口径（以 baseVersion 行内容为基准），否则确认清单前后端不一致 |
| 4 | 下一步版本号 | 前端由列表最大版本推算预览号，最终以后端生成为准；冲突返回专用错误码，前端重拉重算（D9） |
| 5 | 占位符注册表（T46） | `GET` 按 briefType 返回 `[{ key, description }]`；**保存校验与对照栏必须同一接口同源**（PRD 故事 4 场景 3），前端不硬编码清单；description 为一句话用途 |
| 6 | 删除守卫错误码 | 激活版本删除返回专用错误码（前端虽无按钮，后端兜底路径需可映射文案「激活版本不可删除，请先切换激活到其他版本」） |
| 7 | 唯一不变量 | 切换/保存/删除的事务性（有且仅有一个 status=1）由后端保证；前端操作后一律重拉列表呈现，不做本地推演（PRD 场景 3.4） |
| 8 | 场景元数据 | 4 场景名称/说明前端静态映射（BriefType 枚举稳定）；若后端要单源下发，接口带 scene label 即可兼容 |
