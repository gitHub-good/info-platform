## 🎯 1. 背景与目标

### 背景（设计前代码核实，2026-09-24）

| 现状 | 核实结果 | 对本方案的意义 |
| --- | --- | --- |
| `subject_master`（V1 建） | 列：`id / subject_code(UNIQUE) / market / subject_type / name / external_codes(JSON TEXT) / industry / status / created_at / updated_at / version`；索引 `idx_subject_type` / `idx_subject_market`；V2+V17 种子共 45 只（42 股票 + 4 指数 + 港股 1 只） | 已具备全量承载能力；缺"连续缺失计数"列 → V18 加一列（§4.1，ADR-0028） |

### 目标（对齐 PRD，可量化）

- 首轮同步后标的池 45 只 → 约 8500 只（实测 A 股 5561 + 港股主板/GEM 2927），任意上市股票可搜索、可加自选、行情可取。
- 每日一轮自动保鲜：新上市入库、名称/行业更新，**永不发版播种、永不物理删除、status 只 1→0**。
- 同步作为受管任务进任务中心：默认启用、CRON 每日 06:00 可配、手动可触发、每轮计数可查。
- 单轮耗时分钟级（两市场 86 页 + 礼貌间隔 600ms ≈ 2 分钟），06:00 开市前裕量充足。

### 验收红线逐条对齐

| PRD 红线 / 裁决点 | 方案落点 |
| --- | --- |
| 更新不碰 status（停用标的不被复活） | UPDATE 仅 `name / industry / missing_streak=0`，SQL 不含 status 列（§4.4）；停用标的照常更新名称行业（故事 2 场景 4） |
| 消失 N 轮确认才停用（默认 3 可配） | `missing_streak` 列计数，达阈值 `UPDATE ... SET status=0 WHERE subject_code=? AND status=1`（单向守卫，§4.4） |
| 市场失败不推进缺失计数 | 缺失计数只在"该市场本轮拉取成功"的事务内推进；拉取失败在事务开启前即放弃（§4.3 流程 A/B 分离） |
| 每轮全量拉取 + diff | 全量分页遍历 → 内存与 DB diff（§4.3）；天然幂等 |
| 市场级原子 / 跨市场独立 | 拉取在事务外、写库在单市场单事务内；某市场失败不回滚已成功市场，整轮 FAILED 留痕注明失败市场（§4.5） |
| 永不 DELETE / status 只 1→0 | 同步引擎无任何 DELETE 语句；类清单（§4.8）无删除路径；停用走 status=0 |
| 幂等 UNIQUE | `INSERT OR IGNORE`（V17 先例）+ subject_code UNIQUE 兜底（故事 1 场景 4） |
| 同步以外部为准、范围外永不触碰 | diff 按"市场 + subject_type"分桶，指数/板块/基金/债券桶不参与股票同步（§4.2 桶表）；Won't 类型行天然不在 diff 集合 |
| 任务中心接入（可视/手动/热切换/CRON 可配） | ManagedJob 注册即权威（§4.6）；种子 `job.SUBJECT_SYNC` 默认 enabled=true、cron `0 0 6 * * ?` |
| 留痕计数与失败市场可观测 | 每市场 INFO 日志（各计数+耗时）；部分失败 errorMessage 汇总（§3.3 采用方案 A） |

### 非目标（防范围蔓延，对齐 PRD Won't）

- 板块（subject_type=3）/基金/债券同步——板块 secid 编码未验证（沿 V17 暂缓注记）。
- 北交所股票——编码规则未沉淀，不硬塞（需求裁决点 1）。
- 盘中实时上市感知、标的手动维护入口、同步差异明细查询页、自动清理 watchlist 引用——均 PRD Won't。
- 中证指数（m:2 桶）与港股指数（m:124/125/305 桶）——secid 前缀 `2./124./125./305.` 未在既有链路验证，沿 V17 暂缓先例不纳入（指数只同步上证/深证系列，§4.2）。

## 🗺️ 2. 方案总览

### C4 · Container 增补视角（新增组件 7 元素；系统上下文与既有 Container 不变，见主方案 §2）

```
┌────────────────────────────────────────────────────────────────┐
│ 浏览器 SPA（既有 13 页零改动）                                   │
│   任务中心自动出现「标的池同步」；Job 日志页看每轮留痕            │
└───────────────────────────┬────────────────────────────────────┘
                            │ 既有 REST（JWT）——本期零新端点
┌───────────────────────────▼────────────────────────────────────┐
│ 后端单体（DDD 四层不变，aggregation 域内新增同步面 + jobrun 收编）│
│  ① EastMoneyListClient（基础设施层，新增）                      │
│     push2 clist 分页拉取（UA+text/plain 容错沿 EastMoneyHttpSupport）│
│  ② SubjectSyncService（应用层，新增）——同步引擎                 │
│     拉全量(事务外) → 内存 diff → 单市场单事务写库 → 计数产出      │
│  ③ SubjectSyncJob（应用层，新增）implements ManagedJob          │
│     jobKey=SUBJECT_SYNC / CRON / run() 委托引擎                │
│  ④ 仓储端口扩展（domain/aggregation）+ RepositoryImpl 批量实现   │
│  ⑤ V18 迁移（subject_master + missing_streak 列）               │
│  ⑥ JobRuntimeConfigSeeder 增 job.SUBJECT_SYNC 种子             │
│  消费点零改动: 搜索/自选/详情/行情/估值按既有表与 external_codes  │
└───────────────────────────┬────────────────────────────────────┘
                            │ HTTPS 分页 GET（UA + 600ms 礼貌间隔）
              ┌─────────────▼──────────────┐
              │ 外部源：东财 push2 clist     │
              │ A股 fs / 港股 fs / 指数 fs   │
              └────────────────────────────┘
```

核心思路（外行能懂）：每天早上 6 点，任务把东财网页版行情列表用的同一套公开接口按页翻一遍（每页 100 条、翻页歇 0.6 秒），把 A 股和港股的在市股票全名单拿回来，跟数据库里的标的池对账——库里没有的新股票插进去（自动生成东财取数键，行情详情立即可用），名字或行业变了的改过来（但绝不碰启用状态），名单里消失的先记账观察，连续 3 天都不在才停用。哪個市场翻页失败就整个放弃那个市场（不写半截数据），下一天自动重来，任务中心也能手动立即补跑。全程没有任何删除动作。

### 3.2 消失确认存储（ADR-0028）

| 方案 | 思路 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A `subject_master` 加列 `missing_streak` | 每行自带连续缺失计数（V18 `ALTER TABLE ADD COLUMN`） | 一行一次 UPDATE 完成"计 streak + 达标停用 + 回归清零"，无 JOIN 无第二表；diff 引擎本就全量加载该市场行，零额外查询；与 status 同为机制列，语义内聚 | 主数据表混入机制列（status/version 本已如此，先例成立） | ✅ 采用（ADR-0028） |
| B 独立表 `subject_sync_state(subject_code PK, missing_streak, last_seen_at…)` | 同步状态外置 | 主数据表纯净 | 8500 行双表一致性维护；"回归清零/停用"跨表两写，事务面扩大；每轮 diff 需 JOIN 或双查 | ❌ 否决（单人 SQLite 量级收益为负） |
| C 不落库，用 job_execution_log 差集推算 | 每轮把缺失清单写日志，N 轮交集判停用 | 零 DDL | 日志表查询拼接脆弱；市场失败轮与成功轮交错时推算复杂；log 清理（backlog 项）会破坏推断 | ❌ 否决（正确性依赖不该建立在可清理的流水上） |

**选 A**。查询成本核算：计数推进 = `UPDATE ... SET missing_streak=missing_streak+1 WHERE subject_code IN (缺失清单)`（清单内存已有，无需查询）；回归清零并入出现行的 UPDATE；阈值停用 = `UPDATE ... SET status=0, missing_streak=? WHERE subject_code=? AND status=1`。全路径无额外 SELECT。

### 3.3 差异计数的留痕承载

| 方案 | 思路 | 结论 |
| --- | --- | --- |
| A 双通道：成功轮计数进应用 INFO 日志；部分失败轮由 `run()` 抛携带全部市场计数的汇总异常 → `JobExecutor` 落 errorMessage（Job 日志页可见） | 零表改动、零公共链路改动；失败轮恰好是最需要看清计数的轮（PRD 故事 5 场景 2 的"留痕注明失败市场与计数"由 errorMessage 一条文本完整承载） | ✅ 采用 |
| B 给 JobExecutor 加"Job 返回执行摘要"回填 processed_count 通道 | SUCCESS 行也能带计数 | 改公共执行器与全部既有 Job 语义（Recorder 契约、留痕测试基线），M7 范围外 | ❌ 否决（如需再立项） |
| C 每轮差异写独立表 | 明细可查 | PRD Won't（差异明细页挂 backlog） | ❌ 否决 |

### 4.1 数据模型：V18 加列（ADR-0028）

**迁移 `V18__add_subject_missing_streak.sql`**：

```sql
-- T52 · 标的池同步：外部消失连续缺失计数（REQ-20260924-04 裁决点「连续 N 轮确认停用」）
-- 语义：该标的在其所属市场桶的连续「本轮拉取成功但全量结果中未出现」轮数；
--       市场本轮拉取失败 → 整桶跳过，计数不动（防假消失，PRD 故事 3 场景 4）；
--       重新出现 → 同轮 UPDATE 清零（PRD 故事 3 场景 5）；停用后不再计数。
-- 默认 0：种子 45 只与既有行无观察态；status=1 且 streak 达阈值（默认 3，可配）才置 status=0（单向 1→0）。
ALTER TABLE subject_master ADD COLUMN missing_streak INTEGER NOT NULL DEFAULT 0;
```

**回滚 `U18__drop_subject_missing_streak.sql`**：

```sql
-- 回滚 V18：移除同步机制列（同步引擎停用后本列无消费方；SQLite ≥3.35 支持 DROP COLUMN）
ALTER TABLE subject_master DROP COLUMN missing_streak;
```

- 索引不加：同步引擎按 `market + subject_type` 全量加载（既有 `idx_subject_market` 前缀可用），无按 streak 的查询需求。

### 4.2 源接口契约与字段映射（EastMoneyListClient）

**端点**（`adapter.eastmoney.list-url` 可配）：`GET https://push2.eastmoney.com/api/qt/clist/get`

| 源字段 | 含义 | 目标 | 规则 |
| --- | --- | --- | --- |
| `data.total` | 该桶总数 | 完整性校验 | `累计拉取行数 != total` → 该市场本轮放弃（防丢页假缺失） |

| `f12` | 代码（字符串，港股含前导零 `"00700"`） | `subject_code` 前段 / secid 后段 | A股 6 位、港股 5 位原样 |
| `f13` | 市场（1=沪 / 0=深 / 116=港） | 前缀映射 + secid 前缀 | 1→`SH`、0→`SZ`、116→`HK`；`secid = f13 + "." + f12` |
| `f14` | 名称 | `name` | `trim()`；空名行丢弃记 WARN（防御） |
| `f100` | 行业（东财分类中文） | `industry` | `"-"`（港股无行业时的实测占位）→ `null` |

**external_codes 生成**（INSERT 时一次性落，对齐 V2/V17 键约定）：

```
{"eastmoney":"116.00700","tushare":"00700.HK"}   // 港股：116. + 5位代码.HK
```

**市场桶定义（MarketSyncSpec，代码内枚举配置）**：

| 桶 | fs | subject_type | market 列值 | subject_code 规则 | 实测规模/页数 |
| --- | --- | --- | --- | --- | --- |
| A_SHARE_STOCK | `m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23` | 1 | A_SHARE | `SH`/`SZ` + f12（按 f13） | 5561 / 56 页 |
| HK_STOCK | `m:116+t:3,m:116+t:4` | 1 | HK | `HK` + f12 | 2927 / 30 页 |

| 参数（`subject.sync.*`） | 默认 | 依据 |
| --- | --- | --- |

| `missing-streak-threshold` | 3 | PRD 默认（Should 可配） |
| `index-enabled` | true | 指数桶开关（Should 语义） |
| ResilienceSpec | timeout 5s / retry 1 / backoff 500ms | 分页 GET 幂等可重试；单页超时重试 1 次仍败 → 该市场放弃 |

### 4.3 同步引擎流程（SubjectSyncService）

每桶独立执行"流程 A（拉取，事务外）→ 流程 B（diff+写库，单事务）"：

```
syncAll():
  results = {}; failures = []
  for bucket in [A_SHARE_STOCK, HK_STOCK, (CN_INDEX 若启用)]:
    try:
      r = syncMarket(bucket)          # 单桶，失败上抛
      results[bucket] = r             # INFO: 新增/更新/疑似消失/停用计数 + 耗时
    catch e:
      failures += bucket+摘要          # WARN：该市场本轮放弃，未写任何数据
      if bucket == CN_INDEX: 仅记 WARN（Should 不阻塞）
      else: failures 计入整轮
  if failures 非空(股票桶): throw 汇总异常(results + failures)   # JobExecutor 落 FAILED/errorMessage
  # 全成功：正常返回（SUCCESS；计数在 INFO 日志）

syncMarket(bucket):                    # —— 市场级原子单元 ——
  A. 拉取（无事务）:
     external = []; pn = 1
     loop:
       page = client.fetchPage(bucket.fs, pn, pz)     # ResilienceSpec 包裹
       external += page.diff → List<SubjectSnapshot>（code/name/industry/secid）
       sleep(pageIntervalMillis)
       until 行数覆盖 total 或 空页
     校验: external.size == total 且 code 无重复（重复 code 记 WARN 去重）
           pn > maxPages → 抛异常（防御）
     —— 任何一步失败：抛异常，本桶零写入（分页中断无半截数据）
  B. diff + 写库（单事务 @Transactional）:
     db = repository.loadBucket(market, subjectType)   # code → (id,name,industry,status,missing_streak)
     newCodes      = external − db                     → INSERT OR IGNORE 批量(批 500)
                                                        status=1, missing_streak=0, version=0,
                                                        external_codes 按上表生成
     appeared      = external ∩ db
       ├ name/industry 任一变化 → UPDATE name/industry（不碰 status）
       └ missing_streak > 0 → UPDATE missing_streak=0（回归清零；与上一条合并为同一 UPDATE 语句按行执行）
     missing       = db 中 status=1 且 code ∉ external → UPDATE missing_streak=missing_streak+1
       └ 加 1 后 ≥ threshold → UPDATE status=0（WHERE status=1 单向守卫）→ deactivated 计数
     db 中 status=0 且 ∉ external → 不动（已停用不再计数）
     产出 MarketSyncResult{inserted, updated, missing, deactivated, total}
```

- **批量策略（SQLite 单写者）**：首启 5561 行 INSERT 分 12 批（批 500）在同一事务内（WAL 下单事务批量写毫秒级/百行，8500 行总写入秒级）；日常轮 INSERT≈0、UPDATE 为个位数（名称/行业变更）+ 缺失清单（常态 0）。UPDATE 逐行执行（量小且需分类计数）。
- **幂等**：重跑同轮 → newCodes 空、UPDATE 无变化行（比对后才写，无变化跳过）、missing 集合与上轮一致 → 计数不变（streak 不重复推进的前提：每轮最多 +1，由"每轮执行一次"保证；手动+定时并发由 JobExecutor CAS 守卫拦截）。
- **指数桶差异**：f100 恒 `-` → industry 置 null；V17 已种 4 指数按 subject_code 自然对齐走 UPDATE/清零路径，不重复插入（故事 6 场景 1）。

### 4.4 关键 SQL（RepositoryImpl 新增端口）

```sql
-- ① 批量新增（幂等，V17 先例；批 500 参数复用）
INSERT OR IGNORE INTO subject_master
  (subject_code, market, subject_type, name, external_codes, industry, status, missing_streak,
   created_at, updated_at, version)
VALUES (?, ?, ?, ?, ?, ?, 1, 0, ?, ?, 0);
-- 忽略行数由 JDBC batch 各行结果累计 → inserted 计数

-- ② 出现行更新（回归清零；name/industry 仅变化时写入；不碰 status）
UPDATE subject_master
   SET name = ?, industry = ?, missing_streak = 0, updated_at = ?, version = version + 1
 WHERE subject_code = ?;

-- ③ 缺失计数（仅启用标的）
UPDATE subject_master
   SET missing_streak = missing_streak + 1, updated_at = ?, version = version + 1
 WHERE subject_code = ? AND status = 1;

-- ④ 阈值停用（status 单向 1→0 的 SQL 级守卫）
UPDATE subject_master
   SET status = 0, updated_at = ?, version = version + 1
 WHERE subject_code = ? AND status = 1 AND missing_streak >= ?;   -- threshold 参数化

-- ⑤ 桶全量加载（diff 基线；走既有 idx_subject_market 前缀）
SELECT id, subject_code, name, industry, status, missing_streak
  FROM subject_master WHERE market = ? AND subject_type = ?;
```

域端口（`SubjectRepository` 新增，纯增量）：`loadBucket(Market, SubjectType)` / `insertIgnoreBatch(List<Subject>)` / `updateSnapshot(code, name, industry)` / `incrementMissingStreak(code)` / `deactivateIfMissingReached(code, threshold)`。既有方法与乐观锁语义不动。

### 4.5 失败语义与原子性（对齐 PRD 裁决点 5）

- **市场内**：拉取（流程 A）全在事务外——任何分页失败/完整性校验失败时零写入，天然"整轮放弃该市场"；不存在半截入库。
- **跨市场**：桶间串行、互不回滚——A 股成功港股失败时 A 股数据已提交生效；`run()` 末尾抛汇总异常 → `JobExecutor` 记 FAILED，errorMessage 形如：
  `标的池同步部分失败: A_SHARE SUCCESS (inserted=5561,updated=0,missing=0,deactivated=0,elapsed=95s); HK FAILED (第12页拉取超时，已放弃本市场); CN_INDEX SUCCESS (...)`
- **跨轮**：无自动补调度（PRD 裁决）；失败市场下轮自然重试，手动触发即时补跑（复用 202 + CAS 防重入，故事 4 场景 2）。

### 4.7 搜索接口在 8000 行的表现评估（结论：零优化）

- 现状执行计划：`status=1` 等值过滤 + `subject_code/name` 两列 `LIKE '%x%' ESCAPE` + `ORDER BY id LIMIT 20`。`LIKE '%x%'` 无法用 B-tree 索引（前导通配），必然全表扫。
- 量级核算：8000 行 × 2 列不区分大小写匹配，SQLite 本地库实测经验为**个位数毫秒**（纯 CPU 字符串扫描，无 IO 放大，单次查询扫 < 1MB 文本）；搜索为单人低频操作（选择器输入），无并发压力面。
- **裁定：不加 FTS5、不加触发器物化**——8000 行 LIKE 与 FTS 的时延差对人手输入无感知，而 FTS 引入影子表/触发器/重建维护三块新面，违背"无聊但成熟"。留观察点：池规模 > 5 万（如未来纳入美股/债券）或搜索 QPS 上来，再按方案库 05（异构查询）立项 FTS5。
- 前缀可走索引的次优优化也不做：`LIKE 'x%'` 能用索引但会改变"代码任意段/名称任意段"命中语义（如搜 `300750` 需命中 `SZ300750`），破坏故事 1 场景 2 验收。

## 🛡️ 5. 非功能设计（逐项过）

- **性能**：单轮 86 页 × (请求 ~0.2s + 间隔 0.6s) ≈ 1.5~2 分钟（含指数桶 <3 分钟），远低于 06:00→09:00 裕量；写库单市场单事务批量，SQLite WAL 下首启 8500 行秒级。
- **容量**：subject_master 稳态 ≈ 8500 行 × ~200B ≈ 2MB/年增量可忽略；missing_streak 列 1 字节级；无清理需求（永不删除是红线，停用行留存）。
- **安全**：无新端点（零鉴权面变化）；Client 带 UA 但无凭据无敏感数据；external_codes 非敏感。
- **可观测**：每桶 INFO（计数+耗时+total 校验值）、拉取失败 WARN（页码+异常摘要）、整轮失败 ERROR（JobExecutor 既有）+ errorMessage 汇总（§3.3 方案 A）；data_source_event 不接（clist 为列表源非既有 SourceCode 枚举，强接属过度）。
- **可测性预留**（给测试）：分页/间隔/阈值/max-pages 全参数化（测试 profile 调小）；`syncMarket` 按桶独立可测（mock Client 返回固定页）；完整性校验（total 不符）路径可构造；streak 语义可用 H2/SQLite 测试库直连断言。
- **降级预案**：市场级放弃（§4.5）；连续多日失败 → 任务中心观察 + 手动补跑；push2 长期封禁 → 切新浪（A股）需改 Client 一层（fs/端点/字段映射，DTO 不变，ADR-0027 备选路径）；港股源整体不可用 → 需求兜底条款（港股降级走变更控制，A股 Must 不阻塞）。

## 🧪 6. 测试要点（可测性预留）

- **Client**：分页遍历（多页拼接、total 一致、空页终止）；`data:null`/HTTP 非 200/超时路径；text/plain JSON 容错；UA 头存在性。
- **字段映射**：f13→前缀/secid 派生三市场；f100=`"-"`→null；名称 trim；港股前导零保留（`00700`→`HK00700`）；external_codes 双键生成（对齐 V2/V17 样例）。
- **引擎 diff**：新增（含 INSERT OR IGNORE 重复跑计数 0）；更新（name 变/industry 变/双变；**status=0 行照常更新**）；消失 streak+1；达阈值停用（WHERE status=1 守卫）；回归清零（第 3 轮出现→streak=0 且 status 保持 1）；已停用行缺失不动；范围外（板块/基金桶）行不触碰。
- **市场级原子**：第 k 页抛异常 → 该桶零写入（事务断言）；完整性校验失败（拉到的行数≠total）→ 放弃。
- **跨市场独立**：港股失败 A 股已生效 + run() 抛汇总异常（errorMessage 含两侧计数）；指数桶失败仅 WARN 不 FAILED。
- **Job 收编**：注册即出现于任务中心列表；种子 enabled/cron 默认值；手动触发 202 与 CAS 并发拦截；热切换（改 cron 不重启生效，沿 M4 既有测试模式）。
- **迁移**：V18 后既有 45 行 missing_streak=0；U18 回滚可重放。
- **回归红线**：后端 1085 测试基线全绿（重点 `SubjectRepositoryImplTest`/`JobRuntimeConfigSeederTest` 守护纯增量改动）。

## 🧾 决策留痕（ADR 摘要）

### ADR-0027 · 标的池同步数据源选型：东财 push2 clist（实测依据 + 备选）

- 背景：Spike-1 未覆盖"全量列表"源；需求交付架构按五条验收要求实测选型（公开免费/可分页拉全量/字段齐全/secid 可派生/礼貌抓取）。
- 决策：主选东财 push2 clist（A股 fs `m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23` total=5561；港股 fs `m:116+t:3,m:116+t:4` total=2927——**勘定任务建议的 `m:116+t:1` 为人民币柜台桶（485 只）非主板**；指数 `m:1+t:1,m:0+t:5`）；secid=f13.f12 直派生；单页强制 100 行；限速 600ms 间隔。备选：新浪列表（仅 A 股、无行业）、深交所官方（仅深市）；港股备选薄弱（新浪空/港交所 404）走需求兜底。
- 被否：新浪主选（无行业字段/港股不可用）、交易所官方（覆盖不全/上交所不可用）、datacenter 活跃股表（非全量名录）、港交所静态文件（路径失效需人工解析）。
- 后果：详见 [adr/0027-标的池同步数据源选型.md](/docs/02-设计/adr/0027-标的池同步数据源选型.md)。

### ADR-0028 · 消失确认存储：subject_master 内嵌 missing_streak 列（V18）

- 背景：连续 N 轮缺失计数需要落点；候选为加列 vs 独立状态表 vs 日志推算。
- 决策：`subject_master` 加 `missing_streak INTEGER NOT NULL DEFAULT 0`（V18，附 U18 回滚）；计数推进/回归清零/阈值停用全部并入既有行的单条 UPDATE，全路径零额外查询；停用守卫 `WHERE status=1` SQL 级保证单向。
- 被否：独立 subject_sync_state 表（双表一致性/事务面扩大，单人 SQLite 收益为负）；job_execution_log 差集推算（正确性依赖可清理流水）。
- 后果：详见 [adr/0028-消失确认存储设计.md](/docs/02-设计/adr/0028-消失确认存储设计.md)。
