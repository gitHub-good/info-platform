## 📌 一、顶部导航设计（用户要求四之「侧边栏改上边栏」）

### 1.1 方案比选与裁决

现状：桌面（lg+）固定左侧栏 `w-56`（4 分组 17 项纵向堆叠），窄屏顶栏 `h-12` + 左滑抽屉。17 项无法单行平铺，比选如下：

| 方案 | 形态 | 17 项适配性 | 判定 |
| --- | --- | --- | --- |
| A. 单层水平全展 | 17 个 Tab 平铺一行 | 17 × ~80px ≈ 1360px，1280px 视口放不下，必然折行/溢出 | ❌ |
| B. Logo + 分组下拉 | 顶栏 4 个分组 DropdownMenu | 「总览」1 项、「数据」2 项开下拉得不偿失；页面发现性降为悬停才知道；需新引入 Menu/Popover 基件（`components/ui` 现无，违背零新依赖取向） | ❌ |
| C. 面包屑 + 功能页签 | 顶栏只放面包屑，页签在页内 | 面包屑是定位器不是导航器，跨组跳转路径变长 | ❌ |
| **D. 双行顶栏（分组 Tab + 页面页签）** | 主行 = Logo + 4 分组 Tab + 铃铛/登出；页签行 = 当前分组的页面横向页签 | 分组恒定 4 个可平铺；最大分组「分析/运维」各 7 项 × ~88px ≈ 616px，768px 内容宽内放得下；纯 `<a>` + 既有 token，**零新组件依赖**；当前组全部页面 100% 可见 | ✅ **裁决采用** |

**裁决理由汇总**：导航发现性（分组内页面全可见）× 工程成本（复用 `NavItemLink` 模式与 `routeMatches`）× 可达性（原生链接 +
`aria-current`，无自造弹出层焦点管理负担）三项同时满足；且释放 `w-56` 侧栏占宽，内容区主阅读带宽 +224px。

### 1.4 AppLayout 改造要点（开发交接清单）

1. 删除桌面 `aside` 侧栏与内容区 `lg:pl-56`；新增 `TopNav`（主行 + 页签行）两行 sticky 结构。
2. `navConfig.ts`：分组数组与 `routeMatches`/`titleForRoute` 全部复用；仅增加「单页组直跳」标记与分组命中判定
   `groupForRoute(route)`（供页签行取当前组 items）。
3. `NotificationBell` 从 `SidebarContent` 底部移到主行右侧：面板锚定改 `top-full right-0`（原 `bottom-0 left-full` 是侧栏布局
   产物，不改会飞到屏幕外），宽度 `w-80 → w-96`，其余交互（SSE 在线态/全部已读/清空/点击跳转）不动。
4. `data-testid` 兼容：页签沿用 `nav-item-{route}`（既有测试选择器不破）；新增 `nav-group-{label}`。
5. 页面零改动：各页自带 `main + max-w + p-4 sm:p-6`，去侧栏后仅内容区变宽，页内布局不自适应改动（最小改动红线）。

### 3.2 事件流/推荐中心分页化设计（第一批）

- **UI**：列表尾部替换「加载更多」为 `Pagination` 组件（page/pageSize=20/total，条数选择器 10/20/50，翻页在途禁用 + 失败保留列表
  + 重试，完全对齐 M9/资讯库语义）；页头右侧保留「共 N 条」。
- **交互语义**（沿 M9 §5）：筛选（事件四维/推荐重要性等）变更 → `page=1` 骨架重查；翻页保留数据、仅列表区在途态。
- **接口需求（转架构/PM，契约变更先行）**：`GET /api/v1/events`、`GET /api/v1/recommendation-cards` 在现有 `beforeId` 游标参数旁
  **新增 `page`/`size`（offset 语义）参数**；`total` 两个接口均已返回。游标参数保留兼容（SSE/`?focus=` 定位路径不受影响）。
  落接口文档 + ADR 后前端接入；后端就绪前页面维持现状（不落半截形态）。

### 3.3 信息流保留无限滚动的裁决理由（供 PM 确认，见 §9）

1. 阅读型消费流（时间倒序、卡片连续阅读），翻页打断心流，业界流形态惯例；
2. 后端游标协议（`nextCursor` 无 total），分页化需后端补 total + page 模式，收益/成本比低；
3. 用户「失控感」痛点用配套解决：**「已加载 N 条」计数指示 + 浮动「回到顶部」按钮**（§4 优化项 4）。
   若 PM 坚持信息流也分页 → 走界面歧义单流程，预估后端 +1d（total + page 模式），我在收到确认后 1 日内出改稿。

- **纯黑（OLED）模式**：v2 已做过暗色深化（bg 0.13），纯黑会压扁「底/卡片/弹层」三层灰阶层次，成本（第三套 token + 全站走查）远超收益，不做；
- **页面切换过渡动画/列表 stagger 动效**：工程基线「动效克制」，顶栏毛玻璃 + 既有 150ms 微过渡已足够，装饰性动画不做（除非 PM 另有要求）。
