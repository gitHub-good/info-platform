# 📐 V2.0-M16 动态主动推荐 · 技术方案（v1.0）

> V2.0 推荐引擎第一期：事件驱动推荐链路五环落库为三张新表（`recommendation_card` / `recommendation_feedback` / `recommendation_mute`，`event_item` 与既有通知/订阅/管道表**零 DDL 改动**）；链路 = 高价值快速通道（`PIPELINE_EXPRESS` 2min，纯规则预筛分直通，入库→事件落库 ≤4.5min）→ 事件轮询消费（`RECOMMENDATION_FEED` 60s，LEFT JOIN 扫未消费事件）→ 三级关联（P1 标的直接 / P2 行业 / P3 订阅，**P2 行业命中硬阻塞解法 = 行业关注集双通道**：订阅主题经 `IndustryDirectory` 别名目录映射为主力 + 标的池行业 best-effort 自动增强）→ 可解释卡片（brief_type=8 LLM 仅语言组织 + **FactWhitelistValidator 四类白名单比对**拒即模板兜底）→ 推送（PushType `RECOMMENDATION(10)` + 综合分 recscore-v1 排序 + 日上限闸门 + `push_record` 扩 `SILENT(3)` 静默留痕态）→ 反馈闭环（四动作 + 组合降频 7 天/升级静默 30 天 + 采纳统计 adopt-v1 无表派生）。新增 2 个 ManagedJob（调度池 12→14）；`coverage-v2` 口径切换三处同步。本方案为主方案（[技术方案-信息整合平台.md](/docs/02-设计/技术方案-信息整合平台.md)）的 M16 增补，只覆盖 [REQ-20260926-13](/docs/01-需求/REQ-20260926-13-M16-动态主动推荐.md)，架构形态（模块化单体 + DDD 四层）与既有 12 Job / 13 源 / 17 页面契约不变。

**现状差距**（REQ 背景节差距表 #1~#7）：管道有「理解」无「主动」——触发判定/三级关联/卡片/推荐推送/反馈闭环整体不存在；BUG-03 使宏观月度序列失去事件资格（推荐事件源受损）；AMB-02 覆盖率口径摇摆。

### 目标（对齐 REQ 目标节，可量化）

1. **推荐链路五环**：L2 事件落库 → 触发判定（`importance ∈ {HIGH, MEDIUM}` ∧ 三级关联命中非空）→ 三级关联 → 可解释卡片 → SSE 推送 + 推荐中心沉淀，全链路幂等（`UNIQUE(user_id, event_id)` 一事件一卡 + push_record 幂等键一卡一推）。
2. **可解释红线**：逻辑链三环节全部来自结构化事实；卡片标的/行业/数字/方向四类字段经白名单校验器，抽检一致率 100%。
3. **时延双口径**：事件落库→SSE 送达 ≤5min（硬验收，预算分解 §4.11）；入库→SSE 送达 ≤10min（触发级 ≥80% 达标，依赖快速通道 + M15 稳态复测前置）。
4. **降噪护栏**：LOW 永不触发；日推送上限缺省 10 可配；超限/降频只静默不丢；组合降频 7 天 + Should 升级静默 30 天。
5. **反馈闭环与采纳统计就位**：四动作 + 画像回流 + adopt-v1 口径上线可查（对账一致）。
6. **M15 遗留闭环**：BUG-03 序列豁免（T130 前置）+ OBS-04 留痕行归位 + coverage-v2 三处同步（T137）。
7. **零回归**：既有 12 Job、13 源、17 页面、每日推荐（DAILY_RECOMMEND 盘前 Top5）、通知中心既有 9 类事件、提示词治理既有 7 类模板全部不变（`NEWS_PIPELINE` 常规批**零改动**——快速通道为独立新 Job，§3.1）。

## ⚖️ 3. 形态决策（ADR-0051 四项主裁决 + 基建扩位）

### 3.1 高价值优先语义 = 独立快速通道 Job `PIPELINE_EXPRESS`（裁决 1）

**裁决**：新增 ManagedJob `PIPELINE_EXPRESS`（FIXED_DELAY **2min**，可配 1~5min，种子 yml `pipeline.express.*`）。每 tick：取「入库 ≥30s 缓冲且未建 analysis 行」的 news_item（排除 `aiExclusion=ALL` 源）→ noise 快判 → **ImportanceScorer 纯规则预筛分 ≥ `expressScoreThreshold`（缺省 4.0 ≈ 源权重 2.0 + 一个强触发词 2.0）** 的条目立即走 L0 建行（含 BUG-03 序列豁免）→ L1 批量（复用 `ClassificationService`，批 ≤10）→ L2（复用 `EventExtractionService`，当日配额内）；**低于阈值的条目一律不动**，等常规 10min 批。既有 `NEWS_PIPELINE` **零改动**。

**候选对比**（五维度：成熟度=机制风险、学习成本=开发量、可替换性=回滚代价、运维成本=新增运维面、社区=既有体系吻合度）：

| 维度 | A 独立快速通道 Job（选定） | B 单 Job 双档窗口（NEWS_PIPELINE 提频 + 模式交替） | C 全量提速（批窗 10min→2min） | D 挂入库同步触发 |
| --- | --- | --- | --- | --- |
| 机制风险 | 低（新键新类，旧链路零触碰） | 中（改既有 Job 行为语义，M15 稳态回归面） | 中（L1 批更小更频，prompt 摊销成本 +50~80%，护栏口径漂移） | 高（动 M13 摄取事务，违背 ADR-0046 裁决 4「不挂入库同步」同款论证） |
| 开发量 | ~0.5 人天（选择器 + Job 键 + 测试） | ~0.5 人天（tick 计数器 + 档位判定） | ~0.2 人天 | ~1 人天 |
| 回滚代价 | 停用 Job 键即回常规语义 | 需回退既有 Job 代码 | 需回退配置+口径 | 需回退摄取链路 |
| 运维成本 | +1 调度键（任务中心可视） | 0 | 0 | 0 |
| 体系吻合 | 高（每级一 Job 先例沿 ADR-0046 裁决 4 论证） | 中 | 低（改变全量归类承诺的成本结构） | 低 |

**被否**：B（「L2 触发拆两档窗口」——同一 Job 内双档判定把优先语义藏进既有 Job 行为，验收与故障隔离语义混浊，且改的是已验收稳态链路，违背零回归红线）；C（ REQ 拍板五「普通条目仍按既有批窗」虽不禁止提速，但 5 倍调用频次改变成本护栏水位与 M15 稳态口径，代价全量承担）；D（摄取事务被 LLM 时延拖累，采集主链路回归面最大）。

**与常规批的并发幂等**：两 Job 可能同刻拾取同一 news_id——`news_analysis.UNIQUE(news_id)` INSERT OR IGNORE 建行、L1/L2 条件 UPDATE（`WHERE l1_status IN (PENDING,FAILED)`）+ SQLite 单写者串行化，双跑结果幂等（后到者条件更新匹配 0 行自然跳过）。已知边界：快速通道先建行的条目若与未分析的真同稿互为近重复，主条语义取先建行者（published_at 更早者可能被标 NEAR_DUP）——同稿内容一致，损失仅主条时间戳，可接受（§8 风险表）。

**时延与成本**：30s 缓冲 + ≤2min tick + L1 ~10s + L2 ~20s ≈ **入库→事件落库 ≤4.5min**（≤8min 预算的 56%）；强触发条目日 ~10~30 条 → express 批 1~3 次/日，增量 LLM 成本 ≈ ¥0.02/日内（护栏预算 ¥2 的 1%）。

### 3.2 事件消费机制 = 短轮询 ManagedJob `RECOMMENDATION_FEED`（裁决 2）

**裁决**：新增 ManagedJob `RECOMMENDATION_FEED`（FIXED_DELAY **60s**，可配 30s~5min）。消费扫描 = `event_item e LEFT JOIN recommendation_card c ON c.event_id = e.id AND c.user_id = ? WHERE c.id IS NULL AND e.created_at <= now-20s AND e.created_at >= now-24h`（20s 缓冲防 L2 落库事务竞态；24h 上界对齐管道补跑窗口，降级期积压恢复后照常处理）。**不采用进程内事件挂钩**。

**候选对比**：

| 维度 | 轮询 Job（选定） | 进程内事件挂钩（L2 落库后发 Spring 事件 → @Async 消费） |
| --- | --- | --- |
| 重启丢事件 | 天然免疫（状态在 DB，重启后下一轮补扫） | 丢失窗口需要补偿扫描兜底 = 双机制并存 |
| 事务边界 | 消费独立于管道 tick（LLM 30s 不阻塞管道，REQ 非功能「卡片生成不阻塞管道 tick」） | 同事务拖慢管道 / 事务外则回到丢失窗口 |
| 复杂度 | 一个 Job 键 + LEFT JOIN（event_item 日增 ~130，毫秒级） | 事件类 + 异步监听 + 补偿 Job 两套路径 |
| 可观测 | JobRunStats 段式明细 + 任务中心手动触发（验收工具） | 异步监听留痕弱（沿 PushService @Async 先例但无 Job 面） |
| 时延 | ≤60s + 20s 缓冲（满足 ≤2min 消费触发） | 理论秒级（但 5min 预算下无意义优势） |

**被否**：挂钩（上述四行反向；且 ADR-0046 裁决 4 已立「L0 不挂入库同步」同款论证——批式比较天然适合轮询，秒级消费优势在 5min 预算下无意义，而其丢失窗口与双机制复杂度是实打实的代价）。

### 3.3 卡片输出事实白名单 = 四类白名单集合比对校验器（裁决 3）

**裁决**：`FactWhitelistValidator`（domain 纯函数）对 LLM 输出的 logicChain 文本做**四类白名单集合比对**，任一违规即拒 → 同步切模板拼接（不重试 LLM，时效优先）：

| 校验类 | 白名单集合来源 | 违规判据 |
| --- | --- | --- |
| ① 标的 | 允许标的名集 = 卡片标的区 ∪ event.subjects 名 | 文本中出现**标的池内**公司名（全池名扫描，名长 ≥2 contains）但 ∉ 允许集 → 拒（池外未知词不判——只拦「换了/加了标的」不拦普通词汇） |
| ② 行业 | 允许行业集 = event.affected_industries ∪ 用户行业关注命中集 | 文本中出现申万 31 行业名或其别名目录词但 ∉ 允许集 → 拒 |
| ③ 数字 | 结构化数字集 = key_figures[].value 数字化 ∪ quote/title/summary 中出现的全部数字串 | 正则抽取文本数字串（含 %/小数/负号），任一 ∉ 集合 → 拒 |
| ④ 方向 | 方向词表：利好系{利好,上涨,偏多,提振…}/利空系{利空,下跌,偏空,承压…}/中性系{中性,影响平稳…} | 词表命中方向 ≠ event.direction → 拒；NEUTRAL 卡出现强方向词 → 拒 |
| ⑤ 长度护栏 | — | logicChain > 120 字 → 拒（走模板） |

**被否**：①「LLM 输出结构化 JSON 字段、校验后前端拼装」（LLM 退化为字段填充，语言组织价值归零——REQ 拍板三 LLM 职责是「串成通顺自然语言」）；②「只靠提示词约束不校验」（幻觉防线不能建立在提示词自觉上，REQ 红线要求机制保证）；③「校验失败重试 LLM」（一次重试 +30s 时延预算吃紧，且同因失败概率高——模板兜底可用性优先，沿 M1「规则兜底」先例）。

### 3.4 P2 行业命中硬阻塞解法 = 行业关注集双通道（裁决 4，本批最关键裁决）

**问题**：REQ 拍板二 P2 = `event.affected_industries ∩（自选标的所属行业 ∪ 订阅主题映射行业）`。实情：① `subject_master.industry` 当前 5221 只 A 股全 NULL → 「自选标的所属行业」空转，P2 第一通道死；② subscription **无行业订阅类型**（sub_type 仅 1/2/3/4），「订阅主题映射行业」需要本批自建映射。

**裁决**：P2 判定改为 `event.affected_industries ∩ 用户行业关注集 ≠ ∅`，行业关注集 = **双通道并集**：

- **通道 A（订阅主题映射行业，v1 主力，当前数据即可用）**：活跃 TOPIC/POLICY_THEME 订阅的 subKey 经 **`IndustryDirectory`**（申万 31 行业 → 别名/子行业词目录，代码常量种子 ~31×4 词：如 电子→[半导体,芯片,集成电路,消费电子,光电子]、医药生物→[创新药,医疗器械,CXO,中药]……）映射——subKey contains 命中某行业的行业名或别名词 → 该行业入集。例：订阅「半导体」→ 电子；订阅「货币政策」→ 无映射 → 不入集（该订阅走 P3 主题命中）。
- **通道 B（标的行业，best-effort 自动增强）**：自选 ∪ SUBJECT 订阅标的的 `subject_master.industry` 非空者入集；NULL 跳过（不报错不阻断）。**东财主链（f100 含行业）恢复成功一次同步即自动回填**（既有 `SubjectSyncService` 语义，ADR-0027/0030），通道 B 自动增强、P2 命中面扩大、逻辑链「你的自选〔标的〕属于该行业」标的区自动非空——**全程无代码变更**。本批不建回填迁移、不以此为前置（同步链恢复属运维动作，方案对两种数据状态均正确）。

**P2 卡片形态随数据状态自适应**：通道 B 空转时 P2 命中卡标的区为空（展示行业链路「你关注的〔行业〕受该事件影响」+ 订阅来源「源于你订阅的〔主题〕」），与 REQ「P3-only 允许空标的、不硬凑标的」同款形态；通道 B 有数据时标的区列出该行业命中的自选标的（≤5）。

**裁决延伸（P1 判定集）**：P1 = `event.subjects[].code ∈（自选 watchlist ∪ SUBJECT 订阅）标的代码集`——SUBJECT 订阅并入 P1 而非留 P3：显式标的订阅与自选同为「用户显式关注标的」，命中即 P1「直接涉及」语义，避免同强度信号被降级到 P3（文案「直接涉及你关注的标的」覆盖两者）。此为架构裁量扩展 REQ 最小集（REQ 数据源列只写自选），记 ADR-0051。

**被否**：① 以「行业回填迁移」为前置（把运维不确定性放进关键路径，回填失败则 P2 整体不可用）；② 新增行业订阅 subType=5（REQ 无此需求，扩展用户配置面属范围蔓延）；③ 按事件 industries 反查阅读画像行业（reading_event 无行业维度，subject 行业又 NULL，同源死锁）；④ P2 降级并入 P3（丢失「行业命中」这一级语义与降频组合的行业维度）。

```sql

-- T131/T133/T134 · M16 推荐三表（卡片 / 反馈流水 / 降噪组合）+ retention 键
-- ADR-0051：推荐域独立建表，event_item/通知/订阅/管道既有表零 DDL 改动。

--              / SKIPPED_MUTED（降频/静默组合拦截）

  logic_chain    TEXT    NOT NULL,               -- 逻辑链文案（白名单校验后的最终文本）
  logic_inputs   TEXT,                           -- JSON 生成输入快照（结构化事实 + 允许集，抽检对账与复现用）

  updated_at     TEXT    NOT NULL,

CREATE INDEX idx_rc_user_created ON recommendation_card(user_id, created_at); -- 推荐中心卡片流 + 游标分页
CREATE INDEX idx_rc_user_push    ON recommendation_card(user_id, push_status); -- 当日配额计数 / 遗留 PENDING 重推

-- 反馈流水（append-only：同卡可先 DISLIKE 后 UNDO_MUTE 再 DISLIKE，状态由 mute 表承载）
-- action：USEFUL 有用 / DISLIKE 不感兴趣 / ADD_WATCHLIST 加自选 / UNDO_MUTE 撤销降频
CREATE TABLE recommendation_feedback (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL,
  card_id    INTEGER NOT NULL,

  updated_at      TEXT    NOT NULL,
```

### 4.2 T130 前置缺陷：BUG-03 序列误并豁免 + OBS-04 留痕行归位

**BUG-03 序列豁免**（`NearDuplicateDetector` + `L0PrefilterService` 微扩）：判定入口前加一条豁免谓词——候选条目满足以下**任一**条件即**永不标记 NEAR_DUP**（仍正常建行、正常参与 24h 比较池作主条候选，真同稿可引用之）：

```
序列豁免（isSequenceExempt）:
  ① external_id 含 '#'（序列标记，如 RPT_ECONOMY_CPI#2026-08-01——数据源对模板化序列条目的显式分卷编号）
  ② 标题匹配「YYYY年X月份」模式：(19|20)\d{2}年(0?[1-9]|1[0-2])月份（CPI/PPI/LPR 等宏观月度数据标题）
豁免留痕：l0_detail = "seq-exempt:#" 或 "seq-exempt:monthly"（可查可统计，tick 明细计数 l0=seq_exempt:n）
```

实现面：`NewsAnalysisRepository.NewsCandidate` 增 `externalId` 字段（`findUnanalyzed` 查询补一列）；豁免判定放 `NearDuplicateDetector` 静态纯函数（单测直测）。**回归红线**：既有真同稿合并语义零变化（豁免只作用于两类强序列信号，普通近重复照并；M15 抽检样本语义复跑一致——CPI 19 条恢复各自 L1 归类与 L2 事件资格，跨源同稿 USD/JPY 类照并）。

**OBS-04 留痕行归位**（顺手项）：一次性数据修正——定位 `news_analysis.l2_status='EXTRACTED'` 但 `event_item` 无对应行的孤儿留痕行（BUG-01 处置残留，1 行），归位为 `l2_status='FAILED'`（attempts 留痕不动）。落点：T130 单测覆盖的 `L2TraceRepair` 一次性修正方法 + dev/prod 库手工执行同款 SQL 留档于任务提交说明；不做常驻对账 Job（event_item `UNIQUE(news_id)` + UPSERT 既有语义已防新增孤儿）。

### 4.3 高价值优先语义（`PipelineExpressService`，裁决 1 落地）

```

      L0 建行（含 §4.2 序列豁免；importance_score 落库）
  → ClassificationService.classify(本批 PASS 行)           // 复用：批量/拆批/兜底，批 ≤10
  → level == NORMAL ? EventExtractionService.run(当日 SELECTED 重扫) : skip(L2)   // DEGRADED 跳 L2 同常规语义
```

要点：① L2 复用既有「当日 SELECTED 按 importance_score DESC」重扫——express 条目即高分头部，天然优先出事件、天然计入当日配额，无独立配额逻辑；② 与常规批并发靠 `UNIQUE(news_id)` + 条件 UPDATE 幂等（裁决 1）；③ `expressScoreThreshold` 热改键入 `recommendation.express`（首跑校准：命中量 >30 条/日 连续两日提示提阈值，沿 M15 校准惯例）。

### 4.4 关联引擎（`RecommendationAssociationService`，三级 + recscore-v1）

**输入装配**（每用户每 tick 缓存一次，用户级 `AssociationContext`）：关注标的集（watchlist ∪ SUBJECT 订阅 → SubjectRepository 解析 code/name/industry）、活跃订阅（TOPIC/POLICY_THEME 主题词、EVENT_TYPE subKey）、行业关注集（§3.4 双通道：主题词经 IndustryDirectory 映射 ∪ 标的行业非空者）、`UserInterestProfile`（既有 RecommendationPersonalizer）。

**逐事件判定**（纯函数 `associate(event, ctx) → AssociationResult | 空`）：

```
触发门槛: event.importance ∈ {HIGH, MEDIUM} 否则返回空（LOW 永不触发，红线）
P1: event.subjects[].code ∩ ctx.watchCodes ≠ ∅
      → level=P1；标的区 = 命中标的（code 索引取 name/industry/inWatchlist=true）
P2: event.affectedIndustries ∩ ctx.industryInterest ≠ ∅（且 P1 未命中）
      → level=P2；命中行业集 = 交集；标的区 = 关注标的中 industry ∈ 交集者（≤5，可为空——§3.4）
P3: （且 P1/P2 未命中）订阅命中：
      a. EVENT_TYPE 订阅映射：subKey 含"公告" → 公司类事件 6 类（EARNINGS_FORECAST/MA_MERGER/
         BUYBACK_CHANGE/MAJOR_CONTRACT/EXEC_CHANGE/REGULATORY_PENALTY）；含"政策" → POLICY_RELEASE；
         含"新闻" → 全部 9 类；（subKey=枚举名 ANNOUNCE/NEWS/POLICY 同上折算——沿 FeedMatcher 既有折算口径）
      b. 主题词命中：TOPIC/POLICY_THEME subKey contains 命中事件标题或摘要（沿 M2 FeedMatcher 口径）
      → level=P3；标的区 = 空（不硬凑，红线）
无命中 → 返回空（不生成卡片、零留痕；事件流可查）
标的区截断: P1 命中 ∪ P2 命中标的，按（P1 优先 → 画像热度降序）取 ≤5（cardSubjectLimit 可配）
主关联层级: 命中多级取最高（P1 > P2 > P3）
combo_key: eventType | (P2 命中行业首个 ?: affectedIndustries 首个 ?: "-")
```

**recscore-v1 综合分**（`RecommendationScoreCalculator` 纯函数，参数全部 `recommendation.score` 可配、basis 版本化）：

```
recscore = levelCoef × impCoef × profileCoef
  levelCoef: P1=3.0 / P2=2.0 / P3=1.0        （REQ 拍板一冻结值）
  impCoef:   HIGH=2.0 / MEDIUM=1.0           （REQ 拍板一冻结值）
  profileCoef = 1 + α × max( normSubjectHeat, themeHitScore )   ∈ [1.0, 1.25]
    α = 0.25（画像上限加成 25%——只调序不翻天，P3 画像满格 1.25 仍低于 P2 基础分 2.0，层级语义不被画像冲垮）
    normSubjectHeat = min( maxHeat(标的区标的的已读热度) / heatCap(5.0), 1 )   // 热度源=UserInterestProfile.readStats
                                                                      //（heat=Σ0.5^(距今天数/7)，读一次=1，5 次今日阅读封顶）
    themeHitScore  = 0.6（任一主题词 contains 命中事件标题/摘要，或命中事件行业经 IndustryDirectory 反查的别名）
basis = "recscore-v1:lvl=3|2|1;imp=2|1;pf=1+0.25*max(heat/5,theme=0.6)"
```

画像系数来源与范围（PM 交接项补全）：**来源 = 既有 `UserInterestProfile`**（M11 阅读埋点 readStats + 订阅主题词 themeKeywords），不新建画像面；**范围 [1.0, 1.25]**：下界 1 保证无画像用户排序不降级（空画像合法态沿 T29 语义），上界 1.25 保证画像只加权不越级（P1 MEDIUM 基础分 6.0 vs P2 HIGH 4.0 vs P3 HIGH 2.0——画像加成不改变层级×重要性的主序）。

### 4.5 卡片生成（`RecommendationCardService` + brief_type=8 + 白名单校验器）

**模板 v1.0**（brief_type=8，V27 播种；占位符 `{{level}} {{eventTypeLabel}} {{directionLabel}} {{summary}} {{industries}} {{subjects}} {{watchSubjects}}` 注册表登记）：

```
---SYSTEM---
你是推荐卡片逻辑链语言组织引擎。输入是结构化事实（事件与用户关联判定结果），你的唯一职责是把
它们串成一句通顺的中文逻辑链（≤80 字）。红线：不得引入输入之外的任何事实——不添加公司、行业、
数字、百分比、方向判断；不得给出买卖建议。输出合法 json（不要 markdown 代码块）：
{"logicChain": "一句话逻辑链"}
---USER---
关联层级：{{level}}（P1=标的直接 / P2=行业 / P3=订阅）
事件：{{eventTypeLabel}}，方向 {{directionLabel}}，摘要：{{summary}}
事件影响行业：{{industries}}
事件涉及标的：{{subjects}}
用户关注且命中的标的：{{watchSubjects}}
请输出 json：{"logicChain": "..."}
```

**生成流程**（`RecommendationCardService.generate(association, event)`）：

```
1 组装结构化输入 inputs（logic_inputs 快照落卡：事件字段 + 关联结果 + 四类允许集）
2 if guard.level() != NORMAL → 直接模板分支（降级态不调 LLM，REQ 故事 6 场景 4）
3 else LLM: LlmRequest(render(briefType=8), temperature 0.1, maxTokens 512, JSON_OBJECT,
        sceneKey="8", cacheable=false, 软超时 30s)
4 解析 logicChain → FactWhitelistValidator.validate(text, inputs)（§3.5 四类+长度）
5 通过 → gen_method=LLM；被拒/超时/异常/解析失败 → 模板拼接分支（≤1s，不重试 LLM）
6 模板拼接（LogicChainTemplates 纯函数，REQ 拍板二三形态原文）:
   P1: "{summary}——该事件直接涉及你关注的标的{标的1、标的2}。"
   P2: "{summary}——因该事件{方向词}{行业}行业，你关注的标的属于该行业。"（标的空时：
       "{summary}——你关注的{行业}行业受该事件{方向词}影响（源于你订阅的{主题}）。"）
   P3: "{summary}——与你订阅的{主题/事件类型}相关。"
   gen_method=TEMPLATE
7 INSERT OR IGNORE INTO recommendation_card（UNIQUE(user_id,event_id) 幂等；冲突=重复消费直返）
```

**九区块数据面**（卡片视图组装，API 层 join）：事件头/摘要/关键数字/原文引用/时间 = event_item + news_item 直出；逻辑链 = logic_chain；标的区 = subjects JSON（含 inWatchlist 供「加自选」按钮）；操作条/免责 = 前端固定渲染（「AI 分析仅供参考」不进 logic_chain）。**gen_method/prompt_version 不对用户展示**（REQ 拍板三：留痕可查不对用户展示——DB 与对账面可查）。

### 4.6 推送与降噪闸门（`RecommendationFeedService` 推送段 + PushType 10）

**推送编排**（tick 内卡片生成后同段执行）：

```
1 降噪拦截: 本 tick 新卡 + 当日遗留 push_status='PENDING' 卡
    combo = recommendation_mute WHERE user AND status='ACTIVE' AND now < muted_until
    命中 → card.push_status=SKIPPED_MUTED + push_record(status=SILENT)     // 只静默不丢
2 排序取 Top: 剩余 PENDING 卡按 recscore DESC, id ASC 排序
3 日配额: remain = dailyLimit(10, 可配) − COUNT(card WHERE user AND push_status='PUSHED'
          AND pushed_at >= 今日零点 Asia/Shanghai)                          // SILENT 不占配额
4 逐张推送（取前 remain 张）:
    PushRecord.create(userId, null, RECOMMENDATION, cardId, 摘要行) → saveIfAbsent（幂等键 userId:10:cardId）
    → NotificationChannel.send(NotificationEvent.of(RECOMMENDATION, null, null, cardId, 摘要行))
    → card.push_status=PUSHED + pushed_at=now（条件 UPDATE WHERE push_status='PENDING'）
    推送失败沿 PUSH_RETRY 既有语义（status=0 待推/2 失败重试）
5 超限尾部: card.push_status=SKIPPED_QUOTA + push_record(status=SILENT)
6 次日配额自动重置（查询窗今日零点滚动，零代码——沿 M15 换日恢复先例）
```

**摘要行**（铃铛面板 content，≤80 字截断）：`【动态推荐】{事件类型中文}·{方向词}｜{logicChain}`。

**SSE 载荷契约**（既有 NotificationEvent 形状，前端零新增解析面）：

```
event: recommend
data: {"type":"recommendation","subjectId":null,"subjectCode":null,"refId":"123",
       "content":"【动态推荐】回购·增持·减持·利好｜某公司公告回购计划——该事件直接涉及你关注的标的某公司。"}
```

前端铃铛：type=recommendation 渲染卡片摘要（类型徽章+方向色沿 A 股惯例），点击跳 `#/recommendations?focus={refId}` 定位高亮对应卡片；SILENT 不进 SSE，通知历史按既有 history 端点可见（status 含 3）。

### 4.7 反馈闭环与采纳统计（`RecommendationFeedbackService`，adopt-v1）

**四动作 API 语义**（幂等：同卡同动作 1h 窗口内重复 → 200 直返；沿 reading_event 去重惯例）：

| 动作 | 落库 | 副作用 |
| --- | --- | --- |
| USEFUL | feedback(action=USEFUL) | card.adopted 条件置 1 + ACT 埋点 + 画像回流① |
| DISLIKE | feedback(action=DISLIKE, combo_key) | mute UPSERT：新组合 muted_until=now+7d status=ACTIVE；已有 LIFTED → reactivate 续 7d；**升级判定**：feedback 流水滚动 30 天内该组合 DISLIKE ≥3 次（escalateThreshold 可配）→ mute_days=30、muted_until=now+30d（Should 条款）；card.adopted 不置（负反馈非采纳） |
| ADD_WATCHLIST | feedback(action=ADD_WATCHLIST, subjectCode 必填校验) | 复用 WatchlistService 加自选（幂等 409→200）；card.adopted 置 1 + ACT 埋点；标的区 inWatchlist 刷新；画像回流②（P1 命中面自然扩大） |
| UNDO_MUTE | feedback(action=UNDO_MUTE, combo_key) | mute status=LIFTED（后续新卡恢复推送资格；历史 SKIPPED_MUTED 卡不补推）；LIFTED 再撤销 → 200 no-op |

**画像回流**（复用 M2/M11 消费口径，不新建画像写面）：① USEFUL → `ReadingEvent.record(user, subjectId=标的区首标的, RECOMMENDATION_ACT, cardId)`（readStats 热度 +1 次权重，后续卡 profileCoef 上调）；② ADD_WATCHLIST → watchlist 变更即关联输入变更（最强回流）；「不感兴趣」不计负画像（mute 表已承载，避免双重惩罚——REQ 拍板六-3）。

**采纳统计 adopt-v1**（无表派生，`GET /recommendations/stats` 数据面；沿 M15 护栏无表派生先例）：

```
曝光 = ① push_record(type=10, status=SUCCESS, pushed_at ∈ 当日)  —— 推送送达
     + ② reading_event(RECOMMENDATION_VIEW, contentRef=cardId, 当日 distinct 卡)  —— 视口曝光
采纳 = COUNT(recommendation_card WHERE adopted=1 AND adopted 当日首置)   // card.adopted 权威，一卡去重计 1
采纳率 = 采纳 ÷ 曝光（按日可查；北极星 ≥30% 为 M18 全量口径，本期验收=口径上线+对账一致）
对账断言（T138）: COUNT(adopted=1) == COUNT(DISTINCT reading_event WHERE type=RECOMMENDATION_ACT)
                —— ACT 埋点与 adopted 条件更新同点写入，理论恒等（读/反馈/加自选均先条件置位成功再落 ACT）
```

**已读/交互端点**：`POST /recommendations/{id}/read` → read=1 + adopted 条件置 1 + ACT 埋点（REQ 拍板六-4：展开即采纳）；幂等（已读再读 200 直返）。前端在卡片任一跳转（原文/标的/行业）前 fire-and-forget 调用。

## 🛡️ 5. 非功能设计（逐项过）

- **性能**：口径 A 最坏 ~2.7min / 口径 B 最坏 ~7.2min（§4.11 预算表）；FEED tick 全链路（关联毫秒级 + LLM 30s 软超时 + 推送毫秒级）单 tick 最坏 <1min 不追Tick；推荐中心游标分页走 `idx_rc_user_created`（180d 峰值 ~5k 行毫秒级）；两新 Job 与既有调度错峰，SQLite 单写者无长锁（批更新短事务）。
- **容量**：card 日增 5~15 行 / 月 ~300；feedback/mute 极小；180d 峰值 card ~5k 行；express 增量 LLM ~1~3 批/日。
- **成本**：卡片 LLM scene 8：prompt ~600 + completion ~150 token ≈ **¥0.001/卡**；日 10 卡上限天然封顶 ≤¥0.01/日；express ≈¥0.02/日内；护栏 scene 集扩 8 后正常水位 ≈¥0.73/日（预算 ¥2 的 37%），零误触。
- **安全与合规**：JWT 既有鉴权；卡片端点全部 ownerUserId 行级过滤（沿 watchlist/subscription 惯例）；「AI 分析仅供参考」固定尾注；不做预测与投资指令；「加自选」收藏语义；LLM 输出经白名单校验（幻觉防线机制化）；logic_inputs 留痕可审计。
- **可观测**：FEED tick 段式明细 `scan=n; trig=n; hit=n; card=llm:x/tpl:y; push=n; mute=n; quota=n`（JobRunStats）；express 明细同通道；`/recommendations/stats` 三面同源（推荐中心/验收/北极星）；mute/feedback 全留痕可查可撤销；卡片幂等冲突计数（重复消费可观测）。
- **降级预案**：LLM 失败/超时/被拒 → 模板兜底（时效不违约）；护栏 DEGRADED/FUSED → 卡片直接模板（不调 LLM，成本红线联动）；降级期 L2 停 → 无新事件 → 链路自然静默（REQ 故事 6 场景 4）；FEED Job 失败不阻塞管道与采集（ManagedJob 独立容错）；24h 扫描窗重启自动补。
- **可测性预留**：`Clock` 注入（时延/换日配额/降频到期/滚动升级窗用例）；`LlmGateway` fake（白名单拒绝/超时路径零外呼）；两 Job 任务中心手动触发即验收工具；`pushed_at − event.created_at` 断言面；logic_inputs 快照即抽检对账面。

## 🧪 6. 测试要点（T130~T137 单测 + T138 验收）

- **BUG-03**：序列豁免两谓词（external_id 含 # / 标题月度模式）各自命中与双不命中的回归；豁免条目仍可作主条（真同稿引用之）；既有近重复样本复跑语义一致；OBS-04 归位后 EXTRACTED 计数与 event_item 对账自洽。
- **快速通道**：阈值边界（4.0 过/3.99 等）；noise 条目不进 express；DEGRADED 跳 L2 / FUSED 全跳；与常规批并发幂等（同 news_id 双路径建行单行、L1 条件更新后到者匹配 0 行）；L2 配额内优先（高分先出事件）。
- **关联**：触发门槛（LOW 拦 / MEDIUM 无命中拦 / 字段缺失按未命中）；P1（自选 + SUBJECT 订阅并集）、P2 双通道（主题映射命中 / 标的行业 best-effort / NULL 跳过不炸）、P3（EVENT_TYPE 折算 + 主题词 contains）；多级取最高；P3-only 空标的；标的区 ≤5 截断与排序（P1 优先→热度）；recscore 逐项（系数/画像界 [1.0,1.25]/空画像=1.0）。
- **卡片**：白名单四类各违规构造（新增池内标的名/越界行业/未授权数字/方向词冲突/超长）→ 拒走模板；模板三分支文案断言；LLM 超时/异常/解析失败兜底；降级态直接模板；幂等（同关联结果二次生成 INSERT OR IGNORE 单行）。
- **推送**：配额（第 11 张 SKIPPED_QUOTA + SILENT 留痕 + 中心可见）；排序（同 tick 12 卡取 recscore 前 10）；降噪拦截（ACTIVE 未到期 SKIPPED_MUTED）；撤销后新卡恢复推送；次日配额重置（Clock 跨日）；push_record 幂等键防重推；SILENT 不进 SSE/重试/配额。
- **反馈**：DISLIKE 7 天降频（Clock 推进到期恢复）；滚动 30 天 3 次升级 30 天静默；UNDO_MUTE no-op 幂等；ADD_WATCHLIST 复用既有能力 + inWatchlist 刷新；USEFUL 画像回流（readStats 热度上调断言）；采纳置位去重（多动作一卡计 1）。
- **统计**：adopt-v1 三口径 SQL（推送送达/视口/采纳）；对账恒等（adopted=1 ↔ ACT distinct）；stats 端点日期边界。
- **coverage-v2**：分母剔除 NO_EVENT / 滞留 SELECTED 计入；NO_EVENT 占比独立；M15 数据回放 100% 锚点复算。
- **页面**：九区块字段完整渲染；逻辑链三环节回溯可点；筛选分页三态；空态；已降频标记与撤销；testid 契约；铃铛推荐渲染与跳转、既有 9 类零波及。
- **回归红线**：既有 12 Job 留痕零变化；NEWS_PIPELINE 常规批行为字节级不变；每日推荐盘前 Top5 零波及；通知 9 类渲染零变化；提示词治理 7 类模板零波及；2065 基线只增不减。
