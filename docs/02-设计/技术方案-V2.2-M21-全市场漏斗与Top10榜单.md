## ⚖️ 3. 形态决策（ADR-0059 七项主裁决）

### 3.1 回联提升路径 = 写路径修复 + 双通道回填 + 路 C 成员反哺，否决 prompt 增强（裁决 1）

四候选按「根因 → 最小收益比」评估（量化依据 §1.1/§1.2）：

| 候选 | 根因命中 | 收益预估 | 成本 | 结论 |
| --- | --- | --- | --- | --- |
| a) 事件提取 prompt 增强 subjects 输出 | ✗（RC1 证实候选机制已在天花板，null-code 全是非 A 股实体） | ≈0 | 1 人天 + 回归面 | **否决**（证据留档 §1.1 RC1） |
| b) IndustryAssociator 第三路（路 C 行业成员反哺） | ✓（RC3 主根因：行业→标的边缺失） | F2 覆盖 = 成员表覆盖（56%→~100%） | ~1.5 人天 | **采用**（§4.1） |
| c) event_item 生成时行业→标的池批量回联（事件侧灌成员） | △ | F1 污染（行业级事件 ≠ 标的自身催化，蓝图 F1/F2 分维语义正是切割两者） | 1 人天 | **否决**——行业级事件应走 F2 传导（路 C 已覆盖），不进 F1 |
| d) 行业成员重建（写路径修复 + 回填） | ✓（RC3 前置：路 C 需要成员表） | b 的使能器 | ~1.5 人天 | **采用**（§4.1.1~4.1.3） |

**对 ADR-0058 裁决 2 的部分替代**（ADR-0059 显式记录）：ADR-0058 判定 `subject_master.industry`「永远不可靠」的前提是**新浪降级轮把行业覆盖为 null**（写路径缺陷）。本批修复写路径（COALESCE 保留非空）后，该字段变为「东财口径、单调稳定、只在东财自身改类时变化」；且 IndustryAssociator 仍**不直接读原文**，读的是「SW 映射纯函数输出」——东财板块名变化只有映射输出变化时才影响关联，漂移面收窄到可审计。

### 3.2 粗筛切分 = 四键排序可复现 + 三条排除规则留痕（裁决 2）

排序键（任务口径照单全收）：`total_score DESC → f_catalyst DESC → last_event_date DESC（NULL 视最旧）→ subject_id ASC`——纯列排序、无 JSON 解析、无随机、无时钟；同输入同切分（幂等）。排除规则：ST（名称含 ST，实测 201 只）/ 无信号（F1=0 ∧ F2=0，即纯并列组）/ 不另设停牌排除（无库内判据，v2）。被排除标的计数进 funnel_stats 留痕（`excluded:{st,noSignal}`），快照行不动（排除只作用于池）。

### 3.3 深析形态 = 单标的单次调用 + briefType 10 + scene "10"（裁决 3）

**单标的单次**（否决小批多标的）：深析质量是 M21 最大不确定项（蓝图 Confidence 70% 折价来源），单标的上下文纯净、引用对账白名单独立、失败爆炸半径最小；30~50 次/日 × ~3.4k tokens 在预算内（§4.4.7），批量省 token 的收益不抵质量与对账复杂度。scene 键沿 `LlmRequest.briefTypeKey` 契约取 **"10"**（briefType 9 已被行业周报占用；"9" 会造成 scene 与模板错位——编号裁量记 ADR-0059）。

### 3.4 成本护栏 = scene-10 子预算占比 ≤30% 触顶降级（裁决 4）

深析日成本（scene="10" 当日 SUCCESS 留痕和，Asia/Shanghai 日界）÷ `pipeline.budget.dailyBudgetMicros` ≥ `deepDiveCostCapRatio`（缺省 0.30）→ 停止剩余深析，已深析照常合成。`PIPELINE_SCENES` 扩为 `["5","6","7","8","10"]`——深析计入管道总预算与 FUSED 护栏（蓝图语义：深析预算是管道日预算的份额，非独立池）。预估幅面：40 次 × ~3.4k tokens ≈ ¥0.3~0.8/日 vs 上限 ¥0.78（30%×¥2.60）——首跑校准留档（cost-v2 先例）。

### 3.5 合成公式 = final = max(总分, 0.8×总分 + 0.2×深析结构分)（裁决 5）

深析**不产生观点分**（LLM 自评置信度不可复算、破坏防抖），只产生**确定性结构分** diveScore（§4.5.1，从校验后 JSON 结构派生：论点 25 + 亮点 10×min(n,3) + 风险 10×min(n,2) + 引用 5×min(n,5)，合格区间 [75,100]）。max 包络保证深析**只加分不惩罚**（0.8 权重下高分标的被拉向 diveScore 的问题被消除）；0.2 权重保证排序仍以因子分主导（深析幅面 ≤5 分），防抖语义（故事 5 场景 3 的 M22 前置）在 M21 即成立。factor_only 标的 final = 总分，与深析标的同序可比。

### 3.6 榜单版本化 = (rank_date, version) 追加式 + 变动留痕（裁决 6）

同日重跑 version+1 追加（不覆盖，M22 事件触发版本沿用同一机制）；读取走「该日期最大 version」。变动留痕 = 生成时与**昨日最新版本** diff：prev_rank / change_type（NEW/UP/DOWN/SAME）落每行，跌出标的落 batch.dropped_subjects。不建第三张变动表（diff 是确定性的，可由两版本重算——留痕是读优化非真相源）。

### 3.7 页面形态 = #/market-top 第 20 页 + 方法论子路由（裁决 7）

#### 4.1.4 IndustryAssociator 路 C（行业成员边）

```

### 4.4 LLM 深析层（`DeepDiveService`，briefType=10）

#### 4.4.1 模板（V31 播种 `prompt_template` brief_type=10 v1.0，走 M5 页面化治理）

```
---SYSTEM---
你是全市场标的深析引擎。基于输入的结构化事实（因子分解/依据事件/关联资讯/行情快照）撰写单标的深析。
输出合法 json（不要 markdown 代码块）。【红线】只能引用输入中给出的 eventId/newsId；不得编造数字、

【输出 schema】{"thesis": "≤120字论点", "highlights": [{"text":"≤80字","citations":[{"type":"EVENT|NEWS","id":...}]}],

#### 4.4.3 调用编排

单标的单次（裁决 3）：`LlmRequest.json(messages, "10")` → LlmGateway（超时 30s/重试 1 沿 llm.global）→ 解析；调用间隔 200ms。深析前逐次**成本预检**（§4.4.7）。UserId 语境：Job 线程置系统用户上下文（沿管道 scene 5~8 惯例——llm_call_log 留痕 scene="10"）。

#### 4.4.4 校验链（五步固定顺序，首违即止；全程留痕计数）

| 步 | 校验 | 失败处置 |
| --- | --- | --- |
| 1 | JSON 解析 | 模板兜底 |
| 2 | 结构：thesis 非空 ≤120 字；highlights 2~4 条、risks 2~3 条、每条 ≤80 字 | 模板兜底 |
| 3 | **引用对账**（`CitationReconciler`）：每 citation (type,id) ∈ 白名单；无效引用剔除 → 所在条目 0 有效引用则条目剔除；条目数跌破下限 | 模板兜底 |
| 4 | **违禁扫描**（`ProhibitedPhraseScanner`）：thesis 命中 → 整体兜底；条目命中 → 该条目剔除（再判下限） | 条目剔除/模板兜底 |
| 5 | 通过 → diveScore 计算（§4.5.1）+ dive_summary 拼装 | — |

黑名单正则（domain 常量，沿 FactWhitelistValidator 词表先例；首跑后可校准扩充）：
`必涨|必定上涨|保证.{0,4}收益|稳赚|包赚|稳获|买入|卖出|清仓|满仓|梭哈|抄底|加仓|建仓|目标价|涨停|翻倍|十倍|强烈推荐`

#### 4.4.5 引用与库对账（防幻觉的机制化防线，需求锁定语义）

白名单先例（M16 ADR-0051 裁决 3）从「四类文本比对」裁剪为「**结构化 id 集合比对**」——深析输出引用是结构化 (type,id)，比对纯集合运算（比 contains 文本判定更强）：`invalid = citations − whitelist`。invalid 非空即有幻觉企图：剔除 + WARN 留痕（llm_call_log scene="10" + JobRunStats detail.citationDrops 计数）——T187 验收「零幻觉断言」= 对全部深析输出断言 `citations ⊆ whitelist`。

#### 4.4.6 模板兜底（确定性中性文案）

`DeepDiveTemplateComposer`（domain 纯函数）：`近{N}日 {N1} 条关联事件（最高重要度 {imp}，最新 {date}）；所属行业 {ind} 24h 热度排名第 {R}；五维评分 {F1}/{F2}/{F3}/{F4}（权重 {w}）。以上为数据整理，不构成投资建议。` —— 数字全部来自结构化输入（沿 ADR-0054 周报「AI 只写叙述」的更保守档：模板连叙述都不用 AI）。dive_method=TEMPLATE、generation=FACTOR_ONLY（不参与 diveScore）。

#### 4.4.7 成本护栏（`PipelineGuardService` 扩展，裁决 4）

- **子预算预检**（每次深析调用前）：`todaySceneCost("10") + estimatedPerCall > capRatio × pipeline.budget.dailyBudgetMicros` → 停止剩余深析（estimatedPerCall 缺省 100,000μ¥ ≈ ¥0.10/次保守值，可配）。todaySceneCost = llm_call_log 当日（Asia/Shanghai）scene="10" SUCCESS 成本和——**观测与执行分离**（ADR-0015 先例：严格口径以留痕表为准）。
- **降级三档**：①单次调用失败 → 该标的模板兜底（不重试 LLM）；②连续 ≥5 次失败 → 中止剩余深析（degraded_reason=LLM_FAILURE）；③成本触顶 → 停止剩余（degraded_reason=COST_CAP）。②③ batch.degraded=1；次日日界键自然恢复。
- `PIPELINE_SCENES` 扩 `"10"`：深析计入管道 FUSED 两级护栏与 cost 报表（LlmCostReport scene 维度自动多一行，零报表改造）。
- **触顶降级语义**（需求锁定）：跳过的标的按 factor_only 进合成——**榜单恒产出**，页面横幅「深析已暂停（成本护栏），本榜单按因子分排序」。

### 4.5 Top10 合成与变动（`TopComposer` + `RankDiffer`，domain 纯函数）

#### 4.5.1 合成公式（裁决 5）

```
diveScore = 25（thesis 合格） + 10×min(#highlights, 3) + 10×min(#risks, 2) + 5×min(#validCitations, 5)   // 合格区间 [75,100]
final = max(total_score, 0.8×total_score + 0.2×diveScore)   // 深析合格标的（generation=FULL）
final = total_score                                          // factor_only / 降级 / 未深析
排序 = final DESC → f_catalyst DESC → last_event_date DESC（NULL 最后）→ subject_id ASC；截断 topSize=10（恰 10，代码常量不配置——蓝图锁死）
basis = "mt-v1:final=max(total,0.8*total+0.2*dive);dive=25|10x3|10x2|5x5;pool=300;dive=40;cap=0.30"
```

max 包络消除「高分标的被 0.8 权重拉向 diveScore」的惩罚；0.2 权重幅面 ≤5 分保证因子分主导排序（防抖）；diveScore 全部从校验后 JSON 结构派生——**同输入同输出可复算**（dive_detail 即审计锚）。

#### 4.5.2 变动留痕（`RankDiffer`）

与昨日（rank_date−1 自然日，跨假日取最近有榜单日 ≤7 天）最新版本 diff：行内 prev_rank + change_type（NEW/UP/DOWN/SAME，rank_no 对比）；跌出标的 [{code,name,prevRank}] 落 batch.dropped_subjects。首日无昨日榜单 → 全 NEW。

#### 4.5.3 榜单不足 10

合格标的 <10 → 如实呈现：funnel_stats.topSize 记实际数，端点正常返回，页面标注「本日达标标的不足 10 只（{n} 只入榜）」（蓝图验收口径）。

### 4.6 Job 组织（`MarketTopJob`，第 17 个 ManagedJob）

- jobKey `MARKET_TOP_JOB`；ScheduleType **CRON** 缺省 `0 0 18 * * ?`（盘后 18:00）；`job.MARKET_TOP_JOB` 键（enabled/cron 热改）；测试 profile 种子 enabled=false（16 Job 惯例）。
- **独立 CRON 错开而非依赖触发**（裁量，ADR-0059）：FACTOR_SNAPSHOT 17:30 全程 <2min，18:00 有 30 分钟余量；JobExecutor CAS 串行无事件链基建——**快照日守卫**替代依赖编排：当日 `subject_factor_snapshot` 最大 snapshot_date ≠ today → WARN 跳过（次日全量自然修复 + 任务中心手动补触发）；M22 增量链路接入后守卫语义不变。
- 执行流（`MarketTopService.generate()`）：
  1. **阶段 0 回联保障**：成员覆盖率预检（<80% → datacenter 回填，§4.1.2）；
  2. **阶段 1 粗筛**：读当日快照全量行 → PoolBuilder 排除/排序/切分 → 池 300 + 深析候选 40；
  3. **阶段 2 深析**：逐只「成本预检 → 输入组装 → LLM → 校验链 → 兜底」（§4.4）；三档降级监控；
  4. **阶段 3 合成**：TopComposer（层数断言 → final 排序 → 截断 10）→ RankDiffer（昨日 diff）→ V31 两表落库（version = 同日已有最大 +1）；
  5. JobRunStats：processedCount=10 + detail（funnel_stats 全量 + dive 统计 + citationDrops + 成员回填计数）。
- 弹性：仅阶段 0/2 有外部调用（datacenter / LLM）；整段失败降级继续（缺成员照跑 / 单标兜底）；Job 整轮异常不上抛（轮询型惯例）。

## 🛡️ 5. 非功能设计（逐项过）

- **性能**：MARKET_TOP_JOB 全程预算 = 阶段 0 回填（~30 请求 × 1.5s ≈ 45s，仅在覆盖率 <80% 时）+ 粗筛（5221 行内存排序 <100ms）+ 深析 40 次 ×（LLM 5~15s + 200ms 间隔）≈ **4~12min** + 合成落库 <1s——18:00 起步，08:00 红线余量 14h+。读路径：最新版本两表各一次索引查询（UNIQUE 命中毫秒级）；页面 P95 对齐 M9/M12 三态基线。
- **容量**：market_top_rank ≤10 行/版本 ×（日 1~3 版本）× 180d ≈ ≤5,400 行（dive_detail 均值 ~1.5KB）≈ 8MB；market_top_batch 1 行/版本 ≈ 540 行——两个数量级低于快照表，SQLite 无压力；留痕按 M10 窗口滚动。
- **安全**：三端点 JWT 既有鉴权；全只读（GET ×2）+ PATCH 配置带 expectedUpdatedAt 并发防呆（30065）+ 校验器字段级拦截（30091）；无敏感数据；单用户无越权面。
- **可观测**：job_execution_log（funnel_stats/dive 统计/citationDrops/回填计数全量 detail）+ llm_call_log scene="10"（成本/时长/状态）+ cost 报表 scene 维度自动扩展 + coverage 端点 flagCounts 联动观察回联提升效果（NO_ASSOC 曲线即验收口径）。
- **降级预案**（三档 §4.4.7 + 输入侧）：datacenter 回填失败 → 缺成员照跑（NO_ASSOC 如实）；当日无快照 → 守卫跳过（次日修复）；LLM 全失败 → 全模板兜底榜单仍成立（factor_only + degraded）——**主价值链对深析与回填都不设单点依赖**。
- **合规**：免责三处必载（榜单页脚/方法论页/卡片摘要区）+ 违禁扫描拦截 + 深析提示词内嵌红线指令 + AI 局限性说明页面化——裁决 5 全量落地。
