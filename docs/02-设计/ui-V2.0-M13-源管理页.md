```

│ —— 以下仅 JSON 类型展开（RSS 用默认映射，隐藏整区）——                │
│ 条目数组路径 [ result.data ]（可空 = 根数组）                        │
│ 字段映射    标题字段* [ title ]  时间字段 [ time ]                  │
│             ID 字段   [ id ]     摘要字段 [ content ]               │
│ 高级（折叠区，默认收起）：包装前缀 [ var newest= ] / 请求头 UA·Referer│
│                                          [取消] [保存并启用] ←default│

└────────────────────────────────────────────────────────────────────┘
```

**字段与校验**（前端即时校验提交前拦截，沿用 §5.3 惯例；后端错误码文案原样回显在 Dialog 内反馈位）：

| 字段 | 规则 | 提示文案 |
| --- | --- | --- |
| 类型 | rss / json_api 二选一（分段按钮） | — |
| 名称 | 非空 | 「名称不能为空」 |
| 端点 URL | http(s) 格式（沿用既有 `urlError` 正则） | 「URL 须以 http(s):// 开头且格式合法」 |
| 轮询间隔 | 1~60 整数 | 「间隔须为 1~60 的整数（分钟）」 |
| 条目数组路径 | 可空（点分路径，空 = 根数组） | — |
| 标题字段 | JSON 类型必填 | 「标题映射字段必填（诊断映射错误的最低要求）」 |
| 时间/ID/摘要字段 | 可空（时间缺省按抓取时间、ID 缺省靠指纹去重） | — |

- `sourceCode` 不设输入框：技术标识，由后端从名称生成；唯一冲突 / robots 禁抓（30075）按后端文案内联回显，表单保持原值。
- 「保存并启用」即 POST（enabled=1，新建源 `next_due_at = now`）；saving 态按钮「保存中…」disabled。

### 3.4 编辑 / 启停 / 软删 / 恢复

| 动作 | 交互 |
| --- | --- |
| 编辑 | Dialog 回填 §3.3 同一表单（类型分段只读展示不可切换——预置源改 adapterType 后端拒绝，前端一致禁用）；保存 PATCH，反馈「已保存 · 即时生效：下一轮抓取按新参数执行」（源配置天然 LIVE 热生效，无需 EffectBadge） |
| 启停 | 卡头 Switch 即存即生效（下一 tick 摘除/加入），无二次确认（停用可逆、语义轻）；停用卡 `opacity-60` |
| 停用并归档（软删，仅通用源） | outline 按钮 → Dialog 二次确认：「停用并归档后该源停止调度、移入归档；已入库条目保留不删。确认归档？」→ 确认后 DELETE，卡片从分组移除（归档开关开启时可见于「已归档」分组） |
| 恢复 | 归档卡仅两个动作：「恢复」（PATCH 回 deleted=0，恢复为**停用**态，用户确认启用时机）与端点只读展示；归档卡不可编辑参数 |

### 3.5 测试连通 / 立即抓取

| 动作 | 交互 |
| --- | --- |
| 测试连通 | 「测试中…」disabled → 内联结果行（`role="status"`）：成功「连通 · 412ms · 解析 20 条（robots 允许）」emerald；失败「失败：连接超时」rose + `title` 悬停诊断明细（reachable/robots/样本，契约 §4.5 诊断体）。不落库不改配置 |
| 立即抓取 | 「抓取中…」disabled → POST 202 受理 → 3s 轻轮询列表（上限 30s、document.hidden 暂停）至该源 last_attempt_at 更新出终态徽章；期间重复点击 / 后端 30074 在飞 → 收敛为同一「抓取中…」态，不弹错（D6） |

## 🔁 4. 三态与反馈

### 4.1 页面三态（基线沿用 ui-配置与运维可视化 §4.1）

| 态 | 表现 |
| --- | --- |
| loading | 分组骨架：标题条 `Skeleton h-4 w-24` + 卡片 `Skeleton h-48` ×6 |
| empty | 列表为空属异常（预置种子三源恒在）：「暂无资讯源（异常场景，请检查后端种子）」muted 占位；归档开关开启但无归档源：「暂无归档源」muted |
| error | 整页失败：`role="alert"` 错误文案 + outline「重试」；单卡保存/抓取失败仅本卡反馈，不污染他卡；401 走 http 层统一跳登录 |

### 4.2 卡片状态徽章矩阵（最近一轮轮询结果）

| 态 | 徽章 | 样式 |
| --- | --- | --- |
| 成功 | `成功 14:30 · 新3`（时间 + 本轮新增） | emerald（§5.1 成功档） |
| 抓取中 | `抓取中…`（手动触发后 / 在飞） | amber + 行内 `animate-pulse` 微动效 |
| 失败 | `失败 · <last_error 摘要截断>`，`title` 全文 | rose |
| 退避中 | `连续失败 3 次 · 15:20 后重试`（consecutive_failures ≥2 且 backoff_until 未到） | amber |
| 暂未抓取 | `暂未抓取`（新源首抓前 / last_attempt_at 为空） | muted，不报错不空白 |

### 4.3 新增源保存后引导（PM 验收「≤10 分钟出数」的页面侧闭环）

保存成功 Dialog 不自动关闭，引导条替换表单顶部（emerald，`aria-live="polite"`）：

> 已启用 · 首次抓取将在约 1 分钟内执行（调度周期 60s），可点「立即抓取」立即验证出数。

按钮组变 `[立即抓取] [完成]`：「立即抓取」直接对新建源触发 §3.5 手动抓取（Dialog 保持打开看结果行，或关闭回卡片看徽章，二者同一通道）；「完成」关闭并刷新列表——新卡出现在所选分组顶部，卡内 SaveFeedbackBar 同文案常驻至下次操作。

## 💻 6. 给开发注意事项（T105）

1. **零新依赖**：全部复用 `card / badge / button / input / dialog / skeleton` + 自研 `Switch / SaveFeedbackBar`；分组下拉用原生 select（JobLog 先例）；图标 `RadioTower`（lucide 既有版本已验证）。
2. **生效语义统一**：源配置改动全部「下一轮抓取热生效」，无重启生效项——不渲染 EffectBadge，保存反馈用 SaveFeedbackBar `successLabel` 表达（如「已保存 · 下一轮抓取按新参数执行」）。
3. **错误码收敛**：30074 在飞 → 「抓取中…」态不弹错；30072/30075 → 表单/反馈位内联回显后端具体原因，表单保持 dirty 原值；30073 预置删除为前端无入口的双保险，不额外处理。
4. **列表刷新策略**：编辑/启停/归档/恢复按卡局部更新（DatasourceConfig `applySource` 模式）；仅手动抓取触发轻轮询整表（3s × 上限 30s，`document.hidden` 暂停）。
5. **字段映射序列化**：轻量表单 → `config.listPath` + `config.itemMapping[]`（4 个目标字段各一条，transform 后端按目标字段默认），高级区的 stripPrefix/headers 原样并入 config；RSS 类型不带映射键（用引擎默认映射）。
