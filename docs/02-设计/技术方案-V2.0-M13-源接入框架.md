## 🎯 1. 背景与目标

### 背景（设计前代码核实结论）

| 复用点 | 核实结果 | 本批复用方式 |
| --- | --- | --- |
| ManagedJob 调度体系 | `JobScheduler`（ThreadPoolTaskScheduler，FIXED_DELAY/CRON 双型 + `job.{KEY}` 热切换重注册）/ `JobExecutor`（每 jobKey CAS 守卫 + STARTED→SUCCESS/FAILED 留痕）/ `JobRegistry`（静态 bean 注册）；现有 7 个 Job | `SourcePollJob implements ManagedJob` 第 8 个，调度中心仅扩池（§4.4），ADR-0040 |

| data_source_event 留痕 | source_code TEXT 自由文本 + event_type 1缺失/2超时/3错误/4限频，旁路不阻断；retention.global 窗口治理（默认 14d） | 失败/静默期事件沿用（source_code 取 `info:{sourceCode}` 前缀命名），不扩 event_type（§4.8） |

| JobRunStats 留痕计数通道 | ADR-0036 落地：可选接口上报 (processed, detail)，SUCCESS 行 error_message 写明细 | `SourcePollJob` 实现接口，tick 明细 `dispatched=n; ok=n; fail=n`（§4.4） |

**现状差距**（蓝图能力域 B/C）：资讯类仅新浪一条请求驱动的全市场流（不落库，2min 缓存）+ gov.cn 政策单源；源注册表是代码事实（SourceCode 枚举 6 值），页面只能在已注册 provider 里编排参数与降级链；分钟级调度、增量游标、跨源去重、断流恢复均不存在。

### 目标（对齐蓝图 M13 验收要点，可量化）

1. **页面自增源 ≤10 分钟出数**：通用 RSS/JSON 源新增保存 → 首次抓取在 1 个间隔内执行 → 入库 ≥1 条（蓝图故事 1 场景 1）。
2. **分钟级增量不重不漏**：快讯源 1~60 分钟可配轮询；同源同条不重复入库（external_id + 指纹双唯一）；游标只在条目持久化成功后推进（崩溃重拉幂等）；断流恢复后按游标增量补抓（蓝图故事 2 场景 1/2）。
3. **软删语义**：通用源删除 = 停用 + 软删（历史数据保留、配置归档可恢复）；预置源无删除入口只有启停与参数编辑（蓝图裁决 1）。
4. 试点源 3 个稳定出数（§3.4）；既有 7 Job 与降级链零回归（1520 测试基线只增不减）。
5. 大盘数据面落库：每源每日 rollup 计数 + 感知延迟口径可从 `news_item` 现算（§4.8，页面 UI 归 M14）。

## ⚖️ 3. 形态决策（三项架构级裁决 + 试点选型，均记 ADR）

### 3.1 源注册表 DB 化与六源体系边界（ADR-0038）

**裁决**：新表 `info_source` 承载资讯源注册表（预置源 + 用户通用源统一模型），**与既有 `datasource.{CODE}` 运行时配置体系并存、边界冻结**：

| 维度 | 六源业务域（既有，不动） | 资讯源域（M13 新增） |
| --- | --- | --- |
| 驱动模式 | 请求驱动（用户查标的 → 按需拉取 + SourceCache） | 调度驱动（7×24 轮询 → 持久入库） |
| 注册载体 | `SourceCode` 枚举（6 值，代码事实） | `info_source` 表行（DB 事实） |
| 配置载体 | runtime_config `datasource.{CODE}`（含降级链） | `info_source` 行内 config/interval/enabled |
| 失败语义 | 降级链（同容备源切换，ADR-0033/0034） | 退避摘除（源内容异质，无「备源同容」） |
| 数据落点 | 内存聚合响应（NEWS 不落库） | `news_item` 持久累积 |
| 页面 | 数据源配置页 7 卡（零改动） | 新源管理页 #/info-sources |

**理由**：合并需泛化 SourceAdapter/SourceCode/降级链三套强类型体系（1520 测试基线的核心面），回归风险与收益完全倒挂；两域读取模式（按标的拉取 vs 全市场流入库）与失败语义本质不同。「新浪 7×24 升级既有新浪源」（M14 批次一）落地为：zhibo 频道以预置源入 `info_source`（M13 试点即它），既有 NEWS（feed.mix 按标的详情）保持不动——同平台不同频道，不冲突。增删改语义沿蓝图裁决 1：增 = 通用源新增/预置源启用；删 = 停用 + 软删（预置源不提供物理删除，平台资产）；改 = 参数编辑热生效（下一 tick 现读新值，天然 LIVE）。

**被否**：①泛化合并两体系（回归面不可控）；②资讯源配置并入 runtime_config `datasource.*` 键空间（单文档 JSON 装不下行级多源 + 查询/种子/校验三处特例，且「源」从键值变行集正是本批架构目的）。

### 3.2 资讯统一库独立建表与跨源指纹去重（ADR-0039）

**裁决 1（表关系）**：`news_item` **独立新表，不与 `policy_item` 合并、不泛化**。`policy_item` 是政策域专表（ai_tendency/related_industries 等域字段、published_at 仅日期粒度、source_url 去重键、无指纹无游标无软删生命周期），泛化 = 改存量表 + 动政策链路，零收益大风险；政策源（POLICY 六源域）继续写 `policy_item`，**不**同时写 `news_item`（M15 AI 管道若需统一消费，届时以管道读两表解决，不倒逼表合并）。

**裁决 2（指纹算法与粒度）**：**跨源同文去重**（对齐北极星「日净入库 = 跨源去重后」口径）：

```
fingerprint = sha256_hex( NFKC(title) 去全部空白字符 + "#" + published_date )
  - NFKC：全角→半角、兼容分解（中英文标点统一）
  - 去空白：\s+ 全删（标题内空格/换行不影响）
  - 大小写：ASCII casefold（英文源 MarketWatch 与转载同题）
  - published_date：published_at 按 Asia/Shanghai 取 yyyy-MM-dd
    （源缺时间 → 取抓取日；跨日同题不合并——保守方向，宁漏并勿错并）
  - 全局 UNIQUE(fingerprint)：首个入库者胜，后来者计 dup_count 不入正文库
```

**裁决 3（双层去重）**：源内精确去重 = `UNIQUE(source_id, external_id)`（external_id 可空，NULL 不受唯一约束——无 id 的源靠指纹兜底）；跨源同文去重 = `UNIQUE(fingerprint)`。两者都以 `INSERT OR IGNORE` 收敛，批量插入后以「应插数 − 实插数」得 dup_count（§4.8 统计口径）。

**被否**：①指纹含 URL（转载同稿 URL 必不同，跨源去重失效）；②指纹含 source_id（纯源内去重，不满足北极星口径）；③URL 为去重键（policy_item 模式，同②失效）；④SimHash 近似去重（误判面与成本，M15 预筛 Could 项）；⑤合并 policy_item（见裁决 1）。

### 3.3 分钟级调度框架（ADR-0040）

**裁决**：**复用 ManagedJob 体系，一个 `SOURCE_POLL` 聚合 Job 内做源维度调度**（FIXED_DELAY tick 默认 60s，`job.SOURCE_POLL` 可配 15s~300s）：

- 每 tick 现读启用源（enabled=1 且 deleted=0）→ 到期计算 `now ≥ max(next_due_at, backoff_until)` → 有界线程池派发（全局并发上限 4，代码常量）→ 单源在飞集合防重派 → 等待本轮派发完成（预算 45s）→ JobRunStats 上报明细。
- **退避**：连续失败 n 次 → 下次延迟 = interval × 2^min(n,4)，封顶 60min（`backoff_until`）；恢复成功即清零。连续失败 ≥6 次记 data_source_event 告警事件（旁路），此后每 10 次补记一条（防刷屏）。
- **错峰**：预置源种子 `next_due_at = now + hash(source_code) mod interval`；重启后过期源在首 tick 内以 `min(interval, 5min)` 随机抖动重铺，防停机后齐发。
- **增量游标与断流补抓**：`source_poll_state` 持久游标（值 + 类型由源声明：EXTERNAL_ID 数值 / PUBLISHED_AT 时间 / NONE 纯靠去重）；正常轮取第 1 页 newest-first，遇已见条目止；`gap = now − last_success_at > 3 × interval` → 深翻至 maxBackfillPages（默认 3 页）补抓，触页上限仍有未见条目 → `last_round_detail` 记 `backfill=truncated`（可观测，漏抓风险显性化——条目已滚出源侧窗口时物理不可补，如实标注）。
- `JobScheduler` 池 5→8（一个常量；tick 长驻占用 1 线程，防与既有 7 Job 抢占）。

**被否**：①每源一 ManagedJob（JobRegistry 需动态化；interval 双写漂移；任务中心 30+ 行噪音；job_execution_log 每 1min×30 源 ≈4.3 万行/天，现全量表 30d 才 11 万行）；②引入 Quartz/db-scheduler 新调度器（新依赖新运维面，单机 SQLite 过设计，五维度全面劣于扩展自有成熟件）；③绕过 JobScheduler 自建 @Scheduled 动态注册（重复造轮子，失去任务中心可视与统一留痕）。

### 3.5 大盘数据面载体：`source_daily_stats` 日粒度 rollup + 既有表派生（不新建宽表明细）

### 4.2 指纹与去重（领域服务 `FeedFingerprint`，纯函数可单测）

归一化规则（ADR-0039 裁决 2，逐条可测）：

1. `NFKC` 规范化（全角标点/数字 → 半角；兼容组合分解）。
2. 删除全部空白字符（`[\s\u3000]` 全删，含标题中间空格——中文标题空格无语义，英文标题词距不参与判同的保守取舍已由 casefold+去空白共同吸收，误合并风险由「+日期」边界兜底）。
3. ASCII 大小写折叠（casefold）。
4. 拼接定界符 `#` + published_date（`published_at` → Asia/Shanghai → `yyyy-MM-dd`；源缺时间用抓取日）。
5. SHA-256 十六进制小写。

伪码（域服务，Java 标准库，无框架依赖）：

```java
String fingerprint(String title, Instant publishedAt) {
    String normalized = Normalizer.normalize(title == null ? "" : title, NFKC)
            .replaceAll("[\\s\\u3000]", "")
            .toLowerCase(Locale.ROOT);                    // casefold（英文源）
    String date = LocalDate.ofInstant(publishedAt, ZONE_SH).toString();
    return sha256Hex(normalized + "#" + date);
}
```

入库去重流程（`FeedIngestService`，单轮事务内）：

```
items = fetcher.fetch(source, cursor, pages)             // RawFeedItem 列表（引擎输出，§4.3）
  → 过滤：title 非空 && url/externalId 至少其一
  → 补齐：fingerprint 逐条计算（缺 publishedAt → now）
  → 批量 INSERT OR IGNORE INTO news_item (...)           // 两唯一索引同时兜底
  → inserted = 变更行数；dup = items.size - inserted
  → UPDATE source_poll_state SET cursor_value = 本轮最大游标值, ...
  → UPSERT source_daily_stats（INSERT OR IGNORE + UPDATE x = x + delta）
```

并发同稿（两个源同 tick 抓到同文）：两轮事务串行（SQLite 单写者），后到者被 idx_news_fp 拦截计入 dup——无需应用层锁。

### 4.4 调度、增量与恢复（应用层 + 第 8 个 ManagedJob）

**配置键**（`JobRuntimeConfigSeeder` 增第 8 键，通用 job 域规则零特例）：

| config_key | JSON | 生效 | 种子 |
| --- | --- | --- | --- |
| `job.SOURCE_POLL` | enabled(bool) / scheduleType=FIXED_DELAY / intervalMillis（15000~300000，默认 60000） | 启停立即 / 间隔自下一周期 | `@Value("${source.poll.enabled:true}")` 等，测试 profile false → 零注册（七 Job 同惯例） |

**调度伪码**：

```
SourcePollJob.run():                                    // 每 tick（默认 60s）
  actives = infoSourceRepo.findActive()                 // enabled=1 AND deleted=0，每 tick 现读=配置热生效
  due = actives.filter(now >= max(next_due_at, backoff_until))
  due = 抖动重铺（仅 overdue 部分：next_due_at += rand(0..min(interval,5min))，防重启齐发）
  targets = due.filter(不在 inFlight 集合).orderBy(overdue 最久优先).limit(并发余量)
  futures = targets.each(dispatch: ingestService.poll(source))   // 有界线程池 POOL=4（代码常量）
  CompletableFuture.allOf(futures).timeout(45s)         // 超时不中断在飞轮（下 tick 由 inFlight 兜底）
  report(processed = targets.size, detail = "dispatched=n; ok=n; fail=n")   // JobRunStats（ADR-0036 通道）

FeedIngestService.poll(source):                         // 单源单轮（异常全捕获，不外抛）
  attempt: last_attempt_at = now; 计时开始
  pages  = gap > 3×interval ? min(maxBackfillPages=3, ...) : 1
  items  = fetcher.fetch(source, cursor, pages)         // newest-first，ID/TIME 游标遇已见止
  [一个事务]:
    INSERT OR IGNORE news_item 批量
    UPDATE source_poll_state（cursor / next_due_at = attemptStart + interval / 成功字段）
    UPSERT source_daily_stats（poll+1, new+inserted, dup+(n-inserted)）
  成功: consecutive_failures=0, backoff_until=NULL, last_success_at=now
  失败: consecutive_failures++, backoff_until = now + min(interval × 2^min(fails,4), 60min)
        首败与每 10 次 → DataSourceEventRecorder 旁路（source_code="info:{source_code}", event_type=3, detail）
```

**不重不漏论证**：不重 = 双唯一索引 + OR IGNORE（调度重入/补抓重拉/并发同稿三场景收敛）；不漏 = 游标与条目同事务、只进不退（崩溃于事务后游标未推 → 下轮重拉同批 → 幂等吸收）；「物理漏」（断流期间条目滚出源侧翻页窗口）由补抓深翻缓解、超出 maxBackfillPages 时 `backfill=truncated` 显性标注（§3.3）。

### 4.6 预置源目录与种子（`InfoSourceCatalog` + `InfoSourceSeeder`）

- `InfoSourceCatalog`（代码常量，预置源**单一事实源**——对齐 `SourceProviders`/`DataSourceDefaults` 惯例）：M13 种子三源（§3.4 表）；M14+ 每批新增源 = 目录加行，Seeder seed-if-absent 补种（存量行不覆盖，DB 为权威）。
- `InfoSourceSeeder` 启动同步：预置源 INSERT OR IGNORE（按 source_code）+ 为新行初始化 `source_poll_state`（next_due_at = now + hash 偏移错峰）。用户通用源不经种子。
- 合规预检留档（T106）：三源 robots 判读结论（MW robots 403 → RFC 9309 无限制 + 落地复核注记；金十/新浪无 robots）写入目录常量注释与验收留档。

## 🛡️ 5. 非功能设计（逐项过）

- **性能目标**：tick 60s（可配 15s~300s）；单源超时 5s、单轮 ≤50 条入库；全局并发 4；SQLite 单轮事务毫秒级（WAL，busy_timeout=5000 排队）。信息流读端点走 idx_news_published / idx_news_source_published，30 万行量级毫秒级（对齐 ADR-0035 实测基线）。
- **容量预估**：30 源全量后净入库 ≥2000 条/日（跨源去重后），保留 ≥180d 峰值 ≈36 万行 ≈150MB（含索引）；source_daily_stats 30 源×365d ≈1.1 万行/年；job_execution_log 增量 1440 行/日（tick 留痕）——均在既有护栏内（§8 跟进项：M14 扩 retention 键）。
- **安全与合规**：JWT 既有鉴权，无新匿名面；config 禁止存放密钥（UA/Referer 白名单字段校验）；**robots 硬校验**（保存时 30075 拦截 + 连通性测试复判）；预置目录白名单制（红线外源——JS 盾/签名 API/登录墙——根本不入目录，普查 §6 已证）；礼貌抓取 = interval ≥1min 下限 + 浏览器 UA + 必要 Referer；数据仅本机自用。
- **可观测**：tick 明细进 job_execution_log（JobRunStats 通道）；失败/静默旁路进 data_source_event（`info:{source_code}`，节流：首败+每 10 次+恢复）；每源 last_round_detail / last_error 页面可读；统计 rollup 即大盘数据面。
- **降级预案**：单源故障 → 退避摘除（不影响其他源，蓝图 NFR「单源失败不阻塞」）；调度整体故障 → `job.SOURCE_POLL` 页面停用（六源业务域完全不受影响）；补抓截断 → backfill=truncated 显性标注 + 事件留痕（M14 大盘告警挂点）。
- **可测性预留**：`Clock` 注入（七 Job 同惯例）；fetcher 端口可 fake（引擎单测零外呼）；连通性测试/手动抓取端点即验收工具；指纹纯函数用例表（§6）。

## 🧪 6. 测试要点（对齐 04 测试规范，T100~T104 单测 + T107 验收）

- **指纹**：全半角混合 / 中英空白 / 大小写 / 同日跨源同题合并 / 跨日同题不合并 / 空标题拒绝；NFKC 边界（①②③ vs 123）。
- **去重幂等**：同批重复条目 OR IGNORE；并发双源同稿（串行事务后到计 dup）；external_id 为 NULL 多条共存靠指纹；应插−实插 = dup 计数对账。
- **游标与补抓**：游标只随条目事务推进（模拟中途异常 → 重拉零重复）；ID/TIME/NONE 三型游标；gap > 3×interval 触发深翻；深翻触顶 backfill=truncated。
- **调度**：到期计算（interval/next_due/backoff 三者 max 语义）；退避序列 interval×2^n 封顶 60min、成功清零；inFlight 防重派；tick 超时不中断在飞轮；重启抖动重铺；停用/软删下一 tick 摘除。
- **源管理**：预置源 DELETE 403 / 通用源软删后条目仍可按 sourceId 查（stats 端点）而默认流排除；robots 禁抓 400；config 非法字段级提示；连通性测试不落库断言。
- **回归红线**：既有 7 Job 留痕/手动触发/热切换零变化；六源降级链与聚合契约字节级不变；1520 测试基线只增不减。
