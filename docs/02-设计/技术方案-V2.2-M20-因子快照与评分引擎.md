## ⚖️ 3. 形态决策（ADR-0058 六项主裁决）

### 3.1 快照形态 = 日频快照表，非最新态覆盖（裁决 1）

`subject_factor_snapshot` 以 (subject_id, snapshot_date) 为唯一键，每日追加、当日重跑覆盖同键。**否决「最新态覆盖单表」**：M21 榜单入出榜变动、M22 历史命中统计与「按当时权重复现」验收都要求历史序列；最新态覆盖会把复算审计的对照物抹掉。5221 行/日 × 180 天 ≈ 94 万行，SQLite 带索引无压力（§5 容量）。M21 榜单页读「最新快照日」，历史页读指定日期——读取契约在 M20 即定型。

### 3.2 行业传导绕行 subject_master.industry，用关联派生（裁决 2，本批最关键裁决）

行业传导因子的直觉做法 = 读标的所属行业 → 取该行业 H24 热度。**否决**，两层原因：

1. **当前不可用**：5221 只行业 100% NULL（核实项 2）。
2. **永远不可靠**：ADR-0030 口径下新浪降级轮会把东财行业覆盖为 null、东财回归再补回——`subject_master.industry` 是**随源轮换漂移的字段**，一旦入因子，同一历史日的重算结果取决于「重算那一刻标的主数据的行业值」，可复算幂等被结构性破坏。

**替代**：`IndustryAssociator`（领域纯函数）从两路原料派生「标的 ↔ 行业」关联集（窗口 W2，默认 30 天）：

- 路 A（事件回联）：`event_item` W2 窗内 `subjects` JSON 含该标的 → `affected_industries` 全部记为关联行业；
- 路 B（资讯归类回联）：`news_analysis` W2 窗内 `matched_subjects` 含该标的且 `main_category` ∈ 申万 31 → `main_category` 记为关联行业（`sub_industry` 记 0.5 权重次关联）。

关联带最近出现时间，衰减半衰期 = W2（30 天）——「标的与某行业的关联强度随时间自然消退」。关联集为空 → F2 = 0 + `data_flags` 记 `NO_ASSOC_INDUSTRY`（如实标注不隐藏）。该口径完全由库内数据决定，与外部源轮换解耦，幂等成立。

### 3.3 因子分 = 绝对饱和映射纯函数；百分位只做展示层（裁决 3）

每维 0~100 的归一化有两条路：**横截面百分位**（分数 = 当日全市场排名位）与**绝对饱和映射**（分数 = f(原始加权量)）。**选后者**，理由：①增量重评（M22）需要「只重算受影响标的」——百分位使任一标的的分数依赖全集合，局部重算必须全量重排，绝对映射天然局部；②可解释性：「50 分 ≈ 近 10 日 3 条加权重磅事件」可向用户陈述，排名位不可；③幂等定义更干净（单主体函数）。**百分位（全市场排名）在查询层对当日快照行临时计算**，满足详情区块「百分位可查」，不入库不进合成。行业热度的 31 行内排名归一是例外（§4.4.2：固定 31 个枚举行的小范围归一，不构成全市场耦合）。

### 3.4 权重模型 = runtime_config 单键 + 参数指纹入快照（裁决 4）

单键 `score.weight`（域前缀 `score.`），JSON 载荷含五维权重、衰减窗口、三标签阈值与 K 常数；`ValuationConfigValidator` 校验（非负、归一容差、窗口/阈值边界），非法 30087 拦截。快照行落 `weight_basis` 指纹串（如 `vs-v1:w=0.40|0.20|0.20|0.20|0.00;win=10|30;hl=5|30;k=3.0|1.5;bt=60|50|80`）——历史快照按当时参数可复现的审计锚。编辑面沿留痕窗口先例：**任务中心 FACTOR_SNAPSHOT 编辑 Dialog**（GET/PATCH `/value-scores/weights` + expectedUpdatedAt 并发防呆 30065），零新页面（保住 M21 全市场推荐页「第 20 页」序号叙事）。

### 3.5 条件因子去留（裁决 5，Spike-A 实测输入）

Spike-A 结论（§9.1 证据链）：**腾讯批量可行**——600 只/请求（URL ≤5.4KB）稳定、650+ 被拒；全轮 5221 = 9 请求 × 500ms 间隔 8.8s 零失败；PE@52/PB@46 与东财数值完全一致；东财 push2 单只端点至今仍空响应（封禁签名）但批量 ulist 端点可用。**裁决**：

1. **估值水平维（F5）纳入 v1**：横截面口径（当日全市场 PE→PB 回退链，低估值得高分，缺数中性 50），**默认权重 0.00**——计算、落库、详情分解全套交付，但不参与 v1 默认排序基线（不污染四维 Must 链与「有突破」标签），权重页面化可一键启用。时序分位待 `market_daily_snapshot` 序列积累 ≥250 交易日后 v1.x 升级（变更控制）。
2. **量价异动维不纳入**：单日换手/振幅横截面噪声大且无均量基线，v1 只随 F5 落原始值（换手/振幅/涨跌幅/量），v2 用均量比口径启用。
3. **行情拉取实现**：复用既有 `TencentQuoteClient.fetchQuotes`（50 只/块 → 105 请求 × 200ms 间隔 ≈ 40s，Spike-A 已证头部余量充足，暂不提块到 600）；push2 ulist 留 v2 备选（ADR-0058 裁决 5 注记）。

### 3.6 Spike-B 预检留档（裁决 6）

龙虎榜（`RPT_DAILYBILLBOARD_DETAILSNEW`）/ 增减持（`RPT_SHARE_HOLDER_INCREASE`）/ EPS 一致预期（`RPT_WEB_RESPREDICT`，含 EPS1~4/覆盖机构数/目标价/行业板块）三源实测可用；大宗交易 4 个候选报表名未命中（9501），需页面级抓包。结论留档 §9.2 供 v2 REQ，本期不接入。

## 🔧 4. 详细设计（到类级，可直接开发）

### 4.1 数据模型（V30 / U30，SQLite；惯例同 V23：小写下划线、三必备、NOT NULL+默认值、整秒 ISO-8601 UTC 文本、无物理 FK）

```sql
-- V30__create_valuation_snapshot_tables.sql
-- T170 · M20 因子快照两表（行情估值日快照 + 标的因子日快照）。
-- 来源：技术方案-V2.2-M20 §4.1 + ADR-0058 裁决 1/5。

-- 行情估值日快照（F5 原料 + v2 时序分位序列资产；腾讯批量一次落库）
CREATE TABLE market_daily_snapshot (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id    INTEGER NOT NULL,               -- subject_master.id
  snapshot_date TEXT    NOT NULL,               -- Asia/Shanghai yyyy-MM-dd（快照口径日）
  close_price   REAL,                           -- 现价 @3（收后即收盘）
  pct_change    REAL,                           -- 涨跌幅 % @32
  turnover_rate REAL,                           -- 换手 % @38
  amplitude     REAL,                           -- 振幅 % @43
  volume        REAL,                           -- 成交量（手）@6
  pe_ttm        REAL,                           -- PE-TTM @52（空或 ≤0 存 NULL = 缺数）
  pb            REAL,                           -- PB @46（≤0 存 NULL）
  source        TEXT    NOT NULL DEFAULT 'tencent',
  quote_time    TEXT,                           -- 源时间戳 @30（ freshness 对账）
  created_at    TEXT    NOT NULL,
  updated_at    TEXT    NOT NULL,
  UNIQUE(subject_id, snapshot_date)
);
CREATE INDEX idx_mds_date ON market_daily_snapshot(snapshot_date); -- v2 时序分位按日窗取数

-- 标的因子日快照（M20 核心◆：UNIQUE 当日重跑幂等覆盖；M21 粗筛/榜单、M22 统计的读源）
CREATE TABLE subject_factor_snapshot (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id    INTEGER NOT NULL,
  snapshot_date TEXT    NOT NULL,               -- 与 market_daily_snapshot 同口径日
  f_catalyst    REAL    NOT NULL DEFAULT 0,     -- F1 事件催化强度 [0,100]
  f_conduction  REAL    NOT NULL DEFAULT 0,     -- F2 行业热度传导 [0,100]
  f_fundamental REAL    NOT NULL DEFAULT 50,    -- F3 基本面边际 [0,100]，50=中性
  f_risk        REAL    NOT NULL DEFAULT 100,   -- F4 风险安全分 [0,100]，100=无风险
  f_valuation   REAL    NOT NULL DEFAULT 50,    -- F5 估值水平 [0,100]，50=中性/缺数
  total_score   REAL    NOT NULL DEFAULT 0,     -- Σ w_i×F_i / Σw_i
  breakthrough  TINYINT NOT NULL DEFAULT 0,     -- 「有突破」标签（三阈值判定）
  factor_detail TEXT    NOT NULL,               -- JSON 四+一维明细（§4.5 契约；依据事件 id 可下钻 trace-v1）
  data_flags    TEXT    NOT NULL DEFAULT '[]',  -- JSON 例外口径标注（NO_MARKET_DATA/NO_ASSOC_INDUSTRY/NO_VALUATION_DATA/ST_RISK...）
  weight_basis  TEXT    NOT NULL,               -- 参数指纹串（复算审计锚，§3.4 例）
  computed_at   TEXT    NOT NULL,               -- 本行计算时刻（非输入时刻；幂等以输入为准）
  created_at    TEXT    NOT NULL,
  updated_at    TEXT    NOT NULL,
  UNIQUE(subject_id, snapshot_date)
);
CREATE INDEX idx_sfs_date_score ON subject_factor_snapshot(snapshot_date, total_score DESC); -- 排名/百分位/M21 粗筛
```

| MARKET_DAILY_SNAPSHOT | market_daily_snapshot | marketDailySnapshotDays | 365 | 90（时序分位序列资产，窗更长） |

### 4.2 因子公式（领域纯函数，冻结值进配置缺省）

统一记号：`E(s, W)` = 窗口 W 内 `event_item.subjects` JSON 含标的 s 的事件集（code 精确匹配）；`ageDays(e) = snapshot_date − event_date`（日历日，floor）；衰减 `decay(e) = 0.5^(ageDays/hl)`；hl = 5 天（catalyst/fundamental/risk 共用）。**所有窗口锚定 snapshot_date 而非当前时刻**——幂等基石。

**F1 事件催化强度（主维）**

```
raw1 = Σ_{e∈E(s,W1), imp∈{HIGH,MEDIUM}} impCoef(e) × dirCoef(e) × typeCoef1(e) × decay(e)
  impCoef:  HIGH=1.0  MEDIUM=0.5                    （对齐 heat-v1 impCoef）
  dirCoef:  BULLISH=1.0  NEUTRAL=0.3  BEARISH=0.0   （利空不进催化维，归 F4）
  typeCoef1: EARNINGS_FORECAST/MAJOR_CONTRACT=1.0  BUYBACK_CHANGE/TECH_BREAKTHROUGH=0.9
             MA_MERGER=0.8  POLICY_RELEASE=0.6  EXEC_CHANGE=0.4  REGULATORY_PENALTY=0.3  OTHER=0.5
F1 = 100 × raw1 / (raw1 + K1s)，K1s=3.0（≈3 条衰减后 MEDIUM 利好 → 50 分）
```

**F2 行业热度传导**

```
assoc(s) = IndustryAssociator 派生（§3.2 路 A+路 B，窗口 W2=30 天），元素 {industry, lastSeenAge, weight(次关联 0.5)}
heatNorm(i) = (31 − rank_H24(i)) / 30     rank_H24 = 31 行申万 H24 heat_score 降序名次，并列按行业名升序（确定性破并列）
raw2 = max_{i∈assoc(s)} weight(i) × heatNorm(i) × 0.5^(lastSeenAge / W2)
F2 = 100 × raw2                            （raw2 已落 [0,1]，无需再压）
```

**F3 基本面边际（事件近似口径，带符号）**

```
raw3 = Σ_{e∈E(s,W1), type∈基本面类} sign3(e) × typeCoef3(e) × impCoef(e) × decay(e)
  sign3: BULLISH=+1  NEUTRAL=+0.2  BEARISH=−1
  typeCoef3: EARNINGS_FORECAST=1.0  BUYBACK_CHANGE=0.8  MAJOR_CONTRACT=0.7  MA_MERGER=0.5  TECH_BREAKTHROUGH=0.4
F3 = 50 + 50 × tanh(raw3 / K3)，K3=1.5     （无信号=50 中性；±1.5 加权单位 → 88/12 分）
```

注：业绩类事件同时计入 F1 与 F3 是**设计内重叠**（蓝图裁决 1：F1 度量「关注度动量」、F3 度量「基本面方向」）。

**F4 风险安全分**

```
eventPenalty = Σ_{e∈E(s,W1), dir=BEARISH} riskTypeCoef(e) × impCoef(e) × 10 × decay(e)
  riskTypeCoef: REGULATORY_PENALTY=1.5  EARNINGS_FORECAST=1.2  BUYBACK_CHANGE=0.8  EXEC_CHANGE=0.5  其余=0.6
stPenalty = 名称含 "ST"（含 *ST，实测 201 只）？ 40 : 0        —— 事件上限 60 + ST 40 → 下限 0
F4 = clamp(100 − stPenalty − min(60, eventPenalty), 0, 100)
```

**F5 估值水平（条件因子，默认权重 0）**

```
pePct = 当日全市场 pe_ttm>0 标的中的升序百分位（低 PE → 低 pct）；pbPct 同理（pb>0）
basisPct = pePct（有 PE）→ 否则 pbPct（有 PB）→ 否则缺数：F5=50 + data_flags记 NO_VALUATION_DATA
F5 = 100 × (1 − basisPct)                  （低估值得高分；横截面口径，时序分位留 v1.x）
```

**总分与标签**

```
total = Σ_{i=1..5} w_i × F_i / Σ w_i       （除以权和，配置未归一时自动归一；归一后权重记入 basis）
w 缺省 = (0.40, 0.20, 0.20, 0.20, 0.00)
breakthrough = (F1 ≥ 60) ∧ (F2 ≥ 50) ∧ (F4 ≥ 80)   —— 三阈值可配（btCatalystMin/btConductionMin/btRiskMin）
```

**百分位（查询层，不入库）**：同 snapshot_date 行按 total_score 降序，`rank = 严格大于本分的行数 + 1`（并列同名次），`percentile = round(100 × (N − rank) / max(1, N − 1))`。

### 4.3 配置键（`score.weight`，ADR-0017 三件套接入）

```json
{
  "wCatalyst": 0.40, "wConduction": 0.20, "wFundamental": 0.20, "wRisk": 0.20, "wValuation": 0.00,
  "catalystWindowDays": 10, "assocWindowDays": 30, "halfLifeDays": 5.0,
  "k1Saturation": 3.0, "k3Saturation": 1.5,
  "btCatalystMin": 60, "btConductionMin": 50, "btRiskMin": 80,
  "basis": "vs-v1:w=0.40|0.20|0.20|0.20|0.00;win=10|30;hl=5.0;k=3.0|1.5;bt=60|50|80"

```

校验器 `ValuationConfigValidator`（沿 PipelineBudgetConfigValidator 模式）：五权重 ∈ [0,1] 且 Σ>0；窗口 5~30 / 10~60 天；hl 1~15；K 0.5~10；阈值 0~100——非法字段级报错 30087、原值保留。basis 串由参数派生（代码拼装，非用户输入），快照行直接落该串。热生效：保存 → 快照替换 → 下一轮 FACTOR_SNAPSHOT 按新参数（ADR-0017 语义）。

### 4.4 可复算幂等口径（验收语义的技术兑现）

- **纯函数边界**：五个因子计算器 + Composer 均为 `domain.valuation` 静态纯函数，输入 = 五投影（事件窗内行、31 行 H24 热度、关联派生中间表、行情日快照、标的名录）+ 参数，无时钟读取、无随机、无外部调用。
- **输入冻结**：窗口与衰减锚定 snapshot_date；行业热度取「计算时点 H24 快照」——热度 30min 滚动属**输入变化**，同日不同时刻重跑允许 F2 漂移（`factor_detail.conduction` 落了所用 heat 值供对账）；「零漂移」验收口径 = 五输入不变 + 参数不变 → 输出不变。
- **写入幂等**：UNIQUE(subject_id, snapshot_date) UPSERT（方案库 03 裁剪），重跑覆盖同键无重复行。
- **M22 兼容**：增量重评 = 对受影响标的以同一 snapshot_date 重算同键覆盖——绝对映射（裁决 3）保证其他标的分数不因局部重算变动，防抖语义天然成立。

### 4.6 Job 组织（`FactorSnapshotJob`，第 16 个收编任务）

- jobKey `FACTOR_SNAPSHOT`；ScheduleType **CRON** 缺省 `0 30 17 * * ?`（盘后 17:30，沿本机时区惯例对齐 SUBJECT_SYNC 06:00/日报 08:00；需求红线「次日 08:00 前完成」余量充足）；`job.FACTOR_SNAPSHOT` 键（enabled/cron 热改）；测试 profile 种子 enabled=false（15 Job 惯例）。
- 执行流（`FactorSnapshotService.snapshotAll()`）：
  1. **阶段 0 行情拉取**：`MarketDataSnapshotService.refresh(snapshot_date)` —— 取 A_SHARE status=1 全量内部码 → `TencentQuoteClient.fetchQuotes`（50/块 × 200ms 间隔 ≈ 105 请求 40s）→ 解析 @3/@32/@38/@43/@6/@52/@46/@30 → UPSERT `market_daily_snapshot`。**整段失败不中止**：WARN 留痕 + 后续因子照算（F5 缺数中性 + `NO_MARKET_DATA` 标注）——行情是条件因子原料，不配阻塞四维 Must 链。
  2. **阶段 1 输入投影**：一次性读 W2 窗事件行（含 subjects/affected_industries）、W2 窗 news_analysis 回联行、62 行热度快照、标的名录（id/code/name/status）、当日行情快照——全部载入内存（§5 容量实测）。
  3. **阶段 2 逐标的计算**：IndustryAssociator 派生关联 → 五因子 → Composer 合成 + breakthrough → 明细 JSON。
  4. **阶段 3 落库**：批 UPSERT 快照行（500 行/批事务），JobRunStats 上报 processedCount + detail（覆盖率/均值/异常计数）。
- 弹性：仅阶段 0 有外部调用，沿用 client 既有 ResilienceSpec（超时/重试 1）；Job 整轮异常不上抛（轮询型惯例）。

## 🛡️ 5. 非功能设计（逐项过）

- **性能**：全轮预算 = 行情拉取 ~40s + 输入投影（W2 窗事件/回联行数千行级）+ 5221 × 五纯函数（μs 级/只）+ 批 UPSERT ~5s ≈ **<2min**（17:30 起，08:00 红线余量 12h+）。读路径：单行 UNIQUE 查询 + 排名 COUNT（idx_sfs_date_score 覆盖）毫秒级；详情页 P95 不劣于既有分区基线。
- **容量**：subject_factor_snapshot 5221 行/日 × 180d ≈ 94 万行（明细 JSON 均值 ~600B，事件稀疏大多数行轻）≈ 150MB 峰值；market_daily_snapshot 5221 × 365d ≈ 190 万行 ≈ 200MB——单机 SQLite 个人自用可接受；留痕清理按窗口滚动（M10）。
- **安全**：三端点 JWT 既有鉴权；无敏感数据（评分/行情公开数据）；PATCH 带 expectedUpdatedAt 防并发误覆盖；无越权面（单用户）。
- **可观测**：job_execution_log 留痕（processedCount/detail 含覆盖率与 flagCounts）；行情拉取段失败 WARN + data_source_event 心跳不涉（沿用既有 Quote 心跳，不重复记）；coverage 端点即质量看板（验收常驻）。
- **降级预案**：腾讯整段失败 → 四维照算 + F5 中性 + NO_MARKET_DATA（不阻塞）；热度快照缺行 → heatNorm 按缺行行业记 0 分；事件窗空 → F1/F3 中性或 0 + flags。**引擎不因任何单一输入缺失而中止**（对齐「护栏 FUSED 也不停」先例）。
- **合规**：区块级免责一行常驻（§4.8）；评分全量为「信息整理」口径，无买卖指令/收益承诺输出。
