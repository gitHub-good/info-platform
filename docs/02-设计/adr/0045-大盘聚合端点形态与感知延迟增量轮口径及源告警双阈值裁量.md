# ADR-0045：大盘聚合端点形态与感知延迟增量轮简化口径及源告警双阈值裁量

- 状态：已接受（2026-09-22，V2.0-M14 T114/T115/T116 实现裁量留档）
- 日期：2026-09-22
- 决策人：开发工程师（依据[REQ-20260925-11](/docs/01-需求/REQ-20260925-11-M14-批次一源接入与抓取大盘.md) T114「大盘 API 形态归架构、任务书授权新建 /feed-dashboard 端点裁量」、风险表「感知延迟增量轮判定实现可退排除每源首日简化口径（版本化同步，不静默）」与 T115「告警节流窗长归架构/任务书双阈值语义」）
- 关联：ADR-0038（info_source 注册表）、ADR-0039（news_item 去重）、ADR-0040（SOURCE_POLL 调度与退避）、ADR-0042/0043/0044（实测裁量先例）、[REQ-20260925-11](/docs/01-需求/REQ-20260925-11-M14-批次一源接入与抓取大盘.md) 拍板二/拍板三与故事 2/3

## 📌 背景

T114~T116（大盘聚合 API / 源异常告警 / 大盘前端页）在 REQ 冻结语义下有四处实现口径需裁量：

1. **端点形态**：M13 已有 `GET /info-sources/stats?days=`（rollup + 全量口径感知延迟），任务书授权「在其上聚合升级或新建 /feed-dashboard 端点」。
2. **增量轮判定**：REQ 拍板三-1 要求感知延迟「仅增量轮、排除首轮回灌」，判定实现归实现侧；风险表预授权「排除每源首日」简化口径（须版本化注明，不静默）。
3. **日粒度源**：ndrc/csrc/stats/em_macro 四源 published_at 仅日期/序列粒度（ADR-0044 墙钟口径），感知延迟失真，任务书授权「统计时排除或标注」。
4. **告警双阈值语义**：REQ 故事 3「连续 5 轮或 30 分钟，取先到」——「30 分钟」的载体（失败持续时长 vs 退避窗时长）无既有字段可直接支撑前者。

## 🎯 决策

- **新建 `GET /api/v1/feed-dashboard` 端点**（三区块一端点：global/sources/failures），不动既有 `/info-sources/stats`：大盘是只读运维聚合视图，与源管理数据面（配置+统计混排）受众不同；对账验收锁「今日入库」数字同源（同 source_daily_stats 当日行，global = sources 分行之和由构造保证），两端的感知延迟口径不同属预期（stats 保留 M13 全量口径，大盘走增量轮新口径并版本化）。
- **增量轮口径 v1 = 排除每源首日 + 排除日粒度源**，版本串随响应下发（`latency.basis = "incremental-only-v1:exclude-first-day+daily-sources"`）：
  - 首日判定 = `MIN(news_item.created_at)` 按源分组折算 Asia/Shanghai 日，与当日同源即回灌排除。**语义边界**：新源上线当日全部样本（含当日稍后的增量轮）被排除，P50 首日出 null——「回灌不抬 P50」成立（REQ 场景 6 的结果语义），但「当日增量主导」的严格形态自次日达成；news_item 无轮次/回灌标记列，加列属数据模型变更（须回架构），v1 以简化口径先行。
  - 日粒度源排除清单硬编码于 `FeedDashboardService.DAILY_GRANULARITY_CODES`（ndrc_policy/csrc_news/stats_release/em_macro_indicators），随响应 `excludedSourceCodes` 标注；新增日粒度源须登记该常量。
- **源异常告警双阈值 = 连续失败 ≥5 轮或本轮退避窗 ≥30 分钟（取先到）**：退避窗读法取任务书原文「退避 ≥30 分钟」——退避窗由 `interval×2^min(n,4)` 指数扩张，快源（2~5min）由轮数阈值先触达、慢源（30~60min 官方/宏观）首轮失败退避即 ≥60min 由时间阈值先触达（「30 分钟无产出」运营语义）；两阈值均可配（`feed.alert.failure-threshold` / `feed.alert.backoff-threshold-minutes`）。
- **告警节流与恢复**：告警态登记在内存（`ConcurrentHashMap` 占位，恢复前同源不重复；恢复成功发一条 SOURCE_RECOVERED 并重新武装）。**重启语义**：进程重启丢告警态，仍失败的源下一轮会再告警一次——个人单用户平台可容忍的一次性重复，不为此引入持久化表（数据模型变更归架构）。
- **通知类型扩展**：`PushType` 增 `SOURCE_ALERT(6,"source_alert")` / `SOURCE_RECOVERED(7,"source_recovered")`——V6 push_record DDL 的 TINYINT 无 CHECK 约束（仅注释），扩码无需迁移；前端通知面板事件名单与类型徽章同步两行。
- **大盘失败列表跳转定位**：跳 `#/info-sources?source={code}`，源管理页读参数一次性消费（滚动定位 + 5 秒高亮，归档目标自动展开归档区）——既有页零行为变更，仅增跳转锚。

## ⚝ 实现附注（工程事实留档）

- **RowCallbackHandler 契约坑**：`JdbcTemplate.query(sql, rch)` 每行回调一次且游标已定位，回调内再写 `while(rs.next())` 会吞首行（大盘分源计数/首日查询初版实测丢首组，修前红→改 `ResultSetExtractor` 显式迭代→修后绿）。两处聚合查询以强转 `ResultSetExtractor` 消除重载歧义。
- 分位数计算从 SourceRegistryService 抽 `LatencyPercentiles` 公用（stats 端点与大盘同最近邻秩实现，防两处漂移）。

## ⚖️ 被否方案与理由

- **stats 端点升级承载大盘**：数据面（rollup 明细 + 配置态）与大盘（全局卡 + 异常置顶 + 失败列表）字段几乎不相交，混排会双双破坏既有契约（30071~30075 消费方为源管理页）。
- **news_item 加轮次/回灌标记列实现精确增量轮**：数据模型变更（红线归架构回 ADR），且首日落库量级（≤数百条/源）下简化口径偏差有限；v1 版本串保留升级锚。
- **失败持续时长阈值（读 lastSuccessAt 差值）**：新源无成功基线时语义未定（createdAt 起算会把停用后重启的首败误判为长时失败）；退避窗是既有确定性字段（退避公式纯函数有单测）。
- **告警态持久化**：防重启重复告警需新表或扩 source_poll_state 列，代价超过个人平台的一次性重复收益。

## 🔁 后果

- 大盘感知延迟 P50/P90 在源上线首日无值（口径标注明示），次日建立基线；北极星达标判定（P50 ≤5min）在 V2.0 收口时按此口径评估。
- 30~60min 低频源单次瞬时失败即触发告警（退避窗读法的代价）：属「该源将静默 ≥30min」的有效运营信号，节流保证不刷屏；如运营反馈过噪，调 `feed.alert.backoff-threshold-minutes` 即可（无需发版口径变更）。
- `/info-sources/stats` 感知延迟仍为 M13 全量口径（含回灌偏差）——与大盘数字不一致属**口径差异非对账项**，对账验收只锁今日入库；若后续要统一，走架构 ADR 把 stats 切换增量轮口径。
- 前端通知面板对 source_alert/source_recovered 渲染通用徽章文案（源异常/源恢复），无标的跳转（subjectId 恒 null）。
