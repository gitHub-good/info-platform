# ADR-0050 · M15 T127 实现裁量对齐（任务文本与方案原文的出入，方案为准）

- 状态：已接受（2026-09-22）
- 关联：ADR-0048（任务文本出入以方案为准的先例）/ ADR-0049（同款流程）/ [技术方案-V2.0-M15](../技术方案-V2.0-M15-AI归类与分析管道.md) §4.8/§4.10
- 需求：REQ-20260926-12（任务派发单 T127：`GET /api/v1/events` 端点 + 事件流页）

## 背景

T127（事件流端点 + 前端第 17 页）任务派发文本与 M15 技术方案（权威）存在一处契约字段名出入与一处参数错误码授权裁量。
按「不改契约先回架构留痕」的协作规则（ADR-0048/0049 同款流程），本 ADR 逐条记录——**涉及契约的全部以方案原文为准落地**。

## 裁决

### 1. 事件卡片主键字段名：`id`（方案冻结），任务文本的 `eventId` 不落地

- 任务文本：卡片字段 `eventId/newsId/newsTitle/...`。
- 方案 §4.8 `/api/v1/events` 行：卡片 `{id, eventType, summary, industries, direction, importance,
  figures, subjects, quote, newsId, newsTitle, newsUrl, eventTime}`——冻结契约。
- **落法**：按方案落 `id`（`EventStreamView.EventCardView.id`）。行业热度下钻视图（T123
  `IndustryHeatItemsView.ItemView.eventId`）是另一端点的自有字段，互不冲突；前端 T127 消费 `id`。
- 理由：§4.8 已冻结且 T126 同族页面先例均按方案先行；同义双字段名 = 契约面翻倍无收益。

### 2. limit 越界错误码：30079 单码承载（授权裁量）

- 任务文本：`limit 缺省 20 ≤50 越界 400；筛选参数非法值 30079 字段级`——未明示 limit 越界用哪个业务码。
- 方案 §4.8：`/api/v1/events` 仅标注「筛选枚举非法 30079」；30076 已由 ADR-0048 裁量 2 分配给 heat 域查询参数。
- **落法**：`/api/v1/events` 全部参数错误（type/industry/importance/direction 非法枚举 + limit 1~50 越界）统一
  30079 `EVENT_FILTER_INVALID`（http 400，msg 字段级；越界拒绝不截断——M9 口径）。单端点单参数错误码族，语义完整。
- 理由：limit 亦是本端点筛选参数族成员；复用 30076 会跨 heat/events 两域混用同一「管道查询参数非法」码。

### 3. 表结构核实注记：newsTitle/newsUrl 不在 event_item（任务文本「从 event_item 取」的勘正）

- 任务文本：`subjects/figures/quote/newsUrl/newsTitle 从 event_item 取——核实表结构字段名`。
- 核实结论（V23 DDL）：`event_item` 无标题/链接列；`news_item.title` / `news_item.url` 为权威来源
  （§4.1 表定义）。响应字段名不变（newsTitle/newsUrl），取数走 `JOIN news_item`——与行业下钻 events 清单同款。
- subjects/figures/quote/industries 确为 event_item 自有列（JSON 文本列，直查解析）。

## 后果

- 前端 T127 与任何后续消费方拿到的 `/api/v1/events` 卡片线格式自首个提交起即与方案 §4.8 一致。
- 任务文本的 `eventId` 不落地；如后续确需双字段兼容，走新 ADR 变更。
- `JwtAuthFilter` 白名单未动——`/api/v1/events` 自动落入 Bearer 保护面（回归用例 `eventsPath_requiresToken_t127`）。
