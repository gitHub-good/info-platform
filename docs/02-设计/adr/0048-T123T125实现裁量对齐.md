# ADR-0048 · M15 T123/T125 实现裁量对齐（任务文本与方案原文的四处出入，方案为准）

- 状态：已接受（2026-09-22）
- 关联：ADR-0046（M15 六裁决）/ [技术方案-V2.0-M15](../技术方案-V2.0-M15-AI归类与分析管道.md) §3.4/§4.4/§4.8
- 需求：REQ-20260926-12（任务派发单 T123/T125）

## 背景

T123/T125 任务派发文本与 M15 技术方案（权威）存在四处表述出入。按「不改契约先回架构留痕」的协作规则，本 ADR
逐条记录裁量与依据——**全部以方案原文为准落地**，不改任何已冻结契约。

## 裁决

### 1. 21 财经 AI 排除：`info_source.config` 字段，不加列（零 DDL）

- 任务文本：`info_source 加 ai_excluded 列（V25/U25，若 T122 未加）`。
- 方案 §3.4/§4.4/§4.8：`info_source.config` 增 `aiExclusion ∈ {NONE,L2,ALL}` 字段，PATCH 既有端点扩 config
  字段 + 回显。
- **落法**：按方案走 config 字段（`AiExclusion` 枚举 + Codec/Payload/View 三层承载，NONE 不落键——存量 JSON 字节级
  不变）。**T122 未加任何承载（核实结论），本批不消耗迁移号**，V25 留给 T124 模板播种。
- 理由：方案明确「加列或 config」二选一时已拍 config；档位是三值枚举而非布尔，加布尔列反而压缩语义；零 DDL 回归面最小。

### 2. 错误码分配：30076 单码承载「未知窗口/未知行业/未知 type」，30077 不占用

- 任务文本：`错误码 30076~30077（未知窗口/未知行业）`。
- 方案 §4.8：新错误码 `30076 PIPELINE_CONFIG_INVALID(400)` / `30077 INDUSTRY_REPORT_ALREADY_SUCCESS(409)` /
  `30078 INDUSTRY_REPORT_NOT_FOUND(404)` / `30079 EVENT_FILTER_INVALID(400)`；industry-heat 两端点错误栏只写
  `400` 未指名码。
- **落法**：heat 域查询参数非法（window/type/行业名非申万枚举/limit 越界）统一 30076；**30077 保留给 T124
  日报已成功重试 409**，本批不占用。
- 理由：30077 已被方案冻结为日报语义，抢先占用会让 T124 无码可用或被迫改契约；30076 语义（管道参数非法）覆盖
  heat 查询面成立。

### 3. 下钻分页：beforeId 游标（M9/M12 基线），不引入页码双模式

- 任务文本：`下钻分页复用 M9 PageQuery`。
- 方案 §4.8：`beforeId 游标 + limit（缺省 20 ≤50）`；§5「热度榜/事件流读端点走索引 + 游标分页（M9/M12 基线）」。
- **落法**：游标分页直落（limit 1~50 越界拒绝不截断——沿用 M9 的边界口径，仅校验规则同源，不引入 page 模式）。
- 理由：方案对端点形态已冻结为游标；PageQuery 的页码双模式是列表页交互契约，塞进下钻属范围蔓延。

### 4. 提交顺序：T125 先于 T123 落库

- 方案 §4.8 榜单契约含 `pipeline:{level}`（护栏徽章三处同源），依赖 T125 的 PipelineGuardService。
- **落法**：T125（护栏）先提交（d1aabc0），T123（热度）后提交——避免在 T123 中引入「常返 NORMAL 的占位供应商」
  再于下一提交删除的死代码。
- 理由：两任务同批交付、无部署间隔；换序零占位零返工。

## 后果

- T124 拿到完整可用的 V25 迁移号与 30077/30078 错误码；T126/T127 拿到的 industry-heat 契约与 pipeline/status
  完整形态自首个提交起即与方案一致。
