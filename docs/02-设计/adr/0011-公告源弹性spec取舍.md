# ADR-0011：公告源弹性 spec 取舍（noRetry 2s 而非 1s 重试 1）

- 状态：已接受（2026-09-21，T05）
- 日期：2026-09-21
- 决策人：开发工程师（依 ADR-0010 + 技术方案 §4.3 流程 1 + Spike-1 §6.4/§9）
- 补充：ADR-0010（数据源弹性实现选型）、技术方案 §4.3 流程 1（公告超时 2s 重试 1）、Spike-1 §6.4 调整项

## 📌 背景

技术方案 §4.3 流程 1 原写公告源「超时 2s、重试 1（幂等只读）」。Spike-1 §6.4 与 §9 调整项指出：该配置与 2s 页预算冲突——单次 1s + 退避 200ms + 重试 1s ≈ 最坏 2.2s，超 2s 预算；若取单次 2s + 重试，最坏 ~4s+。架构师在技术方案 §8 风险与 Spike-1 §9 均要求开发在 T05 确认 `ResilienceRunner` 是否区分「超时」与「连接失败」后定 spec。

约束：

- 详情页是热路径，首屏 ≤2s（技术方案 §5 性能目标）；各 adapter 超时级联收敛，单源最坏耗时 ≤2s。
- 公告分区属「有则展示、无则 missing 不阻断」的非阻断分区，降级为 MISSING 不影响其他分区。
- 重试只对幂等只读操作（公告列表幂等）。

## 🎯 决策

公告源 `AnnounceSourceAdapter` 取 `ResilienceSpec.noRetry(Duration.ofSeconds(2))`：超时 2s、重试 0。

确认依据（T05 实测 `ResilienceRunner` 源码）：`ResilienceRunner.run` 对 `TimeoutException`（超时）与 `ExecutionException`（连接失败/业务异常）<b>均进入重试分支，不区分两者</b>。故「1s 重试 1 + 200ms 退避」最坏 ≈ 2.2s 超 2s 预算；「2s 重试 1」最坏 ≈ 4s+ 远超。`noRetry(2s)` 最坏恰 2s，与 §4.3 级联收敛一致，由聚合层 `orTimeout` 兜底。

## ⚖️ 候选方案对比

| 方案 | 最坏耗时 | 重试收益 | 是否超 2s 预算 | 结论 |
| --- | --- | --- | --- | --- |
| `noRetry(2s)` | 2s | 无 | 否（恰等于，靠聚合层兜底） | ✅ 采用 |
| `of(1s, 1, 200ms)` | ≈2.2s | 连接失败可重试 1 次 | 是（超 2s） | ❌ 否决，超预算 |
| `of(2s, 1, 200ms)` | ≈4s+ | 同上 | 是（远超） | ❌ 否决 |
| `noRetry(1s)` | 1s | 无 | 否 | 备选——牺牲超时窗口，公告抓取偶发慢时降级率偏高 |

## 💡 理由

公告为幂等只读列表，重试对瞬时连接失败有一定收益，但 `ResilienceRunner` 不区分失败类型导致重试必叠加超时窗口，任一带重试方案均突破 2s 页预算。详情页是热路径（首屏 ≤2s），公告分区属非阻断分区，降级为 MISSING 不影响其他分区。故以预算收敛优先于重试收益，取 `noRetry(2s)`；公告源挂由 `onDegraded` 默认 MISSING 兜底，不阻断详情页。对齐 Spike-1 §9 调整项「采用 `noRetry(2s)`」分支与 ADR-0010「重试只在最外层做一次、不在各源叠加」。

对照选型五维度：成熟度（JDK Future 同级）、社区（无）、学习成本（团队熟悉）、可替换性（spec 配置化，后续切重试仅改声明）、运维成本（零）。

## ⚠️ 影响

- 正面影响：公告源最坏耗时确定 ≤2s，不拖垮详情页首屏；spec 与行情(1.5s)/财务估值(2s) 一致采用 `noRetry`，弹性 spec 风格统一。
- 负面影响 / 代价：瞬时连接失败不重试，公告偶发抓取失败降级为 MISSING（用户可刷新或等缓存 TTL 10min 后重试）。
- 需要跟进的事项：若后续 `ResilienceRunner` 增强为「仅连接失败重试、超时不重试」（区分两者），可重新评估 `of(1s, 1, 200ms)` 以兼顾重试与预算；此时新增 ADR-0012 标记替代关系。

## 🔍 后续验证方式

- T05 上线后观察公告源超时降级率（`data_source_event`，T16 落地后）；若降级频繁且多由瞬时连接失败引起，推动 `ResilienceRunner` 区分失败类型后切重试方案。
- 缓存 TTL 10min（对齐 ADR-0005）兜底降重复 QPS。
