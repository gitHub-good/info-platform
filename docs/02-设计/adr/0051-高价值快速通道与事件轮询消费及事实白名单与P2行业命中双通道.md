# ADR-0051 · 高价值快速通道与事件轮询消费及事实白名单与 P2 行业命中双通道

- 编号：ADR-0051
- 状态：已决

- 需求：[REQ-20260926-13 M16 动态主动推荐](/docs/01-需求/REQ-20260926-13-M16-动态主动推荐.md)（PM 交接四项待设计 + 标的行业 NULL 硬阻塞）
- 方案：[技术方案-V2.0-M16-动态主动推荐.md](/docs/02-设计/技术方案-V2.0-M16-动态主动推荐.md) §3
- 方案库引用：08 定时任务（裁剪）、03 幂等（采用）、07 弹性四件套（裁剪：模板兜底替代重试）

## 背景

M16 推荐链路有四个 PM 交接给架构的机制决策，外加一个设计前代码核实发现的**硬阻塞**：

1. **高价值条目管道优先语义**（口径 B「入库→事件落库 ≤8min」依赖）：当前 L1/L2 随 NEWS_PIPELINE 10min 批窗口，无插队机制。
2. **事件消费机制**（口径 A「消费触发 ≤2min」依赖）：挂钩（L2 落库后进程内事件→关联服务）vs 轮询（新 Job 扫未消费事件）。
3. **卡片输出事实白名单校验机制**（零新增事实红线的落地）：LLM 仅语言组织，输出如何保证不夹带新事实。
4. **通知事件类型/scene/载荷契约**：PushType 编号、铃铛载荷、卡片 LLM 成本归因。
5. **硬阻塞**：REQ 拍板二 P2 行业命中 = `affected_industries ∩（自选标的所属行业 ∪ 订阅主题映射行业）`，但 dev 库实测 `subject_master` 5226 行中 **5221 只 A 股 industry 全 NULL**（东财主链未跑、新浪备选链无行业，ADR-0030）——「自选标的所属行业」通道在当前数据下完全空转；且 subscription 无行业订阅类型（sub_type 仅 TOPIC/SUBJECT/EVENT_TYPE/POLICY_THEME），「订阅主题映射行业」所需映射目录不存在。

## 决策（四主裁决 + 基建扩位）

### 裁决 1 · 高价值优先语义 = 独立快速通道 Job `PIPELINE_EXPRESS`

新增 ManagedJob（FIXED_DELAY 2min 可配 1~5min，池 12→14）：每 tick 取「入库 ≥30s 未建 analysis 行」的 news_item，noise 快判后经 `ImportanceScorer` **纯规则**预筛分 ≥4.0（≈源权重 2.0 + 一个强触发词 2.0，可配）的条目立即 L0 建行（含 BUG-03 序列豁免）→ L1（复用 ClassificationService 批 ≤10）→ L2（复用 EventExtractionService 当日配额内重扫）；低分条目不动等常规批。**既有 NEWS_PIPELINE 零改动**。时延 30s+2min+~1min ≈ 入库→事件落库 ≤4.5min（8min 预算的 56%）；成本 express 批 1~3 次/日 ≈ ¥0.02/日内。

**被否**：①单 Job 双档窗口（NEWS_PIPELINE 提频 + 模式交替）——改已验收稳态链路行为，零回归红线不可触碰，且优先语义藏进既有 Job 验收与故障隔离语义混浊；②全量提速批窗 2min——5 倍调用频次改变成本护栏水位与 M15 稳态口径，全量承担代价；③挂入库同步触发——摄取事务被 LLM 拖累，ADR-0046 裁决 4「不挂入库同步」同款反对理由。

**并发幂等**：双 Job 同刻拾取同一 news_id 靠 `UNIQUE(news_id)` INSERT OR IGNORE + L1/L2 条件 UPDATE + SQLite 单写者串行化，双跑结果幂等。已知边界：express 先建行条目的真同稿主条时间戳可能取后发布者（内容一致，损失仅时间戳），如实标注不修复。

### 裁决 2 · 事件消费 = 短轮询 Job `RECOMMENDATION_FEED`（60s），不用进程内挂钩

新增 ManagedJob（FIXED_DELAY 60s 可配 30s~5min）：`event_item LEFT JOIN recommendation_card (user_id, event_id)` 扫未消费事件（20s 落库缓冲防 L2 事务竞态 + 24h 上界对齐补跑窗口），重启丢事件天然免疫。

**被否**：进程内事件挂钩——①重启/异步线程池拒绝存在丢失窗口，需要补偿扫描兜底 = 双机制并存；②同事务拖慢管道 tick（违背「卡片生成不阻塞管道」非功能）、事务外发则回到丢失窗口；③异步监听留痕弱无 Job 面（任务中心手动触发是验收工具）。秒级消费优势在 5min 预算下无意义，复杂度代价实打实。

### 裁决 3 · 事实白名单 = 四类白名单集合比对校验器 `FactWhitelistValidator`

LLM 输出的 logicChain 文本逐项比对：①标的名（全池扫描，池内名 ∉ 允许集[卡片标的区 ∪ event.subjects] 即拒）②行业（申万 31 名 + 别名目录词 ∉ 允许集[event.affected_industries ∪ 用户行业关注命中集] 即拒）③数字（正则抽取文本数字串 ∉ 结构化数字集[key_figures + quote/title/summary 数字] 即拒）④方向词（词表命中方向 ≠ event.direction 即拒；NEUTRAL 卡见强方向词即拒）⑤长度 >120 字拒。任一违规 → 同步切模板拼接（不重试 LLM，时效优先），gen_method 留痕。

**被否**：①LLM 输出结构化字段前端拼装（LLM 退化为字段填充，语言组织价值归零，违背 REQ 拍板三 LLM 职责定位）；②只靠提示词约束（幻觉防线不能建立在提示词自觉上）；③校验失败重试 LLM（+30s 时延预算吃紧且同因失败率高，模板兜底沿 M1「规则兜底」先例）。

### 裁决 4 · P2 行业命中 = 行业关注集双通道（解硬阻塞）

P2 判定改为 `event.affected_industries ∩ 用户行业关注集 ≠ ∅`，关注集 = 双通道并集：

- **通道 A（订阅主题映射，v1 主力，当前数据即可用）**：活跃 TOPIC/POLICY_THEME 订阅 subKey 经 `IndustryDirectory`（31 行业 → 别名/子行业词目录，代码常量 ~31×4 词，如 电子→[半导体,芯片,集成电路,消费电子]）映射到行业集——REQ 拍板二 P2 行「订阅主题映射行业」原文已预留该映射的需求侧表述，本批自建落地。
- **通道 B（标的行业，best-effort 自动增强）**：自选 ∪ SUBJECT 订阅标的的 `subject_master.industry` 非空者入集，NULL 跳过不阻断。东财主链（f100 含行业）恢复成功一次同步即自动回填、通道 B 自动增强、P2 命中面扩大、逻辑链标的区自动非空——**零代码变更**。不以回填为前置（同步链恢复属运维动作，方案对 NULL/有值两种状态均正确）。

P2 卡片形态随数据自适应：通道 B 空转时标的区为空（展示行业链路 + 订阅来源），与 REQ「P3-only 允许空标的、不硬凑」同款形态。

**裁决延伸（P1 判定集）**：P1 = `event.subjects[].code ∈（自选 watchlist ∪ SUBJECT 订阅）`——显式标的订阅与自选同为「用户显式关注标的」，并入 P1 避免同强度信号被降到 P3（REQ 数据源列只写自选，此为架构裁量扩展最小集，文案「直接涉及你关注的标的」覆盖两者）。

**被否**：①以行业回填迁移为前置（运维不确定性进关键路径，回填失败 P2 整体不可用）；②新增行业订阅 subType=5（REQ 无此需求，扩展用户配置面属范围蔓延）；③按事件 industries 反查阅读画像行业（reading_event 无行业维度、subject 行业又 NULL，同源死锁）；④P2 降级并入 P3（丢「行业命中」级语义与降频组合的行业维度）。

## 后果

- **正面**：NEWS_PIPELINE 与既有推送/订阅/管道表零改动，回归面收敛到「新域新表新 Job」；P2 对行业数据两种状态均正确（解阻塞且不欠债）；白名单使零新增事实从提示词自觉变为机制保证；express 以 ~1% 预算代价把口径 B 压到预算 56%。
- **负面/代价**：调度池 +2（12→14，单机量级无压力）；`PushStatus` 扩 SILENT 触碰推送域枚举（重试/history 查询语义需回归覆盖）；IndustryDirectory 目录维护成本（偏窄=少推不误推，安全侧失败）；express 先建行的主条时间戳边界（如实标注）。
- **跟踪项**：行业回填运维动作（东财主链恢复一次同步即自动增强 P2 通道 B）；recscore-v1/express 阈值首跑校准版本化；口径 B ≥80% 达标复核。
- **关联**：修订/延伸 ADR-0046 裁决 4（Job 组织——每级一 Job 先例延展至优先通道）；不修订 ADR-0030（备选链无行业是其实情，本裁决使其不再阻塞推荐域）。
