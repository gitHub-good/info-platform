# ADR-0046：管道产物独立建表与批量归类调用形态及护栏派生（M15 四级管道六裁决）

- 状态：已接受（2026-09-22，V2.0-M15 设计期裁量留档）
- 日期：2026-09-22
- 决策人：架构设计师（依据[REQ-20260926-12](/docs/01-需求/REQ-20260926-12-M15-AI归类与分析管道.md)「表结构/批大小/失败拆批/衰减函数/Job 组织/模板治理关系归架构」六处授权 + PM 点名「首跑最大不确定点=批量输出格式，允许一次真实外呼验证并留档」）
- 关联：ADR-0039/0040（news_item 与调度体系，复用）、ADR-0015（llm_call_log 成本留痕——护栏数据源）、ADR-0021/0022（提示词版本与占位符，扩类沿用）、ADR-0005/0008（LlmCache——本批管道场景显式绕开）、ADR-0027/0030（标的池行业口径实情）、ADR-0032（种子缺省）、ADR-0045（basis 版本串先例）；方案全文见[技术方案-V2.0-M15](/docs/02-设计/技术方案-V2.0-M15-AI归类与分析管道.md)

## 📌 背景

M15 四级管道（L0 规则预筛 / L1 批量归类 / L2 事件提取 / L3 热度聚合）在 REQ 冻结语义下有六处实现口径需架构拍板，其中批量调用输出格式被 PM 点名为首跑最大不确定点——授权一次真实外呼验证。

## 🎯 决策（六裁决，详论证见方案 §3）

1. **管道产物独立建表，`news_item` 零改动**：L0~L2 逐条状态落独立 1:1 表 `news_analysis`（+ `event_item` / `industry_heat_snapshot` / `industry_daily_report` 共四表，V23/U23）；连 V22 注释预留的 `news_item.status=3` 垃圾标记也不启用——noise/near_dup 落新表，资讯流默认查询零改动即满足「noise 保留可查」。理由：管道逐条状态 ~14 列塞进 feed 域表违反「表归属单一模块」（方案库 01 常见坑）；摄取热路径（INSERT OR IGNORE 批量）零波及；U23 回滚无伤主表。代价：热度/下钻 join（日窗 ≤700 行，毫秒级，接受）。
2. **批量调用形态**：L1 批大小缺省 **20**（可配 10~30，>30 禁配）；输出 schema 用**对象包裹数组** `{"results":[…]}`（JSON mode 只保证 json 对象，裸数组有风险）；失败处理 = **对半拆批递归至单条**（有效行先落库、无效行进重试批；单条终败 `FAILED` 当日重试 ≤3、如实进分母）；管道调用 `cacheable=false` 绕开 LlmCache（同批重试会命中同一份坏输出）。**实测背书**（方案附录 A，2026-09-22 dev 库 20 条真实资讯一次 deepseek-flash 调用）：20/20 合法 JSON 且 id 全对齐、8.1s、prompt 1783 + completion 1833 token、**¥0.009115/批 = ¥0.000456/条**（L1 预算 4.6%）——批 20 vs 30 成本无差（输出 token 主导），取 20 = 更小失败爆炸半径。
3. **提示词治理关系**：BriefType 扩 `5 行业归类 / 6 事件提取 / 7 行业日报`（REQ 条目 10 已锁 Must，本裁决只定机制），V23 播种 v1.0（与实测文本同源），M5 治理页/版本化/热生效零特例复用；**35 枚举校验权威在代码侧 `IndustryCategory` 常量**——模板枚举被页面改坏 → 非法输出按拆批规则处理并进失败统计（模板漂移可见不静默）。
4. **Job 组织**：新增 4 个 ManagedJob——`NEWS_PIPELINE`（FIXED_DELAY 10min，L0+L1+L2 段间容错同 Job）、`INDUSTRY_HEAT_SNAPSHOT`（30min）、`INDUSTRY_DAILY_REPORT`（CRON 08:00）、`SOURCE_STALE_CHECK`（CRON 04:10，T128 独立小 Job 而非搭车 RETENTION_CLEANUP——手动触发验收与故障隔离语义干净）；JobScheduler 池 8→12。L0 挂**批窗口**不挂入库同步（近重复天然批式 + 不动 M13 摄取事务）。测试隔离沿 8 Job 惯例（test profile 种子 enabled=false 零注册）。
5. **护栏无表派生**：管道日成本 = llm_call_log 按 `scene_key ∈ {5,6,7}` 当日 SUCCESS 求和（**权威源直读，不做内存计数**——LlmCostGuard 是单用户口径且 userId=0 跳过，重启清零与报表漂移是已知缺陷）；级别纯派生：≥90% 熔断（全停+PIPELINE_FUSED 告警）/ ≥60% 降级（跳 L2，**日报保留**——REQ 拍板四-1「暂停 L2 与日报外的 AI 生成」= 日报存活）/ NORMAL；换日查询窗口滚动即自动恢复，24h 待处理窗口即补跑，零恢复代码。缺省预算 ¥2/日（实测正常水位 ¥0.70 的 ~3 倍余量）。
6. **K1 缺省 = 10（REQ 建议值 3 的算术勘定）**：REQ 故事 2 场景 2 为冻结验收（A 10 条含 2 高事件 ≥ B 30 条无事件，「K1 缺省权重框架下」），代入 K1=3 得 A=16 < B=30，**验收必挂**（含衰减修正仍差 ~7 分）；K1=10 同新鲜度最严读法 A=30 ≥ 30 成立。拍板三末句「权重取值与实现归架构」授权本勘定；半衰期 H24=12h / D7=48h（7d 同框架不同参，防 7d 榜退化为 3 日榜）；全部 `pipeline.heat` 热改 + basis 版本串随快照/榜单下发。

## ⚝ 实现附注（工程事实留档）

- deepseek-flash 为混合推理模型：实测 completion 1833 中 reasoning_tokens 1220（67%）——若 API 支持关闭 thinking，输出成本另有 ~60% 校准空间（首跑后评估，不动缺省）。
- 实测样本自带两组近重复实证（USD/JPY 双源同题、利比亚管道三源同稿含一条英文）——L0 近重复必要性实证；跨语言同稿不合并为如实标注的边界（非缺陷）。
- 标的池行业字段实情：`subject_master.industry` 为东财口径（ADR-0027 f100），且 dev 库 A 股 5221 行全 NULL（最近同步走了无行业的新浪备选链，ADR-0030）——REQ「含申万行业」表述与实情不符，L1 一致性校验 v1 降格为标的回联留痕（`matched_subjects` 落库），自动行业差异比对留 M16+（需东财→申万映射表且池行业覆盖率恢复）。
- 密钥使用：验证调用经既有 LlmConfigFacade 解密链路取 DB 密文 key（CONFIG_SECRET 来自运行中后端进程环境，仅存内存未落任何输出/日志），调用一次后临时文件即删。

## ⚖️ 被否方案与理由

- **news_item 加列**：管道 14 列挤占 feed 域表（归属混淆）+ 摄取热路径回归面 + SQLite 回滚需表重建；独立表代价仅 join（量级毫秒）。
- **逐条调用 / 50+ 大批**：前者 20 倍调用数与 system 重复成本；后者输出截断风险与失败爆炸半径翻倍（实测 20 条批 completion 1833，50 条批将上探 4.5k+）。
- **失败整批原地重试**：批内失败粒度不可知，同因再失败浪费预算——对半拆批即二分定位（弹性四件套「重试」的批量形态适配）。
- **管道调用走 LlmCache**：缓存键含 messages，同批重试命中同一份坏输出 = 死循环；管道请求本质无重复语义。
- **护栏内存计数器 / 护栏状态表**：前者重启清零 + 与 llm_call_log 报表口径漂移（ADR-0015 已立「严格口径以留痕表为准」）；后者纯派生态落表 = 双写一致性 + 换日清理两笔新复杂度。
- **K1=3 或「测试构造新鲜度差」过关**：前者验收算术不成立；后者把验收语义建立在脆弱构造上，不如正面勘定缺省值（basis 版本化保留调整自由）。
- **停更检查搭车 RETENTION_CLEANUP / L0 挂入库同步**：跨域搭车语义混浊；入库挂接动 M13 摄取事务且近重复需 24h 池比较天然批式。

## 🔁 后果

- `news_item` 与六源域/feed 引擎本期零改动（零回归面最大化）；管道能力整体摘除 = 停 4 Job + U23，感知层无伤。
- LlmRequest 契面扩展（cacheable 缺省 true）：既有 4 类简报调用零感知；管道场景显式 opt-out。
- 热度榜单脚注必须渲染 basis 串（K1=10 与 REQ 建议值 3 的差异对读者可见，不静默）；首跑校准窗口内 K1 若下调，heat basis 升 v2。
- 管道预算缺省 ¥2/日独立于 M3 用户预算——成本报表将出现 scene 5/6/7 新维度（LlmCostReportService 分组自然扩展，无需迁移）。
- 事件表 v1 一条资讯至多一条事件（UNIQUE(news_id)）——多事件提取（M17 影响链）到时需迁移放锁，记方案 §8 开放问题②。
