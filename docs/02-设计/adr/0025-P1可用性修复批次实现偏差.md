## 📌 背景

体检 P1-5/P1-6 与 P2 负缓存三项按体检建议修复（提交 ebae203 / 265c07e / 5f8b97d）。修复指令允许「契约增量字段可加，不改既有字段」，本 ADR 登记三处实现层偏差与四处增量字段。

## 🎯 决策

### 1. feed 推荐只读：每页仍读一次当日缓存（而非「仅首页读一次」）

指令建议「翻页只在首页/首请求时读一次缓存」。实现为**每页只读不触发**（`readDaily` = 一次幂等键 SELECT，毫秒级），不做「仅首页读」：M2 合成游标是**位置型**（按合并条目排序后 1 起递增），推荐条目若首页在、次页缺，第二页条目整体前移 5 位，`id > cursor` 会跳条/重条。保持推荐条目在各页请求中一致在场（就绪态确定性排序首位），游标稳定性不劣化；触发/阻塞语义与指令一致（`generateDaily` 全程不被调用）。M3 预计算落库后由持久 id 承接（既有已知限制不变）。

### 2. 负缓存 TTL 字段为「可选校验 + 读取回落」，不走「种子必填」惯例

`datasource.{CODE}.failureCacheTtlSeconds` 在校验器中为**可选正整数**（present-才校验），与 T36「种子始终写入的字段按必填校验」惯例不同：本批**禁数据库迁移**，存量 `runtime_config` 行没有该字段，若必填则页面首次保存即 2001（合并基线为存量文档）。配套：读取侧 `RuntimeDataSource` 对缺失/≤0 回落 `DataSourceDefaults.failureCacheTtlSeconds`（不阻断）；facade 保存时对旧文档**补种默认**，使「种子始终写入」不变量对后续保存成立（新装环境种子即写入）。

### 3. 简报 FAILED 重试采用「状态回置 + version bump」，不引入 attempt 序号

指令给出三选一（attempt 序号入幂等键 / 状态回置 / 新行软链）。取**状态回置**：`AiBrief.retry(retryAt)` 回置 PENDING、清失败残留、乐观锁 updateById bump version，同任务同幂等键——零 DDL（本批禁迁移）、`uq_ai_brief_idempotency` 与 `getBrief(taskId)` 历史可读性不变。代价：同一 taskId 的多轮尝试不留独立行（`llm_call_log` 仍留每次真实调用成本），create 响应无 `attempt` 序号字段（指令明示为可选增量，未加）。`retry` 同时重置 `createdAt`——重试视作重新受理，30min 懒查超时窗从头起算，否则重试任务在下一次 getBrief 即被懒查打回 FAILED。

## 📋 契约增量字段（均不改既有字段）

| 端点 | 字段 | 语义 |
| --- | --- | --- |
| `GET /api/v1/feed/personal` 响应 | `recommendationPending: boolean` | 每日推荐未就绪（当日简报未触发/在途生成中）；就绪/兜底/空池均为 false。未就绪时 `items` 照常返回、仅缺 `type=recommendation` 条目 |
| `PATCH /api/v1/datasource-configs/{code}` 请求 | `failureCacheTtlSeconds?: long` | 失败负缓存 TTL（秒，正整数；null=不修改） |
| `GET /api/v1/datasource-configs` 响应 | `failureCacheTtlSeconds: long` | 每源卡片回显（存量行无值时显示代码缺省：行情 10 / 其余 30） |
| `DailyRecommendationResult`（内部） | `status=4`（PENDING）+ `recommendationPending` | 仅 feed 只读路径产生；`GET /recommendations/daily` 响应结构不变，不会出现 status=4 |

## ⚖️ 被否方案与理由

- 翻页仅首页读缓存：位置型游标下跳条/重条（见决策 1）。
- 负缓存 TTL 必填校验：禁迁移约束下锁死存量环境的页面保存（见决策 2）。
- attempt 序号入幂等键：键格式变更波及 `generateDaily`/feed 只读的当日查重口径，且需「查最新 attempt」的额外扫描；新行软链需 DDL。均超出最小修复边界。

## ⚠️ 后果

- 负面：同任务多轮重试不留 attempt 行（成本追溯走 llm_call_log）；`recommendationPending` 需前端 Feed 页适配才有产品价值（后续批次）。
- 正面：feed 冷启动不再有 30s 阻塞；故障源请求预算收敛到每 TTL 窗口一次真实取数；当日失败简报可重试、预算耗尽不挡已生成结果读取。
- 需要跟进：前端对齐 `recommendationPending` 占位与 datasource 配置页 `failureCacheTtlSeconds` 编辑项（M6 前端批次）。
