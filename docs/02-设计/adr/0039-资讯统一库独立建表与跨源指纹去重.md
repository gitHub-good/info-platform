# ADR-0039：资讯统一库独立建表 news_item（不与 policy_item 合并）+ 跨源指纹去重（sha256 归一化标题+日期）

- 状态：已接受（2026-09-22，V2.0-M13 源接入框架）
- 日期：2026-09-22
- 决策人：架构设计师（依据见[技术方案-V2.0-M13-源接入框架](/docs/02-设计/技术方案-V2.0-M13-源接入框架.md) §3.2/§4.1/§4.2）
- 关联：ADR-0038（info_source 源注册表，source_id 来源）、ADR-0040（SOURCE_POLL 调度与游标推进）、ADR-0036（段式明细惯例）、V2.0 蓝图北极星「日净入库 = 跨源去重后 ≥2000 条」口径

## 📌 背景

V2.0 需要资讯统一库承载 30 源分钟级资讯流：多源条目、跨源同文去重（财经同稿率高，蓝图 NFR 点名「跨源指纹去重为入库前置」）、增量游标、软删语义、感知延迟口径（源发布→入库）。现状资讯类只有 policy_item（gov.cn 单源政策流）一张持久表，新浪新闻为请求驱动不落库。需裁决：新表 vs 泛化 policy_item；指纹算法与去重粒度（同源 vs 跨源）。

## 🎯 决策

### 1. 独立新表 `news_item`，不与 policy_item 合并

`news_item`：source_id（逻辑关联 info_source，不做物理 FK）/ external_id / title / summary / url / author / published_at（ISO 秒，感知延迟口径基准）/ fetched_at / **fingerprint** / status（1 正常，2 源归档、3+ 垃圾/低质 M15 预留）。policy_item 保持政策域专表不动（POLICY 六源域继续写它，**不**双写 news_item）。

**理由**：两表 schema 与语义差异是本质的——policy_item 有 ai_tendency/related_industries 域字段、published_at 仅日期粒度（gov.cn 列表页只有日期）、source_url 去重键；news_item 需要秒级 published_at、指纹、游标协同、软删源归档。泛化合并 = 改存量表 + 动政策抓取/倾向判断/信息流三链路（1520 基线核心面），零功能收益大回归风险。M15 AI 管道需统一消费时以「管道读两表」解决，不倒逼表合并。

### 2. 指纹 = sha256(归一化标题 + # + 日期)，**跨源全局唯一**

```
fingerprint = sha256_hex(
    NFKC(title) 全空白删除 + ASCII casefold  +  "#" + published_date(Asia/Shanghai, yyyy-MM-dd) )
```

- **粒度裁决：跨源去重**（非同源粒度）——北极星「日净入库（跨源去重后）」与「去重率」大盘口径直接依赖；财经同稿主形态就是多源转载。
- **标题为主、不含 URL**：同稿转载 URL 必不同，URL 入指纹则跨源去重失效；同源同文由 `UNIQUE(source_id, external_id)` 精确兜底（external_id 可空，SQLite 唯一索引对 NULL 豁免，无 id 源靠指纹）。
- **含日期**：同规范化标题跨日不合并（「今日收盘」类泛标题不同日是不同事件）；同稿跨日发布（隔夜转载）不合并是接受的保守代价——宁漏并勿错并。
- 归一化保留标点（判别信息），只做 NFKC/去空白/大小写三步——确定性、可逆验证、零依赖。
- **入库幂等**：`INSERT OR IGNORE` + 双唯一索引（fingerprint 全局、(source_id, external_id) 源内）；「应插 − 实插」= dup_count（同源重复 + 跨源同文合并计数，即大盘去重率分子）。

### 3. 去重与游标的事务关系（与 ADR-0040 联动）

单轮摄取一个事务：条目批量 INSERT OR IGNORE → 游标推进（cursor 只随条目持久化成功推进，崩溃重拉由唯一索引幂等吸收，**不重不漏**）→ 日统计自增。并发双源同稿：SQLite 单写者串行，后到事务被 idx_news_fp 拦截计 dup，无需应用层锁。

## ⚖️ 候选方案对比（指纹算法）

| 方案 | 结果 |
| --- | --- |
| sha256(标题+URL) | ❌ 转载同稿 URL 不同，跨源去重失效——与北极星口径冲突 |
| sha256(标题+source_id)（同源粒度） | ❌ 同上，跨源同稿全部重复入库，去重率口径失真 |
| URL 为去重键（policy_item existsBySourceUrl 模式） | ❌ 同②，且部分快讯源无稳定 URL |
| **sha256(归一化标题+日期) 全局唯一（本 ADR）** | ✅ 跨源同文合并、同源重复兜底、确定性可单测、Java 标准库零依赖；误合并面由日期边界 + 标题判别力约束 |
| SimHash/MinHash 近似去重（容忍标题小改） | ❌ 误判面不可控（财经标题常共享句式）、实现与调参成本高；标题微调的近重复留 M15 S1 规则预筛作 Could 项 |
| 泛化 policy_item 为统一 info_item | ❌ 见决策 1 理由（回归面 vs 零收益） |

## ⚠️ 影响

- 正面：北极星「日净入库/去重率」有权威数据面；入库幂等使调度重入、补抓重拉、手动+定时并发全部安全；policy 链路零波及。
- 负面/代价：同日同规范化标题的不同事件会被误合并（预期极低：财经标题长且具体）；隔夜转载不合并（保守方向）；指纹列 +2 索引（news_item 共 4 索引，红线内）。
- 存储预估：≥2000 条/日 × 180d ≈36 万行（M14 扩 retention 键前的峰值护栏，见方案 §8 跟进项）。
