# ADR-0057：M18 前端与测量批实现裁量（T154~T156/T158：北极星端点形态与首测承载 / 信息流行业筛选数据现实 / tokens 间距阶红线）

- 状态：已接受（2026-09-26，V2.0-M18 T154~T156 + T158 前端测量批）
- 决策人：开发工程师（依据 [REQ-20260926-15](/docs/01-需求/REQ-20260926-15-M18-批次三与UI2.0收官.md) 拍板三/四与任务表「纵深席端点、北极星聚合端点形态、概览工作台摘要契约、tokens 组织形式归架构，本表给需求侧粒度建议」的裁量授权）
- 关联：ADR-0045（大盘端点与增量轮口径）、ADR-0056（cost-v2）、[ui-V2.0-M18-设计基准与走查清单](/docs/02-设计/ui-V2.0-M18-设计基准与走查清单.md)

## 📌 背景

T154（tokens 微升级）/ T155（4 新页精化含大盘 2.0）/ T156（概览工作台 + 信息流行业筛选）/ T158（北极星常驻与首测）四处任务文本留有实现裁量点；落地时发现两处任务假设与数据现实存在出入，按「小偏差记 ADR」条款留档。

## 🎯 决策

### 1. 北极星聚合端点形态：新建 `GET /api/v1/north-star`（不并入 feed-dashboard）

- **理由**：大盘页两请求并行加载，北极星失败单区块降级（错误 + 重试），三区块零耦合；若并入 feed-dashboard，六指标聚合的失败域会污染既有大盘契约（REQ 故事 2 场景 2「既有三区块零回归」）。采纳率按当前用户 adopt-v1 统计（单人平台，UserContext 直取）。
- **口径同源锁**：感知延迟/今日入库/源启停直接复用 `FeedDashboardService.dashboard()` 聚合结果（构造上同值，对账断言即成立）；采纳率复用 `RecommendationQueryService.stats`；成本护栏复用 `PipelineStatusService.status()`（cost-v2）；覆盖率 = news_analysis 当日 L1 DONE 去重申万命中 ÷ 31（新增仓储读方法 `findDistinctMainCategorySince`，白名单过滤归服务层）；稳定源 = source_daily_stats 7 天窗 (poll−fail)/poll ≥95%（现算）。六指标**零新口径**，状态判定 MET/NOT_MET/INSUFFICIENT 常量直出（单测锁定恰等值语义：P50 ≤5min、覆盖率 ≥90%、稳定源 ≥30、曝光 ≥30 张且采纳率 ≥30%、占比 ≤60%、单条 ≤20000 微元）。
- **实时态 vs 验收快照**：端点为实时态当日口径（沿拍板四-1「实时态走大盘」）；窗口首测（≥3 工作日 P50 / 7 天序列 / ≥30 卡）按**现算 + 留档**承载——零新表零新 Job，首测值以 ns-v1 公式对运行库实算并版本化留档进 V2.0 收口报告（T159 消费），机制常驻保证 V2.1 可持续复测。

### 2. 信息流行业筛选：后端参数（`/feed/personal?industry=`）+ 宽松校验；任务假设「L1 行业标签已全量在库」与 #/feed 数据链路存在出入

- **数据现实（核实结论）**：`#/feed` 是 V1 订阅命中链（公告/新闻按标的 fetch + 政策近窗），**不经过统一库 L1 归类管道**——FeedItem 无行业字段；标的 `subject_master.industry` 基本为空（5226 行仅 5 行非空且非申万口径：互联网/综合指数/规模指数）；唯一带行业标签的是政策条目 relatedIndustries（T24 标签，粒度含二级行业如「白酒」，非严格申万一级）。
- **裁量**：不硬凑「31 行业枚举校验」（会把手头唯一可匹配面——政策标签——的大部分值判非法）；参数宽松校验（trim 非空 + 长度 ≤50 防御 400），匹配语义 = 政策按 relatedIndustries 包含、公告/新闻按 `subject.industry` 相等；**推荐条目不入筛选视图**（推荐是全量 Top5、不持有行业维度，掺入即口径混淆）；筛选在分页前应用（游标语义一致）。前端下拉仍按任务要求提供申万 31 项 + 「全部行业」，空态明示行业名。
- **去向**：V2.1 候选——信息流条目透传统一库 L1 main_category 后，行业筛选收敛为严格 L1 口径（需 feed 链路升级，超出本期「零新增数据链路」边界）。

### 3. A 层 tokens：间距阶以「具名变量 + 文档基准」落地，存量页面不回改

- 间距/字阶若全局改动会触碰 18 页布局，直接违背拍板三「不改布局」红线；故色彩/暗色/焦点环/图表色板走变量值升级（18 页被动），间距阶以 `@theme` 具名变量（`--spacing-page/--spacing-section/--spacing-card-grid/--spacing-card-inner`）+ 走查清单文档基准约束新代码；字阶仅加 `h1` 字距与表格 tabular-nums 两条全局规则。
- 全部变更收敛在 `index.css` 单文件（回滚锚点 = 单文件 revert），基准与走查清单见关联文档（ui-tokens-v2）。

### 4. >30 源形态取「纵向滚动 + 表头吸附」（滚动式，阈值 20 行）

- 源表已具备横向滚动（min-w 860px）；30+ 行纵向形态在滚动与分组折叠两式中取滚动式（零信息隐藏、异常置顶语义不变；分组折叠会引入折叠态与「异常源藏在折叠里」的新边界）。阈值 20：既覆盖 30+ 常态，又避免中量行被裁切视口。

### 5. 概览工作台摘要契约（复用既有 API，零新数据链路）

- 热度 Top5 = `GET /industry-heat?window=D7` 前 5 行；最新推荐 = `GET /recommendations?limit=2`；最新事件 = `GET /events?limit=3`（≤5 上限内取 3）；大盘健康 = `GET /feed-dashboard`（源在线 = activeSourceCount/现役启用数、今日入库）+ `GET /pipeline/status`（成本水位 + 护栏等级，新增前端适配层 `api/pipelineStatus.ts` 仅消费护栏与成本字段子集）。四块独立三态（骨架/错误可重试/空态），单块失败不影响其余块与既有五卡；30 秒刷新沿大盘机制（document.hidden 暂停）。

## ⚖️ 被否方案与理由

- **北极星并入 feed-dashboard**：六指标失败域污染三区块契约；大盘既有测试与对账面（全局=分项之和）被牵连。
- **北极星每日快照落库（新表/新 Job）**：16 Job 体系与「零新增数据链路」边界内无此必要；现算口径与既有端点同源，留档进收口报告即满足「首测快照版本化」（拍板四-3 机制常驻 ≠ 数据落库）。
- **industry 参数严格申万 31 校验**：与 #/feed 实际可匹配面（政策标签含二级行业）冲突，会产出「合法值永远匹配不到数据」的假筛选。
- **间距阶全局回改 18 页**：违背「微升级不改布局」红线，投入产出倒挂（A 层定位就是被动受益）。
- **源表分组折叠**：异常置顶语义与折叠态冲突，滚动式信息零丢失。
