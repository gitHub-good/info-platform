# ADR-0031：行情/估值备选源与自动降级——腾讯 TencentQuoteClient + adapter 内组合（ADR-0030 模式推广）

- 状态：已接受（2026-09-24，push2 封禁窗口补强）
- 日期：2026-09-24
- 决策人：开发工程师（依编排者 2026-09-22/24 端点实测 + 开发 2026-09-24 与东财 push2 同日交叉验证；沿 ADR-0030 auto 降级先例）
- 补充：ADR-0003（统一数据访问层）、ADR-0010（弹性收敛在 ResilienceRunner）、ADR-0030（列表源 auto 降级先例）、技术方案 §4.3 流程 1 / §5 降级预案

## 📌 背景

push2（东财行情/估值同端点 `stock/get`）IP 封禁期间**行情+估值两源瘫痪，是全站行情问题的唯一根因**——详情页 quote/valuation 分区、自选页行情行、异动检测（涨跌幅）全部依赖。其余源（datacenter 财务/新浪新闻/gov.cn 政策/东财公告）实测正常。腾讯 `qt.gtimg.cn/q=` 实测可用且极快：GBK 编码响应、`~` 分隔字段、支持批量（`q=sh600519,sz000001`，URL 编码 `%2C` 亦可）、无 UA 要求、无 WAF 迹象。ADR-0030 已为列表源落地「主选失败 WARN 降级备选整拉」模式，本决策把同模式推广到行情/估值。

## 🎯 决策

1. **新增 `TencentQuoteClient`**（infrastructure/aggregation，行情/估值共用——腾讯一次返回全部字段，区别于东财按 f 字段列表裁剪）：
   - 单只 `fetchQuote` + 批量 `fetchQuotes`（≤50 只/请求自动分块防御）；GBK 取 `byte[]` 显式解码（不依赖转换器对 `text/html; charset=GBK` 的行为）；
   - **输出即东财 f 键中间结构**（f43/f60/f162…）：两 adapter 既有字段映射配置（`eastmoney-quote.json` / `eastmoney-valuation.json`）零改动即可消费，聚合契约零感知；
   - 字段映射按 **2026-09-24 实测 + 东财同值交叉核对**落（核对表全文见 `TencentQuoteClient` Javadoc）：现价@3/昨收@4/今开@5/量@6/涨跌@31/涨跌幅@32/高低@33-34/成交额@37/换手@38/振幅@43；估值位两市场分叉——A 股 PE@52/PB@46、港股 PE@39/PB@58（港股 46 位是英文名）；
   - 证券代码换算：内部码 `SH600519`→`sh600519` / `SZ`→`sz` / `HK`→`hk00700`（大小写不敏感，实测腾讯港股为 5 位码 `hk00700`）；**不依赖 eastmoney secid**——external_codes 缺 secid 的标的也能走备选源；
   - 防御：垃圾行/字段数<40 短行跳过记 WARN；字段值空白或 `-` 时对应 f 键不产出（映射白名单自然跳过目标字段，半行数据优于整行丢弃）。

2. **两 adapter 组合双 client + auto 降级**（`QuoteSourceAdapter` / `ValuationSourceAdapter`，不改 `SourceAdapter` 端口与聚合契约；弹性/缓存/心跳语义不变）：
   - 配置 `adapter.quote-source` / `adapter.valuation-source: auto | eastmoney | tencent`（默认 **auto**；笔误启动 fail-fast，空值回落 auto——对齐 ADR-0030 `parseMode` 先例）；
   - **auto 降级触发条件 = 东财失败（HTTP 错误/异常）或空响应（200 + data:null）**。空响应是封禁实测签名，与「盘外无数据」不可区分——降级两可：腾讯有数据即恢复、也无数据仍 MISSING，无误伤面；
   - 东财成功直用（**每轮仍先东财**，封禁解除自动回归主选）；降级 WARN 留痕，腾讯也失败才走既有弹性语义降级（腾讯异常上抛，东财原因挂 `suppressed` 留诊断链）；
   - **可观测口径（从简不破坏三态契约）**：降级轮 `RawFetch.source` 标注「东方财富行情→腾讯备选」/「东方财富估值→腾讯备选」（强制 tencent 为「腾讯行情」/「腾讯估值」）——OK/MISSING/FAILED 三态不变，来源标注 + WARN 日志可区分「东财失败但腾讯兜底成功」；不改 `DataSourceEventRecorder` 心跳签名（OK 心跳 detail 维持 "ok"）；
   - **弹性预算口径**：auto 的「东财+腾讯」两次调用合用同一 ResilienceSpec 预算（行情 1.5s）——封禁失败为快速失败（空响应/RST），预算内可完成；东财若**挂起至超时**，整次取数按既有超时语义降级（不保证兜底），已知限制可接受。

3. **发现修复（东财路径，随本批回归用例修前红修后绿）**：东财以 `"-"` 表示无值（2026-09-24 实测港股估值 `116.00700` f162='-'），直传使 `FieldMapper.toDecimal` 抛 `FieldMappingException` → 估值/行情分区异常而非按字段缺失降级。`EastMoneyClient` 统一剔除 `-` 值 → 走映射白名单「源字段缺失→目标字段不产出」既有语义（港股估值产出 pb、缺 peTtm）。

## ⚖️ 被否方案与理由

| 被否方案 | 理由 |
| --- | --- |
| 新建独立 `TencentQuoteSourceAdapter` + 路由层分发 | 需在 `RoutingSourceAdapter`（real/mock 热路由）之外再叠一层源路由，装配面翻倍；client 层产出东财中间结构 + adapter 内组合即可，对端口/聚合零改动 |
| 腾讯做强接主选 | 东财估值字段语义为既有基线（行业字段/估值口径随源），东财恢复后应自动回归主选，auto 每轮先东财（ADR-0030 同款理由） |
| auto 只在东财「异常」时降级（空响应不算） | 封禁实测签名恰是 200 + 空 data——只盯异常则封禁期不触发兜底，本决策失效 |
| A 股 PE 取腾讯 39 位（社区口径 PE-TTM） | 2026-09-24 交叉核对：腾讯 **52 位**与东财 f162 茅台 17.37/平安 4.27 两样本**数值完全一致**（39 位为 18.99/5.05，口径不同）——备选源首要目标是换源无感，按数值一致位映射；口径问题（f162 究竟 TTM 还是动）为东财映射既有待验证项，另案跟踪 |
| 降级成功改记 OK 心跳 detail 标注源 | 需改 `DataSourceEventRecorder` 公共签名（全源共用心跳节流），收益低——来源标注已进 `SourceResult.source`，健康徽章/日志可区分 |
| auto 降级做两源字段拼接（东财缺 PE 补腾讯 PE） | 两源口径不同（字段位/单位/快照时点），拼接产物口径混杂；整轮取数单源化最简 |

## 💡 后果

- push2 封禁期间行情/估值分区自动恢复（自选页行情行、详情页两分区、异动检测的行情依赖同步恢复）；封禁解除自动回归东财，无需人工切回；排障可 `adapter.quote-source/valuation-source: eastmoney|tencent` 强制单源。
- 口径注记：① A 股成交额腾讯为**万元粒度**（×10000 后≈东财精确元值）；② A 股 PE 走与 f162 数值一致的 52 位（TTM/动口径之辨为既有东财映射遗留观察项）；③ 港股 PB 3.07 vs 东财 3.05 为快照时点/净资产口径差异，量级无害；④ 港股成交量腾讯带 `.0` 小数串，client 归一为 long 对齐东财。
- 东财 `-` 缺失值修复使港股估值从「异常」变「pb 缺 peTtm 的部分数据」；若需港股 PE，可强制 `valuation-source: tencent`（腾讯港股位可补齐）。
- 类清单净增 `TencentQuoteClient` / `BackupSourceMode` 两主类 + 四测试类；分层不变（infrastructure 内组合，ArchUnit 全绿）。
- 已知限制：东财**挂起至超时**（非快速失败）时兜底不保证触发（同一弹性预算）；板块码（BK 前缀）无腾讯符号，备选路径按无数据处理。
