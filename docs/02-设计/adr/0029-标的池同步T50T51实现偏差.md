# ADR-0029：标的池同步 T50/T51 实现偏差——列表源端口化 + 写库单元拆分 + 快照更新口径（REQ-20260924-04 / M7）

- 状态：已接受（2026-09-24，M7 开发阶段）
- 日期：2026-09-24
- 决策人：开发工程师（依技术方案增补 §4.2/§4.3/§4.4/§4.8 落地中的结构性微调，语义不变）
- 补充：ADR-0027（数据源选型）、ADR-0028（missing_streak 存储）、技术方案-标的池定时同步.md §4.8 类清单

## 📌 背景

T50/T51 按方案类清单落地时遇到三处方案未显式覆盖的点：①应用层引擎（SubjectSyncService）需调用基础设施层客户端（EastMoneyListClient），而 ArchUnit 禁 `application..` 与 `infrastructure..` 切片循环（infrastructure 已反向依赖 application 的 Facade 端口，先例 DataSourceConfigFacade）；②「拉取在事务外、写库在单市场单事务」两个边界落在同一类时，Spring 代理自调用无法让 @Transactional 穿过；③更新分支的字段口径：方案 SQL ② 只更新 name/industry 并把 streak 清零合入同语句，而任务交付口径要求「名称/行业/取数键（external_codes）任一变化才更新、更新不碰 status/missing_streak、回归清零单独发生」。

## 🎯 决策

1. **增应用层端口 `SubjectListSource`**（`fetchAll(MarketSyncSpec)`，EastMoneyListClient 实现）——沿用 DataSourceConfigFacade 先例的依赖倒置；换备选源（ADR-0027）只换实现类，引擎零改动。类清单较 §4.8 增此一接口。
2. **写库拆独立 bean `SubjectSyncWriter`**（`@Transactional writeBucket`）——SubjectSyncService 保留「拉取（事务外）→ 委托写库（单市场单事务）」编排与跨市场失败汇总；事务注解落在真实调用链上。类清单较 §4.8 增此一类。
3. **快照更新口径**：`updateSnapshot(code, name, industry, externalCodes)` 更新三列（**不碰 status / missing_streak**），触发条件为名称/行业/取数键任一变化；取数键按「既有键 + 生成键增量合并」（手工额外键如 akshare 保留，生成键覆盖同名键）；**回归清零独立端口 `clearMissingStreak`**（`WHERE missing_streak > 0`）。与方案 SQL ②「合并同语句」相比语句数 +1，但终态一致且「更新不碰 missing_streak」由语句级保证。
4. **`MarketSyncResult` 增 `unchanged`（不变行数）计数**——任务交付口径的「新增/更新/不变/缺失确认/停用数」五计数齐备（方案字段为四计数 + total/elapsed）。
5. **`Subject.reconstruct` 以重载补 `missingStreak` 参数**（旧 11 参签名委托、落 0）——存量 26 处调用零改动（最小改动原则）。
6. **`ResilienceRunner` 增 String 源标签重载**——clist 为列表源、非既有七源 `SourceCode` 枚举（方案 §5 已裁定不强接），弹性机制复用而日志标签独立。
7. **停用动作不在本批接线**（T52）：`collectMissing` 留挂点注释（旧 streak+1 ≥ 阈值 → `deactivateIfMissingReached`，SQL 守卫 `WHERE status=1`），`MarketSyncResult.deactivated` 字段已就位、本批恒 0。

## ⚖️ 被否方案与理由

| 被否方案 | 理由 |
| --- | --- |
| 应用层直接注入 EastMoneyListClient 具体类 | 与 infrastructure→application 既有依赖构成切片循环，LayeredArchitectureTest 红 |
| SubjectSyncService 自注入代理（self-injection）拿事务边界 | 隐晦且脆弱，不如独立 bean 直白 |
| 更新语句合并 streak 清零（照方案 SQL ② 原样） | 与任务交付口径「更新不碰 missing_streak」冲突；合并/拆分终态一致，拆分把两条红线各自由语句级保证 |
| clist 强接入 SourceCode 枚举 | 列表源非七类数据源，扩枚举污染既有缓存/事件/路由按键（方案 §5 已裁定） |

## 💡 后果

- 类清单净增 `SubjectListSource` / `SubjectSyncWriter` 两文件（其余与 §4.8 一致）；分层依赖方向不变，ArchUnit 全绿。
- T52 落停用时只需：仓储端口 + SQL ④ 实现、`collectMissing` 挂点接线、阈值参数 `subject.sync.missing-streak-threshold` 注入——引擎结构零改动。
- 取数键合并语义：同步永不删键、只补/覆盖生成键（eastmoney/tushare），手工键保留。
