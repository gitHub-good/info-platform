## 📌 背景

T45/T46 按 M5 技术方案实现（提交 6c82934 / ac6817e / d72973f）。HTTP 契约（§4.4 六端点、错误码 30066~30070、零 DDL）逐字落地；以下四处为**实现层**的小偏差/方案未提及的技术补全，登记备查。

## 🎯 决策（四处）

1. **`PlaceholderProvider` 端口形状：`Set<BriefType> briefTypes()` 而非方案草图的单值 `briefType()`**。方案 §4.5 接口签名与同节「BriefContextBuilder 场景 1 与 2 共用 17 键清单」自相矛盾——单值返回装不下双场景供给。取集合返回调和之，聚合语义（`Map<BriefType, List<PlaceholderDescriptor>>`，17/17/7/6）不变。
2. **sqlite UNIQUE 冲突翻译下沉到仓储实现层**。sqlite-jdbc 不抛 JDBC4 约束子类（`SQLiteException` 直承 `SQLException`），Spring 异常翻译产出 `UncategorizedSQLException` 而非 `DuplicateKeyException`——方案「UNIQUE 兜底 30070」在 MyBatis-Plus + SQLite 组合下不会自动成立。补全：`PromptTemplateRepositoryImpl.insert` 按消息含 `UNIQUE` 关键字翻译为 `DuplicateKeyException`，AdminService 据此转 30070。集成测试（@SpyBean 过期读模拟并发竞争）验证回滚零变更。
3. **`PromptTemplate` 实体增补 `createdAt/updatedAt`（Instant）与 `newVersion` 工厂**。方案 §4.8 改动清单未列实体本身，但列表/详情契约（§4.4.1/§4.4.2）需要时间戳——以 reconstruct 重载补齐，既有 5 参调用点零改动；`BriefType` 同理增 `displayName()`（管理面分组标题）。均为纯增量，零 DDL 红线未破。
4. **`POST /api/v1/prompt-templates` 响应泛型取 `Result<Object>`**。成功（CreateResult）与 30068（removed/unknown 清单）两分支 data 形态不同，Java 泛型无法单签名双形态；按 `code`（0 / 30068）区分形态，swagger 文档以注释说明。

### 补登（2026-09-24，DEFECT-1 修复，M5 测试报告 §4）

5. **并发写冲突翻译扩展到 BUSY/LOCKED 码族，activate 并发败者同判 30070**。第 2 条的 UNIQUE 翻译只覆盖「生成器 max+1 仍撞既有版本」；真实并发下败者在写阶段（deactivateActive/insert）先撞 **SQLITE_BUSY 族**（create 读写同事务，WAL 下另一事务其间提交 → 写命中过期快照，busy_timeout=5000 不挽救；测试报告 DEFECT-1 实证对外 500/50000）。修复（沿用第 2 条同层同策略，报告 §4 修复建议口径）：
   - `PromptTemplateRepositoryImpl` 三个写方法（insert/deactivateActive/updateStatus）统一把 `SQLITE_(BUSY|LOCKED)` 码族（含 cause 链；文件库 WAL 为 BUSY/BUSY_SNAPSHOT，测试共享内存库为 LOCKED/LOCKED_SHAREDCACHE——同属「败者须回滚重试」）翻译为 `CannotAcquireLockException`；非冲突不吞不译原样冒泡。
   - `AdminService.create` 的 30070 捕获扩大到整个写阶段（先置废 + 插入，`DuplicateKeyException | CannotAcquireLockException` 同判）；`activate`（读目标行后置 1 的同构读后写事务）补同判 30070「激活切换冲突…请刷新列表后重试」——方案 §4.4.4 未列举 activate 并发错误码，此为同机制收敛（409 族，语义与 30070 一致）。
   - 不做服务端写冲突重试：BUSY_SNAPSHOT 后本事务已不可继续，重试须回滚后重走读阶段（换新快照），须拆事务拆方法，超出缺陷修复边界；客户端重试即成（前端冲突 UX 已有，且 UI 在途互斥锁使常规路径难触发）。
   - 回归实证：双线程真实并发集成测试（latch 编排无时序抖动，修前红 `UncategorizedSQLException`/500、修后绿 30070 且胜者数据完好不变量保持）+ 翻译单测以生产 BUSY 族报文逐方法断言；`PromptVersionGenerator` 边界用例顺带补至行/分支 100%（测试报告 R3）。

## ⚖️ 被否方案与理由

- 1 的替代「BriefContextBuilder 拆两个 Provider 内部类」：为接口草图形状拆类，违背方案「不拆 buildContext 结构、生成链路零改动」精神，无收益。
- 2 的替代「AdminService 直接 catch `UncategorizedSQLException`」：把方言知识泄漏到应用层，且未来换 ORM/驱动即失效；翻译属基础设施职责。
- 4 的替代「`ResponseEntity<? extends Result<?>>`」：通配符签名可读性差，springdoc 渲染同样丢失类型。

## ⚠️ 后果

- 负面：`Result<Object>` 使 OpenAPI 对该端点 data 无强类型描述（前端以 §4.4.3 契约文档为准）。
- 正面：sqlite 翻译补全使 30070 兜底真实可用（集成测试实证）；端口形状与「1/2 共用清单」解耦，未来场景复用装配器零改端口。
- 需要跟进：无（四处均不触及 HTTP 契约与数据模型；如架构复审对 1/4 有异见，改内部形状不影响调用方）。
