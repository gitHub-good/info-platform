# ADR-0010：数据源弹性实现选型（自建超时+重试 / 熔断留接口位）

- 状态：已接受（2026-09-20，T02）
- 日期：2026-09-20
- 决策人：开发工程师（依 ADR-0003/0005 与方案 07）
- 补充：ADR-0003（统一数据访问层每 adapter 裹弹性四件套）、ADR-0005（缓存）

## 📌 背景

ADR-0003 定每个数据源 adapter 外裹弹性四件套（超时/重试/熔断/降级），方案 07 要求"一切跨进程调用配齐"。T02 落地
SourceAdapter 通用骨架，需选定弹性四件套的具体实现：自建、Spring Retry、还是 Resilience4j。

约束：

- 后端基线为轻量级（`java -jar` 单包，零外部服务）；不应为弹性引入重型依赖。
- 超时需级联收敛到 2s 预算（§4.3 流程 1），且工作线程须可被中断，避免线程泄漏。
- 重试只对幂等只读操作；降级须返回 MISSING/FAILED 不阻断聚合。
- 熔断首期场景未达复杂度门槛，但需留接口位便于后续接入。

## 🎯 决策

自建轻量弹性组件，不引入 Spring Retry / Resilience4j：

- 超时：`ResilienceRunner` 用虚拟线程（Java 21）执行器提交 doFetch，`Future.get(timeout)` 超时后 `cancel(true)` 中断工作线程。
- 重试：`ResilienceSpec`（timeout / maxRetries / backoffBase）配置化，指数退避 + 25% 抖动；仅幂等只读配 >0。
- 降级：`AbstractSourceAdapter.onDegraded` 抽象钩子，默认返回 `SourceResult.missing`（不阻断），子类可覆写为 `failed`。
- 熔断：`CircuitBreaker` 端口接口 + `NoopCircuitBreaker` 占位（始终放行、不记账），模板层调 allowRequest / recordSuccess / recordFailure，留配置位，真实实现后续替换 Bean 即可。

## ⚖️ 候选方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 自建（JDK + 虚拟线程） | 零新增依赖；spec 配置化、可控；中断语义清晰；与 Caffeine 一致轻量 | 自行实现退避/熔断；熔断需后续补 | ✅ 采用 |
| Spring Retry | 注解式成熟 | 需引 spring-retry + spring-boot-starter-aop；`@Retryable` 注解式不便注入动态 spec；AOP 与虚拟线程协作需验证 | ❌ 否决，依赖与注解耦合偏重 |
| Resilience4j | 超时/重试/熔断/限流一站式 DSL | 多一个外部依赖、配置项偏重；首期熔断未达引入门槛 | ❌ 否决，跟进条件保留 |

## 💡 理由

对照选型五维度：成熟度（JDK Future/Caffeine 同级成熟）、社区（JDK 原生无社区风险）、学习成本（团队熟悉 Future/虚拟线程，最低）、可替换性（CircuitBreaker 端口隔离，后续换 Resilience4j 仅替换 Bean）、运维成本（零外部组件）。虚拟线程承载阻塞式外部调用，超时 `cancel(true)` 中断线程，避免传统线程池被慢调用占满（方案 07 常见坑）。重试只在最外层（模板层）做一次，不在各源叠加，防重试风暴。

## ⚠️ 影响

- 正面影响：零新增依赖、spec 差异化（行情 1.5s 重试 0 / 公告 2s 重试 1 等）由子类声明、熔断可平滑替换。
- 负面影响 / 代价：熔断当前为 Noop 占位，未真正快速失败；退避自实现需测试覆盖（已补单测）。
- 需要跟进的事项：若多 provider / 多源熔断与限流场景复杂化（错误率阈值、半开试探、并发限流），重新评估引入 Resilience4j 替换 `CircuitBreaker` Bean。

## 🔍 后续验证方式

- T03~T08 各源接入后，观察实际 P99 与超时降级率；若超时频繁或线程中断未生效则回看 `cancel(true)` 语义。
- 熔断是否需落地：观察 `data_source_event`（T16）连续失败计数，达阈值再实现真实熔断。
