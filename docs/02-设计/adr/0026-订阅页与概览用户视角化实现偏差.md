# ADR-0026：订阅管理页与概览用户视角化的契约缺口吸收与实现偏差

- 状态：已接受（2026-09-22，M6 编码阶段，开发工程师依任务指令「小偏差记 ADR-0026+ 并说明」登记）
- 日期：2026-09-22
- 决策人：开发工程师（两处均为前端实现层偏差 / 契约字段缺口在 UI 侧吸收，未改任何后端契约与数据模型，无需回架构重审；缺口项列 §4 供后续裁定）
- 关联：[系统体检-20260924-交互与业务优化清单.md](/docs/02-设计/系统体检-20260924-交互与业务优化清单.md) P1-3/P1-4 与 E2；ADR-0025（`recommendationPending` 增量字段）；[ui-配置与运维可视化.md](/docs/02-设计/ui-配置与运维可视化.md) §3.1/§4 三态基线

## 📌 背景

体检 P1-3（订阅无管理入口）与 P1-4（首页视角错位 + 每日推荐无消费页）按任务指令实现：新增 `#/subscriptions` 订阅管理页（订阅 CRUD 全接后端既有契约）、Feed 空态 CTA 修正指向、概览改两段式（今日推荐/今日异动/最新政策 + 平台健康三卡收纳）。任务要求后端不动；读码对照契约后三处小偏差与两处契约缺口在此登记。

## 🎯 决策

### 1. 订阅列表不展示「创建时间」——契约无该字段，UI 侧吸收

任务提纲要求订阅卡展示创建时间，但后端 `SubscriptionView`（`application/subscription/SubscriptionView.java`）只有 `id/subType/subKey/channel/status` 五字段，无 `createdAt`（视图层刻意不含时间戳，对齐技术方案 §4.1.6「不含内部 userId/version/时间戳」）。加字段属契约变更（架构领地），本批不动后端——订阅卡以「类型徽章 + 订阅内容 + 渠道 + 状态」呈现。如产品需要创建时间，需架构侧扩视图字段后再补列。

### 2. 概览推荐卡挂载走 feed 只读判读，不直接调触发式 GET /recommendations/daily

任务提纲「消费 GET /recommendations/daily」——实现拆成两路，分工依据端点语义：

- **挂载（只读）**：`GET /feed/personal` 首页（`readDaily` 只读语义，毫秒级，不受理不生成）。`recommendationPending=true` → 未生成空态（CTA「立即生成」）；`false` 且含 `type=recommendation` 条目 → 直接渲染 Top5（就绪态推荐条目确定性排在首页头部，`FeedService.recommendationEntries` 保序）；`false` 且无条目 → 空池空态。
- **「立即生成」（触发）**：`GET /recommendations/daily`（触发式：未生成受理异步生成并服务端轮询至终态；已生成/在途幂等直返）。响应 `status` 1=AI / 2=规则兜底（角标「规则排序」）/ 3=空池。

理由：概览是登录默认落地页，若挂载即调触发式端点，FAILED 日每次打开页面都自动重触发 LLM 生成（P1-6 已允许 FAILED 重试）——无用户意图的自动重试烧钱，正是体检总评确立的「一切自动重试必须有上限」反模式（P0-3 同根）。测试断言挂载路径零 `/recommendations/daily` 调用。

### 3. 「未生成」与「生成中」在只读契约下不可区分，合并展示策略

`recommendationPending=true` 同时覆盖「当日未触发」与「在途生成中」两种后端状态，只读契约无法区分。实现：挂载只读命中 pending 统一显示「未生成 + 立即生成 CTA」（若实际在途，点击后触发式端点幂等直返同一任务并轮询至终态，无重复计费）；「生成中」占位态仅出现在用户点击 CTA 之后（客户端已知生成已发起）。

## 📋 其余实现口径（非偏差，备忘）

- 订阅类型四类全量支持（任务提纲列三类，后端枚举含 4 政策主题 POLICY_THEME，列表与新建表单均覆盖）；事件类型 subKey 取中文标签（公告/新闻/政策），`FeedMatcher.eventTypeMatch` 按中文标签 contains 命中，展示无需二次映射。
- 退订走后端软退订语义，UI 文案「退订」而非「删除」；已退订条目保留展示并提供「重新订阅」（POST 同键幂等激活，复用既有契约）。
- 「信息面活跃度」列：`TopRecommendation` 契约无独立活跃度字段（依据在 reason 文本中），推荐行展示代码+名称+理由首行。
- 重复订阅：后端幂等直返不报错；前端对已加载页做本地判重给「已在订阅列表中」友好文案（分页未加载项仍由后端幂等兜底）。
- 任务中心「每日推荐」Job 生产默认 `enabled=false` 保持不变（体检建议项 C）：概览「未生成」空态的「立即生成」按钮即触发入口，无需开 Job。

## ⚖️ 被否方案与理由

- 挂载直调 GET /recommendations/daily：默认落地页 × FAILED 日 = 无界自动 LLM 重试（见决策 2）。
- 前端为订阅卡补「创建时间」：需后端视图扩字段（契约变更），超出「后端不动」边界；不造假数据。
- 生成中轮询 feed 端点刷新占位：触发式端点本身阻塞至终态（服务端轮询），客户端再加轮询属冗余请求；单请求挂起期间展示占位即可。

## ⚠️ 后果

- 负面：订阅卡无创建时间（产品如需 → 架构扩 `SubscriptionView` 字段后再补）；「未生成」空态在他人触发生成期间显示略有滞后（点 CTA 即对齐，无重复计费）；feed 只读路径的就绪 Top5 无「规则排序」角标（feed 条目不携带 status，触发路径才有）。
- 正面：订阅 CRUD 闭环全接通（个性化闭环起点补齐）；概览首页价值前置（推荐/异动/政策），平台健康收纳下半部；推荐生成零自动触发成本，用户意图驱动。
- 需要跟进：无（`recommendationPending` 前端类型已在 `types/feed.ts` 补齐，ADR-0025 遗留的前端适配项本批完成）。
