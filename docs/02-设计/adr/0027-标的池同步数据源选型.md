# ADR-0027：标的池同步数据源选型——东财 push2 clist（实测依据 + 备选）（REQ-20260924-04 / M7）

- 状态：已接受（2026-09-24，M7 设计阶段）
- 日期：2026-09-24
- 决策人：架构设计师（依 REQ-20260924-04「候选源验收要求」五条交架构选型 + 技术方案增补 §3.1）
- 补充：Spike-1（secid 编码约定 §5）、ADR-0003（统一数据访问层）、ADR-0010/0011（数据源弹性）

## 📌 背景

Spike-1 覆盖行情/估值/财务/公告/新闻/政策六源，**未覆盖「A 股/港股全量上市列表」源**。需求交付架构按五条验收要求选型：公开免费（无 token/积分墙）、可分页拉全量（A 股约 5400 只/港股约 2600 只，允许分市场异源）、字段齐全（代码/名称/尽量含行业/可派生东财 secid）、可礼貌抓取（限速分页、失败可重试）、港股不可稳定获得可走降级兜底。选型全部结论来自 2026-09-22/24 本机 curl 实测（工作区临时目录 spike，未动项目代码）。

另需勘定：任务建议的港股 fs 参数 `m:116+t:1` 需验证是否为港股主板（需求任务书自注「类似，待核」）。

## 🎯 决策

**主选东财 push2 clist 单源三桶**（`GET https://push2.eastmoney.com/api/qt/clist/get`，与既有 EastMoneyClient 同域名族、复用 `EastMoneyHttpSupport` 的 UA + text/plain JSON 容错）：

| 桶 | fs（实测勘定） | 实测 total | 说明 |
| --- | --- | --- | --- |
| A 股沪深股票 | `m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23` | **5561**（深主板+创业板+沪主板+科创板） | 与需求口径一致（不含北交所） |
| 港股主板+创业板 | **`m:116+t:3,m:116+t:4`** | **2927**（主板 2616 + GEM 311） | **勘定**：`m:116+t:1` 实测为人民币柜台+房托桶（仅 485 只），非主板；权威定义取自东财行情中心页面 JS（`hk_mainboard=m:116+t:3`、`hk_gem=m:116+t:4`） |
| 沪深指数（Should） | `m:1+t:1,m:0+t:5` | 待 T54 首拉验证 | 同为页面 JS 权威定义（`index_sh`/`index_sz`）；中证 `m:2` 与港股指数 `m:124,125,305` 的 secid 前缀未沉淀，沿 V17 暂缓先例不纳入 |

配套实测结论：

1. **字段映射**：`f12` 代码（港股 5 位含前导零）/ `f13` 市场（**即 secid 市场前缀本身**：1=沪/0=深/116=港）→ `secid = f13 + "." + f12` 零映射表直派生；`f14` 名称；`f100` 行业（港股多为 `-` 置 null）。
2. **分页**：`pn`/`pz` 翻页，**服务端强制单页上限 100 行**（pz=500/1000 实测均只回 100 行、响应字节相同）；每轮页数 = A股 56 + 港股 30 = 86。
3. **限速（关键实测证据）**：带浏览器 UA、间隔 300~400ms 连续约 28 次请求全部成功；约 30 次密集请求后触发 **IP 级封禁**——`push2.eastmoney.com` 与 82/90/17 编号镜像、`push2delay` 全部 `Empty reply`（连接即断 <0.2s），>10 分钟未自愈（任务已知其历史上间歇恢复）；**datacenter/np-anotice 域名不受影响**。对策：默认页间隔 600ms（参数化）、日频 06:00 执行避开盘中、市场级放弃 + 下轮重试 + 手动补跑。
4. **完整性校验**：响应 `data.total` 为权威总数，累计行数不符即放弃该市场（防丢页假缺失）。

## 💡 理由

唯一同时满足五条验收要求的候选：三市场一接口同构（Client 一套代码）、字段含行业（备选均无）、`f13` 直即 secid 前缀（外部代码体系与取数链路零翻译层——这是行情/估值链路「新标的立即可取数」的结构前提）；且与既有 `EastMoneyClient` 同域名族，WAF 行为（UA 依赖、text/plain 漂移、IP 间歇封禁）已有工程对策沉淀（`EastMoneyHttpSupport`）。备选源字段/覆盖短板是硬伤，无法靠工程手段补齐。

## ⚠️ 影响

- 正面：A 股+港股一站拉全（86 页/轮，600ms 间隔 ≈2 分钟）；DTO 统一后换源只动 Client 一层；指数桶复用同一引擎（Should）。
- 负面 / 代价：push2 IP 级间歇封禁为持续运维事实（本轮实测再次复现）——依赖礼貌限速 + 失败下轮重试；源字段（fs/f100 口径）非契约，东财改版需跟改（URL/fields/fs 全参数化留门）。
- 需要跟进：T54 首拉记录指数桶 total（本轮实测因封禁窗口未取得）；连日失败时按备选路径人工切源（新浪仅 A 股——港股无备选，走需求兜底条款降级变更控制）。
- 对既有决策的影响：无（沿 Spike-1 公开免费源约束与 ADR-0003 统一数据访问层）。

## 🔍 后续验证方式

- T50 交付后连续 7 个交易日观察：每轮 SUCCESS 率、单轮耗时（预期 1.5~3 分钟）、86 页是否零封禁（间隔 600ms 假设验证；若触发则回调至 1000ms 并在此记录）。
- 首启建池后抽样 10 只新入库标的走详情/行情链路取数（故事 1 场景 3 的实证）。
- 每季度抽查 clist 字段口径漂移（f12/f13/f14/f100 语义变化会在完整性校验/映射单测暴露）。
