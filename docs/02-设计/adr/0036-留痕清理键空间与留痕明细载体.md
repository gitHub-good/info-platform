# ADR-0036：留痕清理键空间独立 + SUCCESS 行 error_message 复用为留痕明细 + 枚举白名单删除端口（REQ-20260925-07 / M10）

- 状态：已接受（2026-09-22，M10 留痕数据生命周期治理）
- 日期：2026-09-22
- 决策人：架构设计师（依据见[技术方案-留痕数据生命周期治理](/docs/02-设计/技术方案-留痕数据生命周期治理.md) §3）
- 关联：ADR-0017（配置中心/调度中心，本批直接复用）、ADR-0032（种子来源代码内置默认，同系列）、ADR-0035（深分页护栏——本批即其「清理优先」路径落地）

## 📌 背景

REQ-20260925-07 要求四张旁路留痕表（job_execution_log / data_source_event / llm_call_log / reading_event）定期清理，收编为 ManagedJob 任务中心 `RETENTION_CLEANUP`，窗口 runtime_config 可配热生效、误配双重防御、清理轮自身留痕（processed_count 合计 + 逐表明细）。PM 交接四项待定形态：retention 键空间（独立域文档 vs 并入 job 文档）、逐表明细留痕载体（errorMessage 只记失败的前提下成功轮明细记哪）、删除端口形态（四表各自实现 vs 统一工具）、删除批大小与 CRON 时刻。设计前代码核实：`job_execution_log` 的 `markSuccess` 将 error_message 显式置 null、SUCCESS 行该列恒空；`JobExecutor` 成功路径恒记 `(0,0)`；Job 日志页已渲染 errorMessage（truncate + title）；`SubjectRepositoryImpl` 已有 JdbcTemplate 先例；SQLite 默认构建未开 `SQLITE_ENABLE_UPDATE_DELETE_LIMIT`。

## 🎯 决策

### 1. retention 键空间：独立 `retention.global` 域文档（调度键 `job.RETENTION_CLEANUP` 另立）

窗口四字段（jobExecutionLogDays/dataSourceEventDays/llmCallLogDays/readingEventDays，整型 ≥ 表下限 7/2/35/35，无上限）独立成键；`job.RETENTION_CLEANUP` 只装调度语义（enabled/CRON/cron=`0 30 3 * * ?`），入 `JobRuntimeConfigSeeder` 第 7 键走通用 job 域校验零特例。理由：`job.{KEY}` 文档由通用校验器+类型化视图六键一套规则消费，并入窗口字段须三处开单键特例；JobScheduler 只订阅 `job.*` 变更重注册，窗口键每轮现读互不触发；对齐 `llm.global`/`aggregation.global` 域前缀惯例；防止「Job 文档塞业务参数」模式固化。

### 2. 逐表明细载体：SUCCESS 行 `error_message` 复用为「留痕明细」（零 DDL）+ JobRunStats 可选通道扩展

- `processed_count` = 四表删除合计；SUCCESS 行 `error_message` 写固定格式明细 `job_execution_log=n1; data_source_event=n2; llm_call_log=n3; reading_event=n4`（段序=枚举序），另发每轮 INFO 摘要日志。列语义由「FAILED 异常摘要」扩展为「终态附加信息」：FAILED=异常摘要（不变），SUCCESS=留痕明细（仅计数型 Job）。
- 通道扩展非破坏性：新增可选接口 `JobRunStats`（lastProcessedCount/lastRunDetail），`JobExecutionLog.markSuccess`/`JobExecutionRecorder.success` 各增带 detail 重载（原签名语义不动），`JobExecutor` 成功路径 instanceof 读取——六个既有 Job 不实现该接口，SUCCESS 行仍 (0,0) 且 error_message 为 NULL，字节级不变。FAILED 路径不动。

### 3. 删除端口：`RetentionLogTable` 枚举白名单 + 单端口 `ExpiredLogDeleter` + JdbcTemplate 子查询分批

- 枚举四项携物理表名/下限/默认窗口/JSON 字段名，是白名单与表级常量的单一事实源；端口签名 `deleteExpiredBefore(RetentionLogTable, Instant cutoff, int limit)` **收枚举不收字符串**——业务表名无从传入、无注入面（表名编译期常量拼接，cutoff/limit `?` 绑定）。
- SQL 形态 `DELETE FROM {t} WHERE id IN (SELECT id FROM {t} WHERE created_at < ? LIMIT ?)`：SQLite 默认构建 `DELETE … LIMIT` 不可用，子查询可移植且内层可走 created_at 索引。不改四表现有仓储端口（删除是横切生命周期关注点，集中一处可审计）。
- 判定：cutoff = now − 窗口**整秒截断**（两侧同为整秒 ISO-8601 文本，字典序=时间序），`created_at < cutoff` 严格早于——边界相等保留；job_execution_log 判定列取 created_at（V15 索引在列，与 start_time 同刻写入语义等价，countSince 先例）。

### 4. 执行参数留档：批大小 500 独立事务循环删；CRON 每日 03:30；种子默认启用

500 行/批毫秒级提交（首轮 15,987 行 ≈32 批亚秒~秒级，WAL 读写不互斥）；批大小为代码常量不入配置键。03:30 避开 06:00 标的池同步与 09:00 每日推荐；`retention.cleanup.enabled` 默认 true（首启即收敛存量），CRON 型测试隔离天然友好。

## ⚖️ 被否方案与理由

| 被否方案 | 理由 |
| --- | --- |
| 窗口并入 `job.RETENTION_CLEANUP` 文档 | 校验器/种子/任务中心视图三处单键特例；PATCH /jobs 契约混入非调度字段语义失真；诱导后续 Job 塞业务参数 |
| 每表一键（retention.{table} 四键） | 四字段恒同读同写，拆键徒增键数与部分写中间态 |
| 新增 `detail` 列（V19/U19 DDL） | 为 1/7 Job 的明细加列走全链路改动（迁移+实体+视图+前端列），与轻量批零 DDL 优先倒挂；PM 点名首选项即 error_message |
| 仅 INFO 日志记明细（不加字段） | 「逐表可读」只剩日志文件一途，Job 日志页读不到，故事 3 场景 1 验收面弱化 |
| 四仓储端口各扩 deleteExpiredBefore | 删除逻辑散四处、白名单失去单点、四份近似 SQL 难审计 |
| MyBatis `${}` 动态表名 Mapper | 与 JdbcTemplate 等价但引入字符串拼接模板面，枚举+JdbcTemplate 更直白 |
| DELETE … LIMIT 直写 | SQLite 默认构建未编译该开关，不可移植 |
| 批大小入配置键 | 执行细节非运维参数，配置面蔓延 |
| data_source_event/reading_event 补 created_at 单列索引 | 稳态 1.4 万/十行级全扫毫秒级，DDL 与收益倒挂；量级抬升走变更控制 |

## 💡 后果

- 四表获得统一生命周期治理：稳态 job_execution_log ≈11 万行（距 ADR-0035 50 万护栏 >4 倍），架构不变量「旁路留痕必须有节流与生命周期」生命周期半边闭环。
- error_message 列语义扩展为「终态附加信息」——后续 Job 若写入 SUCCESS 明细须遵循 `表名=行数` 段式约定；Job 日志页列头文案可顺带改「明细 / 异常」（T73 可选项）。
- `JobRunStats` 成为计数型 Job 上报轮次统计的标准入口（此前 JobExecutor 恒记 (0,0)，计数只能进 INFO 日志）。
- 零 DDL：无迁移与回滚脚本义务；运行回退 = 任务中心停用该 Job（键残留无害）。
- 净增 12 个后端类 + 2 个前端文件，改动 4 处（Seeder/JobExecutionLog/Recorder/JobExecutor）+ TaskCenter Dialog（Should）；任务 T70~T74 合计 5.5 人天。
