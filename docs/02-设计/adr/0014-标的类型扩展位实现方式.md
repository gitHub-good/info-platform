# ADR-0014：标的类型扩展位实现方式（T31）——预留标记 + 领域构建守卫 + adapter 类型支持自声明

- 状态：已接受（2026-09-22，T31）
- 日期：2026-09-22
- 决策人：开发工程师（依任务表 T31 + PRD「预留基金/债券扩展接口，不在本期实现」口径）
- 补充：ADR-0003（统一数据访问层）、技术方案 §4.2 subject_master / §4.4 SourceAdapter

## 📌 背景

任务表 T31 原文「SubjectType 枚举补 FUND/BOND 值（预留）」，目标为「新增一种标的类型的成本降到最小」。实现前盘点发现与任务表描述存在三处事实偏差：

- **枚举值已存在**：T01 落地的 `SubjectType` 已含 `FUND_RESERVED(4)`/`BOND_RESERVED(5)`，V1 DDL 同步预留了编码注释——T31 无需"补值"。
- **不存在标的创建接口**：系统无 REST 标的创建端点（标的经 V2 迁移种子落库），任务描述"既有接口校验拒绝预留类型"缺少承接面。
- **类型判断无 switch/if 散落**：聚合/订阅/推送/前端盘点确认核心链路均不分支标的类型；「股票专用」的隐含假设只存在于各 adapter 的 `external_codes` 取数逻辑（对任意类型标的都发起取数，靠源端无数据降级 MISSING），缺显式的类型→源注册点。

## 🎯 决策

**三件套落地扩展位，全部为追加式、既有契约零变更：**

1. **`SubjectType` 增补 `label`（中文标签）与 `reserved`（预留标记）字段**，附 `activeTypes()`（全部已开放类型的不可变集合）。预留类型在类型体系层完全开放（`fromCode(4/5)` 可还原，读路径不受限）。
2. **创建守卫放领域层 `Subject.Builder#build()`**：预留类型抛 `IllegalArgumentException`（信息含类型标签与编码）。因无 REST 创建接口，领域构建入口是所有当前/未来创建路径的唯一咽喉；未来新增创建端点时经全局异常处理自然映射 2xxx/400。读路径 `Subject.reconstruct` 刻意不走守卫（容忍历史/预留行回读）。
3. **类型→源注册位为 `SourceAdapter` 端口 default 方法 `supportedSubjectTypes()`**（自声明式，非中心映射表）：默认 = `SubjectType.activeTypes()`；股票专用源覆写收窄——财务/估值/公告六类（真实 + mock 各三）收窄为 `EnumSet.of(STOCK)`（F10 财务、PE/PB 个股估值语义、上市公司公告端点均为公司专属）。`AggregationService` 按声明过滤：不适用类型不调外部源，分区按既有 `missing` 三态降级（`sourceStatus` 契约不变）。

**新增一种标的类型（如基金启用）的全部动作**：① `SubjectType` 改非预留；② 各源 adapter 按需覆写 `supportedSubjectTypes()`；③ 提供 external_codes 映射种子。核心聚合/订阅/推送/前端零改动。

## ⚖️ 候选方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| adapter 自声明支持类型（端口 default 方法） | 注册位与源能力同处一类；新增源/类型互不牵扯（OCP）；mock/real 各自对齐 | 声明分散在各 adapter（经单测锁定一致性） | ✅ 采用 |
| 中心化 类型→源 映射表（配置或注册表类） | 全景一屏可见 | 新增任一源都要改中心表，违背"注册不改核心"目标；与既有 sourceCode 自标识风格割裂 | ❌ 否决 |
| 按 类型→adapter实例 注册（每类型一套 bean） | 类型间完全隔离 | 同一源要为每类型写重复 adapter；Spring 装配复杂度陡增，超出 1 人天预算 | ❌ 否决 |
| 新增 REST 创建端点仅返回预留类型错误码 | 满足任务表字面 | 为报错造接口，YAGNI；未来真实创建需求落地时契约还要再议 | ❌ 否决（守卫放领域层承接） |

## 💡 理由

PRD 明确首期不实现基金/债券，本任务的交付物是"扩展位"而非功能，故以最小改动把隐含假设显式化：预留标记让"未开放"成为机器可读状态（而非注释约定）；守卫收口在领域实体创建入口，比散在各应用服务校验更 DRY 且不依赖接口存在性；自声明注册位对齐既有 `sourceCode()` 自标识风格，`AggregationService` 的过滤逻辑对类型无感知（`contains` 判断），天然对新类型开放。股票专用源收窄到 STOCK 对现网零影响（存量标的全部为股票），对指数/板块标的反而省掉对财务/估值/公告端点的无效外呼。

对照选型五维度：成熟度（枚举标记 + 端口 default，JDK/Spring 常规手段）、社区（零新依赖）、学习成本（一个方法一个标记）、可替换性（未来切中心配置表仅需提取声明，消费方不变）、运维成本（无）。

## ⚠️ 影响

- 正面影响：新增标的类型改动面收敛为「枚举标记 + adapter 声明 + 种子」三处；股票专用源对指数/板块/预留类型不再发起无效外呼；预留类型的"未开放"状态可被校验逻辑与前端直接消费。
- 负面影响 / 代价：股票专用判断从"源端自然无数据"改为"取数前过滤"，若未来某源开始支持指数估值（如指数 PE），需显式放宽该 adapter 声明（一次性、可测试）；`supportedSubjectTypes()` 声明分散，靠单测锁定 mock/real 一致。
- 需要跟进的事项：基金/债券启用时按上述三步开放，并评估是否需要新错误码替代 `IllegalArgumentException` 映射（届时新增创建接口一并处理）。
- 接口契约影响：无。`GET /api/v1/subjects/{id}/detail` 响应结构不变；不适用分区沿用 `sourceStatus=missing`（既有三态）。前端无类型分支（`SubjectType` 联合类型已含 4/5，`MARKET_LABEL` 有兜底），零改动。
- 数据迁移影响：无（无新增迁移，V1 已预留 subject_type 4/5 编码）。

## 🔍 后续验证方式

- `SubjectTypeTest`（编码/标签/预留标记/activeTypes 不可变/fromCode 开放与未知编码 fail fast）、`SubjectTest`（开放类型构建不回归、预留类型拒绝且错误信息可定位、reconstruct 读路径放行）。
- `AggregationServiceTest`（不适用类型跳过 fetch 且分区 missing、默认声明覆盖指数/板块）；三个真实 adapter 测试类与 `MockSourceAdaptersTest` 锁定六源声明（股票专用收窄、通用源默认）。
- 回归：`mvn verify` 全绿（616 tests，spotless/jacoco 门禁通过，改动类行覆盖 89%–100%）；运行时冒烟——股票详情七分区、sections 过滤、30001/2001 异常路径、自选清单加标的均正常。
