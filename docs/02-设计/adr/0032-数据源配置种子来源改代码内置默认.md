# ADR-0032：数据源配置种子来源改代码内置默认——application.yml 删除 `adapter:` 段，页面配置即唯一真相 + 备选源开关热化

- 状态：已接受（2026-09-22，M7 后配置来源收口）
- 日期：2026-09-22
- 决策人：开发工程师（依用户决策「数据源配置改为页面（runtime_config DB）唯一来源」；架构口径不变，ADR-0017 仍有效）
- 补充：ADR-0020（同构先例：LLM 配置去 yml 化 / LlmDefaults）、ADR-0017（运行时配置热生效：seed-if-absent + 快照）、ADR-0030（A 股列表源备选）、ADR-0031（行情/估值腾讯备选源）

## 📌 背景

ADR-0017 落地（T34~T36）后数据源域已是「runtime_config `datasource.{CODE}` 7 键 + 页面可改 + LIVE 热生效」，但 application.yml 仍残留 `adapter:` 段，形成与 ADR-0020 改造前 LLM 域完全同构的双来源：

- **种子双轨**：`DataSourceRuntimeConfigSeeder` 的 params 种子值取 `adapter.*` yml 绑定（@Value），超时/重试/TTL 却取代码内置 `DataSourceDefaults`——同一颗种子两个来源，认知割裂；
- **启动期绑定的残留开关**：`adapter.quote-source` / `adapter.valuation-source`（ADR-0031）与 `subject.sync.a-share-source`（ADR-0030）是 @Value **启动期绑定**——页面时代的例外：改这两个开关必须重启（ADR-0031 明言「启动期生效需重启」）；
- **永远不会再被改的配置文件**：日常调整（切源/改超时/换端点）全部发生在页面，yml 同名键只在首启空库时生效，是「看起来能配其实不生效」的陷阱；
- **两处缺口**：`adapter.eastmoney.announce-referer` 在 yml 有值但种子 params 缺键（T36 遗漏，client 每调用读 params 永远回落构造期值）；列表源端点（`adapter.eastmoney.list-url` / `adapter.sina.stock-*`）与腾讯端点（`adapter.tencent.quote-url`）无 SourceCode 归属，散落各 client 的 @Value 缺省。

## 🎯 决策

**删除 application.yml 的 `adapter:` 段（含 `subject.sync.a-share-source` 行），`DataSourceDefaults` 扩充为数据源配置单一事实源**（对齐 ADR-0020 `LlmDefaults` 先例），同时把三个备选源开关从启动期绑定升级为**运行时热读**：

### 1. 迁移范围（yml 键 → 新家，值不变只换存放地）

| 原 yml 键 | 新家 |
| --- | --- |
| `adapter.mock.enabled=true` | `DataSourceDefaults.DEFAULT_MODE=MOCK`（分源 mode 种子缺省 + ConfigCenter 缺键回落，T36 语义平移） |
| `adapter.eastmoney.quote-url` / `fields` / `valuation-fields` | `params(QUOTE/VALUATION)`（T36 已有，本次核对无漂移） |
| `adapter.eastmoney.finance-url` / `finance-referer` | `params(FINANCE)`（已有） |
| `adapter.eastmoney.announce-url` / `announce-page-size` / `announce-detail-url-template` | `params(ANNOUNCE)`（已有） |
| `adapter.eastmoney.announce-referer` | **补齐** `params(ANNOUNCE).announceReferer`（T36 缺口：client 已热读但种子缺键） |
| `adapter.sina.news-*`（5 键） | `params(NEWS)`（已有） |
| `adapter.gov.policy-url` / `policy-referer` | `params(POLICY)`（已有） |
| `adapter.eastmoney.list-url` | 常量 `DataSourceDefaults.EASTMONEY_LIST_URL`（列表源无 SourceCode 键，构造期缺省） |
| `adapter.sina.stock-list-url` / `stock-referer` | 常量 `SINA_STOCK_LIST_URL` / `SINA_STOCK_REFERER`（原就无 yml 行，值即代码缺省，收口防漂移） |
| `adapter.tencent.quote-url` | 常量 `TENCENT_QUOTE_URL`（行情/估值共用端点，构造期缺省，RESTART 级） |
| `adapter.quote-source` / `adapter.valuation-source` | **热化**：`datasource.{QUOTE,VALUATION}.params.backupSource`（见决策 2） |
| `subject.sync.a-share-source` | **热化**：独立键 `subject.sync` 文档字段 `aShareSource`（见决策 2） |

三处用途共用同一份常量（不漂移）：① `DataSourceRuntimeConfigSeeder` 种子值（去 @Value，直读 DataSourceDefaults）；② `ConfigCenter` 缺键回落（`adapter.mock.enabled` @Value 退役 → `DEFAULT_MODE`）；③ 各 client 构造期回落缺省（@Value 全部退役，Spring 构造直取常量，测试全参构造保留指定值能力）。

### 2. 备选源开关热化（语义升级：RESTART → LIVE）

- **行情/估值**：`datasource.{QUOTE,VALUATION}.params.backupSource`（oneOf `auto | eastmoney | tencent`，缺省 `auto`）；消费点 `QuoteSourceAdapter` / `ValuationSourceAdapter` 的 `doFetch` **每次取数用时读快照**（经 `AbstractSourceAdapter.configCenter`），页面保存下一次取数即新源。原「配置笔误启动 fail-fast」语义由写路径 oneOf 校验接管（`DataSourceConfigValidator` params 分支）；读取侧对 DB 手改坏值 WARN 回落 auto 兜底（不阻断取数）。
- **A 股列表桶**：独立键 `subject.sync`（文档 `{"aShareSource":"auto|eastmoney|sina"}`，新种子 `SubjectSyncRuntimeConfigSeeder` + 校验器 `SubjectSyncConfigValidator`）；消费点 `RoutingSubjectListSource.fetchAll` 每次取数读快照，同款坏值 WARN 回落。未并入 `job.SUBJECT_SYNC`（调度语义键不混取数行为）也不并入 datasource 键空间（列表源无 SourceCode）。
- **契约增量**：`datasource.{QUOTE,VALUATION}` 的 params 新增 `backupSource` 键、`datasource.ANNOUNCE` 的 params 新增 `announceReferer` 键、新键 `subject.sync`——配置页 params 为透传 Map，页面响应自然多出这些字段（前端无需改动即可编辑，值受后端 oneOf/URL 校验）。

### 3. 不变项

① 接口契约（除上述 params 键增量）、键空间主体、校验规则框架、LIVE/RESTART 分级全部不动；② 已有库的 runtime_config 行不受影响（seed-if-absent，页面改过的值权威）；③ 全新库首启播种结果与旧 yml 种子同值（`fields` 以 yml 值为准含 f168——运行时口径本就来自种子，client 构造期旧缺省漏 f168 从未生效）；④ 测试隔离语义等价平移：测试 profile 无 adapter 覆盖 → 种子 mode=MOCK（`DEFAULT_MODE`），与改造前「yml mock.enabled=true → MOCK」完全一致。

## ⚖️ 候选方案对比

| 方案 | 结果 |
| --- | --- |
| 保留 yml `adapter:` 段不动 | ❌ 双来源认知成本持续；开关类必须重启，与页面时代语义相悖 |
| yml 保留但加注释「仅首启种子」 | ❌ ADR-0020 已证伪：注释救不了语义 |
| **代码内置 `DataSourceDefaults` 扩充 + 开关热化（本 ADR）** | ✅ 单一事实源；数据源参数只剩页面一个入口；开关热生效对齐 mode/超时等同级语义；对齐 ADR-0020 先例 |
| 开关热化但保留 yml 键作为种子 | ❌ 热化后 yml 值仅在首启空库时生效，与页面默认 auto 无差别——死配置 |

## ⚠️ 影响

- 正面：数据源配置（URL/字段/referer/条数/开关/模式/弹性）只剩页面一个入口；三个备选源开关改完即生效（原需重启）；`DataSourceRuntimeConfigSeeder` 76 行 @Value 绑定退役；client 构造不再依赖配置文件键。
- 负面 / 代价：改「出厂缺省」（如端点迁移）从改配置文件变为改代码 + 发版——但这些值本就只在首启空库时生效，页面已可覆盖一切；开关热读在取数路径多一次快照读（内存 Map 读取，可忽略）。
- 行为兼容：已有库无感（DB 值权威）；全新库首启播种与旧 yml 同值（迁移测试锁定）；`announceReferer` 首次真正进 DB（此前种子缺键但 client 回落值相同，行为不变）。
- 测试影响：`DataSourceRuntimeConfigSeederTest` 从「yml 属性注入断言」改写为「DataSourceDefaults 防漂移断言」；Quote/Valuation Fallback 测试的 fail-fast 键名改为运行时键名；`RoutingSubjectListSource` 保留 3 参构造作为固定模式测试口径。

## 🔍 后续验证方式

- `DataSourceDefaultsBootstrapTest`（@SpringBootTest，yml 已无 `adapter:` 段，对齐 ADR-0020 `LlmDefaultsBootstrapTest` 模式）三条语义保证：① 全新库首启 7 键 + `subject.sync` 由内置缺省播种、视图全链路可用（含 backupSource/announceReferer/MOCK 隔离）；② DB 已有值再走启动就绪（重启模拟）不覆盖页面权威值；③ 备选源开关写 runtime_config → 快照换 → 视图即新值 + 非法值被 oneOf 拦截。
- `BackupSourceHotSwitchTest`（行为层）：同一 adapter/路由实例两次取数之间换快照值即走新源（无重建 bean）；坏值 WARN 回落 auto。
- 全量 `mvn verify` 回归（1196 基线只增不减）。
