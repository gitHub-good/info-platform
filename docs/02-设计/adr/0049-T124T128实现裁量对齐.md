# ADR-0049 · M15 T124/T128 实现裁量对齐（任务文本与方案原文的出入，方案为准）

- 状态：已接受（2026-09-22）
- 关联：ADR-0046（M15 六裁决）/ ADR-0048（任务文本出入以方案为准的先例）/ [技术方案-V2.0-M15](../技术方案-V2.0-M15-AI归类与分析管道.md) §4.5/§4.7/§4.8
- 需求：REQ-20260926-12（任务派发单 T124/T128，后端收尾批）

## 背景

T124（行业日报 Job）/ T128（疑似停更标记）任务派发文本与 M15 技术方案（权威）存在多处表述出入，另有两处方案授权范围内的实现裁量。
按「不改契约先回架构留痕」的协作规则（ADR-0048 同款流程），本 ADR 逐条记录——**涉及契约的全部以方案原文为准落地**。

## 裁决

### 1. 日报重试端点：`/retry`（方案冻结），不引入 `/regenerate`

- 任务文本：`POST /api/v1/industry-reports/{date}/regenerate`。
- 方案 §4.8：`POST /api/v1/industry-reports/{reportDate}/retry` —— 重试 FAILED 日报（202 受理走 JobExecutor 手动通道）。
- **落法**：按方案落 `/retry`。任务文本的「regenerate 幂等替换」语义在方案中对应 **FAILED 行 UPSERT 整行替换**（§4.5 步骤 4），
  已由实现覆盖；SUCCESS 行不提供替换入口（幂等红线，见裁决 2）。
- 理由：端点路径是 §4.8 冻结契约（T126 前端契约 mock 已按方案先行）；同义双端点 = 契约面翻倍无收益。

### 2. 错误码归属：30077=已成功重试 409 / 30078=不存在 404（方案冻结，任务文本两码对调）

- 任务文本：单日详情不存在 30077、regenerate 冲突 30078。
- 方案 §4.8 + ADR-0048 裁决 2：`30077 INDUSTRY_REPORT_ALREADY_SUCCESS(409)` / `30078 INDUSTRY_REPORT_NOT_FOUND(404)`，
  且 ADR-0048 已明确「30077 保留给 T124 日报已成功重试 409，本批不占用」。
- **落法**：按方案/ADR-0048 分配；详情与重试共用 30078（不存在）、重试独占 30077（已 SUCCESS 409）。

### 3. 手动重试范围：任意 FAILED 日期（方案未设限），不限「当日/前日」

- 任务文本：`regenerate（手动重生成当日/前日）`。
- 方案 §4.8：重试 FAILED 日报——未限定日期范围；§4.7 Job 职责「含 FAILED 重生成幂等」。
- **落法**：任意 FAILED 行均可重试（端点校验 FAILED 即受理）。实现载体：`IndustryDailyReportJob.armRetry(date)` 武装指定日 +
  `JobCenterFacade.trigger`（JobExecutor CAS 守卫 + job_execution_log 留痕 = 方案「202 受理走手动通道」）；trigger 未受理（409
  运行中）时 disarm 回滚，不污染下一轮定时语义。定时路径不受限（补跑窗口 [前日, 昨日]）。

### 4. FUSED「留痕次日补」实现：定时补跑窗口 [前日, 昨日]

- 任务文本：`FUSED 跳过（留痕次日补）`；方案 §4.6：FUSED 全跳 + 换日窗口滚动自动恢复。
- **落法**：`runScheduledWindow` 每轮逐日生成 [前日, 昨日] 两天（oldest first，SUCCESS 幂等跳过）——被 FUSED 跳过的日期最迟在
  次日定时轮补齐；正常态只有昨日缺行，行为与单日生成等价（每轮恒定 ≤2 次生成，无重复成本）。

### 5. 空数据日不调 LLM（成本裁量）

- 方案未覆盖：昨日零资讯零事件时是否调用 LLM。
- **落法**：空数据日直接产出纯统计版（summary 固定「数据冷清日」文案，narrativeDegraded=false——非失败），不调 LLM、不发完成
  通知。理由：模板禁止引入未提供数字，空输入下叙述无从展开；省一次调用成本。

### 6. T128 停更标记载体：`info_source.config.staleSince`（方案冻结），不加列零 DDL

- 任务文本：`载体：config.staleSince 字段热写 or 独立列——按 ADR-0048 的 config 模式裁量`。
- 方案 §4.7：`info_source 展示态打标（config.staleSince 写入日，恢复入库清除）`。
- **落法**：按方案走 config 字段（`SourceConfig.staleSince` + Codec 编解码；null 不落键——存量 JSON 字节级不变，ADR-0048 裁量 1
  同款）。补两处一致性承载：① PATCH 编辑配置时保留既有 staleSince（页面不改写 Job 运行态）；② 源管理页卡片与大盘源维度行
  透出 `staleSince`（徽章数据面，T126 前端消费）。不进 SourceConfigPayload（请求面不可写，Job 独占写入）。

### 7. 停更阈值分级：月频源 35 天窗（方案授权裁量）

- 任务文本：`停更阈值按源频控分级（月频源 35 天窗，你裁量实现）`；方案 §4.7：连续 7 个 stat_date new_count=0。
- **落法**：缺省窗 7 天；月频源清单常量 `MONTHLY_SOURCE_CODES = [em_macro_indicators]`（东财宏观指标序列月更）走 35 天窗——
  清单常量对齐 `FeedDashboardService.DAILY_GRANULARITY_CODES` 先例（新日粒度源时在此登记）。判定 = 窗内 `source_daily_stats`
  净入库（Σnew_count）= 0 且源龄 > 窗长（新建源不满窗不误标）；恢复 = 窗内任一日净入库 > 0 即清除标记（自动解除）。

### 8. T128 Should 通知裁剪

- 方案 §4.7：`+ Should 通知；不自动停用`。
- **落法**：本批只落标记与解除 + 数据面透出，通知裁剪留档（Should 语义可裁；日报/告警通知通道已繁忙，停更徽章在源管理页与
  大盘可见即达意）。后续需要时走 PushService 既有广播通道加一行。

## 后果

- T126 前端拿到的 industry-reports 三端点与 30077/30078 语义自首个提交起即与方案 §4.8 一致；源管理页/大盘拿到 staleSince 徽章数据面。
- 任务文本的 `/regenerate` 与两码对调按 ADR-0048 先例不落地（方案为准）；如后续确需「强制重生成已成功日报」，走新 ADR 变更。
- 停更标记为展示态（不自动停用源），清除依赖恢复入库——长期停更源徽章持续显示是预期行为。
