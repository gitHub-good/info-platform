# ADR-0021：提示词版本号受控生成与排序——零 DDL + 服务端 bump 生成 + Java 数值排序（REQ-20260922-03 / M5）

- 状态：已接受（2026-09-22，M5 设计阶段）
- 日期：2026-09-22
- 决策人：架构设计师（依 REQ-20260922-03 风险表「版本号排序语义」+ 技术方案增补 §3.1/§4.1/§4.2）
- 补充：ADR-0016（v1.1 随迁移播种的先例）、ADR-0020（配置真源页面化的 M4 先例）、方案库 03（幂等，裁剪记录见增补 §2）

## 📌 背景

`prompt_template.version` 为 TEXT 语义版本（`v1.0`），`UNIQUE(brief_type, version)`；"取启用版本"查询为 `WHERE brief_type=? AND status=1 ORDER BY version DESC LIMIT 1`。两个既有事实：

1. **字典序错序风险**：TEXT 字典序下 `v1.10 < v1.9`。当前存量仅 v1.0/v1.1 无实际危害，但 M5 开放页面自由创建版本后必然出现两位数次版本。
2. **版本号至今无运行时生成通道**：v1.0（V8）与每日推荐 v1.1（V14）全部由 Flyway 迁移手写；PRD 要求"默认自动递增次版本、可选升主版本、冲突拦截、不让用户自由填写"（风险表裁定）。

同时 PM 已裁定（Won't）：不做变更审计日志（版本行即留痕）、单人场景。设计需回答：要不要为版本管理改表（如 created_by/备注列、数值版本列）？

## 🎯 决策

**prompt_template 零 DDL（无 V16/U16），版本号服务端受控生成，真实版本序由应用层表达：**

1. **不加列**：`created_by` 在单人系统（ADR-0002 裁剪 RBAC）恒为同一用户无信息量；备注/描述不在冻结需求内。最小改动。
2. **版本生成器（`PromptVersionGenerator` 纯函数）**：解析该场景全部既有版本 `^v(\d+)\.(\d+)$`（非法格式忽略 + WARN，防御手工改库）；`MINOR`（默认）= (maxMajor, maxMinor+1)，`MAJOR` = (maxMajor+1, 0)；用户只传 `bump` 不传版本号；`UNIQUE(brief_type, version)` 为冲突最后防线（409）。
3. **排序口径**：列表展示与"最新版"判定在 Java 按 (major, minor) 数值降序；`findActiveByBriefType` 的 `ORDER BY version DESC` 保持原样，仅作"唯一激活不变量被手工改库破坏"时的防御兜底（配合既有 `LIMIT 1`，双激活不致崩溃，正常态下该排序无实际作用）。

## ⚖️ 候选方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A 零 DDL：TEXT + 服务端生成 + Java 数值排序 | 无迁移无回填；与存量 v1.0/v1.1 零冲突；版本序消费点（列表/最新判定）本就在应用层 | DB 层无法用 ORDER BY 表达真实版本序 | ✅ 采用 |
| B version 改双 INTEGER 列（major/minor） | DB 可排序 | 迁移 + 存量回填 + PO/实体/仓储连带改造，而本期无任何 SQL 层版本排序需求 | ❌ 否决，代价与收益不成比例 |
| C 零填充字符串（v01.09→v01.10） | 字典序恢复正确 | 存量 v1.0/v1.1 需回填；展示观感差；99 之后仍要扩位，治标 | ❌ 否决 |

## 💡 理由

版本序的真实消费方只有两处——页面列表排序与"哪个是最新版"——都发生在应用层（每场景版本数个位数到几十行，全量读入后数值排序开销可忽略）。DB 字典序唯一残留点是有 74 行既有注释背书的防御性 `ORDER BY`，其正确性前提（唯一激活不变量）由 M5 管理接口的事务设计另行保证（增补 §4.6），不依赖排序正确。为一个无消费方的 SQL 排序能力做 DDL + 数据回填，违背最小改动；TEXT 语义版本（v2.0 对人的"大改"暗示）也是 Spike-2 §7.5 既定语义，值得保留。

## ⚠️ 影响

- 正面：迁移序列停在 V15/U15，T45 无迁移工作量；存量数据零触碰；生成链路查询语义零改动（即时生效结构不受影响）。
- 负面 / 代价：版本序正确性依赖应用层约定——任何人绕过接口手写 SQL 插入"v1.0.1"之类非两段式版本会被生成器忽略（WARN 日志可见），但不破坏运行（该版本仅无法成为自动生成的 max 基数）。
- 接口契约影响：POST /api/v1/prompt-templates 请求体只含 `versionStrategy`（MINOR/MAJOR，字段名对齐 UI 方案），响应回显生成的版本号（增补 §4.4.3）。
- 需要跟进：错误码 30066~30070 登记（ErrorCode，T45）。

## 🔍 后续验证方式

- 版本生成器单测：MINOR/MAJOR 两档、v1.9→v1.10 的排序断言（1.10 > 1.9）、非法格式忽略、空集起步 v1.0。
- 列表契约测试：versions 顺序按数值降序不按字典序。
- 回归：`findActiveByBriefType` 行为不变（既有 PromptTemplateRepositoryImplTest 全绿）。
