## 🧩 2. 分区轻量分页条基线（复用 M9 Pagination）

### 2.1 复用路径裁决（D1 展开）

PRD「交互形态统一裁决」留给 UI 的命题：分区轻量条（无每页条数选择器）与 M9 整页级 Pagination 是**一个组件还是两个**。裁决：**一个组件，Props 可选化**。

对比过派生方案 `SectionPagination` 后放弃的理由：

1. **行为重叠面 100%**：折叠算法（`getPaginationItems`）、单页精简态、total=0 整条隐藏、显示层 clamp 守卫、在途禁用、`aria-current`/`nav aria-label`/原生 button 键盘可达——分区条全部要、一样不缺；派生即复制，后续改折叠规则/可达性要改两处，必然漂移。
2. **差异面全部可 Props 化**：少条数选择器（=回调不传就不渲染）、页数封顶（=一个数字）、总数文案（=一个 ReactNode）、testid 前缀（=一个字符串）——没有结构性分叉，不需要第二个组件。
3. **向后兼容零回归**：4 个改动全部可选，Policy/JobLog 现有调用（`onPageSizeChange` 必传）行为不变，`pagination.test.tsx` 存量断言不破。
4. **不做薄包装**（分区公用一个 `SectionPagination` 包装再调 Pagination）：仅 2 个消费方（公告/事件）、6 个左右 Props，包装只加一层间接不加任何行为；分区差异（maxPages/totalLabel/label/testid 前缀）直接写在各分区调用点，可读性与可测性更好。

### 2.2 组件 Props 扩展（向后兼容，4 项）

```tsx
export interface PaginationProps {
  page: number;                       // 既有：当前页（1 起，受控）
  pageSize: number;                   // 既有：每页条数（受控；分区恒定，不提供切换）
  total: number;                      // 既有：总条数（total=0 → return null 不变）
  onPageChange: (page: number) => void;   // 既有
  onPageSizeChange?: (size: number) => void; // 必选 → 可选：不传即不渲染「每页 N 条」选择器（分区轻量态）
  disabled?: boolean;                 // 既有：在途禁用
  pageSizeOptions?: readonly number[];    // 既有（分区场景不传）
  label?: string;                     // 既有：分区传「公告分页」/「事件监控分页」
  maxPages?: number;                  // 新增：页数上限封顶（公告传 5）
  totalLabel?: ReactNode;             // 新增：总数文案覆盖（事件传「共 {total} 条（近 7 天）」；缺省「共 {total} 条」）
  testIdPrefix?: string;              // 新增：testid 前缀（缺省 'pagination' 存量不变；分区传 'announce-pagination' 等）
}
```

`maxPages` 语义（显示层封顶，不动 total 真值）：

```
effectiveTotalPages = min( Math.ceil(total / pageSize), maxPages ?? Infinity )
  - 页码折叠、页码指示「第 x / y 页」的 y、上一页/下一页禁用边界 → 全部以 effectiveTotalPages 计算
  - 「共 N 条」仍显 total 真值（公告 1074 条如实展示，不缩水成 50）
  - 显示层守卫沿用：current = min(max(1, page), effectiveTotalPages) clamp
```

单页精简态在分区下的形态：`total > 0 且 effectiveTotalPages = 1` → 仅「总数文案 + 第 1/1 页」，无翻页按钮、无条数选择器（事件场景 3 断言点）。total=0 整条隐藏（现状不变）。

### 2.3 分区条布局线框（D2）

```
分区卡片（以公告为例，lg 三列约 1/3 视口宽）
┌ Card · 公告                        [徽章 ok] ┐
│ ┌ 列表内容区（md:max-h-[26rem] md:overflow-y-auto）┐ │
│ │ 条目 1（标题 / 分类 · 时间 · 来源）              │ │
│ │ 条目 2 …                                          │ │
│ │ …（超出 26rem 内部滚动，分区头与底控件不随之滚走）│ │
│ └──────────────────────────────────────────────────┘ │
│ ─────────────── mt-4 border-t pt-4 ────────────────── │
│ 共 1074 条                            第 1 / 5 页      │
│ ⟨上一页⟩ [1] [2] [3] [4] [5] ⟨下一页⟩                 │
└───────────────────────────────────────────────────────┘
  容器类沿用 M9：mt-4 flex flex-wrap items-center justify-between
                gap-x-4 gap-y-2 border-t border-border pt-4

窄卡换行形态（lg 三列或更窄时自然发生，无需额外处理）
│ 共 1074 条                                            │
│ 第 1 / 5 页 ⟨上一页⟩[1][2][3][4][5]⟨下一页⟩           │
```

- 页码按钮/当前页高亮/省略号/上下页样式**逐条沿用 M9 §2.2**（ghost h-8 min-w-8 / default 高亮 + `aria-current="page"` / icon button + `aria-label` / `aria-hidden` 省略号）。
- 公告 5 页 ≤ 7 恒全显 `[1]~[5]`，折叠算法在分区场景实际不触发（封顶保证）；事件窗内条数通常 ≤ 几十页，折叠算法照常兜底。
- 可达性：容器 `<nav aria-label={label}>`（公告「公告分页」、事件「事件监控分页」），键盘 Tab/Enter 原生 button。

### 2.4 三态与交互细则（分区级）

| 态 | 触发 | 表现 |
| --- | --- | --- |
| 默认 | — | §2.3 布局；页码/上下页可点；条数选择器不存在 |
| 在途 | 分区翻页请求发出 | 全控件 `disabled`（防连点）+ 分区内容区 `aria-busy="true"` + 列表区轻微 `opacity-60`（可选，过渡 150ms）；**列表数据保留不闪骨架**（D9）；「加载中…」提示行**仅在翻页耗时预期较长时由页面态决定是否渲染**（事件本地查询快可省，公告外呼建议渲染 `text-xs text-muted-foreground aria-live="polite"` 于分页条上方） |
| 单页 | effectiveTotalPages=1 | 精简态：总数文案 + 第 1/1 页，无翻页按钮 |
| 隐藏 | total=0（含 ok 但空） | 整条 `return null`；分区空态由 SectionCard 既有兜底渲染 |
| 错误 | 翻页请求失败 | 组件本身纯受控不渲染错误；**分区卡片内**分页条上方错误行 `text-sm text-destructive role="alert"`「加载第 {p} 页失败：{原因}」+ outline sm「重试」（重发同一目标页）；当前页数据保留、控件恢复可用（点其他页=换目标重试的等效通道）；其他分区零感知 |
| 降级 | 公告备选源生效（巨潮） | 分页条整体不渲染，原位一行 `text-sm text-muted-foreground`「当前公告源不支持翻页」（§3.1） |

交互细则：

1. **切页**：点击页码/上一页/下一页 → 回调目标页 → 分区独立发请求；页码高亮保持当前页直到成功（不提前跳，失败后高亮与数据不错位——M9 同款）；成功后分区内**整体替换**条目 + **内容滚动容器 `scrollTop = 0`**（不是页面 `scrollIntoView`！卡片在页面中位置不动，只有卡内列表回到顶部——这是与 M9 页面级列表的关键差异）。
2. **键盘可达**：原生 button，Tab 聚焦、Enter/Space 触发；当前页 `aria-current="page"` 双通道（视觉 + 语义）。
3. **页大小恒定**：分区不发 size 切换（PRD Won't 8），`pageSize` 由分区语义固定（公告=announcePageSize 契约值、事件=10）。

## 📄 3. 四分区逐一设计

### 3.1 公告分区（页码分页 + 5 页上限 + 降级态 + 源站出口）

**常态（东财源，多页）**：§2.3 线框。`maxPages=5`，total 显真值。

```
第 1 页（共 1074 条，ceil=108 → 封顶 5）
│ 共 1074 条                        第 1 / 5 页 │
│ ⟨上一页·禁用⟩ [1*][2][3][4][5] ⟨下一页⟩      │

第 5 页（effective 末页 + total > 50 → 截断成立）
│ 共 1074 条                        第 5 / 5 页 │
│ ⟨上一页⟩ [1][2][3][4][5*] ⟨下一页·禁用⟩      │
│                      更多历史公告 ↗（源站）   │  ← mt-2 text-sm 右对齐外链
```

- **「更多历史公告」**：`target="_blank" rel="noopener noreferrer"` 的源站公告列表链接，`ExternalLink` 图标（lucide 已验证）+ `text-sm text-primary hover:underline`；渲染条件 `total > pageSize × maxPages && current === effectiveTotalPages`（截断语义，见 D4）。URL 来自契约（建议 announce 分区响应带 `moreUrl` 字段，§7.2 联判 2）；字段缺失时不渲染链接（防御缺省）。
- **降级态（巨潮备选生效）**：分区数据正常展示第一页（sourceStatus 仍 ok、来源标注含备选字样——现状机制），分页条位置替换为一行 muted「当前公告源不支持翻页」；无页码、无上下页、无「更多历史公告」（备选源无深翻能力，链接同样指向不明则不如不给；若契约能给备选源的源站列表 URL，则该行末尾追加「，去源站查看 ↗」——默认先按纯文案交付，URL 可得性归架构联判）。降级判定消费契约布尔（如 `paginationSupported: false`，§7.2 联判 2）。
- 首页条数=每页条数（announcePageSize 3→10 后），列表直出第 1 页，无「先给 3 条再补」的中间态。

**三态**：在途/错误/单页按 §2.4；`total ≤ pageSize`（如 8 条）→ 精简态「共 8 条 · 第 1/1 页」无翻页按钮、无源站链接（未截断）。

### 3.2 新闻分区（加载更多两态 + 去重 + 停止文案）

```
┌ Card · 新闻 [徽章] ──────────────────────┐
│ ┌ 列表内容区（md:max-h-[26rem] 内滚）─┐  │
│ │ 已加载条目（首屏命中 + 追加，不重排）│  │
│ │ …                                    │  │
│ └──────────────────────────────────────┘  │
│ ─────────── mt-4 border-t pt-4 ────────── │
│            [ 加载更多相关新闻 ]            │  ← idle：outline sm 居中
└────────────────────────────────────────────┘
```

| 态 | 触发 | 表现 |
| --- | --- | --- |
| idle | 首屏命中 > 0 | 按钮 `variant="outline" size="sm"` 居中，文案「加载更多相关新闻」；可点 |
| loading | 点击后请求在途 | 按钮 `disabled` + 文案「加载中…」+ `aria-busy="true"`（防连点；按钮自身即状态载体，不加独立状态行，D5） |
| appended | 成功且有新增 | 条目**追加**到列表尾部（既有条目不动、不重排、不闪变）；跨源页重复条目（同稳定标识）**去重后不渲染**，无「重复」视觉标记；按钮恢复 idle 文案；**首条新增条目 `scrollIntoView({ block: 'start' })` 滚入卡内视口**（内容区内滚，页面不滚） |
| stopped | 连续 2 源页无新增 / 源页耗尽 / 累计探页达 10 | **按钮移除**，原位渲染 `text-sm text-muted-foreground` 居中「没有更多相关新闻」；不再发出外呼（同一标的会话内终态；切标的重置后重新探测） |
| failed | 加载请求失败 | 已加载内容保留；按钮位置上方错误行 `text-sm text-destructive role="alert"`「加载更多失败：{原因}」+ outline sm「重试」（重发同一探页目标）；「加载更多」按钮同时恢复可用（等效重试通道） |
| 空态 | 首屏源第 1 页无命中 | 维持 SectionCard 既有 missing 兜底「本分区暂未返回数据」，无按钮（PRD 场景 5，现状语义不变） |

- 追加语义下列表 `key` 沿用 `item.id ?? item.title`（去重保障不重渲染，key 冲突无从发生）；去重判定用契约稳定标识（docid 级，归 T92 契约）。
- 单次点击最多探 2 个源页（首个空页自动续探）为后端/请求层语义，UI 无中间可见态（在途仍是一次「加载中…」）。

## 🧱 4. 卡片高度策略（三列网格重排裁决，D3 展开）

PM 交接命题：翻页/加载更多致条目数变化 → 三列网格同行卡片高度重排，两个候选——最大高度内滚动 vs 自然增高。**裁决：分档混合**。

| 断点 | 策略 | 理由 |
| --- | --- | --- |
| ≥md（两列/三列网格） | 列表内容区 `md:max-h-[26rem] md:overflow-y-auto`（416px ≈ 5~6 条两行条目 / 4~5 条三行事件条目）；分页条/加载更多/入口行/降级文案**常驻滚动区外** | ① 网格同行卡片共享行高（CSS grid 默认 stretch），自然增高下任一分区翻页 = 同行全部卡片跳动，直接违反「分区独立、零闪变」验收；② 卡片高度恒定后翻页只剩卡内内容替换，页面布局零位移；③ 概览页（七分区）若各卡自然长到 700px+，整页 2000px+，「全景概览」变长卷轴；④ 控件常驻滚动区外 → 翻页按钮/页码位置不动，连点下一页光标不移 |
| <md（单列） | 自然增高（无 max-h 无 overflow） | 单列各卡独立成行，高度变化不牵动邻卡（跳动痛点不存在）；移动端触摸嵌套滚动截获手势、体验有害；自然增高让移动用户线性扫读 |

**不做分区头 sticky**：SectionCard 结构为 CardHeader（头）+ CardContent（列表 + 控件），头与底部控件天然在滚动容器之外，滚动只发生在列表内容区——sticky 没有要解决的问题，从简不做。

配套细则：

1. 翻页成功：内容滚动容器 `scrollTop = 0`（§2.4 交互 1）；新闻追加：首条新增条目滚入视口（§3.2）。
2. 事件条目三行较高，同样 26rem 封顶（视口内能看 4~5 条 + 分页条，翻页可达其余，监控语义不损失——总数与页码可见即「没有静默截断」的透明性承诺）。
3. 骨架屏（页面首查）高度现状 `h-40`，与 26rem 内容区有差，首查→内容落地的卡片高度有一次跳变——**接受**（一次性、方向可预期，且属页面级首查通道而非分区翻页通道；为消这一次跳变把骨架加高到 26rem+ 反而拖慢视觉感知，不值）。

## 🔁 5. 联动语义（分区独立 × 切标的重置）

### 5.1 两类 loading 分离（M9 §5.1 平移到分区级）

```
页面级首查（挂载 / 切换标的 / 页面重试）
  → 现状 LoadingSkeleton 整页骨架（不动）；分区无独立骨架

分区级在途（公告/事件翻页、新闻加载更多）
  → 该分区列表保留 + 控件禁用 + aria-busy + （公告）「加载中…」行
  → 成功：分区内整体替换（新闻为追加）+ 卡内滚动定位（§4 配套 1）
  → 失败：保留当前内容 + 分区卡内错误行 + 重试（§2.4 / §3.2）
  → 其他分区零请求零重渲染零高度变化
```

### 5.2 状态联动规则（给开发的唯一事实源）

| 触发 | 分区 page | 数据呈现 | total |
| --- | --- | --- | --- |
| 挂载/切标的（聚合首查） | 1（初始） | 页面骨架（现状） | 响应带出 |
| 翻页点击（公告/事件） | 目标页 | 保留 + 在途禁用 | 不变 |
| 翻页成功 | 目标页 | 分区内整体替换 + 卡内滚回顶 | 以响应覆盖 |
| 翻页失败 | **回退显示当前页**（目标页收进重试闭包） | 保留 + 错误行 + 重试 | 不变 |
| 新闻加载更多成功 | —（无页码概念） | 追加 + 去重 + 首条新增滚入视口 | —（无 total 展示） |
| 新闻停止条件触发 | — | 按钮移除 + 「没有更多相关新闻」终态 | — |
| 切换标的（路由变化） | **全部分区重置**：page=1、新闻列表/停止标志/探页计数清零、错误态清空 | 新标的页面骨架 | 新响应 |

- **分区独立请求**：每分区独立 AbortController（M9 §5.4 平移）——同分区新请求 abort 旧请求；任何分区的请求生命周期不触碰其他分区 state。
- **切标的重置机制**（D8）：推荐 `App.tsx` `<SubjectDetail key={subjectId} …>`（JobLog key 先例，一行改动，全部分区状态随重挂载归零，无枚举遗漏风险）；若开发评估重挂载成本（如保留页面滚动位置诉求）选择 state 方案，按上表「切换标的」行逐项重置，测试按 PRD 场景 5.2 断言「不残留上一标的页码」。
- **埋点回归**：分区翻页/加载不触发新的 SUBJECT_DETAIL 阅读埋点（会话级 once 语义现状不动）；设计不新增任何埋点调用。
- **非 ok 分区**：不渲染分页条/加载按钮/更多入口（SectionCard 兜底机制自然满足，PRD 场景 5.3）；恢复 ok 后控件随内容出现。
