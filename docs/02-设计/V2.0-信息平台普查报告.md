## 📐 1. 调研方法与合规口径

### 1.1 实测方法

- **时间 / 环境**：2026-09-25，macOS + curl 8.x，境内网络（实测出口 IP 沪）。
- **请求形态**：标准浏览器 UA（Chrome 126 串）、无 cookie、无登录、无签名参数、每站 1~2 次请求（快讯接口带 `pageSize=5` 降噪）——**即平台后端可拿到的最朴素形态**，实测可得才计绿/黄。
- **robots.txt 判读**（抽查 38 个 host）：`200 且含 Disallow` → 逐条遵守；`404 / 空文件 / 302 跳页 / 403(AccessDenied)` → 按 RFC 9309 视为无限制（落地期仍逐源复核）。
- **证据留存**：响应体与元数据存临时目录 `/tmp/census-v2/out/`（60+ 文件，不入库）；报告中每行给「状态码 + 字节 + 内容片段」三段证据，可按 §7 方式复现。

### 1.2 分级判据（对齐合规红线：公开免费、无登录墙、无付费墙、无验证码体系、尊重 robots、不绕过反爬）

| 级别 | 判据 |
| --- | --- |
| 🟢 一级 | 无认证公开 RSS / JSON / 稳定 HTML，curl 直取 200 且内容字段完整，接入成本低（配置化可覆盖） |
| 🟡 二级 | 公开可得但需适配：HTML 模板解析 / 参数（sqlId、CATALOGID、Referer）按页面对照 / 频控严格（如人民网 Crawl-delay 120s）/ 结构稳定性需落地期验证 |
| 🔴 三级 | 登录墙 / 付费墙 / 强反爬（JS 盾）/ 接口需加密签名（逆向即违反红线）/ robots 禁止 / 境内网络不可达 |

## 🎯 4. 「30 平台」目标可达性结论

### 4.1 计数（平台口径，频道不重复计平台）

| 口径 | 平台数 | 明细 |
| --- | --- | --- |
| 已接入平台 | 5 | 东方财富、新浪、中国政府网、巨潮资讯、腾讯 |
| + 新增一级平台 | 4 | 金十数据、澎湃新闻、同花顺、MarketWatch |
| + 新增二级平台 | 24 | 官方 8 + 报纸 10（人民网·经济/中国经济网计入）+ 门户 6（腾讯资讯为已有平台新频道不计） |
| **一级+二级合计** | **33** | **≥ 30，达成，余量 3** |

### 4.2 结论与替代策略

1. **结论：30 目标在不触碰任何三级受限源的前提下可达成**（33 个平台，余量 3；若按频道口径，新浪 7×24、东财快讯、东财宏观、腾讯资讯等平台内新频道可再叠 4 条，弹性更大）。
2. **分期输入建议**（成本递增序）：第一批一级 7 频道（JSON/RSS 配置化即可）→ 第二批官方 HTML 8（政策域补强，与既有政策源同构）→ 第三批报纸媒体 11（资讯流横向铺量）→ 第四批门户 6（含格隆汇 payload、腾讯端点定位两个专项）。
3. **缺口兜底策略**（若 PM 要求 30 个均为「全新平台」——即不计已接入 5 家）：平台口径新增为 28，差 2。可按序补：① 平台内频道纵深（每平台 1~3 频道，东财/新浪/同花顺均有富余）；② 国际 RSS 横向扩展（Barron's/Nasdaq 等标准 RSS，逐个验 robots + 境内可达性后入池）。**不建议**采用 RSSHub 等第三方聚合服务补量——其路由多为对平台私有接口的逆向封装，与本平台合规红线冲突。
4. **不可达结论的稳健性**：三级中 5 家为「境内网络不可达」（FT/Reuters/Investing/Yahoo/BBC），属部署环境事实而非平台合规事实；若未来部署出口变化可重测，但当下按 V2.0 边界排除。

## 🧩 5. 通用采集框架技术可行性预判（简报级，不做设计）

1. **三类通用适配器均实证可行**：本次 45 个新候选的访问形态收敛为三类——**JSON 直连**（金十/东财/同花顺/澎湃/深交所等 9 条，差异仅在分页参数与字段名，可复用既有 FieldMapper 白名单映射）、**HTML 模板源**（官方+报纸 19 项，差异在列表选择器与编码——同花顺 HTML 为 GBK、gov.cn 已有 GovPolicyClient/Jsoup 先例）、**RSS 标准源**（MarketWatch 1 条，标准化程度最高，Rome 或轻量自解析均可）。财联社式的「签名 API」、智通式的「JS 盾」**不设适配器**——它们属于红线外，不是技术问题。
2. **源注册表从「代码事实」演进到「DB 可运营」**：一句话评估——架构影响小、方向正确：与既有 runtime_config / 降级链热生效（ADR-0031~0033）同构，把「源 = 类型 + 端点模板 + 字段映射 + 频控 + 降级链」落成配置行即可；真正的新增复杂度在**30+ 源的调度层**（同源频控合并、失败事件同源节流——恰是 M8~M10 backlog 已挂账的项），任务中心需支持按源注册化调度与并发上限。详细设计（含表结构与 ADR）待路线图定稿后在 V2.0 技术方案中展开。
