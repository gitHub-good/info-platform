### 目标（对齐 REQ 目标节，可量化）

1. **四级管道**：当日资讯 L0 零成本预筛（noise 隔离 + 近重复关联主条）→ L1 批量归类（35 选 1 + 次行业 + 置信度 + 低置信兜底）→ L2 事件提取（重要性预筛 ≤20% 配额 + ≥8 类结构化事件 + 标的回联）→ L3 热度聚合（24h/7d 快照 + 每日日报）。
2. **时效与质量基线**：T+30min L1 归类率 ≥95%（口径：`classified_at − fetched_at ≤30min` 占比）；L2 当日高价值覆盖 ≥80%；抽检归类准确率 ≥85%、事件结构完整率 ≥90%。
3. **三页面**：`#/industry-heat`（第 16 页，热度榜/日报双 Tab）+ `#/events`（第 17 页）；榜单/事件流/日报计数全链路对账一致。
4. **成本护栏**：管道日成本 ≤管道日预算 60% 触顶自动降级只保 L0+L1（缺省预算 ¥2/日，§4.6）；二级熔断 90%；次日自动恢复 + 24h 补跑；单条成本校准版本化（初值 ¥0.0011/条，实测+推算，附录 A）。
5. **M14 遗留闭环**：21 财经条款预检承载（源级「AI 深度分析排除」配置与标注，两分支语义按 REQ 拍板五-1）+ AMB-01「疑似停更」自动标记（Should，T128）。
6. **零回归**：既有 8 Job、13 源采集、15 页面、提示词治理既有 4 类模板、1773 测试基线只增不减。

## ⚖️ 3. 形态决策（六项架构级裁决，统一记 ADR-0046）

### 3.1 管道产物独立建表，`news_item` 零改动（裁决 1）

**裁决**：L0~L2 逐条状态与归类产物落**独立 1:1 表 `news_analysis`**（+ 事件表 / 快照表 / 日报表，共四张，V23）；`news_item` **不加一列**（连 V22 注释预留的 `status=3` 垃圾标记也不启用——noise 标记落 `news_analysis.l0_result`，资讯流默认查询零改动 = noise 条目天然「保留可查」）。

**理由**：① 管道逐条状态约 14 列（l0 结果/近重复引用/重要性分/l1 三态+枚举+置信度+回联/l2 六态+尝试数），塞进 news_item 会把 feed 域表变成管道表，违反方案库 01「表归属单一模块」红线；② 摄取热路径（INSERT OR IGNORE 批量）零波及 = M13/M14 回归面最小化；③ U23 回滚 = DROP 四表，news_item 数据与索引无伤。**代价**：热度聚合/下钻需 join（日窗口 ≤700 行、7d ≤4.4k 行，走 `idx_news_published` 窗口扫 + UNIQUE(news_id) 命中，毫秒级，可接受）。

**被否**：①news_item 加列（上述三条理由反向）；②管道状态塞 runtime_config / 内存（丢状态、不可对账）；③noise 用 news_item.status=3（语义挤占「源归档」同列三维状态，且资讯流默认查询需改排除逻辑——违背「noise 可查」反而要做查询特判）。

### 3.2 批量调用形态：20 条/次 + JSON mode 对象包裹数组 + 对半拆批（裁决 2，实测背书）

**裁决**：L1 批大小缺省 **20**（可配 10~30）；输出 schema 为**对象包裹数组** `{"results":[{id, main, sub, confidence, reason}]}`（DeepSeek JSON mode 只保证输出合法 json **对象**，裸数组有解析风险）；失败处理 = **对半拆批递归至单条**（整批调用异常或整体解析失败 → 拆半重试；部分行无效 → 有效行落库、无效行合并进重试批；单条仍失败 → `FAILED` 计入统计，当日重试 ≤3 次）。**实测背书**（附录 A，2026-09-22，20 条真实当日资讯一次调用 deepseek-flash）：格式可靠 20/20、id 全对齐、8.1s、prompt 1783 + completion 1833 token、¥0.009115/批 = **¥0.000456/条**（L1 预算 0.01 元/条的 4.6%）。批大小 20 vs 30 成本近乎无差（输出 token 主导），取 20 = 更小失败爆炸半径 + 更短时延；>30 禁配（拆批深度与输出截断风险）。

**被否**：①逐条调用（20 倍调用次数与 system prompt 重复成本，且 T+30min 无必要）；②50+ 大批（输出 token 上探 8k 截断风险，失败重试代价翻倍）；③失败整批原地重试（批内失败粒度不可知，重试大概率同因失败浪费预算——拆批即二分定位）；④管道调用走 LlmCache（同批重试会命中同一份坏输出——`LlmRequest` 增 `cacheable=false` 绕开，§4.3）。

### 3.3 管道提示词入治理页：BriefType 扩 5/6/7，35 枚举代码侧权威（裁决 3）

**裁决**：REQ 条目 10 已锁 Must（3 类模板入 M5 体系）——落点为 **BriefType 枚举扩 3 码**：`5 行业归类 / 6 事件提取 / 7 行业日报`，V23 播种 v1.0 模板（含 35 枚举清单 + few-shot 示例），治理页/占位符注册表/版本化热生效零特例复用。**边界**：模板文本中的枚举清单可被页面编辑，但**校验权威是代码侧 `IndustryCategory` 常量**（35 值白名单）——模板枚举被改坏 → 输出非法枚举行按拆批规则处理并计入失败统计（可观测的模板漂移信号，不静默吞）。占位符：归类/提取用 `{{batchSize}}/{{items}}`，日报用 `{{reportDate}}/{{industryStats}}/{{topEvents}}`（注册表登记描述符，ADR-0022 惯例）。

**理由**：归类提示词是本批最大不确定点（REQ 风险表首条「连续两周抽检 <80% 触发模板调整」），页面热生效 = 抽检不达标当天可迭代，不发版；代码侧白名单同时守住「枚举漂移」底线。

**被否**：①模板做代码常量（丢 M5 热生效迭代能力，违背 REQ Must）；②枚举清单只存模板（校验无权威，热度榜聚合面被页面编辑左右）。

### 3.4 管道 Job 组织：4 个新 ManagedJob，调度池 8→12（裁决 4）

**裁决**：新增 `NEWS_PIPELINE`（FIXED_DELAY 10min，L0+L1+L2 三段顺序编排、段间独立容错）、`INDUSTRY_HEAT_SNAPSHOT`（FIXED_DELAY 30min，零 LLM）、`INDUSTRY_DAILY_REPORT`（CRON `0 0 8 * * ?` 可配）、`SOURCE_STALE_CHECK`（CRON `0 10 4 * * ?`，T128 疑似停更，独立小 Job 而非搭车——验收要手动触发 + 单 Job 失败不阻塞语义干净）。JobScheduler 池常量 8→12（FIXED_DELAY 任务长驻占线程，ADR-0040 同款论证）。L0 挂接点：**随 NEWS_PIPELINE 批窗口跑，不挂入库同步**（近重复需对 24h 池比较天然批式；动 M13 摄取事务 = 徒增回归面；T+30min 不受影响——L0+L1 同 tick 完成）。测试隔离：4 键种子走 `@Value` 缺省 true、test profile false → 零注册（八 Job 同惯例）。

**被否**：①L0/L1/L2 各一 Job（三段强顺序依赖，拆开要跨 Job 传窗口状态，留痕噪音 ×3）；②近重复检查挂入库（见上）；③停更检查嵌入 RETENTION_CLEANUP 尾步（跨域搭车，验收与故障隔离语义混浊）。

### 3.5 护栏：llm_call_log scene 口径 + 无表派生，不做内存计数（裁决 5）

**裁决**：管道日成本 = `SELECT SUM(cost_micros) FROM llm_call_log WHERE scene_key IN ('5','6','7') AND status='SUCCESS' AND created_at >= 当日零点(Asia/Shanghai)`，**每次批执行前现算**；护栏级别**无表派生**：`cost ≥ 90%×预算 → FUSED`（管道 L1/L2/日报全停 + 通知告警一次）、`cost ≥ 60%×预算 → DEGRADED`（跳过 L2，L1 与日报保留——REQ 拍板四-1「暂停 L2 与日报外的 AI 生成」= 日报存活）、否则 NORMAL。换日查询窗口自动滚动 = **次日恢复零代码**；降级期间只入库未处理条目由 24h 待处理窗口自然补跑。告警态内存节流（重启重告一次可容忍，ADR-0045 同款）。预算缺省 **¥2.00/日**（micros 2,000,000；按实测单条 ¥0.0011 × 632 条/日 ≈ ¥0.70 正常水位 35%，留 3 倍放量余量），`pipeline.budget` 可热改。

**被否**：①内存计数器（LlmCostGuard 同款）——重启清零、与 llm_call_log 报表口径漂移（ADR-0015 已立「严格口径以留痕表为准」先例，本裁决直接用权威源）；②新建护栏状态表（状态可由成本现算纯派生，落表 = 双写一致性问题 + 换日清理逻辑）；③管道预算挂 M3 用户预算（userId=0 跳过限流是既有语义，动它波及全部系统调用）。

### 3.6 热度权重 K1 缺省 = 10（REQ 建议值 3 的算术勘定，裁决 6）

**裁决**：K1 缺省 **10**（可配，basis 版本化），重要度系数 HIGH=1.0 / MEDIUM=0.5 / LOW=0.25、半衰期 24h 窗 12h / 7d 窗 48h。

**论证**：REQ 故事 2 场景 2 是冻结验收（「A 10 条含 2 条高事件 不低于 B 30 条无事件，K1 缺省权重框架下」），但 REQ 拍板三自注 K1=3（一条高事件 ≈ 4 条资讯）——代入：A = 8×1 + 2×(1+3) = 16 < B = 30，**验收必挂**。即使计入衰减（B 均匀分布 24h、半衰期 12h → B 有效 ≈16.2；A 集中近 1h → A ≈ 9.4 + 1.88×K1），K1=3 仍差 7 分。K1=10 使同新鲜度构造（最严读法）A = 28+2×11 = … 重算：A = 8 + 2×(1+10) = 30 ≥ 30 成立，含衰减时留有裕量。拍板三末句「权重取值与实现归架构」授权本勘定；K1=10 语义 = 一条高重要事件 ≈ 11 条普通资讯（「降准级」事件应显著主导「哪里在起变化」榜单），与 31 行业日均 ~20 条/业的量级匹配。首跑校准若嫌事件独大，热改 `pipeline.heat.k1` 即可（basis 串随快照/榜单下发，不静默）。

**被否**：K1=3（验收算术不成立）；K1=5+依赖「测试构造新鲜度差」过关（验收语义存疑，不如正面勘定缺省值）。

### 4.2 L0 规则预筛（领域服务纯函数，零 LLM）

**挂接点**（裁决 4）：`NEWS_PIPELINE` tick 内、L1 之前。每 tick：取「入库已过 X 分钟仍未有 analysis 行」的 news_item（X=2min 缓冲，避免与摄取事务竞态；实为 `LEFT JOIN news_analysis WHERE na.id IS NULL AND created_at <= now-2min`）批量建 `news_analysis` 行并跑两段判定：

**① noise 规则**（`NoiseRuleEngine`，规则可配 `pipeline.l0`）：
- 关键词表（标题或摘要命中即 NOISE）：缺省种子 `广告/推广/开户/开户礼/佣金万/礼包/课程/直播间的优惠/赞助/征文/订报/读者福利/招聘启事` 等 ~15 词（开发可在种子内按 13 源实情增删，留档于常量注释）；
- 正则表（缺省 3 条）：纯链接/短码帖（`^https?://\S+$`）、财富课程营销（`(免费|限时).*(领取|报名|听课)`）、平台自宣（`关注(本台|我们).*(公众号|频道)`）；
- 命中即 `l0_result=NOISE`，`l0_detail` 记规则名——**零误删兜底**：NOISE 仅隔离统计（不进 L1/L2/热度），资讯流照常可查，规则过杀的代价只是少归类，可接受且可观测。

**② 近重复判定**（`NearDuplicateDetector`，纯 JDK；scope = 本批条目 × 24h 内 `l0_result=PASS` 的存量条目，跨源同稿为主、同源顺带）：

```
simhash64(title):  字元 bigram 分词 → 每片段 hash64 → 加权投票（UTF-16 码元）
                  → 64 位指纹（中文标题 20~60 字 → 20~60 bigram，稳定）
预筛:  hamming(simhash_new, simhash_old) <= 3          —— O(1) per 对
确认:  normLevenshtein(title_new, title_old) <= 0.25    —— 编辑距离 / max(len)
       且 min(len) >= 8（超短标题误并风险高，直接豁免）
主条:  同组取 published_at 最早者为 PASS 主条（同刻取 id 小者），
       其余 l0_result=NEAR_DUP, near_dup_of=主条 news_id,
       l0_detail="hamming=2;lev=0.14"
```

量级：新批 ≤30 条 × 24h 池 ≤700 条 = 2.1 万次海明比较（long 位运算）+ 通过预筛的少量编辑距离（O(60²)），毫秒级。**已知边界**：跨语言同稿（如实测样本中利比亚管道中英文三载体）标题相似度不可判，不合并——热度虚增如实保留（§8 风险）；M13 指纹精确去重先行兜底完全同文场景。

**统计口径**：每 tick 的 `l0=pass:n; noise:n; near_dup:n` 进 JobRunStats 段式明细（ADR-0036 通道）。

```

                     JSON_OBJECT, "5", cacheable=false))       // 裁决 2：绕缓存

  valid  = rows.filter(id对齐 && main∈35枚举 && conf∈[0,1])
  broken = items - valid                                          // 非法枚举/缺 id/重复 id
  for r in valid: 落库(r)                                        // 条件 UPDATE ... WHERE l1_status IN (PENDING,FAILED)
  │    兜底: confidence < floor(0.45) → main=市场·其他, low_confidence=1, raw_main=原值
```

### 4.4 L2 事件提取（`EventExtractionService` + `ImportanceScorer`）

**重要性预筛**（打分对象 = 本 tick L1 刚 DONE 的条目 + 当日 l2_status ∈ {SKIP, SELECTED} 的存量重扫；参数 `pipeline.l2` 全可配）：

```
score = sourceWeight(info_source.category)        // 政策/宏观 2.0 · 快讯 1.5 · 媒体/国际/自建 1.0
      + Σ strongTriggers 命中 × 2.0               // 业绩预告/预增/预亏/并购/重组/收购/回购/增持/减持/
      │                                           // 重大合同/中标/处罚/立案/降准/降息/关税/管制/突破/获批
      + Σ mediumTriggers 命中 × 1.0               // 签约/合作/投产/上调/下调/涨价/降价/新高/新低/停牌/复牌/
      │                                           // 辞职/聘任/上线/发布
      + subjectBonus(1.5, 命中标的池公司即计一次)
命中 = score >= threshold(缺省 2.5) → l2_status=SELECTED
```

**配额**（REQ 场景 4：命中量校准至 ≤20%）：日配额 = `quotaRatio(0.2) × 当日 L1 DONE 数`；SELECTED 按 `importance_score DESC, id ASC` 排序，超配额尾部 `l2_status=DEFERRED`（次日低峰 L2 批次先还 DEFERRED 旧账再处理当日新账，仍超则保持 DEFERRED 如实统计）。首跑校准：若命中量 >25% 连续两 tick → 提示调 threshold（页面热改，校准动作记入 `pipeline.l2` 变更留痕 runtime_config updated_at）。

### 4.5 L3 行业聚合（`HeatSnapshotService` + `DailyReportService`，零 LLM / 日报 1 次 LLM）

**热度公式**（裁决 6 参数，全部 `pipeline.heat` 可配、basis 版本化）：

```
score(industry, window) = Σ_pass条目(main=industry)  (1 + K1×impCoef(其事件)) × 0.5^(ageHours/hl(window))
                        + Σ事件(affected ∋ industry, 事件条目 main ≠ industry)  K1×impCoef × 0.5^(ageHours/hl)
  impCoef：HIGH 1.0 / MEDIUM 0.5 / LOW 0.25 / 无事件 0
  K1 缺省 10；hl：H24 窗 12h、D7 窗 48h
  ageHours = 窗口终点 - news.published_at；NOISE/NEAR_DUP/容器条目不参与（事件扩散除外）
  prev 窗口 = [窗口终点-2×窗长, 窗口终点-窗长)（等长对齐错位）；delta_pct 见表注释
basis = "heat-v1:k1=10;imp=1.0/0.5/0.25;hl=12h|48h"   // 参数热改后首快照起换串（v2），榜单脚注直读
```

事件权重双计入说明：事件条目自身行业走第一项（1+K1×coef），其余受影响行业走第二项（K1×coef）——「降准」条目 main=宏观不进榜，其事件扩散到银行/房地产拿 K1×coef，正是 REQ「容器类不进榜但事件驱动行业热度」的语义。

**快照 Job**（`IndustryHeatSnapshotJob`，FIXED_DELAY 30min）：现算 31×2 行 → UPSERT（含 0 分行沉底）+ `snapshot_at`；量级：24h 窗 ≤700 行 + 7d 窗 ≤4.4k 行 join 现算，实测预估 <50ms。

**日报 Job**（`IndustryDailyReportJob`，CRON `0 0 8 * * ?` 可配；FUSED 态跳过、DEGRADED 态保留——裁决 5）：

```
1. 统计昨日（Asia/Shanghai）：各行业 news_count/event_count（含容器计数）、Top5 行业（昨日窗热度降序）、
   代表事件（每行业 importance DESC 取 1~2 条，quote+figures 取自 event_item 结构化列）
2. render(brief_type=7, {reportDate, industryStats, topEvents}) → LLM 产出
   {summary(3~5句), topIndustries:[{industry, commentary}]×5, watchPoints[3], disclaimer}
   —— 数字一律模板注入（统计 SQL 产出），LLM 只写叙述文本；disclaimer 固定「AI 分析仅供参考」
3. 组装 content = {summary, topIndustries(合并统计数字+commentary+refEventIds),
   containerCounts, totalNews, totalEvents, disclaimer}
```

### 4.6 护栏与降级（`PipelineGuardService`）

```
level()（每 tick 批执行前调用，无表派生）:
  cost = Σ llm_call_log.cost_micros WHERE scene_key IN ('5','6','7')
         AND status='SUCCESS' AND created_at >= 今日零点(Asia/Shanghai, UTC 落库折算)
  budget = runtime.pipeline.budget.dailyBudgetMicros (缺省 2_000_000，热改即时生效)
  cost >= 0.9×budget → FUSED     : L1/L2/日报全跳过；L0/快照照常（零成本）；
                                  进入即 PushType.PIPELINE_FUSED(8) 告警一次（内存节流，重启重告一次可容忍）
  cost >= 0.6×budget → DEGRADED  : L2 全跳过（含还 DEFERRED 旧账）；L1 与日报保留；job 留痕 skipL2=n
  else               → NORMAL
恢复：查询窗口按日滚动 → 次日首 tick 自然 NORMAL；24h 补跑由待处理窗口自动覆盖（§4.3/§4.4）
红线兜底：网关层 M3 日预算硬守卫不动（管道 userId=0 虽跳过用户守卫，provider 级失败/限频仍被网关弹性链兜住）
```

**降级可见性**：`GET /api/v1/pipeline/status`（§4.8）返回 level/成本/预算/阈值/各级当日计数——热度榜与事件流页顶部横幅、成本报表、验收断言三处同源。**动作留痕**：每 tick JobRunStats 明细带 `l0=..; l1=..; l2=..; skipL2=..(degraded)`。

**单条成本校准版本化**（REQ 拍板四-4）：首日全级运行后 `校准值 = Σ管道 cost_micros ÷ 当日净入库条数` 写入 `pipeline.budget.calibratedPerItemMicros + costBasis`（初值 1100 micros = 实测 L1 ¥0.00046 + L2 推算 ¥0.0006 + 日报摊薄，附录 A）；>¥0.02 触发一次校准（批大小/阈值/配额/模板任一热改，变更留痕 runtime_config + basis 升版，同步相关方不静默）。**日报生成前后各查一次 level**，生成途中越线不回滚（单次 ¥0.01 量级，无撕裂风险）。

## 🛡️ 5. 非功能设计（逐项过）

- **性能**：批窗口 10min（实测单批 8.1s，拆批最坏 +1min）；快照现算 <50ms/31×2 行；日报软目标 ≤2min（网关 30s 超时 ×3 段重试兜底）；热度榜/事件流读端点走索引 + 游标分页（M9/M12 基线）；管道批更新短事务（≤20 行 UPDATE 毫秒级）+ 与 SOURCE_POLL 错峰偏移——SQLite 单写者无长锁。
- **容量**：日增 news_analysis ≈680、event_item ≈130、快照 62 行 UPSERT、日报 1 行；180d 峰值 news_analysis ≈12 万行（news_item 同窗同清，retention 清单 +1 表）；llm_call_log 增 ~90 行/日（L1 ~34 批 + L2 ~13 批 + 日报 1）；均在既有护栏内。
- **成本**（附录 A 实测）：L1 ¥0.000456/条；L2 推算 ¥0.0006/条均摊（≤20% × ~¥0.003/事件）；日报 ~¥0.01/日；**单条全管道初值 ≈¥0.0011**（0.02 元红线的 5.5%）；管道日成本正常水位 ≈¥0.70（缺省预算 ¥2 的 35%，护栏零误触）。deepseek-flash 为混合推理模型（实测 reasoning tokens 占输出 67%）——若 API 支持关闭 thinking，校准空间再省 ~60% 输出成本（首跑校准可选项，记 ADR 后果）。
- **安全与合规**：JWT 既有鉴权无新匿名面；管道无新密钥面（走既有网关与 DB 密文 key）；21 财经两分支语义 + 预检留档（§4.4）；AI 产出（日报叙述）固定「AI 分析仅供参考」；不做股价预测与投资指令（永久红线）；L2 quote/figures 只取原文（幻觉防线）。
- **可观测**：tick 段式明细 `l0=..; l1=..; l2=..; skipL2=..(degraded); cost=..micros`（JobRunStats/ADR-0036）；`/pipeline/status` 三面同源（横幅/成本报表/验收）；llm_call_log scene 5/6/7 天然成本归因；NOISE/NEAR_DUP/DEFERRED/FAILED 全量可查不静默。
- **降级预案**：一级降级（跳 L2 保 L1+日报）→ 二级熔断（全停 + PIPELINE_FUSED 告警）→ 网关 M3 硬守卫兜底；L0/快照恒零成本常跑；恢复 = 换日窗口滚动 + 24h 补跑，无人工介入；单点失败（模板被改坏/枚举漂移）落在失败统计可见 + 抽检信号。
- **可测性预留**：`Clock` 注入（SLA/衰减/换日恢复用例）；`LlmGateway` 端口 fake（零外呼单测拆批/兜底/配额）；`/pipeline/status` 即护栏验收断言面；4 Job 任务中心手动触发即验收工具；simhash/编辑距离/打分/热度全纯函数用例表。

## 🧪 6. 测试要点（T120~T128 单测 + T129 验收）

- **L0**：noise 关键词/正则命中与豁免；simhash 海明边界（改 1~3 字 vs 4+ 字标题）；编辑距离阈值与 minTitleLength 豁免；主条取最早 published_at；跨源同稿（实测样本 2110/2113 双源同题回放）；NOISE 不进 L1（待处理查询过滤断言）。
- **L1**：批量 schema 解析（对象包裹数组/裸数组/markdown 围栏容错）；非法枚举行进重试批；低置信兜底（confidence<0.45 → 市场·其他 + raw_main 留痕）；对半拆批递归（fake 网关第 N 次抛异常 → 断言拆批路径与 attempts 计数）；cacheable=false 断言（管道请求不读写缓存）；T+30min 口径 SQL 用例（Clock 注入构造 29/31min 边界）。
- **L2**：打分公式逐项（源权重/强中触发词/标的加成）；配额截断 DEFERRED 如实统计；次日还旧账排序；subjects 回联（命中 code / 未命中 name-only）；skipped → NO_EVENT；aiExclusion=L2 源条目照常归类不产事件；=ALL 源不建 analysis 行。
- **L3**：公式断言（REQ 场景 2：10 条含 2 高事件 vs 30 条无事件，K1=10 → A ≥ B 同新鲜度构造；场景 3：衰减压制昨热）；容器条目不进榜但事件扩散计入；prev 窗口对齐与 delta_pct 边界（prev=0）；快照 UPSERT 幂等重跑；basis 串随参数热改变更。
- **护栏**：60%/90% 两级派生（llm_call_log 造数）；DEGRADED 跳 L2 不跳 L1/日报；FUSED 全跳 + 告警一次节流；换日自动恢复（Clock 跨日）；24h 补跑窗口取数；校准值写入与 basis 升版。
- **日报**：08:00 CRON 触发（Clock）；覆盖前一日窗口；FAILED 重试 / SUCCESS 重生成 409；content 数字与统计 SQL 相等；disclaimer 存在。
- **页面**：榜单排序/空行业沉底/口径脚注/降级横幅三态；事件流四维筛选与分页三态；下钻计数=榜单数字（对账 §4.10）；testid 契约。
- **回归红线**：既有 8 Job 留痕/手动触发/热切换零变化；news_item/六源域/feed 引擎字节级不变；提示词治理既有 4 类模板零波及；1773 基线只增不减。

## 📎 附录 A · 批量归类真实小样验证留档（2026-09-22，PM 授权的一次真实外呼）

**样本**：dev 库 2026-09-25 当日真实 news_item 20 条（跨 10 源分层抽样，每源 ≤2 条；含快讯/媒体/政策/宏观/国际全部源类别）。

| 指标 | 实测值 | 结论 |
| --- | --- | --- |
