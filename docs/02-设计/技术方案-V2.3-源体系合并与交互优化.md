## ⚖️ 3. 形态决策（ADR-0062 三主裁决 + 次级裁量）

### 3.1 裁决一 · 三轨合并形态 = gov_policy 纯目录配置（JSON_API）+ 引擎纯日期分支扩展 + policy-scope-v1 单 SQL 共用读口

**接入形态三候选**：

| 候选 | 形态 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| a) 目录配置 JSON_API + `FieldMapper.toIsoDatetime` 纯日期分支 | `InfoSourceCatalog` 加一行（itemMapping TITLE/URL/DOCRELPUBTIME→title/url/publishedAt、externalId=URL、cursorType=NONE、maxItems=50、60min） | 零新 Java 类；33 源中 10+ 同通道最成熟路径；治理（启停/频控/连通性/大盘/软删）零成本继承；GovPolicyClient 及其 `datasource.POLICY` 配置耦合可随轨 A 干净删除 | 引擎需一个日期解析分支（~6 行 + 单测） | ✅ 采用 |
| b) 桥接 GovPolicyClient 为 PresetFeedAdapter | 新 adapter 类包 client | 复用既有解析代码 | **client 读 `datasource.POLICY` runtime_config 键——桥接即延长将冻结的配置域寿命**，退役目标自相矛盾；返回 raw map 仍需日期映射；多一层无谓间接 | ❌ 否决 |
| c) 新写独立 PresetFeedAdapter | 全新实现 | 无耦合 | 重复实现 JSON 数组解析/白名单过滤（client 已验证逻辑），代码量最大的「新写」 | ❌ 否决 |

**引擎扩展点（唯一代码改动）**：`FieldMapper.toIsoDatetime` 增加 `yyyy-MM-dd` 纯日期分支 → 当日 00:00 Asia/Shanghai → ISO-8601 UTC（gov.cn `DOCRELPUBTIME` 即此格式；语义对齐 V22「源仅给日期 → 归一 00:00:00」既有约定，替代现状「回落抓取时刻」的失真路径）。失败仍抛 `FieldMappingException` 整源降级（沿引擎白名单语义）。

**目录条目要点**：`sourceCode=gov_policy` / `category=政策`（第 5 个政策类源）/ endpoint=ZUIXINZHENGCE.json / UA+Referer(gov.cn) 同轨 B 既有礼貌抓取头 / `cursorType=NONE`（URL 非单调，重复轮由 `(source_id, external_id)` 唯一索引幂等吸收——ndrc_policy 同款先例）/ 60min（官方源频段上限）。种子经 `InfoSourceSeeder` seed-if-absent 自动入 `info_source` + `source_poll_state`（错峰），大盘/源管理页随 SELECT 自然纳入，**零迁移零新端点**。

**去重语义迁移（PM 裁量项）**：policy_item 的 `existsBySourceUrl` → ①同源同 URL：externalId=URL 由 `(source_id, external_id)` 唯一索引吸收；②跨源同稿：`FeedFingerprint` 归一化指纹（标题+日期）全局唯一——与既有 33 源同口径，政策条目无特例。

**policy-scope-v1 读口（次级裁量：单 SQL OR vs 两段 UNION）**：

```sql
-- PolicyScopeQueryService 共用读口（三消费面同一 SQL 骨架）
SELECT ni.id, ni.title, ni.summary, ni.url, ni.published_at,
       s.source_code, s.name AS source_name, s.category AS source_category,
       na.main_category, na.sub_industry, na.matched_subjects
FROM news_item ni
JOIN info_source s  ON s.id = ni.source_id
JOIN news_analysis na ON na.news_id = ni.id
WHERE ni.status = 1
  AND na.l0_result = 'PASS'
  AND ni.published_at >= :fromIso          -- days 窗口
  AND ( s.category = '政策'                                         -- ① 政策源（5 源，含 gov_policy）
        OR (na.l1_status = 'DONE' AND na.main_category = '监管·政策') ) -- ② 全源 L1 容器
  -- 追加过滤（全 AND）：industry → (na.main_category=:ind OR na.sub_industry=:ind)
  --                    sourceCode → 旁路①②（显式选源含宏观源，见 §4.1）
  --                    keyword → (ni.title LIKE … OR ni.summary LIKE …)
  --                    subjectCode → (na.matched_subjects LIKE '%":code"%' OR 行业∈关联集)
ORDER BY ni.published_at DESC, ni.id DESC LIMIT :limit OFFSET :offset
```

裁决：**单 SQL OR 形态**。news_item 4051 行 + 窗口裁剪 + `idx_news_published`/`idx_na_main` 在册，毫秒级；两段 UNION 在「count + 分页」双查询下 SQL 面翻倍、万行级内无实测收益（预留注释：news_item >10 万行再切 UNION 两段）。**零新索引零新表**——REQ「查询口径非物化新表」不可让步项成立。

**三消费面共用**：`PolicyScopeQueryService`（application/policy，PolicyScopeFilter 值对象：days/industry/sourceCode/keyword/subjectCode/limit/offset）——政策页列表（§4.1）、信息流 policyContents（days=7、limit=50 沿现值）、详情分区（§4.3）。口径串常量 `policy-scope-v1` 随响应 `basis` 字段返回（行业热度 basis 同款惯例）。

### 3.2 裁决二 · 双轨退役方式 = 代码整链删除（非种子停用留壳），Job 18→16

| 候选 | 形态 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| a) 代码整链删除 | 删 bean/类 + V34 清 runtime_config 两 job 键 | Job 面真 16（任务中心不再出现）；无死代码维护面；git 历史 + ADR 即留档；`job_execution_log` 历史行保留 = 「停跑留痕可查」 | 不可运行时回退（回退 = git revert 同批代码） | ✅ 采用 |
| b) 种子 enabled=false + 代码保留 | JobRuntimeConfigSeeder 置停 | 一键恢复 | JobRegistry 仍收编 bean → **任务中心仍显示两 Job，违背 Job 18→16 验收**；死代码与将冻结的 `datasource.POLICY` 配置域无限期共存 | ❌ 否决 |
| c) 仅停 Job、摘 adapter 保留 | 折中 | — | 同 b 的任务中心问题 + 半死半活最难审计 | ❌ 否决 |

**删除清单**（编译期收敛，`SourceCode.POLICY` 枚举删除由 switch 穷尽性兜底全引用面）：

- application/policy：`PolicyTendencyJob`/`PolicyTendencyService` 删除；`PolicyService`/`PolicyListView`/`PolicyPagedView`/`PolicyView`/`PolicyDetailView`/`RelatedSubjectView` 重写为 news 背书（§4.1/4.2）。
- domain/policy + infrastructure/policy：`PolicyItem`/`PolicyRepository`/`PolicyIndustryClassifier`/`AiTendency`/`PolicyListFilter`/`PolicyFetchJob`/`PolicyItemPO`/`PolicyMapper`/`PolicyRepositoryImpl` 整包删除（读面切换后零消费方）。
- 轨 A：`PolicySourceAdapter`/`GovPolicyClient`（含 INDUSTRY_KEYWORDS 字典）/`MockPolicySourceAdapter` POLICY 分支/`RoutingSourceAdapter` POLICY 路由/`SourceCode.POLICY`/`DataSourceDefaults`·`SourceCache`·`AggregationRuntimeSettings` 中 POLICY 分支——详情 fan-out 五源化（§4.3）。
- 配置域：`datasource.POLICY` runtime_config **行保留冻结留档**（零消费方，随 policy_item 一并纳入 M10 生命周期治理）；`job.POLICY_FETCH`/`job.POLICY_TENDENCY` 两键 **V34 删除**（防孤儿键校验误报）；yml `policy.fetch.*`/`policy.tendency.*` 键删除。
- `policy_item` 表：停写只读 → 读代码全下线后冻结（35 行不迁移不清理，沿「历史不回填」先例）。

**contentId 换代（次级裁量）**：`policy:{policyId}` → **`policy:news:{newsId}`**——rawId 采用 `news:{id}` 命名空间前缀，与历史 `policy:{policyId}`（1~35 与 news id 数值域重叠）**零撞名**，readingEvent 历史留痕可继续无歧义续读；换代一次性、版本化留档（本方案 + ADR-0062），历史已读不回填。类型前缀 `policy:` 保留 → POLICY 埋点语义延续（REQ 拍板六）。

**SSE/通知面**：`PushType.POLICY` 当前零消费方（代码核实）——倾向推送本就走 L2 事件通知链（M16 PushType 10 值族），**本期零改动**；「政策倾向」语义由 L2 政策发布事件的 `direction`（BULLISH/BEARISH/NEUTRAL）承接，通知徽章文案随 T205 详情视图呈现方向，链路零新增。

## 🔌 4. 接口契约

> 版本策略说明：`/api/v1/policies` 数据面原地切换而非升 v2——唯一消费方是同仓前端同批发布（T201/T205 同 PR 窗口），无第三方调用方；「批内直接切换」为 REQ 拍板一既定，换代决策 ADR-0062 留档。

### 4.1 GET /api/v1/policies（政策时事页列表 · 切换数据面）

| 参数 | 语义 | 变化 |
| --- | --- | --- |
| days / keyword / page / size | 沿 M9 页码模式与校验（2001/长度 2~64） | 不变 |
| industry | **L1 口径**：申万 31 行业（main **或** sub 命中）或 `监管·政策`（仅 main） | 原 3 行业字典语义替换 |
| sourceCode | 源筛选：显式选源时**旁路 scope ①②**（宏观源 stats_release/em_macro_indicators 可选出数） | 新增（追加式） |

响应（页码模式）：`{ policies: [{ id(news_item.id), title, summary, url, sourceCode, sourceName, publishedAt, mainCategory, subIndustry, matchedSubjects: [{code,name,industry}] }], total, page, size, basis: "policy-scope-v1" }`。游标模式随数据面同步换血（`nextCursor` = 末条 news id）；`relatedIndustries`/`aiTendency` 字段移除。

### 4.2 GET /api/v1/policies/{id}（详情视图 · id = news_item.id）

`{ id, title, summary, url, sourceCode, sourceName, publishedAt, mainCategory, subIndustry, matchedSubjects[], relatedEvents: [{ id, eventType, summary, direction, importance, eventDate }] }`——relatedEvents = `event_item WHERE news_id=:id`（UNIQUE 至多一条）；`direction` 即倾向承接面（BULLISH 利好/BEARISH 利空/NEUTRAL 中性，trace-v1 可下钻事件流）。无关联事件时空数组；aiTendency 字段删除。错误码沿 30040（404）/2001（400）。

### 4.3 GET /api/v1/subjects/{code}（详情聚合 · policies 分区新形态）

`data.policies` 从 `List<Map>` 换为分区对象（T202/T206 同批切换）：

```json
"policies": {
  "items": [ { "id": 4089, "title": "...", "url": "...", "publishedAt": "...",
               "sourceName": "中国政府网·政策", "matchType": "SUBJECT | INDUSTRY" } ],
  "fallback": { "items": [ ...同构, 无 matchType... ], "note": "暂无与该标的行业直接相关的政策，以下为近期宏观政策" },
  "basis": "policy-scope-v1"
}
```

容量：关联段与兜底段同用 `POLICY_SECTION_CAP=10`（沿 M12 分区容量惯例，常量集中定义）。`sourceStatus.policy` 恒 `"ok"`（库内查询无外呼三态）；六源 fan-out 摘 POLICY 路后 `sourceStatus` 其余键不变。分区计算为聚合服务内同步毫秒级调用（替换原 future 外呼），**首屏时延只降不升**（REQ 非功能）。

### 4.4 GET /api/v1/news-items（资讯库 · 追加式增强）

新增 `publishedFrom`/`publishedTo`（`yyyy-MM-dd`，含端点日；与 sourceId/q/l0/l1 AND 组合；清空恢复）。`LibraryFilter` 扩两字段，SQL 增 `published_at >= :fromT00:00+08 / <= :toT24:00+08` 范围条件。既有参数与响应字段零破坏（V2.1 兼容红线）。

### 4.5 源页（#/sources）

零新端点：面板数据沿 `GET /api/v1/info-sources` 与既有 datasource-config 端点；Tab/搜索/概览全前端态。
