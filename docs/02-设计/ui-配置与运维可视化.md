## 🎯 1. 设计总览与关键决策

| # | 决策 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 导航形态 | **桌面固定左侧栏（w-56），<lg 收为顶栏 + 抽屉**；废弃「Watchlist 页头部挂按钮」模式 | 12 个页面 × 4 分组顶栏放不下；`index.css` 已预置完整 `--sidebar-*` 暗 token；PRD 场景 1.1 明确「桌面侧边栏、移动端收起」 |
| D2 | 任务中心与 Job 日志关系 | **不合并，两页并存**：任务中心=控制面（5 个平台任务现状 + 手动触发 + 调度管理），Job 日志=审计面（job_execution_log 完整历史，游标分页）；任务中心每行「历史」按钮带 `?jobName=` 跳转 Job 日志预过滤 | JobLog 页已交付且验收通过（游标分页/过滤/三态齐全），内嵌重做徒增复杂度；两页导航均 ≤1 次点击可达，满足 PRD 场景 1.1 |
| D3 | 「保存即生效 vs 重启生效」区分 | **字段级生效徽章（EffectBadge）+ 保存成功反馈必须枚举生效范围**；生效方式以后端返回的 `effectiveMode` 渲染，不前端硬编码 | PRD 红线「重启生效项必须页面明示」；架构尚未裁定各参数生效机制，前端按接口返回渲染可适配两种结局 |
| D4 | 保存反馈形式 | **内联反馈条（SaveFeedbackBar），不用 toast** | 仓库无 toast 组件且零新依赖原则；内联常驻可测、可回读（aria-live） |
| D5 | 开关组件 | **自研轻量 Switch**（button + `role="switch"`，对齐 `ui/dialog.tsx` 自研先例），不引入 Radix/base-ui Switch | 仓库刻意规避重依赖（dialog 注释明示「无 base-ui Dialog 依赖以降低联调风险」）；下拉沿用 JobLog 原生 select 先例 |
| D6 | 保存粒度 | **分区保存**：全局参数区一个保存按钮，每个 provider 卡 / 数据源卡 / 每行任务独立保存 | 局部失败不污染其他区；反馈条按区聚合生效范围文案（D3） |
| D7 | 信息流分页 | **触底自动加载（IntersectionObserver 哨兵）+「加载更多」按钮兜底**，游标分页 | PRD 场景 6.1「向下滚动触发游标分页」；按钮兜底保证 IO 失败/键盘用户可用 |

**交互说明**：

1. **生效方式徽章（D3）**：模型名 / provider 启用与默认切换字段标签后置 amber「重启后生效」徽章；即时生效参数不加徽章（省噪），其生效范围在保存成功反馈中枚举。徽章渲染依据接口返回的 `effectiveMode`（§6.2 联判点 2）。
2. **保存流程**：编辑后按钮激活（未变更禁用）→ 点击进入 saving（按钮「保存中…」+ disabled）→ 成功显示反馈条（emerald，常驻至下次操作，`aria-live="polite"`）；失败显示 rose 文案 + 字段级错误定位，**原值不变**（PRD 场景 2.5）。
3. **预算二次确认**：新日预算 < 接口返回的今日已用量时，保存前弹 Dialog「预算 5000 低于今日已用 8400 token，保存后新调用将被预算守卫拦截，确认？」（PRD 风险表「配置页误操作」对策）。
4. **API Key 脱敏（PRD 场景 2.4 + 非功能红线）**：
   - 已配置：Badge「已配置（尾 4 位 \*\*\*\*abcd）」；未配置：Badge「未配置」。
   - 「更换 / 录入」打开 Dialog：`type="password"` + `autocomplete="new-password"` + placeholder「留空保持不变」；保存成功后回到脱敏态，**刷新不回显明文**；明文不写 console、不写网络日志。
5. **连通性测试**（PRD 条目 6）：每卡按钮 → 「测试中…」disabled → 内联结果「连接成功 · 312ms」（emerald）或「失败：401 密钥无效」（rose，展示后端错误码文案）；不修改任何配置。
6. **默认 provider 语义**：默认 = 单选。非默认启用卡显示 outline sm「设为默认」，点击即保存；默认卡显示 Badge「默认」。停用 provider 不可设为默认；停用当前默认 provider 需二次确认（Dialog：先选新默认或确认无默认）。
7. **单价**：`元/百万 token`，允许 0（免费档 glm）；修改只影响新调用，历史成本不重算（PRD 场景 2.3，卡片说明文案注明）。

**组件清单**：`ui/card`、`ui/badge`、`ui/button`、`ui/input`、`ui/dialog`、`ui/skeleton`、自研 `EffectBadge`、`SaveFeedbackBar`、`Switch`（§5.2）。

**三态**：

| 态 | 表现 |
| --- | --- |
| loading | 全局卡 1 行 + provider 卡 ×4 骨架（`Skeleton h-48`） |
| empty | 无 provider 条目（异常场景）：全局卡正常渲染，provider 区显示「暂无 provider 配置」muted 占位（新增/删除条目不在本期，正常不触发） |
| error | 整页加载失败：错误文案 + 重试（基线 §4.1）；保存失败/校验失败见交互 2；连通性测试失败仅内联回显不影响保存 |

**交互说明**：

1. **健康徽章**：取 `data_source_event` 最近一次结果——成功（emerald）/ 失败（rose）/ 超时（amber）+ 时间；从未抓取显示 muted「暂无抓取记录」，不报错不空白（PRD 场景 3.5）。颜色语义带文字，沿用 JobLog 状态徽章惯例。
2. **运行模式**：卡内分段选择（`Button` 组：真实=default 高亮 / mock=outline），**非 Switch**（mock ≠ 停用，两个独立概念：启用管「是否参与聚合」，模式管「真实 or 模拟数据」）。真实→mock 切换保存前弹 Dialog：「切换后该源返回模拟数据，验证完成请记得切回」，卡顶常显 mock 提示条（PRD 风险表对策）。
3. **参数编辑**：超时（ms）/ 重试（次）/ 取数条数在卡内 Input；URL 较长，卡内截断展示 + `title` 悬停全文，编辑在「编辑参数」Dialog 中（宽 Input，避免撑破卡片）。保存粒度按卡（D6）。
4. **测试抓取**：每卡按钮 → 「抓取中…」→ 内联结果（成功：耗时 + 条数；失败：错误摘要），不落库不改变配置（接口形态见 §6.2 联判点 3）。
5. **事件源特殊卡**：只读说明卡（ADR-0013：事件源读本地 anomaly-event 表），仅显示启用开关 + 最近结果，无 URL/超时/模式控件。
6. 取数条数字段仅对有分页语义的源展示（公告 3 / 新闻 20 等，来自现状配置），不适用的源显示 `—`。

**组件清单**：`ui/card`、`ui/badge`、`ui/button`、`ui/input`、`ui/dialog`、`ui/skeleton`、自研 `Switch`、`SaveFeedbackBar`。

| --- | --- |
| loading | 总超时条 + 7 卡骨架（`Skeleton h-56`） |

2. **手动触发**：「立即执行」→ 按钮立即置「触发中…」→ 接口成功后 5 秒内轮询显示「运行中」（amber 徽章 + 行内 `animate-pulse` 微动效）→ 终态后更新为成功/失败并写入 job_execution_log（PRD 场景 4.2）。

6. **调度编辑**：「编辑调度」打开 Dialog：间隔型给数字 Input（秒）；cron 型给文本 Input（前端格式粗校验 5~6 段）；停用任务也可编辑（保存后待启用生效）。
7. **启停与生效方式（PRD 场景 4.6 红线）**：Switch 切换即保存；若接口返回该操作为 `restart` 生效，切换后行内立即显示 amber 徽章「重启后生效」并保留到下次重启确认（EffectBadge 同 LLM 页）；停用需 Dialog 二次确认「停用后不再自动调度，可手动触发」。
8. **从未执行空态（PRD 场景 4.5）**：上次执行列显示 muted「从未执行」，下次执行正常展示，不报错。

| --- | --- |
| loading | 表格 5 行骨架（`Skeleton h-12` ×5） |
| empty | 任务注册表为空（异常场景）：「暂无注册任务」muted 占位（正常 5 任务恒在，不触发） |

## 🔁 4. 三态与反馈总规范

### 4.1 页面三态基线（全站统一，沿用既有惯例）

| 态 | 模式 | 说明 |
| --- | --- | --- |
| loading | 骨架屏 `Skeleton`，结构对位（卡片页 h-48/56、表格页 h-12×行数） | 不用全屏 spinner；导航不进 loading 态 |
| empty | `py-10 text-center text-sm text-muted-foreground` 占位文案；有明确去向的空态配 CTA 按钮（如信息流无订阅） | 文案具体到「去哪、做什么」，不写「暂无数据」了事 |
| error | `text-sm text-destructive` 文案（`role="alert"`）+ outline「重试」按钮 | 带具体错误原因（ApiError.msg 优先）；401 走 http 层统一跳登录 |

### 4.2 「保存即生效 vs 重启生效」视觉区分（PM 红线落地）

| 元素 | 即时生效 | 重启后生效 |
| --- | --- | --- |
| 字段级 EffectBadge | 不显示（默认，降噪） | amber outline 徽章「重启后生效」，跟在字段标签后 |
| 保存成功反馈条 | 「✓ 已保存 · 即时生效：<字段清单>」 | 「✓ 已保存 · 即时生效：<A/B>；<C> 重启后生效」必须**逐项枚举** |
| 生效方式来源 | 后端字段 `effectiveMode: hot \| restart`（§6.2 联判点 2） | 同左；接口缺失时**一律按 restart 渲染**（宁多示不漏示） |

- 禁止出现「保存成功」却不说明生效范围的静默反馈。
- 任务启停/间隔（PRD 场景 4.6「两者择一」）：同样按 `effectiveMode` 渲染，热切换则行内短暂显示「已生效」。

### 4.3 保存流程状态机（配置页通用）

```
idle ──编辑──▶ dirty ──点保存──▶ validating ──前端校验失败──▶ dirty（字段级错误，原值不变）
                  │                    │通过
                  │                    ▼
                  │              saving（按钮 disabled「保存中…」）
                  │                    ├──成功──▶ saved（反馈条，回到 idle·新值）
                  │                    └──失败──▶ dirty（反馈条 rose + 后端错误文案）
                  └──未变更时保存按钮 disabled（防误保存）
```

### 4.4 防重入态（任务中心专用）

- 运行中行：「立即执行」→ disabled + 文案「运行中…」+ 状态徽章 amber；后端「已在运行」错误码与前端状态判断**收敛为同一视觉**，不弹错误 toast/对话框。
- 触发接口在途（未返回）：按钮「触发中…」disabled，防连点。

### 4.5 API Key 脱敏规范（安全红线）

| 场景 | 规范 |
| --- | --- |
| 展示 | Badge「已配置（尾 4 位 \*\*\*\*abcd）」或「未配置」；永不出现完整明文 |
| 录入 | Dialog 内 `type="password"` + `autocomplete="new-password"` + placeholder「留空保持不变」；保存后回脱敏态，刷新不回显 |
| 日志 | 前端不 console.log 表单值；不将 key 拼进 URL 查询参数 |

## 🎨 5. 设计规范约定

### 5.1 色彩语义（复用暗色 token，零新增 CSS 变量）

| 语义 | class 约定 | 用途 | 对暗底（oklch 0.145）对比度 |
| --- | --- | --- | --- |
| 成功 / 健康 / 即时生效 | `text-emerald-400` + `bg-emerald-500/15` | 抓取成功、任务成功、连通通过 | ≥ 9:1 |
| 运行中 / 告警 / 重启生效 / mock | `text-amber-400` + `bg-amber-500/15` | STARTED、WARNING、mock 提示条 | ≥ 10:1 |
| 失败 / 超时 / 危险 / 错误文案 | `text-rose-400` + `bg-rose-500/15`（错误文本用 `text-destructive`） | FAILED、连通失败、校验错误 | ≥ 7:1 |
| 中性 / 未知 / 从未 | `bg-muted text-muted-foreground` | 从未执行、暂无记录 | ≥ 7:1 |
| 高亮（信息流命中词） | `bg-amber-500/25 text-amber-200` | KeywordHighlight | ≥ 10:1 |

- 全部状态色**同时带文字**（徽章文案），不裸用颜色传达信息（既有惯例延续）。
- 信息流类型徽章色（公告 emerald / 新闻 sky / 政策 violet / 推荐 amber）仅用于分类识别，不承担好坏语义；对比度按同档亮色选值，开发落地时跑一次对比度抽查。

### 5.2 新增自研组件清单（全部轻量、零新依赖）

| 组件 | 职责 | 实现要点 |
| --- | --- | --- |
| `AppLayout` + `AppSidebar` | 全局侧栏布局与移动端抽屉 | 纯配置渲染（静态数组），`--sidebar-*` 既有 token；active 项 `bg-sidebar-accent`；`data-testid="nav-item-*"` |

### 5.3 表单校验规范（前后端双侧，前端先行）

| 字段 | 规则 | 前端提示文案（示例） |
| --- | --- | --- |
| 日预算 | 正整数且 > 0 | 「日预算须为正整数」 |
