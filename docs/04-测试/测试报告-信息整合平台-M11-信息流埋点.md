## 4. 画像消费链路证据等级说明（任务要求专节）

**结论：数据面（落库→画像取数集）为真实运行一级证据；聚合数值与理由文本为单元/集成缝合二级证据；生成侧（真实推荐生成）未执行，按任务授权裁量「避免真实 LLM 外呼、规则兜底路径可行」降档。**

分层证据链（本报告实测）：

1. **落库（真实）**：经 8080 真实服务 POST 3 条 FEED（`announce:e2e-m11-a1` / `news:e2e-m11-n1` / `news:e2e-m11-n2`，同 subjectCode=SH600519、不同 contentRef 避开去重键——等价 PRD 场景 2.3 的「窗口外共 3 次」构造），全部 `recorded:true`，subject_id 解析为 1。
2. **画像取数集（真实库同构谓词）**：`RecommendationPersonalizer.buildProfile` 的取数经 `ReadingEventRepositoryImpl.findByUserSince`（`user_id=1 AND created_at ≥ now-30d ORDER BY id DESC LIMIT 500`，**SQL 不筛 content_type**——与 aggregateReads「不筛 contentType」javadoc 互证）。在真实库执行同构谓词：3 行 FEED 与 5 行 SUBJECT_DETAIL 同池返回，subject_id=1 聚合计数 5→8、同日口径 heat 5.0→8.0（每读 1.0），已超 READ_HEAT_FULL=3.0 饱和点 → readBonus=10.0 满格（PRD「满格 10.0」语义可达）。
3. **聚合口径（单元缝合）**：T81 三用例锁死——单条 FEED count=1/heat=1.0、与 SUBJECT_DETAIL 同日混合 count=2/heat=2.0（同权不打折不加权）、subject_id=null 跳过。
4. **理由文本（集成缝合）**：`RecommendationRelevanceIntegrationTest`（真实 beans + SQLite 内存库 + Flyway V14）断言推荐理由含「已读热度+3.3」（heat=1.0 → 10.0×⅓）；该链路为 SUBJECT_DETAIL 同构输入，FEED 因聚合不筛类型而等价流入。
5. **未覆盖（降档声明）**：未真实触发 `GET /recommendations/daily` 生成（当日无 brief_type=4 缓存，触发即真实 LLM 外呼计费）；readDaily 只读路径已经 `GET /feed/personal` 实走（AI 缓存命中分支）。**规则兜底分支（FAILED/空输出 → personalizer+scorer）未被真实服务走到**，其正确性由上述 3/4 层单元与集成证据承载。下次自然生成推荐时理由含「已读热度+」即闭环（转 §7 R2 观察项）。
