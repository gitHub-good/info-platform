## 5. 回归红线与专项定级（前后对照）

### 5.1 政策 JSON 分支 live 实证（故事 4 数据面）

判定：**JSON 分支工作正常，分区 missing 为行业过滤零命中（设计内），非源故障**。证据链：

- 直连源：`ZUIXINZHENGCE.json` HTTP 200 / 264KB / `Content-Type: application/json` / 字段 TITLE-URL-DOCRELPUBTIME 齐备（curl）；**用应用同款 truststore 的 Java 探针同样 200**（排除 JVM/TLS 因素）。
- 平台侧真实取数：服务启动（03:08:05）PolicyFetchJob 经 JSON 分支**新入库 22 条真实 gov.cn 政策**（URL 均为 zhengce/content/…，existsBySourceUrl 去重幂等）——V20+JSON 分支端到端工作；连通性测试第二次 161ms 真实外呼（第一次 33ms 为连接复用），返回 MISSING。
- MISSING 根因：连通性测试/详情分区的取数经 `PolicySourceAdapter` **行业关联过滤**（探针标的=首个启用标的），当前 30 条最新国家政策（审计法/防汛抗旱/碳达峰等）无该行业热词命中 → 0 条 → missing。与 PRD「命中本就稀疏（0~3 条常态）」「无命中维持现状」一致；与 V20 前旧 HTML 目录页选择器 0 命中的持续 exhausted（09-24 事件记录）性质不同——本轮为过滤后空、取数成功。
- data_source_event POLICY exhausted/no-data 行为沿既有降级不阻断语义（missing 兜底，非 HTTP 错）。

### 5.2 编排者移交观察项定级：announcePageSize 无上限校验

**定级：非缺陷（已闭环），不开缺陷单。** 实证：

- `PATCH /datasource-configs/ANNOUNCE` 携 `announcePageSize=100` → **400 拒绝**，msg=`params.announcePageSize: 须在 1~50 之间`——T90 已按 ADR-0037 跟进项将校验从「正整数」收紧至 1~50（`DataSourceConfigValidator.ANNOUNCE_PAGE_SIZE_MAX=50`，运行时行为与代码一致）。
- 边界闭环：`=50`（合法上界）→ 受理，子端点缺省页大小随之 50（`page=1` 无 size → size=50、50 条）；`=51/100` → 400。显式 `size` 参数仍受 PageQuery 1~50 独立校验（A6）。
- 移交描述中「DB 可为 100」为**历史存量**：旧校验（仅正整数）时期写入的 100，V19 条件迁移正确保护未动（100≠3 不迁移，用户意图优先的设计行为），编排者已手工还原 10——存量值与校验器是两个时间层的问题，当前版本下无法再写入越界值。
- 建议（记档，非必须）：数据源配置页 params 输入框可带范围提示（UI 增强，随下批排期）。
