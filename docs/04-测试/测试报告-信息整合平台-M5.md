## 4. 缺陷清单（定级与复现）

### DEFECT-1【P2】并发创建同场景版本：败者 500/50000（SQLITE_BUSY 未映射），设计承诺的 409/30070 在真实并发下不可达

> **状态：已关闭（2026-09-24）**——修复 `bdba390`（仓储 BUSY/LOCKED 码族翻译 + create/activate 双路径 30070，ADR-0023 补登第 5 条），修前红/修后绿实证 + 真机复测通过（复审全记录见 §7）。

- **复现步骤**（真实服务，HEAD `3f805cb`）：
  1. 登录取 JWT；对同一 briefType（如 1）同时发起两个 `POST /api/v1/prompt-templates`（相同合法 body，两线程并发，Python `threading` 即可稳定复现）；
  2. 观察两响应与后端日志。
- **期望**：一者 201；另一者 409/`30070 版本号冲突…（可能被并发创建，请刷新列表后重试）`（技术方案 §4.4.3 + ADR-0023-2 的 UNIQUE→DuplicateKeyException 翻译路径）。
- **实际**：一者 201（v2.1 正常落库激活）；**另一者 HTTP 500 / code 50000「服务异常」**。日志根因：`org.sqlite.SQLiteException: [SQLITE_BUSY] The database file is locked`，发生在 `PromptTemplateAdminService.create` 事务内写阶段（deactivateActive/insert）。
- **根因分析**：`create` 为 `@Transactional` 读写同事务——先 SELECT（底稿/既有版本/激活行）后 UPDATE+INSERT。WAL 下另一事务在两者之间提交时，本事务写命中**过期快照**（SQLITE_BUSY_SNAPSHOT 族，busy_timeout=5000 无法挽救），sqlite-jdbc 抛 `SQLiteException`；仓储翻译层只认 `UNIQUE` 关键字（ADR-0023-2），SQLITE_BUSY 走不进 `DuplicateKeyException` → 冒泡 500。**同机制适用于 activate/delete 的并发写**。30070 路径仅 `@SpyBean` 过期读模拟（集成测试）可达，真实并发下 SQLITE_BUSY 先于 UNIQUE 发生。
- **影响**：①错误契约偏离（50000 vs 30070，前端冲突专用 UX「已刷新请重试」不会触发，退化为通用错误反馈）；②数据层面**无损**：败者事务完整回滚、激活唯一不变量保持（实证 activeCount=1、无半行残留）、胜者结果正确、重试即成功。触发面窄：设计已裁剪并发防护（方案库 03：低频单人 + 前端二次确认），且前端同场景在途互斥锁（UI §3.5 交互 3）使 UI 路径难触发；直接 API 并发或绕过前端锁才可复现。
- **为什么自动化没拦住**：`create_uniqueConflictRollsBack_priorActiveUntouched` 用 `@SpyBean` 模拟过期读，走的是 UNIQUE 翻译路径（该路径正确）；无针对 SQLITE_BUSY 的并发集成用例。
- **修复建议（供开发参考，非指令）**：仓储翻译层将 `SQLITE_BUSY`（含 SNAPSHOT）一并翻译为可重试冲突（30070 或专用错误码，文案引导刷新重试）；或 create 改语句级自提交（沿 `RuntimeConfigRepositoryImpl` 对同类问题的既有先例）。**必须附回归用例**：双线程真写同表的集成测试（或 fake 数据源抛 SQLiteException 的翻译单测），修前红修后绿。
- **定级依据**：次要路径异常（并发边缘）+ 有绕行（重试即成）+ 数据无损 + 设计明示并发防护裁剪 → P2，本迭代内修复。

### 7.1 修复方案复核（diff 与 ADR）

- 仓储 `PromptTemplateRepositoryImpl` 三个写方法（insert/deactivateActive/updateStatus）统一把 `SQLITE_(BUSY|LOCKED)` 码族（**含 cause 链遍历**；文件库 WAL 为 BUSY/BUSY_SNAPSHOT、测试共享内存库为 LOCKED/LOCKED_SHAREDCACHE 两种隔离机制同判）翻译为 `CannotAcquireLockException`；非冲突异常原样冒泡（不吞不译）——与 §4 修复建议第一条一致（码族识别而非仅 `SQLITE_BUSY` 单串）。
